# Terminal Opener

`scripts/open-terminal.js`를 사용하여 실행 파일과 모든 인자를 각각 별도의 프로세스 항목으로 유지합니다. 셸 명령 문자열을 절대 보간하지 마세요. 모든 spawn은 `shell: false`로 유지합니다. 기본값은 실행하지 않는 계획입니다. 사용자가 실제 창을 명시적으로 요청하고 argv를 검토한 후에만 `--launch`를 사용합니다.
실행된 프로세스는 호출한 프로세스의 전체 환경을 상속하며, 비밀 값을 담은 변수도 포함됩니다. 런처는 환경을 필터링하지 않습니다. 대상 명령에 노출해도 안전한 환경을 가진 셸에서 실행하세요.

## 명령 실행

런처 옵션은 `--` 앞에 전달하고, 그 뒤에 정확히 하나의 실행 파일과 그 인자 배열을 전달합니다.

```bash
node skills/terminal-opener/scripts/open-terminal.js \
  --launch \
  --cwd /absolute/host/path \
  -- ssh -t example.test command-with-arguments
```

먼저 일반 모드로 실행합니다. WezTerm이 새 창으로 mux를 시도하게 두고, mux를 사용할 수 없으면 런처가 분리된 `wezterm start` 프로세스로 대체하게 합니다. 대체 경로를 사용했다면 JSON 출력의 `muxFailure`(또는 사람이 읽을 수 있는 실패 줄)를 확인해 mux 경로가 실패한 이유를 진단합니다.

## 터미널 설정에서 복구

사용자 설정이나 mux 상태가 요청한 명령을 방해할 수 있으면 `--recover` 또는 `--standalone`을 추가합니다. 다음 옵션으로 분리된 WezTerm 프로세스를 시작합니다.

```text
--skip-config start --always-new-process
```

복구 모드는 의도적으로 사용자의 모든 터미널 설정을 건너뛴다는 점을 예상하세요.

## 실행 전 점검

`--launch`를 생략하거나 `--dry-run`을 추가하고 `--json`을 함께 사용하면, 창을 열지 않고 정확한 실행 파일, argv, 작업 디렉터리, 터미널 어댑터, 기본 실행, 대체 실행을 확인할 수 있습니다. JSON 계획을 호출자 측의 구성 경계로 취급하세요.

명령 없이 `--detect --json`을 실행하면 터미널 사용 가능 여부를 확인할 수 있습니다. 어댑터가 없거나 지원되지 않을 때는 반환된 `action`을 따르세요. 현재 어댑터로는 WezTerm을 사용합니다. 다른 요청 터미널은 실행할 명령이 아니라 지원되지 않는 계획으로 취급합니다.
