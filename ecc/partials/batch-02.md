# batch-02

### ai-first-engineering

- **한 줄 요약**: 에이전트가 구현 대부분을 생성하는 팀을 위한 프로세스·리뷰·테스트 기준을 짧게 정리한 운영 모델 스킬.
- **설명**: 에이전트가 코드를 많이 쓰는 팀이 프로세스, 리뷰, 아키텍처를 설계할 때 참고한다. Process Shifts(계획 품질, eval 커버리지, 리뷰 초점을 문법에서 시스템 동작으로 이동), Architecture Requirements(명시적 경계, 안정된 계약, 타입 인터페이스, 결정적 테스트), Code Review(회귀, 보안 가정, 데이터 무결성, 실패 처리, 롤아웃 안전성 위주), Testing Standard(터치한 도메인의 회귀 커버리지 필수, 엣지 케이스 단언, 경계 통합 검사)를 나열한다. 실행 절차나 도구 없이 원칙 목록만 있고, 산출물은 없다.
- **분류**: 프로세스 / 팀 운영 가이드
- **관련도**: Medium
- **관련 축**: V, I
- **판단 근거**: "Code Review in AI-First Teams"가 리뷰 대상을 행동 회귀·보안·데이터 무결성 등으로 재정의하고, "Testing Standard"가 생성 코드에 대한 테스트 기준 상향을 요구한다. 다만 체크리스트 수준의 원칙 나열이며 구체적 메커니즘(게이트, 명령, 리포트)은 없다.
- **관심 포인트**: 스타일은 자동화에 맡기고 사람 리뷰는 시스템 동작에 집중시키는 역할 분담, "측정 가능한 acceptance criteria"와 eval을 AI 시대 핵심 역량으로 보는 관점, 생성 코드에 회귀 커버리지를 필수로 두는 기준.
- **확신도**: 높음

### continuous-agent-loop

- **한 줄 요약**: 자율 에이전트 루프의 유형 선택, 권장 스택, 실패 모드, 복구 절차를 간단히 정리한 스킬.
- **설명**: 자율 루프를 돌릴 때 쓰는 요약 스킬로, 본문은 매우 짧다. Loop Selection Flow가 엄격한 CI/PR 통제면 continuous-pr, RFC 분해면 rfc-dag, 탐색적 병렬 생성이면 infinite, 기본은 sequential로 분기시킨다. Combined Pattern은 RFC 분해, 품질 게이트(`/quality-gate`), eval 루프(`eval-harness`), 세션 영속화(`nanoclaw-repl`) 4단 스택을 권하고, Failure Modes(진척 없는 churn, 동일 원인 재시도, merge queue 정체, 비용 드리프트)와 Recovery(루프 동결, `/harness-audit`, 실패 단위로 범위 축소, 명시적 acceptance criteria로 재실행)를 나열한다. 실제 구현은 다른 스킬에 위임되어 이 파일에는 없다.
- **분류**: 오케스트레이션 / 루프 패턴
- **관련도**: High
- **관련 축**: F, V
- **판단 근거**: 루프 선택 흐름, 품질 게이트·eval 게이팅, Failure Modes와 Recovery(freeze, audit, scope 축소, replay)가 루프 제어와 실패 복구라는 F축을 정면으로 다룬다. 다만 본문은 개요 수준이라 상세 메커니즘은 참조된 스킬에 있다.
- **관심 포인트**: 루프 실패를 "진척 없는 churn, 같은 원인 반복 재시도, 비용 드리프트"로 유형화한 점, 복구를 동결, 감사, 범위 축소, 기준 명시 후 재실행 순서로 규정한 점, eval 게이트와 세션 영속화를 결합한 권장 스택.
- **확신도**: 중간

### skill-comply

- **한 줄 요약**: 스킬/규칙/에이전트 정의를 에이전트가 실제로 따르는지 시나리오를 자동 생성해 실행하고 준수율을 리포트하는 스킬.
- **설명**: .md 파일에서 기대 행동 시퀀스(spec)를 자동 생성하고, 프롬프트 엄격도가 낮아지는 3단계 시나리오(supportive, neutral, competing)를 만든다. `claude -p`를 실행해 stream-json으로 tool call 트레이스를 수집한 뒤, LLM이 호출을 spec 단계에 분류하고 시간 순서는 결정적으로 검사한다. 산출물은 spec, 시나리오 프롬프트, 시나리오별 준수 점수, LLM 분류 라벨이 붙은 tool call 타임라인을 담은 자립형 리포트이며, 준수율이 낮은 단계에는 hook 승격을 권고한다. `--dry-run`으로 비용 없이 spec과 시나리오만 생성할 수 있다.
- **분류**: 검증 / 준수 측정
- **관련도**: High
- **관련 축**: V, L, I
- **판단 근거**: 핵심 목적이 "지침을 줬다고 지켜질 거라 가정하지 말고 측정"하는 것이며(Key Concept: Prompt Independence), 트레이스 캡처, 분류, 순서 검증, 리포트 파이프라인이 구체적이다. 규칙과 스킬이라는 지침(I)의 이행을 행동 로그(L)로 검증(V)한다.
- **관심 포인트**: 프롬프트 지지도를 낮춰가며 준수가 유지되는지 보는 3단계 엄격도 설계, LLM 분류(의미 판단)와 결정적 순서 검사의 혼합, 준수율이 낮은 단계를 hook 강제로 승격하는 권고, 스킬/규칙/에이전트 정의 모두를 대상으로 하는 점.
- **확신도**: 높음
