# Blueprint — 구축 계획 생성기

한 줄짜리 목표를, 어떤 코딩 에이전트든 맥락 없이 바로 실행할 수 있는 단계별 구축 계획으로 바꿉니다.

## 사용 시점

- 큰 기능을 명확한 의존성 순서를 가진 여러 PR로 나눌 때
- 여러 세션에 걸치는 리팩터링이나 마이그레이션을 계획할 때
- 서브 에이전트들의 병렬 작업 흐름을 조율할 때
- 세션 사이에 맥락이 사라지면 재작업이 생기는 모든 작업

**사용하지 마세요.** 단일 PR로 끝나는 작업, 도구 호출이 3회 미만인 작업, 또는 사용자가 "just do it"이라고 말한 경우에는 사용하지 않습니다.

## 동작 방식

Blueprint는 5단계 파이프라인으로 실행됩니다.

1. **Research(조사)** — 사전 점검(git, gh 인증, 원격 저장소, 기본 브랜치)을 수행한 뒤, 프로젝트 구조, 기존 계획, 메모리 파일을 읽어 맥락을 수집합니다.
2. **Design(설계)** — 목표를 하나의 PR 크기 단계로 나눕니다(보통 3~12단계). 각 단계마다 의존성 간선, 병렬/직렬 순서, 모델 등급(최상위 모델 또는 기본 모델), 롤백 전략을 지정합니다.
3. **Draft(초안)** — `plans/` 아래에 자체적으로 완결된 Markdown 계획 파일을 씁니다. 모든 단계에는 컨텍스트 브리프, 작업 목록, 검증 명령, 완료 기준이 들어가므로, 새로운 에이전트가 앞선 단계를 읽지 않고도 어떤 단계든 실행할 수 있습니다.
4. **Review(검토)** — 체크리스트와 안티패턴 목록을 기준으로, 최상위 모델의 서브 에이전트(예: Opus)에게 적대적 리뷰를 위임합니다. 최종 확정 전에 모든 치명적 지적 사항을 수정합니다.
5. **Register(등록)** — 계획을 저장하고, 메모리 인덱스를 갱신하며, 단계 수와 병렬성 요약을 사용자에게 보여 줍니다.

Blueprint는 git과 GitHub CLI 사용 가능 여부를 자동으로 감지합니다. git과 GitHub CLI가 모두 있으면 브랜치/PR/CI 워크플로 전체를 포함한 계획을 생성합니다. 없으면 직접 모드(브랜치 없이 제자리에서 편집)로 전환합니다.

## 예시

### 기본 사용

```
/blueprint myapp "migrate database to PostgreSQL"
```

`plans/myapp-migrate-database-to-postgresql.md` 파일을 생성하며, 다음과 같은 단계를 포함합니다.
- 단계 1: PostgreSQL 드라이버와 연결 설정 추가
- 단계 2: 테이블별 마이그레이션 스크립트 작성
- 단계 3: 저장소 계층을 새 드라이버를 사용하도록 수정
- 단계 4: PostgreSQL 대상 통합 테스트 추가
- 단계 5: 기존 데이터베이스 코드와 설정 제거

### 다중 에이전트 프로젝트

```
/blueprint chatbot "extract LLM providers into a plugin system"
```

가능한 곳에서는 병렬 단계를 포함한 계획을 만듭니다(예: 플러그인 인터페이스 단계가 끝난 뒤 "Anthropic 플러그인 구현"과 "OpenAI 플러그인 구현"을 병렬로 실행). 또한 모델 등급도 지정합니다(인터페이스 설계 단계에는 최상위 모델, 구현 단계에는 기본 모델). 그리고 매 단계 후에 불변 조건을 검증합니다(예: "기존 테스트가 모두 통과한다", "core에 provider import가 없다").

## 주요 기능

- **콜드 스타트 실행** — 모든 단계에 자체적으로 완결된 컨텍스트 브리프가 있습니다. 이전 맥락이 필요 없습니다.
- **적대적 리뷰 게이트** — 모든 계획은 완전성, 의존성 정확성, 안티패턴 탐지를 다루는 체크리스트를 기준으로 최상위 모델의 서브 에이전트가 검토합니다.
- **브랜치/PR/CI 워크플로** — 모든 단계에 기본으로 포함됩니다. git/gh가 없으면 직접 모드로 자연스럽게 전환됩니다.
- **병렬 단계 탐지** — 의존성 그래프가 공유 파일이나 출력 의존성이 없는 단계를 찾아냅니다.
- **계획 변경 프로토콜** — 단계를 나누거나, 삽입하거나, 건너뛰거나, 순서를 바꾸거나, 포기할 수 있으며, 형식화된 프로토콜과 감사 기록을 남깁니다.
- **런타임 위험 없음** — 순수 Markdown 스킬입니다. 저장소에는 `.md` 파일만 있고, 훅, 셸 스크립트, 실행 가능한 코드, `package.json`, 빌드 단계가 없습니다. Claude Code의 기본 Markdown 스킬 로더 외에는 설치나 호출 시 아무것도 실행되지 않습니다.

## 설치

이 스킬은 ECC와 함께 배포됩니다. ECC가 설치되어 있으면 별도의 설치가 필요 없습니다.

### 전체 ECC 설치

ECC 저장소 체크아웃에서 작업 중이라면, 다음 명령으로 스킬이 있는지 확인합니다.

```bash
test -f skills/blueprint/SKILL.md
```

나중에 업데이트하려면, 업데이트 전에 ECC 변경 사항을 검토하세요.

```bash
cd /path/to/ECC
git fetch origin main
git log --oneline HEAD..origin/main       # review new commits before updating
git checkout <reviewed-full-sha>          # pin to a specific reviewed commit
```

### 독립 벤더링 설치

전체 ECC 설치 없이 이 스킬만 벤더링한다면, 검토가 끝난 파일을 ECC 저장소에서 `~/.claude/skills/blueprint/SKILL.md`로 복사합니다. 벤더링된 사본에는 git 원격 저장소가 없으므로, `git pull`을 실행하지 말고 검토가 끝난 ECC 커밋에서 파일을 다시 복사하여 업데이트하세요.

## 요구 사항

- Claude Code (`/blueprint` 슬래시 명령용)
- Git + GitHub CLI (선택 사항 — 전체 브랜치/PR/CI 워크플로를 활성화합니다. Blueprint는 없으면 자동으로 직접 모드로 전환합니다)
