# 에이전트 자기 평가 보고서 템플릿

작업을 마친 후 이 템플릿을 복사하여 채우세요. 형식은 `scripts/evaluate.py`의 출력과 일치합니다.

```
============================================================
AGENT SELF-EVALUATION REPORT
============================================================
Summary: 5개 품질 축에 걸친 전체 점수 X.X/5.

  Accuracy         █████ 5/5    or    ███░░ 3/5
    + [근거: 통과한 테스트, 검증된 주장]
    - [공백: 검증되지 않은 주장, 얼버무리는 표현]
    → [점수가 5 미만일 때의 개선 사항]

  Completeness      █████ 5/5
    + [다룬 내용: 모든 요구사항과 엣지 케이스]
    - [빠진 내용: 공백을 명시적으로 인정]
    → [점수가 5 미만일 때의 개선 사항]

  Clarity           █████ 5/5
    + [구조: 제목, 코드 블록, 글머리 기호]
    - [문제: 정의되지 않은 용어, 긴 글 덩어리, 요약 없음]
    → [점수가 5 미만일 때의 개선 사항]

  Actionability     █████ 5/5
    + [사용자가 할 수 있는 일: PR 머지, 명령 실행, 파일 검토]
    - [장애물: 빠진 단계, 모호한 제안]
    → [점수가 5 미만일 때의 개선 사항]

  Conciseness       █████ 5/5
    + [간결함: 중복 없음, 높은 정보 밀도]
    - [군더더기: 채우기 문구, 메타 해설, 반복되는 요점]
    → [점수가 5 미만일 때의 개선 사항]

  OVERALL           X.X/5

CRITICAL ISSUES (axes ≤ 2):
  [축] N/5 — 필요한 구체적 수정
  (2 이하인 축이 없으면 "None")

자체 점검: 사용자도 이 평가에 동의할까? [예/아니오 + 간단한 근거]

TOP IMPROVEMENTS:
  1. [영향이 가장 큰 수정]
  2. [두 번째로 큰 수정]
  (점수가 4 미만인 축만, 사용자 영향 순으로 나열)

VERDICT: [그대로 전달 / N개 문제를 고친 후 전달 / 처음부터 다시 작업]
```

## 생략 조건

다음의 경우 평가를 생략하세요:
- 작업이 단일 도구 호출이었을 때 (예: "이 파일 읽어 줘" — 평가할 것이 없음)
- 사용자가 "평가하지 마" 또는 "그냥 해"라고 명시한 경우
- 작업이 순수한 대화(인사, 잡담)인 경우
- 작업 흐름의 중간이라서, 사용자가 중간 단계가 아니라 최종 결과물을 판단할 것인 경우

## 평가 후 조치

| 전체 점수 | 할 일 |
|---|---|
| ≥4.5 | 그대로 전달. 변경 필요 없음. |
| 3.5–4.4 | 가장 큰 개선 사항을 표시하고 전달. 30초 안에 고칠 수 있으면 고침. |
| 2.5–3.4 | 무엇을 바꿀지 밝히고 사용자에게 묻기: "[축]을 다시 할까요, 아니면 그대로 전달할까요?" |
| <2.5 | 전달하지 않음. "이 결과는 [점수]점이며, 이유는 [근거]입니다. [구체적 수정]으로 다시 해 보겠습니다."라고 말한 뒤 다시 작업. |
