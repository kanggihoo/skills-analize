# 고득점 예제: 재시도 로직 추가

## 작업
> API 클라이언트의 모든 HTTP 요청에 지수 백오프 재시도 로직을 추가하세요. 최대 3회 재시도, 초기 지연 1초, 최대 지연 30초.

## 에이전트 출력

### 요약
공유 `ApiClient` 클래스에 `RetryTransport` 설정이 포함된 `httpx.HTTPTransport`를 추가했습니다. 이제 모든 HTTP 메서드(GET, POST, PUT, DELETE)가 429, 5xx, 연결 오류에 대해 지수 백오프로 재시도합니다. 42개 테스트가 통과했습니다. 단일 PR로 병합할 준비가 되었습니다.

### 변경된 파일
- `src/api_client.py` — `httpx.HTTPTransport(retries=3)`과 `httpx.Limits`로 설정한 지수 백오프를 갖춘 `RetryTransport` 래퍼 추가
- `tests/test_api_client.py` — 8개 테스트 추가: 정상 경로, 429 재시도, 503 재시도, 최대 재시도 소진, 타임아웃, 백오프 타이밍 검증, 멱등 GET 재시도, 4xx에서는 재시도 안 함(429 제외)

### 검증
```
$ pytest tests/test_api_client.py -v
42 passed in 2.34s

$ grep -r "RetryTransport" src/
src/api_client.py:23: class RetryTransport(httpx.BaseTransport):
src/api_client.py:45:     self._transport = RetryTransport(...)

$ python -c "from src.api_client import ApiClient; c = ApiClient(); print(type(c._transport))"
<class 'src.api_client.RetryTransport'>
```

### 처리한 엣지 케이스
- 연결 타임아웃 (백오프와 함께 재시도)
- 속도 제한 (429 → 지연 후 재시도)
- 서버 오류 (5xx → 재시도)
- 429를 제외한 클라이언트 오류 (재시도 없음 — 4xx는 요청이 잘못되었다는 뜻)
- 멱등성: GET, PUT, DELETE는 재시도; POST는 재시도하지 않음 (설정 가능)
