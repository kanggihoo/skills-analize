# Agent Harness 구축

에이전트가 계획을 세우고, 도구를 호출하고, 오류에서 회복하고, 완료로 수렴하는 방식을 개선할 때 이 스킬을 사용합니다.

## 핵심 모델

에이전트 출력 품질은 다음에 의해 제약됩니다.
1. 액션 공간의 품질
2. 관찰의 품질
3. 회복의 품질
4. 컨텍스트 예산의 품질

## 액션 공간 설계

1. 안정적이고 명시적인 도구 이름을 사용합니다.
2. 입력은 스키마 우선이며 좁게 유지합니다.
3. 결정적인 출력 형태를 반환합니다.
4. 격리가 불가능한 경우가 아니라면 모든 것을 처리하는 catch-all 도구를 피합니다.

## 세분성 규칙

- 고위험 작업(배포, 마이그레이션, 권한)에는 마이크로 도구를 사용합니다.
- 일반적인 편집/읽기/검색 루프에는 중간 크기 도구를 사용합니다.
- 왕복 오버헤드가 지배적인 비용일 때만 매크로 도구를 사용합니다.

## 관찰 설계

모든 도구 응답에는 다음이 포함되어야 합니다.
- `status`: success|warning|error
- `summary`: 한 줄 결과
- `next_actions`: 실행 가능한 후속 조치
- `artifacts`: 파일 경로 / ID

## 오류 회복 계약

모든 오류 경로에 대해 다음을 포함합니다.
- 근본 원인 힌트
- 안전한 재시도 지침
- 명시적인 중단 조건

## 컨텍스트 예산 관리

1. 시스템 프롬프트는 최소한으로, 불변으로 유지합니다.
2. 큰 지침은 필요할 때 로드되는 스킬로 옮깁니다.
3. 긴 문서를 인라인으로 넣기보다 파일 참조를 선호합니다.
4. 임의의 토큰 임계값이 아니라 단계 경계에서 압축합니다.

## 아키텍처 패턴 지침

- ReAct: 경로가 불확실한 탐색적 작업에 적합합니다.
- Function-calling: 구조화되고 결정적인 흐름에 적합합니다.
- 하이브리드(권장): ReAct 계획 + 타입이 있는 도구 실행.

## 벤치마킹

다음을 추적합니다.
- 완료율
- 작업당 재시도 횟수
- pass@1 및 pass@3
- 성공한 작업당 비용

## 안티 패턴

- 의미가 겹치는 도구가 너무 많음.
- 회복 힌트가 없는 불투명한 도구 출력.
- 다음 단계가 없는 오류 전용 출력.
- 관련 없는 참조로 인한 컨텍스트 과부하.
