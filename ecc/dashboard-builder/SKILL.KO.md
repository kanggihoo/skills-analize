# 대시보드 빌더

사람들이 실제로 운영에 활용할 수 있는 대시보드를 만드는 작업일 때 이 스킬을 사용한다.

목표는 "모든 메트릭을 보여주는 것"이 아니다. 다음 질문에 답하는 것이 목표다:

- 정상 상태인가?
- 병목은 어디인가?
- 무엇이 바뀌었는가?
- 누가 어떤 조치를 취해야 하는가?

## 사용 시점

- "Kafka 모니터링 대시보드를 만들어 줘"
- "Elasticsearch용 Grafana 대시보드를 만들어 줘"
- "이 서비스용 SigNoz 대시보드를 만들어 줘"
- "이 메트릭 목록을 실제 운영 대시보드로 바꿔 줘"

## 가드레일

- 시각적 레이아웃에서 시작하지 않는다. 운영자의 질문에서 시작한다.
- 존재한다는 이유만으로 사용 가능한 모든 메트릭을 넣지 않는다.
- 구조 없이 상태, 처리량, 리소스 패널을 섞지 않는다.
- 제목, 단위, 합리적인 임계값 없이 패널을 배포하지 않는다.

## 워크플로

### 1. 운영 질문 정의하기

다음 항목을 중심으로 구성한다:

- 상태 / 가용성
- 지연 시간 / 성능
- 처리량 / 볼륨
- 포화도 / 리소스
- 서비스별 위험

### 2. 대상 플랫폼 스키마 살펴보기

먼저 기존 대시보드를 살펴본다:

- JSON 구조
- 쿼리 언어
- 변수
- 임계값 스타일링
- 섹션 레이아웃

### 3. 최소한의 유용한 보드 만들기

권장 구조:

1. 개요
2. 성능
3. 리소스
4. 서비스별 섹션

### 4. 보여주기용 패널 잘라내기

모든 패널은 실제 질문에 답해야 한다. 그렇지 않다면 제거한다.

## 패널 세트 예시

### Elasticsearch

- 클러스터 상태
- 샤드 할당
- 검색 지연 시간
- 인덱싱 속도
- JVM 힙 / GC

### Kafka

- 브로커 수
- 복제가 부족한(under-replicated) 파티션
- 수신 / 송신 메시지
- 컨슈머 랙(lag)
- 디스크 및 네트워크 부하

### API 게이트웨이 / 인그레스

- 요청 속도
- p50 / p95 / p99 지연 시간
- 에러율
- 업스트림 상태
- 활성 연결 수

## 품질 체크리스트

- [ ] 유효한 대시보드 JSON
- [ ] 명확한 섹션 그룹화
- [ ] 제목과 단위가 있음
- [ ] 임계값/상태 색상이 의미를 가짐
- [ ] 일반적인 필터를 위한 변수가 존재함
- [ ] 기본 시간 범위와 새로고침 주기가 합리적임
- [ ] 운영자에게 가치가 없는 보여주기용 패널이 없음
