# PPTX 생성, 편집, 분석

`.pptx`는 XML 파일을 담은 ZIP 아카이브다. 작업에 따라 방법을 고른다:

| 작업 | 방법 |
|---|---|
| **새로 만들기**: 새 deck 생성 | `pptxgenjs` 스크립트를 작성한다. 아래 함정을 참고한다 |
| **편집**: 기존 deck을 고치거나 템플릿으로 만들기 | 압축 해제 → `ppt/slides/slideN.xml` 편집 → 다시 압축 |
| **읽기**: 내용 읽기 | `markitdown deck.pptx` (`<!-- Slide number: N -->` 마커 아래에 슬라이드마다 블록 하나씩 나온다). 시각적 격자는 `python scripts/thumbnail.py deck.pptx` |

## 스크립트

경로는 이 스킬 디렉터리 기준 상대 경로다. 나머지는 일반 Python, `node`, 셸 스크립트다.

| 스크립트 | 역할 |
|---|---|
| `scripts/thumbnail.py deck.pptx [prefix]` | 모든 슬라이드를 라벨이 붙은 격자 이미지로 만든다. 템플릿 레이아웃을 고를 때 쓴다. `.pptx`만 지원한다. `prefix`를 꼭 넘겨라. 기본값은 `thumbnails`라서, 같은 디렉터리에서 작업한 다른 deck의 격자 이미지를 덮어쓴다 |
| `scripts/add_slide.py unpacked/ slide2.xml [--after slideN.xml]` | 패키지 관리 작업을 모두 처리하며 슬라이드(또는 `slideLayoutN.xml`)를 복제한다. `-o out.pptx`와 함께 `.pptx` 파일을 직접 받을 수도 있다 |
| `scripts/clean.py unpacked/` | 더 이상 참조되지 않는 슬라이드, 미디어, rels를 삭제한다. `<p:sldIdLst>`가 **확정된 뒤에** 실행한다 |
| `scripts/office/validate.py deck.pptx [--original src.pptx]` | 스키마, 관계(relationship), 콘텐츠 타입, 차트, 슬라이드를 검사한다. 실패할 때마다 수정 방법을 함께 알려준다. 템플릿에서 만든 deck에는 `--original`을 넘겨라. 템플릿을 기준으로 스키마 검사를 맞춰서, 템플릿 자체의 XSD 오류가 내 실수처럼 보이지 않게 한다 |
| `scripts/office/soffice.py --headless --convert-to pdf deck.pptx` | LibreOffice 래퍼다. 이 샌드박스에서는 그냥 `soffice`를 쓰면 멈춘다 |

## pptxgenjs로 생성할 때의 함정

`pptxgenjs`는 이미 설치되어 있다. `npm install`부터 실행하지 말고, 스크립트를 작성해서 `require('pptxgenjs')`를 바로 호출하라. 이 require가 실패할 때만 `npm install pptxgenjs`를 실행한다. API는 모델이 이미 알고 있으므로, 아래는 실제로 자주 걸리는 함정만 정리한 것이다.

- **슬라이드를 추가하기 전에 `pres.layout`을 설정하라.** 기본 캔버스인 `LAYOUT_16x9`는 **10" × 5.625"**이지, 13.3" 너비가 아니다. 가장자리를 넘는 좌표는 클램프되지 않고 그대로 기록되므로, 해당 도형은 슬라이드 밖에 놓인다. (`LAYOUT_WIDE`는 13.3" × 7.5"다.)
- **16진수 색상에는 `#`을 붙이지 말고, 8자리로 쓰지 마라.** `color: "FF0000"`처럼 쓴다. `"#FF0000"`이나 hex에 알파를 넣은 `"00000020"`은 **파일을 손상시킨다**. 투명도는 채우기와 이미지에서는 `transparency: 0-100`, 그림자에서는 `opacity: 0.0-1.0`으로 준다. 각 옵션은 반대 대상에서는 조용히 무시된다.
- **pptxgenjs는 옵션 객체를 제자리에서 변경한다.** 첫 사용 시 값을 EMU로 바꾼다. 옵션 객체 하나(예: `shadow`)를 `add*` 호출 두 개에 공유하지 마라. 호출할 때마다 새 객체를 만든다.
- **그림자 `offset`은 0 이상이어야 한다.** 음수면 파일이 손상된다. 그림자를 위쪽으로 드리우려면 `angle: 270`에 양수 offset을 준다.
- **`letterSpacing`은 조용히 무시된다.** 실제 옵션은 `charSpacing`이다.
- **목록:** 각 항목에 `bullet: true`를 주고, 리터럴 `•`는 쓰지 마라. 글머리 기호가 두 번 나온다. 배열의 마지막 항목을 제외한 모든 항목에 `breakLine: true`를 설정한다. 글머리 기호가 있는 단락의 간격은 `lineSpacing`이 아니라 `paraSpaceAfter`로 준다. `lineSpacing`을 쓰면 간격이 과하게 벌어진다.
- **출력 파일 하나마다 `new pptxgen()`을 한 번만 호출하라.** 인스턴스를 재사용하지 마라.
- **`rectRadius`는 `ROUNDED_RECTANGLE`에서만 동작한다.** `RECTANGLE`에서는 동작하지 않는다.
- **그라데이션 채우기는 지원하지 않는다.** 대신 그라데이션 이미지를 배경으로 쓴다.
- **텍스트 상자에는 내부 여백이 기본으로 들어 있다.** 텍스트를 같은 x 위치의 도형, 선, 아이콘에 맞춰야 하면 `margin: 0`을 설정한다.
- **발표자 노트는 `slide.addNotes("...")`로 넣는다.** 일반 텍스트이고, 슬라이드마다 한 번만 쓴다. 슬라이드 위 텍스트 상자에 넣지 마라.
- **차트는 네이티브로 유지하라.** PowerPoint가 차트로 그릴 수 있는 것은 모두 `addChart()`로 만든다. 콤보 차트는 `{type, data, options}` 배열을 넘긴다. 라이브러리가 노출하지 않는 PowerPoint 네이티브 기능(추세선, 오차 막대 등)은 추가 시리즈를 직접 계산하거나, 생성된 OOXML을 후처리한다. 렌더링한 이미지로 대체하지 마라. PowerPoint에 네이티브 형태가 없는 차트 종류(Sankey, network, chord)만 이미지로 넣는다.
- **기본 차트는 장식 없이 그려진다.** 제목도, 데이터 레이블도 없고, 낡은 팔레트가 쓰인다. `showTitle` + `title`을 설정하고, `showValue: true` + `dataLabelPosition`을 설정하고, 팔레트로 `chartColors: [...]`를 지정한다. 프레임은 차분하게 정리한다(`catAxisLabelColor`/`valAxisLabelColor`, `valGridLine: { color, size }`, `catGridLine: { style: "none" }`, 시리즈가 하나뿐이면 `showLegend: false`).
- **누적 막대형 또는 누적 세로 막대형 차트에서 `dataLabelPosition`은 `ctr`, `inEnd`, `inBase` 중 하나여야 한다.** `outEnd`는 **파일을 손상시킨다**.
- **`secondaryValAxis`/`secondaryCatAxis`를 쓰는 콤보 시리즈에는 차트 옵션에 `valAxes`와 `catAxes`가 모두 필요하며, 각각 항목이 두 개씩 있어야 한다.** 없으면 pptxgenjs는 선언하지 않은 축 *id*를 기록하고, PowerPoint는 **그 차트를 버리고** 파일을 손상된 것으로 보고한다. `valAxes`만 넣는 것으로는 충분하지 않다.
- **`writeFile()` 뒤에는 `python scripts/office/validate.py deck.pptx`를 실행하라.** 위 두 가지 차트 결함과, PowerPoint가 거부하는 슬라이드 XML 결함을 찾아내고, 각각의 수정 방법을 알려준다. 패킹된 XML을 손으로 고치지 말고, 생성 코드에서 고쳐라.
- **`<p:presentation>`의 자식 요소 순서를 바꾸지 마라.** pptxgenjs는 `<p:notesMasterIdLst>`를 `<p:sldIdLst>` 바로 뒤에 쓰고, 두 마스터가 같은 테마 파트를 가리키게 한다. PowerPoint는 이것을 문제없이 읽지만, 요소를 옮기면 같은 deck이 열리지 않게 된다.
- **아이콘:** `react-icons`를 SVG로 렌더링하고(`ReactDOMServer.renderToStaticMarkup`), `sharp`로 256px 이상 래스터화한 뒤, `addImage({ data: "image/png;base64," + buf.toString("base64") })`로 넣는다. `image/png;base64,` 접두사는 필수다. `react-icons`, `react`, `react-dom`, `sharp`는 미리 설치되어 있다. require가 실패할 때만 `npm install react-icons react react-dom sharp`를 실행한다.

## 기존 deck과 템플릿 편집

먼저 레이아웃을 고른다. `python scripts/thumbnail.py template.pptx template-thumbs`는 모든 슬라이드의 라벨이 붙은 격자 이미지를 만들고, 생성한 파일 이름을 출력한다. 12장을 넘으면 `template-thumbs-N.jpg`로 나뉜다. **두 번째 인자는 항상 deck 이름을 따서 지정하라.** 기본값은 `thumbnails`라서, 같은 디렉터리에서 deck 두 개를 썸네일로 만들면 서로의 격자 이미지를 조용히 덮어쓴다. 첫 번째 deck의 이미지는 그냥 사라진다. 이 격자는 템플릿 분석용이다. 시각 QA에는 [이미지로 변환](#이미지로-변환)에서 만드는 전체 해상도 렌더링이 필요하다. 이 명령은 `.pptx`만 받으므로, `.potx`는 먼저 `.pptx` 이름으로 복사하라. `markitdown`과 함께 써서 각 콘텐츠 섹션을 템플릿 슬라이드에 대응시키고, 레이아웃은 다양하게 써라. 모든 섹션을 같은 제목-글머리 기호 슬라이드에 넣지 마라.

```bash
python3 -c "import sys,zipfile; zipfile.ZipFile(sys.argv[1]).extractall('unpacked')" deck.pptx
python scripts/add_slide.py unpacked/ slide2.xml --after slide2.xml   # 슬라이드(또는 slideLayoutN.xml)를 복제한다. 새 슬라이드의 경로를 출력한다
# 슬라이드 순서 변경과 삭제 = ppt/presentation.xml의 <p:sldIdLst> 편집
python scripts/clean.py unpacked/                                     # 삭제 후 실행한다. 고아 슬라이드, 미디어, rels를 제거한다
# ppt/slides/slideN.xml에서 슬라이드 내용을 편집한다
(cd unpacked && rm -f ../out.pptx && zip -Xr ../out.pptx .)           # 반드시 디렉터리 안에서 zip한다. rm을 먼저 해야 삭제된 파트가 남지 않는다
python scripts/office/validate.py out.pptx --original deck.pptx
```

- **슬라이드 내용을 편집하기 전에 구조 작업(추가, 삭제, 순서 변경)을 모두 끝내라.** `add_slide.py`는 슬라이드 파일을 그대로 복사한다. 편집한 뒤에 복제하면 편집된 내용까지 복제된다. `clean.py`는 `<p:sldIdLst>`에 없는 슬라이드를 모두 삭제하는데, 방금 작성한 슬라이드도 예외가 아니다.
- **슬라이드 파일을 손으로 복사하지 마라.** `add_slide.py`가 새 슬라이드에 필요한 등록 작업을 모두 처리하고, 무엇을 만들었는지 보고한다(`Created ppt/slides/slide17.xml from slide2.xml`). 파일에 직접 쓸 수도 있다: `add_slide.py deck.pptx slide2.xml -o out.pptx`. **`-o`를 붙여라.** 없으면 입력 deck을 그 자리에서 덮어쓴다. 복제된 슬라이드는 원본의 차트, SmartArt, 내장 개체 파트를 복제하지 않고 *참조*한다. 그래서 한 슬라이드의 차트를 편집하면 다른 슬라이드의 차트도 바뀐다.
- **`python-pptx`를 쓴다면** 다음 세 가지는 지원하지 않는다는 점을 기억하라. 슬라이드 복제(진입점이 `add_slide(layout)`뿐이다), `text_frame.text = "..."`로 서식 유지(단락이 스타일 없는 단일 run으로 합쳐진다. 대신 `run.text`에 값을 넣어라), 대부분의 템플릿 아트가 쓰는 SVG/EMF 읽기(`add_picture`가 `UnidentifiedImageError`를 낸다).
- 구형 `.ppt`는 먼저 변환해야 한다: `python scripts/office/soffice.py --headless --convert-to pptx file.ppt`. `.potx` 템플릿은 풀고 묶는 방식이 `.pptx`와 같다. 출력 파일은 `.potx` 확장자를 유지하라.
- 템플릿 아이콘이나 이미지를 재사용하려면, 그것이 이미 들어 있는 슬라이드나 레이아웃을 복제하라.

템플릿을 채울 때는 다음을 지켜라.

- XML 변환을 스크립트로 작성한다면 `defusedxml.minidom`으로 파싱하라. OOXML을 `xml.etree.ElementTree`로 왕복 처리하면 네임스페이스 접두사가 바뀌어 deck이 손상된다.
- **템플릿 슬롯과 원본 항목은 다르다.** 템플릿에 팀원 4명이 보이는데 원본에는 3명뿐이라면, 4번째 팀원의 그룹 전체(이미지 + 텍스트 상자)를 삭제하라. 텍스트만 지우지 마라. 그리고 QA에서 짝을 잃은 시각 요소가 남았는지 확인하라.
- **목록 항목마다 `<a:p>`를 하나씩 쓴다.** 항목을 한 단락에 이어 붙이지 마라. 간격을 유지하려면 형제 `<a:pPr>`를 복사한다. 제목, 섹션 헤더, 인라인 라벨(`Status:`, `Owner:`)의 `<a:rPr>`에는 `b="1"`을 준다.
- 글머리 기호는 레이아웃에서 상속받게 하라. 재정의할 때만 `<a:buChar>`, `<a:buAutoNum>`(번호 목록), `<a:buNone>`을 추가한다. 텍스트에 리터럴 `•`를 넣지 마라.
- 앞뒤에 공백이 있는 텍스트는 `<a:t>`에 `xml:space="preserve"`가 필요하다.

## 디자인 아이디어

**지루한 슬라이드를 만들지 마라.** 흰 배경에 평범한 글머리 기호는 아무에게도 인상을 주지 못한다. 슬라이드마다 아래 목록에서 아이디어를 검토하라.

### 시작하기 전에

- **대담하고 콘텐츠에 맞는 색 팔레트를 골라라**: 팔레트는 이 주제를 위해 디자인된 것처럼 느껴져야 한다. 같은 색을 전혀 다른 프레젠테이션에 넣어도 "그럴듯하게" 작동한다면, 색 선택이 충분히 구체적이지 않은 것이다.
- **균등하게 나누기보다 주도색을 세워라**: 색 하나가 시각적 무게의 60–70%를 차지하게 하고, 보조 톤 1–2개와 날카로운 강조색 하나를 둔다. 모든 색에 같은 무게를 주지 마라.
- **어두운 배경과 밝은 배경의 대비**: 제목과 결론 슬라이드는 어두운 배경, 콘텐츠 슬라이드는 밝은 배경을 써서 "샌드위치" 구조를 만든다. 또는 프리미엄 느낌을 위해 처음부터 끝까지 어둡게 간다.
- **시각적 모티프 하나를 정하고 끝까지 지켜라**: 고유한 요소 하나를 골라 반복한다. 둥근 이미지 프레임, 색 원 안의 아이콘 등이 예다. 모든 슬라이드에 같은 요소를 이어 가라. **색 막대나 강조 띠를 모티프로 쓰지 마라**(피할 것 목록 참고).

### 슬라이드마다

**모든 슬라이드에는 시각 요소가 있어야 한다.** 이미지, 차트, 아이콘, 도형 중 하나다. 텍스트만 있는 슬라이드는 기억에 남지 않는다.

**레이아웃 옵션:**
- 두 단 구성(왼쪽 텍스트, 오른쪽 일러스트)
- 아이콘 + 텍스트 행(색 원 안의 아이콘, 굵은 제목, 아래 설명)
- 2x2 또는 2x3 격자(한쪽에 이미지, 다른 쪽에 콘텐츠 블록 격자)
- 반쪽을 꽉 채운 이미지(왼쪽 또는 오른쪽 전체)에 콘텐츠를 겹친다

**데이터 표현:**
- 큰 수치 강조(60–72pt 큰 숫자, 아래에 작은 라벨)
- 비교 열(전/후, 장단점, 나란히 놓은 선택지)
- 타임라인 또는 프로세스 흐름(번호 붙은 단계, 화살표)

**시각적 다듬기:**
- 섹션 헤더 옆의 작은 색 원 안 아이콘
- 핵심 수치나 태그라인에는 기울임 강조 텍스트

### 타이포그래피

**`.pptx`에 적는 글꼴 이름은 이 환경이 아니라 사용자의 PowerPoint가 렌더링한다.** 시각 QA는 LibreOffice로 렌더링하는데, LibreOffice는 없는 글꼴을 대체 글꼴로 바꾼다. 일부 글꼴은 대체 글꼴의 너비가 달라서, QA 미리보기에서는 텍스트가 넘치거나(또는 맞아 보이지만), 실제 deck에서는 그렇지 않을 수 있다. QA를 믿을 만하게 유지하려면 다음을 지켜라.

- **안전한 글꼴**(QA에서 너비가 정확하게 렌더링되고, *동시에* Office에 기본 포함된 글꼴): **Arial, Calibri, Cambria, Times New Roman, Courier New, Bookman Old Style, Century Schoolbook**. 본문과, 맞춤이 중요한 모든 곳에 이 글꼴을 써라.
- **QA 위험 없이 개성 있는 헤더**: 안전 목록의 세리프 헤더(Cambria, Bookman Old Style, Century Schoolbook)와 안전 목록의 산세리프 본문(Calibri 또는 Arial)을 짝지어라. 넘침 검사를 믿을 수 있는 상태를 유지하면서도 시각적 대비를 얻을 수 있다.
- **사용자가 안전 목록 밖의 글꼴을 요청하면**(예: Georgia 또는 Trebuchet MS): 요청한 곳에는 그대로 쓰되, 그 컨테이너는 여유를 더 두고(약 10%) 크기를 잡는다. 그 요소의 QA 텍스트 맞춤 결과는 신뢰하지 마라. 그 글꼴의 미리보기는 근사치다. 사용자가 지정하지 않았다면 본문에는 안전 목록 글꼴을 우선 써라.
- **QA 결과를 믿기 어려운 글꼴**(대체 글꼴의 너비가 달라서 넘침 검사가 틀릴 수 있다): Georgia, Trebuchet MS, Impact, Arial Black, Garamond, Consolas, Palatino Linotype. Calibri Light는 환경에 따라 대체 방식이 달라서 QA 결과를 믿기 어려운 것으로 취급하라. 여유를 두고 제목이나 강조용으로는 쓸 수 있지만, 이 글꼴들의 QA 텍스트 맞춤 결과는 믿지 마라.
- **Aptos를 기본값으로 쓰지 마라.** Office가 2023년 이후 기본으로 삼은 글꼴인데, 이 환경에는 메트릭 호환 대체 글꼴이 없고, 구버전 Office에는 아예 없다. 양쪽 모두에서 믿을 수 없다.

| 요소 | 크기 |
|---------|------|
| 슬라이드 제목 | 36–44pt 굵게 |
| 섹션 헤더 | 20–24pt 굵게 |
| 본문 | 14–16pt |
| 캡션 | 10–12pt, 차분한 색 |

### 간격

- 최소 여백은 0.5"
- 콘텐츠 블록 사이는 0.3–0.5"
- 여백을 남겨라. 1인치마다 채우지 마라.

### 피할 것 (흔한 실수)

- **같은 레이아웃을 반복하지 마라.** 슬라이드마다 열, 카드, 강조 상자를 바꿔라.
- **본문을 가운데 정렬하지 마라.** 단락과 목록은 왼쪽 정렬하고, 제목만 가운데 정렬하라.
- **크기 대비를 아끼지 마라.** 14–16pt 본문과 구분되려면 제목은 36pt 이상이어야 한다.
- **파란색을 기본값으로 쓰지 마라.** 주제를 반영하는 색을 골라라.
- **간격을 무작위로 섞지 마라.** 0.3" 또는 0.5" 중 하나를 정해 일관되게 써라.
- **한 슬라이드만 꾸미고 나머지는 밋밋하게 두지 마라.** 전부 제대로 꾸미거나, 처음부터 끝까지 단순하게 가라.
- **텍스트만 있는 슬라이드를 만들지 마라.** 이미지, 아이콘, 차트, 시각 요소를 넣어라. 제목 + 글머리 기호만 있는 구성은 피하라.
- **텍스트 상자 여백을 잊지 마라.** 선이나 도형을 텍스트 가장자리에 맞출 때는 텍스트 상자에 `margin: 0`을 주거나, 여백만큼 도형 위치를 보정하라.
- **대비가 약한 요소를 쓰지 마라.** 아이콘과 텍스트 모두 배경과 뚜렷하게 대비되어야 한다. 밝은 배경에 밝은 텍스트, 어두운 배경에 어두운 텍스트를 쓰지 마라.
- **제목 아래에 강조선을 절대 쓰지 마라.** AI가 만든 슬라이드의 전형적인 특징이다. 여백이나 배경색을 써라.
- **장식용 색 막대나 강조 띠를 절대 추가하지 마라.** 여기에는 슬라이드 너비를 가로지르는 머리글/바닥글 막대, 슬라이드 한쪽 가장자리를 따라 내려오는 세로 사이드바 띠, 카드나 콘텐츠 블록 한쪽 가장자리를 따라 있는 얇은 강조 띠, 사각형의 "한쪽 면 테두리"가 모두 포함된다. 이런 요소는 AI가 만든 채움 요소로 읽힌다. 카드를 돋보이게 하고 싶다면 옅은 배경 틴트, 그림자, 아이콘을 써라. 가장자리 띠는 쓰지 마라.
- **크림이나 베이지 배경을 기본값으로 쓰지 마라.** 배경이 지정되지 않았다면 흰색(`FFFFFF`) 또는 사용자의 브랜드 팔레트를 써라. `F5F5DC`, `FAF0E6`, `FAEBD7`, `FFF8E1` 같은 따뜻한 중립색 기본값은 피하라.
- **도형을 넘치는 텍스트를 배포하지 마라.** 텍스트가 들어가지 않으면 글자 크기를 줄이거나, 여러 슬라이드로 나누거나, 컨테이너를 키워라. 콘텐츠가 잘리거나 경계를 넘어가게 두지 마라.

## QA (필수)

첫 렌더링에는 보통 실제 문제가 몇 개 있다. 겹침, 넘침, 정렬 어긋남 같은 것들이다. 이것들을 찾아 고치고, 바꾼 슬라이드만 다시 렌더링한 뒤 멈춰라.

### 콘텐츠 QA

```bash
markitdown output.pptx
```

누락된 내용, 오타, 잘못된 순서가 없는지 확인하라.

**템플릿을 쓸 때는 남은 placeholder 텍스트가 없는지 확인하라:**

```bash
markitdown output.pptx | grep -iE "\bx{3,}\b|lorem|ipsum|\bTODO|\[insert|this.*(page|slide).*layout"
```

grep에 결과가 나오면, 성공을 선언하기 전에 고쳐라.

### 파일 QA (필수)

```bash
python scripts/office/validate.py output.pptx                      # 처음부터 만든 경우
python scripts/office/validate.py output.pptx --original src.pptx  # 템플릿에서 만든 경우
```

**deck이 템플릿에서 왔다면 반드시 `--original`을 넘겨라.** 템플릿 자체에 XSD가 거부하는 파트가 있을 수 있다. 그래서 옵션 없이 실행하면 내가 만들지 않은 실패가 보고될 수 있고, 진짜 회귀는 그 사이에 묻힐 수 있다. `--original`은 스키마와 슬라이드 검사를 템플릿 기준으로 맞춰서, 템플릿에 이미 있던 오류는 억제한다. 관계, 콘텐츠 타입, 차트 같은 구조 검사는 `--original`을 무시하고, 어느 쪽이든 템플릿에서 물려받은 문제를 보고한다. 그 결과는 그 자체로 판단하라.

pptxgenjs는 PowerPoint가 열기를 거부하는 차트 XML을 만들어 내지만, 다른 도구는 모두 받아들인다. python-pptx는 그런 deck을 열고, LibreOffice는 렌더링하고, XSD도 통과시킨다. 모든 실패에는 수정 방법이 함께 나온다. 생성기에서 고치고 다시 빌드하라.

### 시각 QA

슬라이드를 이미지로 변환하고([이미지로 변환](#이미지로-변환) 참고) 모든 장을 확인하라. 생성 코드를 오래 들여다본 뒤에는 실제 렌더링 결과가 아니라 기대한 모습을 보기 쉬우므로, 이미지를 새 눈으로 봐라. 서브에이전트가 있다면 이 일을 맡기면 잘 된다. 사용자에게 보이는 결함은 다음과 같다.

- **상자나 슬라이드 경계에서 텍스트가 넘치거나 잘리는지. 이것을 가장 먼저 확인하라.** 가장 흔한 결함이고, 항상 사용자에게 보인다. (타이포그래피 항목에서 말한, 미리보기가 신뢰하기 어려운 글꼴이라면 미리보기는 근사치다. 보이는 맞춤 결과가 아니라 남겨 둔 약 10% 여유를 믿어라.)
- 요소 겹침(텍스트가 도형을 관통하거나, 선이 단어를 관통하거나, 요소가 겹쳐 쌓임)
- 출처 표기나 바닥글이 위의 콘텐츠와 부딪힘
- 요소가 너무 가깝다(0.3" 미만 간격), 또는 카드/섹션이 거의 맞닿아 있다
- 간격이 고르지 않다(한쪽은 큰 빈 공간, 다른 쪽은 빽빽함)
- 슬라이드 가장자리 여백이 부족하다(0.5" 미만)
- 열이나 비슷한 요소의 정렬이 일관되지 않다
- 대비가 낮은 텍스트(예: 크림색 배경 위의 밝은 회색 텍스트)
- 텍스트를 바꾼 뒤 템플릿 장식의 위치가 어긋남(예: 한 줄용으로 놓인 제목 밑줄인데, 바뀐 제목이 두 줄로 줄바꿈됨)
- 대비가 낮은 아이콘(예: 대비되는 원 없이 어두운 배경 위의 어두운 아이콘)
- 텍스트 상자가 너무 좁아서 줄바꿈이 과하게 생김
- 남은 placeholder 콘텐츠

## 이미지로 변환

시각 확인을 위해 프레젠테이션을 슬라이드별 이미지로 변환하라.

```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
rm -f slide-*.jpg
pdftoppm -jpeg -r 150 output.pdf slide
ls -1 "$PWD"/slide-*.jpg
```

**위에서 출력된 절대 경로를 그대로 뷰 도구에 넘겨라.** `rm`은 이전 실행의 오래된 이미지를 지운다. `pdftoppm`은 페이지 수에 맞춰 0을 채운다. 10페이지 미만 deck은 `slide-1.jpg`, 10–99페이지는 `slide-01.jpg`, 100페이지 이상은 `slide-001.jpg`다.

**수정한 뒤에는 위의 명령 네 개를 모두 다시 실행하라.** 편집된 `.pptx`로부터 PDF를 다시 만들어야 `pdftoppm`이 변경 사항을 반영할 수 있다.

## 의존성

`pptxgenjs`(npm, 미리 설치됨. `require('pptxgenjs')`가 실패할 때만 설치) · `markitdown[pptx]`, `Pillow`, `defusedxml`, `lxml`(pip. 텍스트 추출, 썸네일, clean, validate에 쓰임) · LibreOffice(`soffice`, `scripts/office/soffice.py`를 통해 샌드박스 환경에 자동 설정됨) · `pdftoppm`(Poppler)
