# XLSX 생성, 편집, 분석

| 작업 | 접근 방식 |
|---|---|
| 수식/서식을 포함해 **생성**하거나 **편집** | `openpyxl` 사용. 아래 gotchas 참고 |
| 데이터를 대량으로 **입출력** | `pandas` 사용(`read_excel`, `to_excel`) |
| 시트를 **빠르게 훑어보기** | `markitdown file.xlsx`. 시트마다 `## SheetName` 헤더로 출력하고 `.xlsm`도 읽는다. 셀 좌표가 없으므로 이 결과로 편집 계획을 세우지 않는다 |
| 모델을 **읽기**(수식*과* 값 모두) | `load_workbook`을 두 번 호출한다. 아래 gotchas 참고 |

> `openpyxl`, `pandas`, `markitdown`은 이미 설치되어 있다. 먼저 `pip install`을 실행하지 말고 스크립트를 작성해 바로 import한다. import가 실패하거나 `markitdown` 명령이 없을 때만 빠진 패키지를 `pip install`한다.

> 아래 스크립트 경로는 이 스킬 폴더 기준 상대 경로다.

## 모든 결과물의 필수 요건

- 사용자가 다르게 말하지 않는 한 **전체에 전문적인 글꼴**(Arial, Times New Roman)을 쓴다.
- **수식 오류는 0개여야 한다.** `recalc.py`가 `errors_found`를 보고하는 상태로 파일을 넘기지 않는다. 오류가 이전부터 있었다고 생각되면 증명한다. 원본을 `data_only=True`로 열어 해당 셀을 확인한다. 내가 만든 오류와 물려받은 오류는 겉보기에 똑같다.
- **계산 결과를 하드코딩하지 말고 수식을 쓴다.** Python으로 계산한 합계를 넣지 말고 `sheet['B10'] = '=SUM(B2:B9)'`처럼 쓴다. 입력값이 바뀌면 시트가 다시 계산되어야 한다.
- **사용자 명세를 글자 그대로 따른다.** 탭 이름, 열 헤더, 사용자가 적어 준 수식을 정확히 맞춘다. 더 우아하더라도 다른 것을 계산하도록 재설계하면 실패로 본다.
- **모든 가정과 하드코딩된 숫자를 독자가 볼 수 있는 곳에 기록한다.** 셀 코멘트나 표 끝의 인접 셀을 쓴다. 실제 출처가 있으면 인용한다(`Source: Company 10-K, FY2024, Page 45, Revenue Note, [SEC EDGAR URL]`). 숫자가 사용자에게서 나왔다면 그렇다고 분명히 적는다.
- **다른 사람이 채워 넣을 워크북을 만들 때**는 편집할 셀을 밝히는 짧은 범례를 넣고, 기대하는 형식을 보여 주는 현실적인 예시 행을 하나 넣는다. 편집을 요청받은 기존 파일에는 예시 행을 절대 넣지 않는다.
- **기존 파일을 편집할 때는 그 파일의 관례를 정확히 따른다.** 파일의 관례가 이 문서의 모든 지침보다 우선한다. 먼저 입력 셀을 찾는다. 글자색, 채우기, 음영처럼 구별되는 표시가 입력 셀을 나타낸다. 그 셀에만 쓰고, 기존 수식은 모두 그대로 둔다.

## 재계산(수식이 있으면 항상 필수)

openpyxl은 수식을 캐시 값 없이 문자열로 쓴다. 재계산하기 전까지는 캐시 값을 읽는 도구(`pandas`, `load_workbook(data_only=True)`, 대부분의 미리보기 도구)에서 모든 수식 셀이 `None`으로 보인다.

```bash
python scripts/recalc.py output.xlsx [timeout_seconds]   # 기본값 30
```

LibreOffice가 모든 수식을 계산하고, 파일을 제자리에서 다시 쓰며, JSON을 출력한다.
`status`(`success` 또는 `errors_found`), `total_formulas`, `total_errors`, 그리고 오류 유형별로 최대 100개 셀을 담은 `error_summary`가 들어 있다. `locations_truncated`는 생략한 개수를 알려 준다. 목록 길이가 아니라 `total_errors`를 믿는다. 지목된 오류를 고치고 다시 실행한다. **`status` 대신 `error` 키가 있는 JSON이 나오면 재계산이 전혀 되지 않은 것이다.** 이 경우에만 종료 코드가 0이 아니다. `errors_found`는 종료 코드 0으로 끝나므로 종료 코드가 정상이라고 해서 워크북이 정상이라고 판단하지 않는다.

**재계산이 깨끗하게 끝나도 수식이 *계산된다*는 것만 증명할 뿐, *맞다*는 증명은 아니다.** 범위가 한 칸 어긋나거나 엉뚱한 행을 참조해도 오류 없는 파일이 나오지만 숫자는 틀린다. 격자를 전부 채우기 전에 수식 2~3개를 먼저 작성해서 기대한 값을 가져오는지 확인한다.

**다른 파일에 링크된 워크북은 openpyxl로 다시 저장한 뒤 재계산하면 그 링크가 사라진다.** 이런 수식은 `='[1]Returns Analysis'!$B$2`로 보인다. `[1]`은 외부 참조 목록의 인덱스이고, 시트가 아니라 디스크에 있는 *별도 파일*을 가리킨다. 그 파일은 이 환경에 거의 없으므로 셀의 캐시 값만이 데이터를 쥐고 있다. openpyxl은 저장할 때 그 값을 지운다. 이후 LibreOffice는 참조를 실제로 해석하려다 실패하고 `#NAME?`을 쓰며 모든 링크를 지운다. `recalc.py`는 이 상태에서 실행을 거부한다. 원본에서 해당 셀의 값을 먼저 복사해 두고 나서 덮어쓴다(`--force`로 강제할 수 있지만 손실을 감수해야 한다).

## 검증을 통과하는 수식 고르기

LibreOffice는 Excel보다 함수를 적게 구현한다. 평가하지 못하는 함수는 결과물 파일에 `#NAME?` 리터럴로 박힌다.

- **Excel 2007 시절 함수를 우선 쓴다.** `SUMIFS`, `INDEX`, `MATCH`, `IFERROR`, `SUMPRODUCT`처럼 접두사가 필요 없는 함수다.
- **2007 이후 함수 6개는 `_xlfn.` 접두사를 붙여야 동작한다.** openpyxl은 수식을 XML에 그대로 쓰고, Excel은 2007 이후 함수 이름을 접두사와 함께 저장하기 때문이다(Excel UI에서는 접두사가 보이지 않는다). 대상은 `_xlfn.TEXTJOIN`, `_xlfn.CONCAT`, `_xlfn.IFS`, `_xlfn.SWITCH`, `_xlfn.MAXIFS`, `_xlfn.MINIFS`다. 접두사 없이 쓰면 각각 `#NAME?`이 된다.
- **`XLOOKUP`, `XMATCH`, `SORT`, `FILTER`, `UNIQUE`, `SEQUENCE`는 절대 쓰지 않는다.** 실행 환경의 LibreOffice는 접두사를 붙여도 평가하지 못한다. 최신 빌드는 평가하지만 이들은 스필(spill) 배열 함수이고, openpyxl이 쓴 파일에는 스필 메타데이터가 없다. 그래서 범위의 왼쪽 위 셀만 값을 받고, `recalc.py`는 잘린 결과를 `total_errors: 0`으로 보고한다. 조회에는 `INDEX`/`MATCH`를 쓰고, 정렬·필터·중복 제거는 셀에 쓰기 전에 Python에서 처리한다.
- LibreOffice가 파싱하지 못한 수식은 소문자로 바뀌어 되돌아온다. `#NAME?` 옆에서 이 현상이 보이면 원인을 알려 주는 단서다.

## openpyxl gotchas

- **모델을 읽을 때는 두 번 불러온다.** `data_only=True`는 수식이 사라진 캐시 값을 주고, 기본 모드는 값 없이 수식 문자열을 준다. 한 번만 읽어서는 둘 다 얻을 수 없다.
- **`data_only=True`로 읽은 워크북을 저장하면 파괴적이다.** 그 워크북에는 더 이상 수식이 없으므로, 저장하면 모든 수식이 리터럴 값으로 영구히 바뀐다.
- **openpyxl이 방금 쓴 파일을 `data_only=True`로 읽으면 모든 값이 `None`이다.** 먼저 `recalc.py`를 실행한다. (결과가 `""`인 수식도 `None`으로 읽힌다.)
- **병합 셀은 왼쪽 위 앵커에만 쓴다.** 범위의 나머지 셀은 `.value`가 읽기 전용인 `MergedCell`이다.
- **`.xlsm`은 `load_workbook`에 `keep_vba=True`를 넘기지 않으면 매크로가 사라진다.**
- **공백이 들어간 시트 이름은 다른 시트를 참조할 때 따옴표로 감싼다.** 예: `='Assumptions Inputs'!$B$5`. 따옴표가 없으면 `#VALUE!`로 평가된다.

## 금융 모델

사용자가 다르게 말하지 않거나 기존 파일이 다른 방식을 쓰고 있지 않으면 아래를 따른다.

**색상:** 하드코딩된 입력값과 시나리오 조정 변수는 파란 글자(`0,0,255`), 수식은 검은 글자, 다른 시트로 연결되는 링크는 초록 글자(`0,128,0`), 다른 파일로 연결되는 링크는 빨간 글자(`255,0,0`), 핵심 가정과 사용자가 채워야 할 셀은 노란 채우기(`255,255,0`)를 쓴다.

**숫자:** 통화는 `$#,##0`으로 쓰고, 단위는 헤더에 적는다(`Revenue ($mm)`). 0은 `-`로 표시한다. 퍼센트 형식에서도 마찬가지다(`$#,##0;($#,##0);-`). 음수는 괄호로 감싼다. 퍼센트는 `0.0%` 형식을 쓰고 **소수(fraction)로 저장한다**(`0.15`는 `15.0%`로 보이고, `15`를 저장하면 `1500.0%`로 보인다). 밸류에이션 배수는 `0.0x`로 쓴다. 연도는 텍스트로 쓴다(`"2024"`. `2,024`처럼 쓰지 않는다).

**구조:** 모든 가정은 자기만의 라벨 붙은 셀에 두고, 그것을 사용하는 수식이 그 셀을 참조하게 한다(`=B5*(1+$B$6)`. `=B5*1.05`처럼 숫자를 직접 넣지 않는다). 모든 예측 기간에 걸쳐 수식을 일관되게 유지한다. 행 중간의 셀 하나만 고쳐 쓰면 가장 흔한 조용한 오류가 된다. 0이 될 수 있는 분모는 가드한다.
