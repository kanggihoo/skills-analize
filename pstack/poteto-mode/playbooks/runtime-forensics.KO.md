### 런타임 포렌식

**진단에 책임을 진다. 소스에서 추측하지 말고 살아 있는 프로세스를 계측한다.** 산출물은 근거가 제시된 진단이지, 수정이 아니다.

1. 맞는 표면에서 control skill을 통해 살아 있는 신호를 캡처한다. 스핀하는 프로세스라면 CPU 프로파일, 누수라면 힙 스냅샷, 시각적 글리치라면 CDP trace. 추측이 아니라 실제 산출물이어야 한다.
2. 산출물을 결정적 증거로 줄인다. 핫 패스의 함수, 누수된 객체에서 GC 루트까지 이어지는 retainer 체인, 입력 없이 발화하는 루프 등이다. 큰 산출물은 subagent에서 파싱한다(**guard-the-context-window** principle skill). 줄인 결과만 메인 스레드에 둔다.
3. 믿기 전에 메커니즘을 증명한다. 실행 중인 프로세스에 CDP eval로 계측을 주입하거나, 다시 로드하지 않고 살아 있는 코드를 핫픽스해서 가설을 값싸게 확인한다.
4. 발견 사항을 소스로 되짚는다. 파일, 심볼, 할당하거나 스케줄하는 줄.
5. 처리량 체크포인트는 한 줄로 유지한다: `throughput checkpoint: n/a, read-only forensics`.

**응답:** 캡처한 신호, 줄여서 얻은 발견 사항, 메커니즘을 증명한 방법, 소스 위치, 산출물 경로. 요청이 없으면 수정하지 않는다. 원인을 알게 되면 Bug fix 또는 Perf로 되돌린다.
