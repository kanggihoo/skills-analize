### 자율 실행

**종료 조건은 당신이 책임진다. 완료 기준을 정한 뒤 멈추지 않고 그 기준까지 밀고 간다.**

1. 첫 반복을 시작하기 전에 종료 조건을 확인 가능한 술어로 명시한다 (테스트 통과, 재현 문제 해결, N개 PR 모두 병합, 픽셀 diff 0 등).
2. 깨어날 방식은 Cursor의 `/loop` 명령을 사용해 고른다 (pstack 스킬이 아닌 내장 기능). 감시할 이벤트(CI, 병합, ref 진행)가 있으면 그 이벤트에 깨어나는 감시 subagent를 두고, 대비용으로 긴 시간 기반 heartbeat를 둔다. 감시할 이벤트가 없으면 결과를 다시 확인할 가치가 있는 시점에 맞춘 고정 간격 heartbeat를 둔다.
3. 각 반복은 증거가 정당화하는 가장 작은 변경만 한다. 술어에 맞춰 검증하고, 진전이 있으면 커밋하며, 도움이 되지 않은 변경은 버린다. "도움이 될지도 모른다"는 식의 중복 방어 변경은 그대로 두지 말고 되돌린다.
   **sequence-verifiable-units** 원칙 스킬에 따라 작업 순서를 정한다. 검증은 마지막에 몰아서 하지 않고, 각 단위를 검증한 뒤 다음 단위로 넘어간다.
4. 실행 중 발견한 문제는 당신이 처리한다. 깨진 스킬, 관련 버그, 불안정한 검증기, 리뷰 노이즈, 도구 실패, 고아 상태의 후속 작업, 고칠 수 있는 드리프트를 poteto-mode를 통해 직접 해결한다. 실행과 무관한 수정은 별도 PR로 낸다. 되돌릴 수 있는 작업을 사람에게 넘기거나 `AskQuestion`을 사용하지 않는다. 되돌릴 수 없는 행동, 어떤 실험으로도 결정할 수 없는 실제 제품 또는 선호 판단, 실제 막다른 길만 보고한다. 측정 기준은 계속 주 동력으로 두고, 부수적인 수정을 마칠 때마다 그 기준으로 돌아온다.
5. **show-me-your-work** 스킬을 통해 매 반복을 체크포인트로 남긴다. 무엇이 바뀌었는지, 술어가 움직였는지 여부를 한 행으로 적는다.
6. 술어가 충족되면 멈춘다. 정체 상태는 멈출 이유가 아니므로 접근 방식을 바꿔 정체를 넘어선다. 진짜 막다른 길은 맹목적으로 돌지 말고 보고한다. 승리를 선언하려고 술어를 완화하지 않는다.

**응답:** 종료 조건, 수행한 반복 수, 반영된 변경, 버린 변경, 최종 술어 상태.
