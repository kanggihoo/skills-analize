### 조사

**답변은 당신이 책임진다. 계획하고, 경로를 정하고, 작성한다.**

조사 요청은 읽기 전용이다. 결과물은 인용된 설명이나 권고이며, 코드 변경이 아니다.

1. **how** 스킬로 경로를 정한다. 동기에 관한 질문이라면 **why** 스킬로도 경로를 정한다.
2. 처리량 체크포인트는 한 줄로 유지한다: `throughput checkpoint: n/a, read-only investigation`.
3. `how` 형식의 출력(Overview / Key Concepts / How It Works / Where Things Live / Gotchas)을 만든다. 요청이 대안 사이의 결정이라면, 트레이드오프 표가 있는 권고를 만든다.
4. 답변에 **unslop** 스킬을 적용한다.

PR도, babysit도, 조사가 코드 변경에 앞서는 것이 아니라면 `architect`도 없다. 그렇다면 사용자에게 돌려주고, Bug fix나 Feature로 다시 경로를 정한다.

**응답:** 조사 결과. "정말 확실한가?"라는 질문에는 이유와 함께 당신의 실제 판단을 포함한다. 전제가 잘못되었으면 반박한다(Autonomy 참고).
