### 세션 이어받기

**재개 지점에 책임을 진다. 이전 기록을 읽고, 다시 하지 않는다.**

1. 이전 기록을 찾는다. 활성 워크스페이스의 `agent-transcripts/` 디렉터리 아래 로컬 transcript(경로는 시스템 프롬프트에 있다. `~/.cursor/projects/*/`를 glob으로 훑지 않는다. 그렇게 하면 워크스페이스 경계를 넘어 관계없는 프로젝트의 비공개 채팅을 읽게 된다), cloud agent URL, 또는 push된 branch. 먼저 메타데이터 개요와 마지막 메시지를 읽고, 그다음 결정 지점을 거슬러 훑는다. 긴 transcript는 subagent에서 파싱하고, 줄인 타임라인만 메인 스레드에 둔다(**principle-guard-the-context-window** skill).
2. 운영 상태를 복원한다. branch와 worktree, 이미 착지한 것(`git log`, 기준 대비 `git diff`), 열린 todo, 내려진 결정. 이전 기록은 권위 있는 입력이다. 다시 도출하고 싶은 편향을 억누른다.
3. 끝난 것과 남은 것을 비교한다. 출하된 것과 계획된 것을 대조하고, 재개 지점을 명명한다. 이전 재현을 다시 돌리거나 끝난 작업을 다시 하지 않는다. "처음부터 다시 검증하자"는 식의 패스는 이전 기록이 권위 있는 자료인데 신뢰할 수 없다고 취급하는 것이다.
4. 남은 작업을 맞는 playbook으로 라우팅하고 판정을 고른다. 실행을 계속하기, 완성된 추천을 출하하기, 이전 결론을 승인하거나 뒤집기, 실패한 실행을 사후 분석하기. 이어받기 playbook은 여기서 끝난다. 라우팅된 playbook이 나머지를 책임진다.
5. 이어받은 주장을 실제 산출물에서 원래 목표에 대해 검증한다(**principle-prove-it-works** skill). 이전 agent가 스스로 통과했다고 보고한 것은 증명이 아니다.

**응답:** 이전 agent가 어디에서 멈췄는지, 이어받은 것과 다시 한 것(이상적으로는 다시 한 것이 없음), 재개 지점, 결과.
