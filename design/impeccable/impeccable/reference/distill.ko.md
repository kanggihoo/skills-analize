디자인에서 핵심을 남깁니다. 자리를 차지할 이유가 없는 중복 요소, 반복 정보, 장식 잡음, 겉치레 복잡성을 제거합니다.

---

## 현재 상태 평가

무엇이 디자인을 복잡하거나 어수선하게 만드는지 분석합니다.

1. **복잡성의 원인 확인**:
   - **요소가 너무 많음**: 서로 경쟁하는 버튼, 중복 정보, 시각적 혼란
   - **과도한 변형**: 목적 없이 색상, 글꼴, 크기, 스타일을 너무 많이 사용
   - **정보 과부하**: 점진적 공개 없이 모든 내용을 한 번에 보여 줌
   - **시각적 잡음**: 불필요한 테두리, 그림자, 배경, 장식
   - **불분명한 위계**: 가장 중요한 것이 무엇인지 모호함
   - **기능 증가**: 선택지, 동작, 진행 경로가 너무 많음

2. **핵심 찾기**:
   - 사용자의 주요 목표는 무엇인가요?(하나여야 합니다.)
   - 실제로 필요한 것은 무엇이고, 있으면 좋은 것은 무엇인가요?
   - 무엇을 제거하거나 숨기거나 합칠 수 있나요?
   - 가치의 80%를 만드는 20%는 무엇인가요?

코드베이스만으로 이 중 어느 하나라도 분명하지 않으면 추측하지 않습니다. 사용할 수 있다면 Codex의 구조화된 사용자 입력 / 질문 도구로 묻고, 없으면 채팅에서 답을 받은 뒤 계속합니다.

단순화는 기능을 없애는 것이 아니라 사용자의 목표를 가로막는 장애물을 줄이는 것입니다. 모든 요소가 존재 이유를 설명할 수 있어야 합니다.

## 단순화 전략 계획

과감하게 편집할 계획을 세웁니다.

- **핵심 목적**: 이것이 달성해야 할 한 가지는 무엇인가요?
- **필수 요소**: 목적을 달성하는 데 정말 필요한 것은 무엇인가요?
- **점진적 공개**: 필요할 때까지 무엇을 숨길 수 있나요?
- **통합 기회**: 무엇을 합치거나 다른 요소 안에 넣을 수 있나요?

훌륭한 결과를 위해 좋은 아이디어를 내려놓을 수 있어야 합니다.

## 디자인 단순화

다음 영역의 복잡성을 체계적으로 줄입니다.

### 정보 구조
- **범위 축소**: 보조 동작과 중복 정보 제거
- **점진적 공개**: 명확한 시작점(아코디언, modal, 단계형 흐름) 뒤에 복잡성을 숨김
- **관련 동작 결합**: 비슷한 버튼을 합치고 양식을 통합하며 관련 콘텐츠를 묶음
- **명확한 위계**: 주요 동작은 하나, 보조 동작은 소수만 두고 나머지는 3차 동작으로 보내거나 숨김
- **중복 제거**: 다른 곳에서 말한 내용은 여기서 반복하지 않음

### 시각적 단순화
- **팔레트 축소**: 5~7색이 아니라 1~2개의 색과 중성색 사용
- **타이포그래피 제한**: 글꼴 계열 1개, 크기 최대 3~4단계, 굵기 2~3단계
- **장식 제거**: 위계나 기능에 도움이 되지 않는 테두리, 그림자, 배경 제거
- **구조 평탄화**: 중첩을 줄이고 불필요한 컨테이너 제거. 카드를 카드 안에 넣지 않음.
- **불필요한 카드 제거**: 기본 레이아웃에는 카드가 필요하지 않습니다. 간격과 정렬을 사용합니다.
- **간격 일관성**: 하나의 간격 체계를 사용하고 임의 간격을 없앰

### 레이아웃 단순화
- **선형 흐름**: 가능하다면 복잡한 그리드를 단순한 세로 흐름으로 변경
- **사이드바 제거**: 보조 콘텐츠를 본문에 넣거나 숨김
- **전체 너비 사용**: 복잡한 다열 레이아웃 대신 사용 가능한 공간을 충분히 활용
- **정렬 일관성**: 왼쪽 정렬 또는 가운데 정렬 중 하나를 선택하고 계속 사용
- **넉넉한 여백**: 콘텐츠가 숨 쉴 공간을 두고 빽빽하게 채우지 않음

### 상호작용 단순화
- **선택지 축소**: 버튼과 옵션을 줄이고 진행 경로를 분명히 함(선택의 역설은 실제 문제)
- **스마트 기본값**: 흔한 선택은 자동으로 처리하고 필요한 경우에만 질문
- **인라인 동작**: 가능하다면 modal 흐름을 인라인 편집으로 바꿈
- **단계 제거**: 흐름에서 단계를 줄일 수 있는가?
- **다음 동작 명료화**: 경쟁하는 다섯 동작이 아니라 분명한 다음 동작 하나

### 콘텐츠 단순화
- **문구 단축**: 의미가 아니라 군더더기를 자름
- **능동태 사용**: “변경사항 저장”이지 “변경사항이 저장됩니다”가 아님
- **전문 용어 제거**: 쉬운 말이 우선
- **훑어보기 쉬운 구조**: 짧은 단락, 글머리표, 명확한 제목
- **필수 정보만 남김**: 마케팅 군더더기와 지나친 완곡 표현 제거
- **중복 문구 삭제**: 도입을 되풀이하는 제목이나 반복 설명을 두지 않고 한 번만 말함

### 코드 단순화
- **사용하지 않는 코드 제거**: 불필요한 CSS, 사용하지 않는 컴포넌트, 참조되지 않는 파일
- **컴포넌트 트리 평탄화**: 중첩 깊이 줄이기
- **스타일 통합**: 비슷한 스타일을 합치고 유틸리티를 일관되게 사용
- **변형 축소**: 컴포넌트에 정말 12가지 변형이 필요한가요, 아니면 3개로 사례의 90%를 처리할 수 있나요?

**피할 것**:
- 필요한 기능 제거(단순함은 기능이 없다는 뜻이 아님)
- 단순화를 위해 접근성 희생(명확한 레이블과 ARIA는 여전히 필요)
- 지나치게 단순화해 의미를 알 수 없게 만들기(수수께끼는 미니멀리즘이 아님)
- 결정에 필요한 정보를 사용자에게서 제거
- 위계를 완전히 없애기(일부 요소는 눈에 띄어야 함)
- 복잡한 도메인을 지나치게 단순화하기(실제 과업의 복잡성에 맞춤)

## 단순화 검증

단순화가 사용성을 개선했는지 확인합니다.

- **과업 완료 시간 단축**: 사용자가 목표를 더 빠르게 달성할 수 있나요?
- **인지 부담 감소**: 무엇을 해야 하는지 더 쉽게 이해하나요?
- **기능 완전성 유지**: 필요한 기능을 모두 계속 사용할 수 있나요?
- **위계 개선**: 가장 중요한 것이 분명한가요?
- **성능 향상**: 더 단순한 디자인이 더 빨리 로드되나요?

## 제거한 복잡성 기록

기능이나 선택지를 제거한 경우:
- 제거 이유를 기록합니다.
- 대체 접근 경로가 필요한지 검토합니다.
- 관찰할 사용자 피드백을 기록합니다.

삭제한 결과가 적절해지면 최종 점검을 위해 `$impeccable polish`로 넘깁니다. Antoine de Saint-Exupéry의 말처럼 “더할 것이 하나도 남지 않았을 때가 아니라, 덜어낼 것이 하나도 남지 않았을 때 완벽이 이루어진다.”
