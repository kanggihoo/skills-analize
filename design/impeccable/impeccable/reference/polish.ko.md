> **추가로 필요한 맥락**: 품질 기준과 출시 제약.

Polish는 개선이지 재설계를 숨기는 일이 아닙니다. 기존 시각 세계, 콘텐츠, 동작, 범위 밖의 요소를 보존합니다. 개념 자체가 잘못됐다면 그렇게 말하고 대체 디자인을 슬쩍 넣는 대신 재설계나 `bolder`를 권합니다.

탐지기 결과는 결함의 근거이지 품질의 증명은 아닙니다. 렌더링된 경험과 실제 상호작용 흐름을 확인합니다.

## 1. 시스템 파악

DESIGN.md와 대표 토큰, 공유 컴포넌트, 패턴, 주변 흐름을 읽습니다. 공식 시스템 문서가 없다면 프로젝트의 일관된 관례를 사용합니다.

각 불일치는 수정 전에 분류합니다.

- **토큰 누락**: 시스템에 재사용 가능한 값이 필요
- **일회성 구현**: 기존 공유 컴포넌트나 패턴으로 대체해야 함
- **개념 불일치**: 흐름, 정보 구조, 위계가 비슷한 제품 영역과 다름
- **지역 결함**: 구현이 불완전하거나 일관되지 않음

가장 좁고 정확한 수준에서 원인을 수정합니다. 시스템을 구속하는 원칙을 맥락에서 추론할 수 없다면 묻습니다.

## 2. 근거 수집

대표 화면 크기에서 직접 기능을 사용합니다. 웹은 데스크톱과 모바일, 네이티브(`ios` / `android` / `adaptive`) 플랫폼은 플랫폼 참조의 Verifying the build 절차에 따라 simulator, emulator, 실제 기기에서 출시 대상 기기 종류별로 캡처합니다. 다음을 파악합니다.

- 경로가 기능적으로 완성됐는가
- 목표 품질과 사용할 수 있는 시간
- 알려진 제약이나 의도적으로 미완성인 작업
- 사용자가 실제로 접할 상태, 콘텐츠 길이, 역할, 입력 방식

이전 critique가 있다면 다음을 한 근거로 사용합니다.

```bash
.agents/skills/impeccable/scripts/impeccable critique-storage latest "<resolved target>" --json
```

Exit 0은 최신 snapshot의 `body`와 정확한 `snapshot_file` 식별자를 포함한 JSON을 반환합니다. 검토가 끝날 때까지 `snapshot_file`을 유지합니다. 로컬 파일 대상이면 helper가 현재 파일의 정확한 content fingerprint를 critique 시점의 fingerprint와 비교합니다. staged, unstaged, untracked 여부와 상관없이 변경되지 않은 내용은 최신 상태입니다. 바이트 변경, 삭제, 파일이 아닌 값으로 교체된 경우 critique에서 식별한 백로그를 trend 기록은 보존한 채 닫고 exit 2를 반환합니다. URL 대상은 로컬 fingerprint가 없으며 명시적으로 닫을 때까지 최신입니다. 최신 상태라면 `body`의 관련 P0/P1 발견 사항을 반영하고 읽은 snapshot을 명시합니다. Exit 2는 snapshot이 없거나 대상이 변경됐다는 뜻입니다. 어느 경우든 독립적으로 한 차례 검사합니다.

## 3. 우선순위 분류

기능 결함과 외관 문제를 구분하고 아래 순서로 수정합니다.

1. 작업 실패 / 차단, 데이터 손실, 오해를 부르는 상태, 접근 불가능한 경로
2. loading, empty, error, success, disabled, permission 상태 누락
3. 흐름, 위계, 반응형, 디자인 시스템과의 괴리
4. 시각 및 모션의 불일치
5. 코드와 에셋 정리

나머지가 같은 품질 기준에 미달한 상태로 한 구석만 완벽하게 다듬지 않습니다.

## 4. 전체 흐름 다듬기

### 흐름과 위계
- 주변 기능의 사용 모델, 용어, 공개 방식, 탐색, 저장 동작, 낙관적 / 비관적 패턴과 맞춥니다.
- 모든 요소의 무게를 똑같게 만들지 않으면서 주요 과업과 현재 상태를 분명히 합니다.
- 도착, 전환, 빈 상태, 복구 경로를 서로 분리된 화면처럼 동작하게 하지 말고 연결합니다.

### 레이아웃과 타이포그래피
- 프로젝트 grid와 간격 체계에 맞춥니다. 수학적 정렬뿐 아니라 광학적 정렬도 고칩니다.
- 관련 콘텐츠는 모으고 독립된 그룹은 넉넉히 분리합니다.
- 같은 역할의 타이포그래피를 일관되게 유지하고 행 길이, 줄바꿈, 현지화 확장, 확대, 글꼴 로드를 확인합니다.
- 현재 스크린샷만 고치지 말고 지원하는 모든 viewport에서 확인합니다.

### 색상, 이미지, 아이콘
- 테마 전반에서 의미 토큰과 안정적인 색상 의미를 사용합니다.
- 모든 상태에서 텍스트, 컨트롤, 초점 대비를 검증합니다.
- 아이콘 계열, 선 굵기, 크기, 광학적 정렬을 일관되게 합니다.
- 이미지가 레이아웃을 움직이지 않도록 하고, 올바른 비율, 반응형 소스, 유용한 대체 텍스트를 제공합니다.

### 상호작용과 상태
- 모든 컨트롤이 적절한 기본, hover, focus, active, disabled, loading, error, success 동작을 제공합니다.
- 화면에 보이는 키보드 초점, 논리적인 탭 순서, 레이블, 플랫폼에 적합한 터치 영역을 유지합니다.
- 모션은 일관되고, 중단 가능하며, 성능이 좋아야 합니다. polish가 눈에 띄도록 애니메이션을 추가하지 않습니다.
- 제품에서 만날 수 있는 경우 긴 콘텐츠, 누락, 현지화, 오프라인, 느린 연결, 권한 제한 상태를 확인합니다.

### 콘텐츠와 코드
- 용어, 대소문자, 문장부호, 사실 문구를 일관되게 유지합니다. 주장을 바꾸기 전에는 묻습니다.
- debug 출력, 죽은 코드, 사용하지 않는 import, 오래된 스타일, polish 과정에서 생긴 중복을 제거합니다.
- 시스템에서 소유한 패턴에는 사용자 지정 구현 대신 공유 컴포넌트를 사용합니다.
- 진짜 재사용할 값만 토큰으로 승격하고 한 번의 예외에 시스템 추상화를 만들지 않습니다.

## 5. 검증 및 마무리

마우스, 키보드, 해당되는 경우 터치를 사용해 전체 흐름을 다시 밟습니다. 다음을 확인합니다.

- 웹의 모바일 / 중간 / 넓은 레이아웃. 네이티브는 양방향을 지원하는 기기 클래스의 세로 / 가로 size class.
- loading, empty, error, success, disabled, 긴 콘텐츠, 누락 콘텐츠 상태
- 확대, 대비, 초점, 시맨틱, 스크린 리더 이름
- 모든 화면에서 console error, 레이아웃 이동, 상호작용 지연, 이미지 로딩. 웹은 지원 브라우저, 네이티브는 지원 OS 버전, 런타임 경고, 프레임 드롭.
- DESIGN.md, 주변 기능, 사용자의 범위와 일치

`impeccable context`와 hook에서 제공한 품질 지침을 따르고 관련 QA 명령을 실행합니다. context가 자동 탐지기를 사용할 수 없는 경우에만 수동 검사를 요청합니다. 탐지기를 추가로 실행하지 않습니다. 실제 결함만 고치고 좁은 의도적 예외만 문서화합니다. 탐지 결과가 깨끗해도 시각 판단은 별도로 필요합니다.

마지막에 소스 diff를 확인해 우발적인 변경, 고아 코드, 중복 값, 임시 결과물을 제거합니다. 전체 흐름에서 기능적으로 완성되고 일관되게 마무리된 경우에만 출시합니다.

이 pass에서 snapshot의 모든 Priority Issue를 해결했다면 해당 snapshot을 닫습니다.

```bash
.agents/skills/impeccable/scripts/impeccable critique-storage close "<resolved target>" "<latest가 반환한 snapshot_file>"
```

이 pass가 실제 처리한 snapshot만 닫습니다. 그 사이에 더 최신 critique가 들어왔다면 해당 백로그를 유지합니다. snapshot을 읽지 않았거나 `snapshot_file`을 유지하지 않았거나 Priority Issue가 남아 있다면 닫지 않습니다.
