완벽한 데이터에서만 작동하는 디자인은 프로덕션에 준비된 것이 아닙니다. 실제 사용자가 입력할 데이터, 오류, 언어, 네트워크 환경을 견디도록 인터페이스를 강화합니다.

## 강화 필요 사항 평가

약점과 예외 상황을 확인합니다.

1. **극단적인 입력으로 테스트**:
   - 매우 긴 텍스트(이름, 설명, 제목)
   - 매우 짧은 텍스트(빈 값, 한 글자)
   - 특수 문자(emoji, RTL 텍스트, 악센트 문자)
   - 큰 숫자(수백만, 수십억)
   - 항목이 많음(목록 1000개 이상, 선택지 50개 이상)
   - 데이터 없음(빈 상태)

2. **오류 상황 테스트**:
   - 네트워크 실패(오프라인, 느림, 시간 초과)
   - API 오류(400, 401, 403, 404, 500)
   - 검증 오류
   - 권한 오류
   - 요청 제한
   - 동시 작업

3. **국제화 테스트**:
   - 긴 번역(독일어는 영어보다 30% 정도 긴 경우가 많음)
   - RTL 언어(아랍어, 히브리어)
   - 문자 체계(중국어, 일본어, 한국어, emoji)
   - 날짜 / 시간 형식
   - 숫자 형식(1,000 vs 1.000)
   - 통화 기호

완벽한 데이터에서만 작동하는 디자인은 프로덕션에 준비된 것이 아닙니다.

## 강화 영역

다음 항목을 체계적으로 개선해 회복력을 높입니다.

### 텍스트 넘침과 줄바꿈

**긴 텍스트 처리**:
```css
/* 한 줄로 자르고 말줄임표 표시 */
.truncate {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

/* clamp를 이용해 여러 줄 제한 */
.line-clamp {
  display: -webkit-box;
  -webkit-line-clamp: 3;
  -webkit-box-orient: vertical;
  overflow: hidden;
}

/* 줄바꿈 허용 */
.wrap {
  word-wrap: break-word;
  overflow-wrap: break-word;
  hyphens: auto;
}
```

**Flex/Grid 넘침**:
```css
/* flex 항목이 부모 밖으로 넘치지 않게 함 */
.flex-item {
  min-width: 0; /* 콘텐츠 크기보다 줄어들 수 있게 허용 */
  overflow: hidden;
}

/* grid 항목이 부모 밖으로 넘치지 않게 함 */
.grid-item {
  min-width: 0;
  min-height: 0;
}
```

**반응형 텍스트 크기**:
- 유동형 타이포그래피에 `clamp()` 사용
- 읽기 가능한 최소 크기 설정(모바일 본문 16px, 타이포그래피 지침과 같은 하한. 보조 텍스트일 때만 14px 허용. 16px 미만의 입력 필드에 초점을 두면 iOS Safari가 화면을 강제로 확대해 양식 레이아웃이 깨짐)
- 텍스트 확대 테스트(200%까지 확대)
- 컨테이너가 텍스트에 따라 늘어나도록 설정

### 국제화(i18n)

**텍스트 길이 증가**:
- 번역을 위해 30~40% 공간을 확보
- 콘텐츠에 맞게 조정되는 flexbox/grid 사용
- 가장 긴 언어(대개 독일어)로 테스트
- 텍스트 컨테이너의 고정 너비 피하기

```jsx
// ❌ 잘못된 예: 영어가 짧다고 가정
<button className="w-24">Submit</button>

// ✅ 좋은 예: 콘텐츠에 맞게 조정
<button className="px-4 py-2">Submit</button>
```

**RTL(오른쪽에서 왼쪽) 지원**:
```css
/* 논리 속성 사용 */
margin-inline-start: 1rem; /* margin-left 대신 */
padding-inline: 1rem; /* padding-left/right 대신 */
border-inline-end: 1px solid; /* border-right 대신 */

/* 또는 dir 속성 사용 */
[dir="rtl"] .arrow { transform: scaleX(-1); }
```

**아랍 문자 관련 세부 사항**(아랍어, 페르시아어, 우르두어, 파슈토어, 쿠르드어):
- Zero-Width Non-Joiner(U+200C)를 보존합니다. 페르시아어와 쿠르드어에서는 합성어 구성 단위 사이에 ZWNJ를 넣어 단어는 붙어 있게 유지하면서 필기체 글자 연결을 끊습니다. 필터나 정리 도구가 이를 제거하면 뜻이 바뀝니다. 절대 정규화 과정에서 없애지 않습니다.
- Yeh와 Kaf의 문자 변형을 처리합니다. 페르시아어는 ی(U+06CC)와 ک(U+06A9)를 사용하고 아랍어는 ي(U+064A)와 ك(U+0643)를 사용합니다. 저장할 때 원본 형식을 보존합니다. 검색과 유효성 검사에서는 대응하는 글자를 같은 것으로 처리해 아랍어 키보드 입력으로 페르시아어 문자를 찾을 수 있게 합니다. 키보드가 다른 변형을 보내는 사용자를 배제하지 않습니다.
- 지역에 맞는 숫자 지원. 페르시아어(`fa-IR`)와 아랍어 locale은 동아라비아-인도 숫자(۰-۹, ٠-٩)를 사용합니다. 서양 숫자를 하드코딩하지 말고 올바른 locale과 함께 `Intl.NumberFormat`을 사용합니다.

```javascript
// ✅ locale에 맞춘 숫자 형식
new Intl.NumberFormat('fa-IR').format(1234); // ۱٬۲۳۴
new Intl.NumberFormat('ar-SA').format(1234); // ١٬٢٣٤
```

- 달력 체계를 존중합니다. 페르시아어 사용자는 태양력 헤지리(Jalali) 달력을 기대하며, 아랍어 사용자는 히즈리(이슬람) 달력을 기대하는 경우가 많습니다. 적절한 locale이나 calendar 매개변수로 `Intl.DateTimeFormat`을 사용합니다.

```javascript
// ✅ locale에 맞는 달력
new Intl.DateTimeFormat('fa-IR').format(new Date());
new Intl.DateTimeFormat('ar-SA-u-ca-islamic').format(new Date());
```

**문자 집합 지원**:
- 모든 곳에서 UTF-8 인코딩 사용
- 중국어 / 일본어 / 한국어(CJK) 문자로 테스트
- emoji(2~4바이트일 수 있음)로 테스트
- 다양한 문자 체계(라틴, 키릴, 아랍 등) 처리

**날짜 / 시간 형식**:
```javascript
// ✅ 올바른 표기를 위해 Intl API 사용
new Intl.DateTimeFormat('en-US').format(date); // 1/15/2024
new Intl.DateTimeFormat('de-DE').format(date); // 15.1.2024

new Intl.NumberFormat('en-US', { 
  style: 'currency', 
  currency: 'USD' 
}).format(1234.56); // $1,234.56
```

**복수형**:
```javascript
// ❌ 잘못된 예: 영어 복수형이라고 가정
`${count} item${count !== 1 ? 's' : ''}`

// ✅ 올바른 i18n 라이브러리 사용
t('items', { count }) // 복잡한 복수 규칙을 처리
```

### 오류 처리

**네트워크 오류**:
- 명확한 오류 메시지 표시
- 재시도 버튼 제공
- 무엇이 일어났는지 설명
- 해당되는 경우 오프라인 모드 제공
- 시간 초과 상황 처리

```jsx
// 복구 기능을 갖춘 오류 상태
{error && (
  <ErrorMessage>
    <p>Failed to load data. {error.message}</p>
    <button onClick={retry}>Try again</button>
  </ErrorMessage>
)}
```

**양식 검증 오류**:
- 필드 근처에 인라인 오류 표시
- 명확하고 구체적인 메시지
- 수정 방법 제안
- 불필요하게 제출을 막지 않음
- 오류가 나도 사용자 입력 유지

**API 오류**:
- 상태 코드별로 적절히 처리
  - 400: 검증 오류 표시
  - 401: 로그인으로 이동
  - 403: 권한 오류 표시
  - 404: 찾을 수 없음 상태 표시
  - 429: 요청 제한 메시지 표시
  - 500: 일반 오류를 표시하고 지원 요청 안내

**점진적 저하**:
- JavaScript가 없어도 핵심 기능이 작동
- 이미지에 alt 텍스트 제공
- 점진적 향상
- 지원하지 않는 기능에 대체 동작 제공

### 예외 상황과 경계 조건

**빈 상태**:
- 목록에 항목 없음
- 검색 결과 없음
- 알림 없음
- 표시할 데이터 없음
- 명확한 다음 동작 제공

**로딩 상태**:
- 최초 로드
- 페이지네이션 로드
- 새로고침
- 무엇을 불러오는지 표시(“프로젝트를 불러오는 중…”)
- 오래 걸리는 작업의 예상 시간 안내

**대규모 데이터**:
- 페이지네이션이나 가상 스크롤링
- 검색 / 필터 기능
- 성능 최적화
- 항목 10,000개를 한 번에 모두 불러오지 않음

**동시 작업**:
- 로딩 중 버튼을 비활성화해 중복 제출 방지
- 경쟁 상태 처리
- rollback 기능을 갖춘 낙관적 업데이트
- 충돌 해결

**중단된 제스처**(사용자 지정 슬라이더, 드래그 표면, 스크롤 가능한 컨트롤 띠):
- 드래그 도중 두 번째 손가락이나 포인터가 들어와도 첫 번째 드래그는 해당 포인터를 계속 사용하거나 깔끔하게 끝내야 하며, 새 포인터로 갑자기 점프하지 않아야 합니다.
- 브라우저가 스크롤을 위해 제스처를 취소(`pointercancel`)하거나, pointer capture가 끊기거나(`lostpointercapture`), 포인터가 컨트롤 바깥에서 놓이거나, 드래그 중 창이 포커스를 잃으면(`blur`) 드래그 상태를 지우고 capture를 해제합니다.
- 각각의 중단 뒤에도 새로고침 없이 다음 탭이나 드래그가 작동해야 합니다.

**권한 상태**:
- 보기 권한 없음
- 수정 권한 없음
- 읽기 전용 모드
- 이유를 명확하게 설명

**브라우저 호환성**:
- 최신 기능의 polyfill
- 지원하지 않는 CSS의 대체 동작
- 브라우저 감지가 아니라 기능 감지
- 대상 브라우저에서 테스트

### 입력 검증과 정리

**클라이언트 측 검증**:
- 필수 필드
- 형식 검증(이메일, 전화번호, URL)
- 길이 제한
- 패턴 일치
- 사용자 지정 검증 규칙

**서버 측 검증**(항상 필요):
- 클라이언트 쪽 검증만 믿지 않음
- 모든 입력을 검증하고 정리
- injection 공격 방지
- 요청 제한

**제약 조건 처리**:
```html
<!-- 제약 조건을 명확하게 설정 -->
<input 
  type="text"
  maxlength="100"
  pattern="[A-Za-z0-9]+"
  required
  aria-describedby="username-hint"
/>
<small id="username-hint">
  Letters and numbers only, up to 100 characters
</small>
```

### 접근성 회복력

**키보드 탐색**:
- 키보드만으로 모든 기능에 접근 가능
- 논리적인 탭 순서
- modal에서 초점 관리
- 긴 콘텐츠에 건너뛰기 링크

**스크린 리더 지원**:
- 올바른 ARIA 레이블
- 동적 변화 알림(live region)
- 설명이 충분한 alt 텍스트
- 시맨틱 HTML

**고대비 모드**:
- Windows 고대비 모드에서 테스트
- 색상만으로 표현하지 않음
- 대체 시각 단서 제공

### 성능 회복력

**느린 연결**:
- 이미지를 점진적으로 로드
- skeleton 화면
- 낙관적 UI 업데이트
- 오프라인 지원(service worker)

## 테스트 전략

**수동 테스트**:
- 극단적인 데이터(매우 길거나 짧음, 빈 값)로 테스트
- 다른 언어로 테스트
- 오프라인 테스트
- 느린 연결(3G 속도로 제한) 테스트
- 스크린 리더로 테스트
- 키보드만 사용해 탐색 테스트
- 오래된 브라우저에서 테스트

**자동 테스트**:
- 예외 상황 단위 테스트
- 오류 상황 통합 테스트
- 중요 흐름 E2E 테스트
- 프로젝트의 테스트 실행기가 입력을 제어할 수 있다면 확인된 제스처 수정마다 동작 회귀 테스트 추가
- 시각 회귀 테스트
- 접근성 테스트(axe, WAVE)

**피할 것**:
- 입력이 완벽하다고 가정(모든 것을 검증)
- 국제화를 무시(전 세계 사용자를 고려)
- 일반적인 오류 메시지(“오류가 발생했습니다”)를 그대로 두기
- 오프라인 상황을 잊기
- 클라이언트 측 검증만 신뢰
- 텍스트에 고정 너비 사용
- 영어 길이의 문구만 가정
- 컴포넌트 하나에서 오류가 나도 인터페이스 전체를 막기

## 강화 검증

예외 상황으로 충분히 테스트합니다.

- **긴 텍스트**: 100자 이상의 이름 입력
- **emoji**: 모든 텍스트 필드에서 사용
- **RTL**: 아랍어나 히브리어로 테스트
- **CJK**: 중국어 / 일본어 / 한국어로 테스트
- **네트워크 문제**: 인터넷 연결을 끄거나 속도 제한
- **대규모 데이터**: 항목 1000개 이상으로 테스트
- **동시 동작**: 제출을 빠르게 10회 클릭
- **중단된 제스처**: 드래그 도중 두 번째 손가락을 추가하고, 컨트롤을 지나 스크롤하고, 컨트롤 바깥에서 손가락을 놓고, 드래그 중 창을 전환한 뒤 다시 드래그
- **오류**: API 오류를 강제로 발생시켜 모든 오류 상태 테스트
- **빈 상태**: 데이터를 모두 지우고 빈 상태 테스트

제스처를 테스트할 때는 증거가 어떤 환경에서 나온 것인지(에뮬레이트 viewport, 합성 터치, 사용 엔진, 실제 기기) 말하고 테스트하지 못한 사항도 밝힙니다.

예외 상황을 모두 다뤘으면 최종 점검을 위해 `$impeccable polish`로 넘깁니다.
