> **추가로 필요한 맥락**: 성능 제약.

모션은 상태, 관계, 위계를 설명하거나 화면이 필요로 하는 한 번의 연출 순간을 만들 때 사용합니다. 목적 없는 장식은 애니메이션 부채입니다.

---

## 방문자 모드

- **Persuade + Experience**: 모션이 화면의 목소리를 전달할 수 있습니다. 반복적인 섹션 등장보다 충분히 연습한 초점 시퀀스 하나를 우선합니다.
- **Operate + Read**: 모션은 피드백, 상태, 연속성을 지원합니다. 일상적인 전환은 빠르게 하고 페이지 로딩을 연출하는 모션으로 사용자를 기다리게 하지 않습니다.
- **네이티브(`ios` / `android` / `adaptive`)**: [ios.md](ios.md) 또는 [android.md](android.md)의 Motion 절과 플랫폼의 Reduce Motion 동작을 따릅니다. 아래의 웹 도구는 적용하지 않습니다.

## 필요한 모션 찾기

기존 모션 표현, 상호작용 상태, 대상 기기, 성능 예산을 살펴봅니다. 다음 역할을 하는 곳에만 모션을 사용합니다.

- 사용자의 동작에 반응하기
- 상태 변화나 공간적 관계를 이해하기 쉽게 표시하기
- 탐색 또는 레이아웃 변화 중 연속성을 유지하기
- 의미 있는 순간에 주의를 이끌기
- 선택한 시각 세계를 표현하기

중요한 제약을 맥락에서 추론할 수 없을 때만 질문합니다. 정적인 영역이 있다는 이유만으로 움직이지 않습니다.

## 모션의 핵심 가설 세우기

구현 전에 짧은 계획을 적습니다.

- **초점 순간**: 연출할 가치가 있는 시퀀스나 상호작용이 있다면 무엇인가요?
- **연속성**: 설명이 필요한 상태 / 레이아웃 / 탐색 변화는 무엇인가요?
- **피드백**: 사용자의 어떤 조작과 결과에 반응이 필요한가요?
- **예산**: 비용이 클 수 있는 효과는 무엇이며 얼마나 자주 실행되나요?

초점 순간은 제품과 화면 개념에서 비롯되어야 합니다. 흔한 fade-and-rise, hover 시 위로 들기, 시차 레이어, 스크롤 공개는 그 자체로 설계 가설이 아닙니다.

## 의미에 맞는 시각 재료 고르기

transform과 opacity는 안정적인 기반이지만 표현 수단의 전부는 아닙니다. 전환이 전달할 의미에 맞는 속성을 선택합니다.

- **연속성과 관계**: shared-element 모션, FLIP 방식 transform, view transition, 목적이 분명한 공간 이동
- **초점과 깊이**: 범위를 제한한 blur, filter, backdrop, 빛 또는 그림자 변화
- **공개와 구성**: mask, clip path, crop, 제한된 가림 효과
- **재질과 에너지**: 시각 세계와 런타임이 지원하는 경우 색상, gradient 위치, 질감, 왜곡, shader 효과
- **상태와 피드백**: 원인과 결과를 분명히 보여주는 최소한의 변화

장관을 위해 효과를 겹쳐 쓰지 않습니다. 강한 재질 표현 하나를 초점 시퀀스에 적용하고 보조 상태는 조용하게 처리하면 대개 충분합니다.

목록이 나타날 때 형제 요소에 stagger를 적용하는 것은 적절합니다. 전체 지연을 제한하고, 스크롤되는 모든 섹션을 stagger 목록처럼 취급하지 않습니다.

## 타이밍과 easing

타이밍은 이동 거리와 결과의 중요성을 드러내야 합니다.

| 지속 시간 | 일반적인 용도 |
|---|---|
| 100~150ms | 즉각적인 피드백 |
| 150~300ms | 일상적인 상태 변화 |
| 300~500ms | 레이아웃, 오버레이, 화면 전환 |
| 500~800ms | 의도적으로 연출한 초점 등장 |

퇴장 애니메이션은 등장보다 빠르게 합니다. 확신 있게 도착하는 움직임에는 `cubic-bezier(0.16, 1, 0.3, 1)` 같은 자연스러운 감속을 사용합니다. 습관적으로 bounce나 elastic 곡선을 쓰지 않습니다. 피드백이 오래 걸리면 지연처럼 느껴집니다.

## 런타임에 맞게 구현

- 선언적 상태와 범위가 정해진 시퀀스에는 CSS transition과 keyframe을 사용합니다.
- 중단, 순서 제어, 동적 값이 필요하면 Web Animations API나 프로젝트에서 이미 쓰는 모션 라이브러리를 사용합니다.
- 상태 사이의 연속성이 중요한 경우 View Transition이나 shared-element 기법을 사용합니다.
- 스크롤과 연동된 움직임은 스크롤 관계 자체가 의미를 전달할 때만 사용하고 안정적인 대체 방식을 둡니다.
- 기존 스택이 간단히 구현할 수 있는 효과에 새 의존성을 추가하지 않습니다.

기본 상태에서 콘텐츠를 보이게 해 스크립트가 실패해도 페이지를 숨기지 않도록 합니다. `width`, `height`, `top`, `left`, margin처럼 레이아웃을 결정하는 속성을 무심코 애니메이션하지 않습니다. 필요하면 FLIP, transform, grid 기법을 사용합니다. blur, filter, shadow, canvas, shader 처리는 분리된 영역에 한정합니다. `will-change`는 애니메이션 중임을 알고 있는 때에만 적용합니다. transform을 사용한다고 빠를 것이라 가정하지 말고 대상 화면 크기와 기기에서 측정합니다.

## 접근성과 제어

자동 재생과 사운드 설정을 존중합니다. 필수가 아닌 반복 모션은 화면 밖이거나 숨겨졌을 때 멈춰야 합니다.

모든 웹 애니메이션은 `prefers-reduced-motion` 경로와 의도된 대안을 제공해야 합니다. 공간 이동을 줄이되 의미가 있는 opacity, 색상, 상태 전환은 유지합니다. Reduced motion은 움직임을 덜 부드럽고 더 적게 쓰라는 뜻이지 모든 모션을 끄라는 뜻이 아닙니다. 사용자의 동작을 확인하는 피드백은 읽을 수 있어야 합니다.

## 검증

- 초점 모션이 선택된 시각 세계와 화면 개념에 구체적으로 맞습니다.
- 모든 보조 애니메이션이 피드백, 상태, 관계를 설명합니다.
- 중단하거나 반복 사용해도 올바르게 동작합니다.
- 데스크톱, 모바일, 키보드 경로를 계속 사용할 수 있습니다.
- `prefers-reduced-motion` 경로가 중요한 피드백과 상태 변화를 없애지 않으면서 움직임을 줄입니다.
- 비용이 큰 효과가 대상 기기에서 매끄럽게 실행됩니다.
- 애니메이션을 제거하면 단순한 장식이 아니라 의미나 연출의 개성이 사라지는 것이 분명합니다.

모션이 제자리를 찾으면 최종 점검을 위해 `$impeccable polish`로 넘깁니다.
