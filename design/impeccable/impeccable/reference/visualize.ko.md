# Visualize: 방향 comp 및 에셋 제작

이미지 생성 기능을 사용할 수 있는 경우(comp 기반 빌드에서 harness 기본 도구 또는 API 대체 경로를 `impeccable context`가 보고함) [new-work.md](new-work.md)에서 이 문서를 불러옵니다. 코드 기반 계약에서는 의도적으로 이 파일을 건너뜁니다. 누락이나 설정 불일치가 아닙니다. 이 경우에는 읽지 않습니다. PRODUCT.md는 전제 조건입니다. DESIGN.md는 확정된 시각 세계에서만 필요합니다. 새 시각 세계나 대체 세계라면 작업을 마칠 때 기록합니다. 해당 화면에서 concept-seed가 출력한 MODE RULES 블록(COMPS)이 이 파일과 함께 comp 작업을 제어하며 두 문서가 충돌하면 MODE RULES를 우선합니다. 이번 세션에서 방향 추첨을 하지 않았다면 new-work.md에서 모드에 해당하는 파일을 읽습니다. new-work에서 시각 세계를 이미 결정했으므로 여기서 세계관 결정을 다시 열지 않습니다. 세션 범위의 구조 설계에서 이미 시각화한 카드 세 장을 사용자에게 보여 주었다면(new-work.md의 확정된 시각 세계 기준) 이 단계를 통과한 것입니다. 잠긴 카드의 comp가 승인 대상이므로 승인을 기록하고 After approval로 이동합니다. 새로운 결과물은 생성하지 않습니다.

검증(probe)은 구성, 서사, 위계, 정보 밀도, 초점 순간, 시그니처 사용, 이미지 요구사항을 테스트합니다. 두 번째 정체성 워크숍이 아닙니다. 시각 세계의 팔레트, 타이포그래피 방향, 재질 언어, 컴포넌트 성격, 이미지 접근법, 모션 문법을 고정합니다. 확정된 시각 세계라면 DESIGN.md에, 새 시각 세계라면 선택한 방향에 고정돼 있습니다.

## 서로 다른 구성 옵션 세 개 만들기

comp 단계는 빌드 phase 상태 안에서 실행합니다. 첫 comp 생성 전에 `impeccable build-phase start --direction <seed reference>`를 이미 실행했어야 합니다(선택한 카드에 decision comp가 있으면 `--decision-comp <path>`도 지정). `comps` phase가 열려 있어야 합니다. 시작 전에 렌더링한 comp는 상태에 포함되지 않으며, 거기서 재개한 세션에는 이어 갈 phase가 없습니다. `impeccable generate-image`는 start 전에 `.impeccable/mocks/`에 파일 쓰기를 거부합니다. harness 기본 이미지 도구도 같은 순서를 따릅니다.

요청 화면의 완성도 높은 기준 comp 세 개를 `.impeccable/mocks/` 아래에 저장합니다. 세션이 끝나도 유지해야 합니다. 선택한 카드에 decision comp가 있으면 그것이 첫 번째 옵션입니다. gate가 `--decision-comp`로 집계할 수 있도록 `.impeccable/mocks/decision/` 아래 지정 경로에 그대로 유지하고 다시 생성하지 않습니다. 나머지 둘을 렌더링합니다. comp는 화면의 실제 viewport로 만듭니다. 네이티브 앱이나 모바일 우선 화면은 기기 크기의 세로, 그 외에는 데스크톱 가로를 사용합니다. 휴대전화 화면을 가로로 그리면 구현하기도 전에 구성이 잘못 전달됩니다. comp는 빌드 thread의 작업이며 다른 agent에 맡기지 않습니다. prompt를 작성한 thread가 방향의 전체 맥락을 알고 빌드 시작 전에 모든 comp를 보아야 합니다. 각 이미지는 workspace 상대 경로로 엽니다. sandbox viewer는 절대 경로를 거부하며 프로젝트 루트 아래에는 상대 경로가 있습니다. 사용자와 이미 개발한 실제 콘텐츠와 화면 개념으로 comp를 만듭니다. 확정된 시각 세계에서는 대표적인 기존 페이지의 스크린샷을 찍어 참조 이미지로 넣어 정체성을 고정합니다(harness 이미지 도구의 입력 이미지 또는 `impeccable generate-image --ref`). prompt는 새 화면 구조를 중심으로 쓰고 참고 이미지는 팔레트, 글꼴, 컴포넌트 성격을 전달합니다. DESIGN.md의 텍스트만으로는 픽셀 참조보다 쉽게 방향이 어긋나기 때문입니다. 참고 이미지가 전달하는 부분과 가져오면 안 되는 부분을 함께 명시합니다. chrome, 팔레트, 글꼴, 컴포넌트 성격은 이어받되 참고 페이지의 콘텐츠는 가져오지 않습니다. 배너, hero, 카드를 그대로 가져오면 충실한 것이 아니라 참고 페이지가 새 화면에 새어 들어온 것입니다. 옵션은 세 개입니다. 한 개만 있으면 사용자에게 그대로 승인해 달라는 인상을 줄 수 있고, 세 개의 차이가 있어야 만들 가치가 있는 구성이 드러납니다. 선택 카드의 decision comp가 세 개 중 첫 번째입니다. 이미 해당 방향을 이 규율에 맞춰 완성도 높게 표현하므로 추가 두 개는 구성에서 첫 번째가 고정한 요소를 바꿉니다. 첫 comp를 입력 이미지로 쓰지 말고 글로 설명한 방향을 사용합니다(참고 이미지는 레이아웃을 고정하므로 comp 세 개가 한 구성으로 수렴할 수 있음). 두 번째와 세 번째 comp에서 허용하는 변화는 모드의 COMPS 규칙이 정합니다. 첫 comp를 단정하게 정리한 버전은 선택지를 늘리지 않습니다. 세 개를 동시에 승인 지점에 전달합니다. 낮은 등급 추첨 결과, identity-mode 화면, decision comp 없이 고정된 방향처럼 결정 comp가 없는 경우에만 여기서 세 개를 모두 생성합니다.

- comp prompt는 짧게 150~300단어로 쓰고 이미지 모델이 알 수 없는 것만 넣습니다. 모델은 prompt에 있는 것을 그리며 구체적으로 지정된 것은 판단하지 않으므로 모든 것을 지정하면 결과가 템플릿이 됩니다. 먼저 화면을 설명합니다. 어떤 제품을 위한 어떤 화면인지(데스크톱 웹 앱, 문서 페이지, 랜딩 페이지, 기기 viewport에 맞춘 네이티브 앱 화면)를 적고 화면 전체를 선명하고 읽을 수 있게 렌더링하며 주변 브라우저 창, 기기, 책상은 그리지 않도록 합니다. 이어 제품과 방문자의 과업을 쉬운 말로 씁니다. 이름, 단위가 있는 수치, 제안 또는 상태, 확실한 정도에 맞는 주장, 이름을 지정한 다음 동작 등 이에 답하는 실제 콘텐츠를 포함합니다. 다음은 이 comp의 주도 요소와 제품 개념(summary-led, timeline-led, offer-led, reference-led), 화면이 담는 부분을 읽는 순서에 따라 각각 한 구절로 씁니다. 마지막으로 제품 마크와 이름, 탐색, 편의 컨트롤, 화면 끝 가장자리를 한 줄로 씁니다. 화면은 완성된 하나의 화면이어야 하며 일부 조각이 아닙니다. 페이지에 탐색이 없다면 새로 만들지 말고 없다고 지정합니다. 사용자가 색상, 글꼴, 브랜드 요소를 고정한 경우 외에는 크기, 위치, 색상, 컴포넌트 스타일을 prompt에 넣지 않습니다. 사용자가 지정한 것은 콘텐츠이므로 명시해야 합니다. 각 렌더링을 자체 검토합니다. 포스터로 걸 수 있거나 텍스트가 붙은 사진처럼 보이면 comp가 아닙니다. 다시 생성합니다.
- 시각적 분위기는 시각 세계에서 가져오며 참고 그림이 있으면 그 그림도 사용합니다. 확정된 세계에는 위에서 말한 스크린샷 참조가 있습니다. 모양은 이미 전달되므로 prompt에 참고 이미지가 전달하는 내용을 설명하는 한 문장만 넣고 스타일 설명은 추가하지 않습니다. 카탈로그 시각 세계에는 카드 이미지가 있습니다. board와 hero 이미지를 참조로 붙이고(NEXT 줄에서 이름 지정. `impeccable generate-image --ref <board> --ref <hero>` 또는 harness 이미지 도구의 입력 이미지 사용), “참고 이미지는 스타일 영감으로만 활용해 실제 작동하는 제품에 맞게 적용하고 레이아웃과 콘텐츠는 복사하지 않는다”고 한 문장 씁니다. 그림을 제공한 뒤 스타일을 다시 서술하면 오히려 덮어쓰게 됩니다. 카드 이미지가 없는 방향은 구체적인 시각 규칙을 2~4문장으로 씁니다. 바탕과 각 색상이 맡는 역할, 글자 스타일, 기억에 남게 만드는 시그니처 하나를 포함합니다. 색상을 필요 이상으로 많이 나열하거나 컴포넌트를 하나씩 설명하지 않습니다.
- 주제가 comp 안에 있어야 합니다. 렌더링을 승인하기 전에 실제 주제가 보이는지 확인합니다. 세계관의 분위기만 묘사하고 주제 자체가 없으면 아무리 분위기를 잘 표현해도 실패입니다. 이 누락은 보통 제외 목록에 주제가 들어가 있어 발생하므로 콘텐츠를 명시해 재생성합니다.
- 화면이 출시될 실제 화면이라고 판단합니다. 이미지 하나만 봐도 방문자의 과업이 읽혀야 합니다. 캡션 없이 렌더링만 보고 화면 모드를 말할 수 있어야 합니다. 모드가 분명하지 않으면 표면이 없는 아트 디렉션입니다. 방문자의 과업을 prompt의 중심에 두고 다시 생성합니다.
- 방향의 깊이는 여러 영역을 장식하는 퍼포먼스가 아니라 표현의 강도입니다. 시각 세계는 주도 동작 하나와 이를 보조하는 재질, 글꼴, 간격으로 들어옵니다. 나머지는 같은 재질을 유지하면서 실제 크기의 콘텐츠를 담고 정적인 상태로 둡니다. 같은 크기의 다른 요소가 주도 요소와 경쟁하면 comp가 소리 지르고 있는 것입니다. 가장 강한 동작은 유지하고 나머지는 조용하게 해서 재생성합니다. 바쁘게 만든다고 더 대담해지지 않습니다.
- 사용자가 여러 개념을 shortlist했다면 세 comp에 골고루 반영합니다.
- 한 방향이 확정된 경우 이미지는 해결하기 쉬운 구성상의 불확실성을 바꿉니다. 화면의 주도 요소, topology, 순서, 정보 밀도, 위계, 초점 구성, 상호작용 관점 등을 변경합니다.
- 도입 순간만 보여 주지 말고 개념이 전체 화면을 이끌 수 있음을 증명할 만큼 충분한 범위를 포함합니다.
- 팔레트 결과물 생성, 새로운 분위기 질문, 다른 글자 스타일, 새 모티프 추가는 하지 않습니다. 확정된 세계가 개념을 지원할 수 없다면 세계를 바꾸지 말고 개념 shortlist로 돌아갑니다.

각 comp는 방향 테스트이지 스크린샷 사양이 아닙니다. 핵심 UI 텍스트, 반응형 동작, 접근성, 시맨틱, 인터랙션 상태는 구현 단계의 책임입니다.

## 승인 지점은 하나

세 comp를 함께 승인 페이지(`impeccable serve-question`, comp마다 하나씩, comp 자체를 hero 이미지로 사용)에 보여 줍니다. 또는 이미지가 결과에 실제로 보이는 harness를 사용합니다. 텍스트만 출력하는 곳은 화면 제시가 아닙니다. 다음을 묻고 기다립니다. 무엇을 이어갈지, 무엇이 시각 세계와 어긋나 보이는지, 선택한 개념을 승인 / 결합 / 수정 / 거부할지 질문합니다. 구조화된 simulated user를 사용했다면 동일한 질문을 받은 것으로 간주합니다.

사용자가 방향을 승인하거나 선택을 명시적으로 위임하기 전에 코드를 시작하지 않습니다. 선택을 위임받으면 작업 브리프, PRODUCT.md, DESIGN.md(새 세계면 선택 방향)를 근거로 결정하고 증거를 기록합니다. 승인은 작업 개념을 구체화하지만 DESIGN.md를 변경하지 않습니다.

이 승인 지점에는 대체 절차도 건너뛰는 조건도 없습니다. 구조화된 질문 도구가 오류를 내면 승인 페이지로 전환합니다. 둘 다 실패한 경우에만 선택권이 위임된 것으로 처리합니다. 위임된 선택도 승인과 똑같이 기록하고 마지막 답장이 아니라 첫 답장에서 이를 공개합니다. Finish reviewer는 기록된 승인 없이 comp 단계에서 만든 comp가 있으면 중요한 발견 사항으로 처리합니다. `.impeccable/mocks/decision/`의 decision comp는 방향 추첨 단계 결과이지 comp 단계 산출물이 아니므로 그것만으로 승인되었다고 볼 수 없습니다.

승인 뒤 도구가 찾을 수 있는 곳에 선택 결과를 기록합니다. 승인된 comp 경로를 화면 브리프에 넣고 prompt sidecar(이미지의 전체 파일명 뒤에 `.json`을 붙임: `a.png`의 경우 `a.png.json`)에 `"approved": true`를 추가합니다(`impeccable generate-image`가 만든 comp에는 sidecar가 있으며 네이티브 도구가 만들지 않았다면 새로 만듦). sidecar는 mocks 폴더와 함께 이동하므로 브리프를 볼 수 없는 세션이나 컴퓨터에서도 승인 상태가 유지되고, `impeccable build-phase advance`가 읽어 comps phase를 종료합니다. 구성과 그대로 재현하면 안 되는 comp 부분을 요약하고 new-work.md로 돌아가 승인된 개념에 따른 방향 계약을 기록한 다음 빌드합니다.

## 승인 후: comp를 명세로 사용

승인된 comp는 의미 있고 반응형이며 접근성이 있는 코드로 옮기는 기준이지 다시 구성해도 된다는 허가가 아닙니다. 팔레트와 분위기만 유지하면서 topology를 다시 그리면 두 번째 아트 디렉션이 됩니다. 핵심 UI 텍스트나 컨트롤을 래스터화하지 않습니다. 승인 뒤 사용자에게 묻지 않고 다른 시각 요소를 동력으로 교체하지 않습니다.

comp의 내용을 기억으로 추정하지 말고 측정합니다. new-work.md 6단계는 `impeccable build-phase`를 이용해 단계별 빌드를 진행합니다. spec 단계에서 comp를 영역 상자와 샘플 팔레트로 나눕니다(`impeccable comp-spec`). 각 영역의 매체는 구현하기 쉬운지에 따라 정하지 말고 픽셀의 실제 성격에 따라 정합니다. 인물, 제품 사물, 기계, 원근이나 음영 또는 일러스트 기술이 필요한 그림, 이름이 붙은 질감(짜인 천, 종이 결, 직물, 가죽, brushed metal)은 모두 `plate` / `image` / `texture` 영역이며 래스터로 제출합니다. 텍스트, 컨트롤, chrome, 셀 수 있는 요소로 구성된 도식, 평면 도형 체계, 움직이거나 크기가 바뀌거나 반응해야 하는 요소는 시맨틱으로 구현합니다. 조각한 패널의 마감을 “CSS”라고 쓰거나 찢어진 가장자리를 여러 꼭짓점의 `clip-path`로 대체하면 승인된 디자인을 조용히 삭제한 것입니다. Detector의 organic-clip-path와 buried-raster 규칙 및 hero gate의 영역 점수가 이를 확인합니다. 이미지 매체로 구현하기로 한 영역을 제거하는 것은 승인 지점에서 사용자가 선택할 범위 결정이지 승인 뒤 조용히 평평하게 바꾸는 일이 아닙니다. 생성된 이미지는 재질이지 사실 주장이 아닙니다. 근거 규칙은 주장, 사양, 추천사, 실제라고 제시한 사진에 적용되지 렌더링 정확도에는 적용되지 않습니다.

## Plate 및 출처

각 래스터 영역의 plate는 페이지 코드를 작성하기 전 plates phase에서 배정된 asset producer 또는 현재 thread가 제작합니다. `.agents/skills/impeccable/scripts/impeccable comp-spec --crop <id>`를 사용해 crop을 가져오고 `impeccable comp-spec --plate-prompt <id>`를 prompt 파일에 저장합니다. crop과 prompt를 harness 이미지 도구에 전달하거나 `impeccable generate-image --ref <crop.png> --prompt-file <prompt.txt> --out <plate.png> --size <WxH> --quality high`를 사용합니다. 분리된 cutout에는 plate-prompt와 API 생성 명령 모두 `--background transparent`를 추가하고 네이티브 PNG alpha를 사용해 흰색으로 칠한 영역과 빈틈을 보존합니다. 전체 프레임 이미지는 `--background opaque`를 사용합니다. 출력 디렉터리를 먼저 만들고 밝고 어두운 배경에서 alpha를 확인합니다. 이미지 생성 맥락은 에셋의 일부입니다. 도구 종류와 관계없이 이미지 생성 뒤 `.agents/skills/impeccable/scripts/impeccable embed-prompt <image> --prompt "<prompt>"`를 실행해 도구에 실제로 전달한 문자열을 파일에 포함합니다(`impeccable generate-image`는 자동 처리). `--read`로 복구하고 `--scan <dir>`으로 prompt가 아직 없는 래스터를 나열할 수 있습니다. 포함된 prompt와 spec의 영역 행이 래스터의 **출처 정보**이며 artifact가 참조하는 모든 래스터에 있어야 합니다. 외부 출처, stock, 기존 래스터는 생성 prompt 대신 원래 출처를 기록합니다. 수정 단계나 reviewer의 재빌드 단계에서 나중에 만들거나 교체한 래스터도 같은 절차로 제작합니다. 수정 단계에서 제외한 래스터는 같은 변경 묶음에서 삭제합니다.

이미지 변환에는 부팅 시 `impeccable context`가 보고한 converter(IMAGE_TOOLS 줄)를 사용합니다. 부팅 시 없다고 나왔을 때만 세션당 최대 한 번 확인하고, 이미지마다 반복 탐색하지 않습니다.

방향 계약, 단계형 빌드, 마무리 작업을 위해 [new-work.md](new-work.md)로 돌아갑니다.
