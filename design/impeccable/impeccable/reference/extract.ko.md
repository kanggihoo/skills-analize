# Extract 흐름

재사용 가능한 패턴, 컴포넌트, 디자인 토큰을 찾아 디자인 시스템에 추출하고 통합해 체계적으로 재사용합니다.

## 1단계: 디자인 시스템 찾기

디자인 시스템, 컴포넌트 라이브러리, 공유 UI 디렉터리를 찾습니다. 구조를 파악합니다. 컴포넌트 구성, 이름 규칙, 디자인 토큰 구조, import/export 관례를 확인합니다.

디자인 시스템이 없다면 아직 새로 만들지 않습니다. 사용할 수 있는 경우 Codex의 구조화된 사용자 입력 / 질문 도구로 묻고, 없으면 채팅에서 답을 받은 뒤 계속합니다. 먼저 사용자가 선호하는 위치와 구조를 파악합니다.

## 2단계: 패턴 찾기

대상 영역에서 추출 기회를 살펴봅니다.

- **반복 컴포넌트**: 3회 이상 쓰인 비슷한 UI 패턴(버튼, 카드, 입력 필드)
- **하드코딩된 값**: 토큰으로 정의해야 할 색상, 간격, 타이포그래피, 그림자
- **일관성 없는 변형**: 같은 개념을 여러 방식으로 구현
- **구성 패턴**: 반복되는 레이아웃이나 상호작용 패턴(양식 행, 도구 모음 그룹, 빈 상태)
- **글자 스타일**: 반복 사용되는 font-size + weight + line-height 조합
- **애니메이션 패턴**: 반복되는 easing, 지속 시간, keyframe 조합

가치를 평가합니다. 의도가 같은 방식으로 3회 이상 사용된 것만 추출합니다. 성급한 추상화는 중복보다 좋지 않습니다.

## 3단계: 추출 계획

체계적인 계획을 만듭니다.

- **추출할 컴포넌트**: 어떤 UI 요소를 재사용 가능한 컴포넌트로 만드나요?
- **만들 토큰**: 어떤 하드코딩 값을 디자인 토큰으로 바꾸나요?
- **지원할 변형**: 각 컴포넌트에 어떤 변형이 필요한가요?
- **이름 규칙**: 기존 패턴과 맞는 컴포넌트명, 토큰명, prop명
- **마이그레이션 경로**: 기존 사용처를 어떻게 새 공유 버전으로 바꾸나요?

디자인 시스템은 점진적으로 성장합니다. 언젠가 재사용할지 모르는 모든 것이 아니라 지금 명확히 재사용할 수 있는 항목만 추출합니다.

## 4단계: 추출하고 보강

더 나은 재사용 버전을 구현합니다.

- **컴포넌트**: 합리적인 기본값이 있는 명확한 props API, 사용 사례에 맞는 변형, 접근성 내장(ARIA, 키보드 탐색, 초점 관리), 문서와 사용 예시
- **디자인 토큰**: 명확한 이름(기본 토큰 vs 의미 토큰), 적절한 위계와 구성, 각 토큰을 언제 쓰는지 설명
- **패턴**: 이 패턴을 사용하는 경우, 코드 예시, 변형과 조합

## 5단계: 마이그레이션

기존 사용처를 새 공유 버전으로 바꿉니다.

- **모든 인스턴스 찾기**: 추출한 패턴을 검색
- **체계적으로 대체**: 각 사용처가 공유 버전을 사용하도록 수정
- **충분히 테스트**: 시각적·기능적 동등성 확인
- **죽은 코드 삭제**: 이전 구현 제거

## 6단계: 문서화

디자인 시스템 문서를 업데이트합니다.

- 새 컴포넌트를 컴포넌트 라이브러리에 추가
- 토큰 사용법과 값을 문서화
- 예시와 지침 추가
- Storybook 또는 컴포넌트 카탈로그 업데이트

**피할 것**:
- 일반화하지 않은 일회성·맥락 전용 구현을 추출
- 지나치게 일반적이어서 쓸모없는 컴포넌트 만들기
- 기존 디자인 시스템 관례를 고려하지 않고 추출
- TypeScript 타입이나 prop 문서 작성 생략
- 모든 단일 값마다 토큰 만들기(토큰에는 의미가 있어야 함)
- 의도가 다른 항목 추출(겉모습이 비슷해도 목적이 다른 두 버튼은 분리 유지)
