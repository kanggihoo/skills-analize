> **추가로 필요한 맥락**: 사용자가 도달해야 하는 “아하” 순간과 사용자 경험 수준.

사용자가 처음으로 가치를 느끼는 순간까지 최대한 빠르게 안내합니다. Onboarding의 목표는 제품을 가르치는 것이 아닙니다. 제품이 시간을 들일 만한 가치가 있다는 것을 증명하는 순간까지 사용자를 데려가는 것입니다.

## Onboarding 필요성 평가

사용자가 무엇을 왜 배워야 하는지 파악합니다.

1. **과제 파악**:
   - 사용자가 달성하려는 것은 무엇인가요?
   - 현재 경험에서 무엇이 혼란스럽거나 불분명한가요?
   - 어디에서 막히거나 이탈하나요?
   - 사용자가 도달하길 바라는 “아하” 순간은 무엇인가요?

2. **사용자 이해**:
   - 경험 수준은 어떤가요?(초보자, 숙련자, 혼합)
   - 동기는 무엇인가요?(즐겁게 둘러보려는가, 업무상 필수인가)
   - 할애할 시간은 어느 정도인가요?(5분? 30분?)
   - 어떤 대안을 알고 있나요?(경쟁 제품에서 왔는가, 범주 자체가 새로운가)

3. **성공 정의**:
   - 성공하려면 최소한 무엇을 배워야 하나요?
   - 사용자가 취하길 바라는 핵심 동작은 무엇인가요?(첫 프로젝트? 첫 초대?)
   - Onboarding이 효과가 있었는지 어떻게 알 수 있나요?(완료율? 첫 가치까지 시간?)

Onboarding은 가능한 모든 내용을 가르치는 대신 사용자가 최대한 빨리 가치를 경험하게 해야 합니다.

## Onboarding 원칙

핵심 원칙을 따릅니다.

### 설명보다 직접 보여주기
- 설명만 하지 말고 작동하는 예시를 시연
- 별도 튜토리얼 모드가 아니라 Onboarding 안에서 실제 기능 제공
- 점진적으로 공개하고 한 번에 한 가지씩 설명

### 가능하면 선택 사항으로 두기
- 경험이 있는 사용자는 Onboarding을 건너뛸 수 있게 함
- 제품 접근을 막지 않음
- “건너뛰기” 또는 “직접 둘러볼게요” 선택 제공

### 가치에 이르는 시간
- 가능한 한 빨리 “아하” 순간으로 안내
- 가장 중요한 개념을 먼저 제시
- 가치의 80%를 만드는 20%를 가르침
- 고급 기능은 사용 맥락에 따른 발견으로 미룸

### 절차보다 맥락
- 미리 전부 가르치지 말고 필요할 때 기능을 설명
- 빈 상태를 Onboarding 기회로 활용
- 실제 사용하는 지점에서 tooltip과 안내 제공

### 사용자의 지성을 존중
- 얕잡아보거나 지나치게 설명하지 않음
- 간결하고 분명하게 표현
- 사용자가 표준 패턴은 스스로 익힐 수 있다고 가정

## 맥락에 맞는 Onboarding 설계

### 최초 제품 Onboarding

**환영 화면**:
- 분명한 가치 제안(이 제품은 무엇인가요?)
- 무엇을 배우거나 달성하는지 설명
- 솔직한 시간 예상 안내
- 경험이 있는 사용자를 위해 건너뛰기 제공

**계정 설정**:
- 필수 정보만 수집(나머지는 나중에 받을 수 있음)
- 각 정보를 요청하는 이유 설명
- 가능한 경우 적절한 기본값 사용
- 알맞은 경우 소셜 로그인 제공

**핵심 개념 소개**:
- 핵심 개념 1~3개만 소개(전부 소개하지 않음)
- 쉬운 언어와 예시 사용
- 가능하면 읽기만 하지 말고 직접 조작
- 진행 상황 표시(step 1 of 3)

**첫 성공**:
- 실제 과업을 사용자가 완수하도록 안내
- 미리 채운 예시나 템플릿 제공
- 완료를 축하하되 과장하지 않음
- 다음 단계를 명확히 안내

### 기능 발견과 채택

**빈 상태**:
빈 공간을 그대로 두는 대신 다음을 보여 줍니다.
- 여기에 나타날 내용(설명 + 스크린샷 / 일러스트)
- 그 내용이 가치 있는 이유
- 첫 항목을 만드는 명확한 CTA
- 예시나 템플릿 선택

예시:
```
아직 프로젝트가 없습니다
프로젝트를 사용하면 업무를 정리하고 팀과 협업할 수 있습니다.
[첫 프로젝트 만들기] 또는 [템플릿에서 시작]
```

**맥락 기반 tooltip**:
- 사용자가 기능을 처음 보는 관련 시점에 표시
- 해당 UI 요소를 직접 가리킴
- 짧은 설명 + 이점
- 닫을 수 있고 “다시 표시하지 않기” 선택 제공
- 선택적으로 “더 알아보기” 링크 제공

**기능 알림**:
- 새 기능이 출시되면 강조
- 무엇이 새로워졌고 왜 중요한지 설명
- 즉시 사용해 볼 수 있게 함
- 닫을 수 있게 함

**점진적 Onboarding**:
- 사용자가 기능을 만날 때 가르침
- 새 기능이나 사용하지 않은 기능에 badge 또는 표시
- 모든 선택지를 처음부터 보여주지 말고 복잡성을 단계적으로 공개

### 안내 투어와 walkthrough

**사용할 상황**:
- 기능이 많은 복잡한 인터페이스
- 기존 제품의 큰 변화
- 도메인 지식이 필요한 업계 전용 도구

**설계 방법**:
- 특정 UI 요소를 spotlight 처리(나머지 페이지는 어둡게)
- 단계를 짧게 유지(투어당 최대 3~7단계)
- 사용자가 자유롭게 클릭하며 진행하도록 허용
- “투어 건너뛰기” 제공
- 도움말 메뉴에서 다시 실행할 수 있게 함

**좋은 방법**:
- 수동 설명보다 직접 조작(실제 버튼을 누르게 함)
- 기능이 아니라 workflow에 집중(“프로젝트 버튼입니다” 대신 “프로젝트 만들기”)
- 동작이 되도록 예시 데이터 제공

### 인터랙티브 튜토리얼

**사용할 상황**:
- 직접 연습해야 하는 과업
- 개념이 복잡하거나 낯섦
- 안전한 환경에서 연습하는 편이 좋은 고위험 작업

**설계 방법**:
- 예시 데이터가 있는 sandbox 환경
- 분명한 목표(“지역별 매출 차트를 만드세요”)
- 단계별 안내
- 검증(올바르게 완료했는지 확인)
- 마무리 순간(“이제 사용할 준비가 됐습니다!”)

### 문서와 도움말

**제품 내 도움말**:
- 인터페이스 곳곳에 맥락에 맞는 도움말 링크
- 키보드 단축키 참조
- 검색 가능한 도움말 센터
- 복잡한 workflow용 영상 튜토리얼

**도움말 패턴**:
- 복잡한 기능 옆의 `?` 아이콘
- tooltip 내 “더 알아보기” 링크
- 검색창의 `⌘K` 같은 키보드 단축키 표시

## 빈 상태 디자인

모든 빈 상태는 다음을 포함해야 합니다.

### 여기에 표시될 내용
“최근 프로젝트가 여기에 표시됩니다.”

### 중요한 이유
“프로젝트를 사용하면 업무를 정리하고 팀과 협업할 수 있습니다.”

### 시작 방법
[프로젝트 만들기] 또는 [템플릿에서 가져오기]

### 시각적 흥미
일러스트나 아이콘 사용(빈 화면에 텍스트만 두지 않음)

### 맥락에 맞는 도움말
“시작하는 데 도움이 필요하신가요? [2분 튜토리얼 보기]”

**빈 상태 유형**:
- **첫 사용**: 이 기능을 아직 사용하지 않음(가치 강조, 템플릿 제공)
- **사용자가 비움**: 의도적으로 모두 삭제함(방해하지 않고 쉽게 다시 생성)
- **결과 없음**: 검색이나 필터 결과가 없음(검색어 변경 제안, 필터 초기화)
- **권한 없음**: 접근할 수 없음(이유와 권한을 얻는 방법 설명)
- **오류 상태**: 데이터를 불러오지 못함(무슨 일이 일어났는지 설명, 재시도 선택 제공)

## 구현 패턴

### 기술 선택지

**Tooltip 라이브러리**: Tippy.js, Popper.js  
**투어 라이브러리**: Intro.js, Shepherd.js, React Joyride  
**Modal 패턴**: 초점 trap, backdrop, 닫기용 ESC  
**진행 저장**: “봤음” 상태 저장에 LocalStorage 사용  
**분석**: 완료율과 이탈 지점 추적

**저장 패턴**:
```javascript
// 사용자가 확인한 onboarding 단계 기록
localStorage.setItem('onboarding-completed', 'true');
localStorage.setItem('feature-tooltip-seen-reports', 'true');
```

Onboarding은 한 번만 보여 줍니다. 완료 상태를 기록하고 사용자가 닫은 상태를 존중합니다.

**피할 것**:
- 제품을 사용하기도 전에 긴 onboarding을 강요
- 명백한 내용을 설명해 사용자를 얕잡아봄
- 같은 tooltip을 반복 표시(닫기 상태 존중)
- 투어 동안 UI 전체를 막음(둘러보기 허용)
- 실제 제품과 동떨어진 별도 튜토리얼 모드 제작
- 처음부터 정보 과부하(점진적 공개!)
- “건너뛰기”를 숨기거나 찾기 어렵게 만듦
- 재방문 사용자를 잊음(최초 onboarding을 다시 표시하지 않음)

## Onboarding 품질 검증

실제 사용자로 테스트합니다.

- **완료 시간**: 사용자가 onboarding을 빠르게 끝낼 수 있나요?
- **이해도**: 완료한 뒤 내용을 이해하나요?
- **행동**: 사용자가 원하는 다음 단계를 수행하나요?
- **건너뛰기 비율**: 너무 많은 사용자가 건너뛰나요?(너무 길거나 가치가 부족할 수 있음)
- **완료율**: 사용자가 완료하나요?(낮으면 단순화)
- **가치에 이르는 시간**: 첫 가치를 경험하기까지 얼마나 걸리나요?

사용자가 빠르게 아하 순간에 도달하고 이탈하지 않으면 최종 점검을 위해 `$impeccable polish`로 넘깁니다.
