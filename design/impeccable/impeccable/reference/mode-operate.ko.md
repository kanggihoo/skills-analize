# Operate 모드

`impeccable concept-seed --mode operate`는 아래 두 절을 MODE RULES 블록으로 출력합니다. Operate 화면에 방문자는 일을 끝내러 왔으므로 페이지는 먼저 해당 범주의 실제 제품처럼 작동해야 하며 시각 세계는 이를 보조합니다.

## 방향

이 도구를 사용할 줄 아는 사람은 시각 세계를 알아차리기 전에 모든 것이 어디 있는지 알아야 합니다. 시각 세계가 보탤 수 있는 것은 네 가지뿐입니다. 글꼴, 팔레트, 정보 밀도, 시그니처 동작 하나입니다. 레이아웃, 탐색 모델, 컨트롤을 정하지 않습니다. 색상은 시각 세계가 제공하는 요소이며 실제 역할을 합니다. shell의 확정 팔레트(색상 rail이나 header, 틴트 바탕), 상태 색, 데이터 계열, 선택, 시그니처 동작에 쓰입니다. 포인트 색 하나만 있는 회색 화면은 절제된 화면이 아니라 범주의 기본형에서 완성도를 뺀 것입니다.

후보, 지정된 방향, 도전 방향을 결합하거나 판단하기 전에 이 한계를 기준으로 모두 읽습니다. 사용자가 조작하는 도구나 장비(terminal, scope, control panel, cockpit) 또는 가상 인터페이스에서 가져온 시각 세계는 실제 작업 화면에 해당 도구의 외관을 의상처럼 입히게 됩니다. 다른 목록에서 가져온 세계로 바꾸거나 글꼴, 팔레트, 정보 밀도, 시그니처 동작으로 옮길 수 있는 요소만 가져옵니다. 카탈로그의 세계가 원래 인터페이스 언어여도 같은 제한이 적용됩니다. 글꼴, 정보 밀도, 팔레트, 시그니처 동작 하나만 빌리고 탐색과 컨트롤은 플랫폼의 표준 방식을 따릅니다(웹에서는 웹 컴포넌트, 앱에서는 네이티브 컨트롤).

각 방향의 첫 viewport는 먼저 제품 shell로 작성합니다. 탐색, 작업 영역과 각 영역의 목적, 방문자가 처음 읽는 데이터와 그 상태를 배치하고, 마지막으로 시그니처 동작을 둘 위치를 정합니다. 시각적 표현은 과업, 상태, 익숙한 affordance를 가리면 안 됩니다. comp와 빌드에서 찾을 수 있게 시그니처 동작을 구체적으로 이름 붙입니다(예: 대중교통 지도처럼 그린 서비스 상태, 시간표의 열 리듬으로 설정한 일정). 색상 테마만으로 나타나는 방향은 아직 시그니처 동작을 찾지 못한 것입니다. 도전 방향을 결합할지 평가할 때 제품이 해당 범주에서 실제로 작동하는 제품처럼 보이는지도 명료성의 일부입니다.

## Comp

comp는 방향의 확정 팔레트로 표현한 제품 화면입니다. shell과 탐색, 각 작업을 위한 구별되는 영역, 데이터가 있는 경우 해당 데이터의 범위를 지정하는 필터, 상태가 분명한 차트와 표를 포함합니다. 시각 세계는 글꼴, 팔레트, 정보 밀도, 시그니처 동작 하나로만 들어옵니다. 페이지의 구성을 대신하지 않으므로 실제 작업 화면이 신문, 포스터, 다른 시각 결과물처럼 보여서는 안 됩니다. 모든 컨트롤은 방문자가 이미 사용법을 아는 표준 요소여야 합니다. 버튼, 탭, 입력, 선택, 필터, 정렬 헤더가 있는 표, 탐색으로 읽히는 탐색을 사용합니다. 시각 세계가 가진 인터페이스를 의상처럼 입히지 않습니다(terminal의 기능 키 bar나 명령 프롬프트, 장비 베젤, 표 대신 쓰는 줄 그은 장부 종이 등). 플랫폼 표준 컴포넌트로 구현할 수 없다면 도구의 그림이지 도구가 아닙니다. 완성도 기준은 해당 범주 최고의 제품입니다. 정렬된 grid, 일관된 간격, 실제 글자 크기 체계, 명확한 위계를 갖춥니다. 시그니처 동작은 이미 깨끗한 화면을 보탤 뿐 그 대신이 될 수 없습니다.

화면의 실제 콘텐츠를 prompt에 포함합니다. 제품명, 그럴듯한 값과 단위가 있는 현실적 데이터, 실제 레이블, 볼 가치가 있는 상태 하나(경고, 성능 저하, 빈 필터 결과)를 넣고 자리표시 타일은 사용하지 않습니다. 상태 색(치명 상태의 빨강, 성능 저하의 호박색)은 의미가 있을 때만 시각 세계의 팔레트 위에 놓습니다. 시간에 따라 변하는 대표 수치는 최근 기록을 함께 보여 주고 변화가 생긴 시점을 표시합니다.

두 번째와 세 번째 comp는 세계가 차지하는 범위를 바꾸지 않고 제품 구성을 다르게 합니다. 탐색 모델(측면 rail, 상단 bar, 명령 우선), 작업 영역을 화면에 나누는 방식, 먼저 보여 줄 데이터, 정보 밀도, 시그니처 동작의 위치를 바꿉니다. thumbnail 크기에서도 첫 comp와 분명히 달라야 합니다. prompt를 읽어야만 차이를 아는 변형은 선택지를 늘리지 않습니다. 세계 재료, 질감, 장식을 더하는 변형은 잘못된 방향으로 더 나아갑니다. 실제 작업 화면에서 세계를 더 드러내는 것은 의상화입니다.

렌더링을 볼 때마다 자체 검토합니다. 이름을 가려도 제품의 범주를 알 수 있나요? 방문자가 이 화면에서 과업을 수행할 수 있나요? 범주의 표준만큼 깨끗하고, 그보다 더 뚜렷한가요? 시각 세계의 결과물처럼 먼저 읽히면 shell과 작업 영역을 구역별로 이름 붙여 다시 생성하고 시각 세계를 네 가지 기여 요소에만 제한합니다.
