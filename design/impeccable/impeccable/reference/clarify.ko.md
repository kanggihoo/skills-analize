> **추가로 필요한 맥락**: 대상 사용자의 지식 수준과 감정 상태.

사용자가 인터페이스에서 무슨 일이 일어났는지, 무엇이 중요한지, 다음에 무엇을 해야 하는지 이해하도록 불분명한 문구를 고칩니다. 사실의 의미, 제품 용어, 브랜드 말투는 유지합니다.

## 문구 점검

문구만 따로 보지 말고 사용자가 거치는 전체 흐름을 읽습니다. 다음을 확인합니다.

- 모호한 명사, 동사, 동작
- 내부 용어 또는 사용자가 이미 안다고 가정하는 정보
- 모호한 레이블, 결과, 시스템 상태
- 결과, 복구 방법, 시점 설명 누락
- 용어와 대소문자의 불일치
- 반복되는 제목, 도입, 도움말, 확인 문구
- 실제 화면 너비나 번역에서 깨지는 문구
- 스트레스, 위험, 성공, 긴급성을 고려하지 않은 말투

제품 맥락과 UI 주변 내용을 보고 사용자의 업무와 지식 수준을 추론합니다. 사실에 관한 주장, 법률적 의미, 도메인 고유 용어를 바꾸기 전에는 묻습니다.

## 메시지 위계 정하기

각 상태에서 다음을 결정합니다.

1. 지금 사용자에게 필요한 핵심 사실 한 가지
2. 다음에 할 수 있는 동작
3. 결정에 영향을 주는 보충 맥락
4. 이 순간에 적절한 말투

각 생각은 한 번씩만 표현합니다. 제목이 이미 상태를 설명한다면 도입 문구는 새로운 정보를 더하거나 사라져야 합니다.

## 기능별로 문구 고치기

### 동작과 탐색

결과가 분명하지 않다면 구체적인 동사와 목적어를 씁니다. 레이블은 동작을 실행하는 제스처가 아니라 실행 결과를 설명해야 합니다. 제품에서 같은 개념은 같은 명사와 동사로 표현합니다.

파괴적 동작에는 대상과 결과를 함께 적습니다. 안전하게 되돌릴 수 있다면 확인보다 실행 취소를 우선합니다. 확인이 꼭 필요하면 메시지와 버튼 모두에 동작 이름을 씁니다. `Yes`, `No`, `OK`, `Submit`은 사용하지 않습니다.

### 양식

계속 보이는 레이블을 사용합니다. placeholder는 예시이지 레이블이 아닙니다. 형식과 자격 요건은 제출 전에 설명합니다. 요청 이유는 분명하지 않을 때만 설명합니다. 필수와 선택 항목의 표시 방식을 일관되게 유지합니다.

검증 메시지는 사용자 탓을 하지 않으면서 필요한 조치와 수정 방법을 알려야 합니다. 관련 안내는 필드 가까이에 두고, 오류를 접근 가능한 방식으로 알립니다.

### 오류와 권한

실행 가능한 오류 메시지는 다음 내용을 답해야 합니다.

1. 무엇이 실패했는가
2. 유용하고 확인된 경우, 왜 실패했는가
3. 어떻게 복구하거나 어떤 대안을 사용할 수 있는가

내부 코드를 핵심 메시지로 노출하지 않습니다. 시스템이 알 수 없는 원인이나 해결 방법을 약속하지 않습니다. 개인정보, 결제, 삭제, 접근 권한 상실, 진행 중인 작업 차단은 심각하게 다룹니다. 친근함은 좋지만 농담은 하지 않습니다.

### 로딩, 빈 화면, 성공 상태

로딩 문구는 실제 작업을 나타내고 기다림이 의미 있을 때 정직한 예상 시간을 안내합니다. 계산 가능한 진행률을 사용할 수 있다면 표시하고, 진행률을 지어내지 않습니다.

빈 상태에서는 처음 사용하는 중인지, 결과가 없는지, 필터 때문인지, 권한 때문인지, 실패했는지 구별합니다. 상태를 설명하고 다음에 할 만한 동작을 제공합니다.

성공 문구는 완료된 결과를 확인해 주고, 사용자가 다음에 해야 할 일이 바뀌는 경우에만 그 결과를 알립니다. 일반적인 성공 문구는 짧게 씁니다.

### 도움말과 안내 문구

도움말은 컨트롤을 반복해서 설명하지 말고 사용자가 암묵적으로 궁금해하는 질문에 답해야 합니다. 흔하지 않은 세부 사항은 점진적으로 공개합니다. 링크 텍스트는 주변 문맥 없이 읽어도 이해되어야 합니다. 아이콘만 있는 컨트롤에는 접근 가능한 이름이 필요합니다.

## 말투, 접근성, 현지화

목소리는 일관되게 유지하되 상황에 따라 말투를 조정합니다. 사용자가 실제로 아는 용어까지 단순화하지 말고 평이하게 씁니다.

- 이어 붙인 조각이 아니라 번역할 수 있는 완결된 메시지를 씁니다.
- 변수를 구조화해 번역자가 순서를 바꿀 수 있게 합니다.
- 섣불리 줄여 쓰지 말고 번역 후 길이가 늘어날 여지를 둡니다.
- 대체 텍스트에는 이미지가 전달하는 정보를 씁니다. 장식 이미지에는 빈 alt를 사용합니다.
- 스크린 리더 이름을 화면에 보이는 레이블과 결과에 맞춥니다.
- 문장부호, 색상, 아이콘만으로 의미를 전달하지 않습니다.

제품 전체에서 용어가 일관되지 않다면 짧은 용어집을 관리합니다. 인터페이스에서 문학적 효과를 내려고 같은 말을 여러 표현으로 바꾸지 않습니다.

## 검증

흐름 전체를 맥락 안에서 읽고 다음을 시험합니다.

- 숨겨진 제품 지식 없이도 이해되는가
- 오류, 빈 상태, 결정 지점에서 다음 동작이 분명한가
- 사실이 정확하고 용어가 일관적인가
- 대상 화면 너비와 200% 확대에서 훑어보기 쉬운가
- 긴 이름, 현지화로 길어진 문구, 복수형, 동적 값이 잘 처리되는가
- 접근 가능한 이름과 상태 변경 안내가 올바른가
- 결과의 중요성 및 사용자의 감정 상태에 말투가 적절한가

최종 문구는 의미와 복구 방법을 잃지 않는 범위에서 최대한 짧아야 합니다.

문구가 명료해지면 최종 점검을 위해 `$impeccable polish`로 넘깁니다.
