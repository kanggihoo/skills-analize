# iOS 플랫폼

네이티브 iOS / iPadOS 앱에 적용합니다. SwiftUI, UIKit, React Native, Expo, Flutter로 Apple 기기에 출시하는 앱이 포함됩니다.

네이티브 화면에서는 방문자 모드가 시각적 표현이 HIG보다 우선할 수 있는 범위를 좁힙니다. 모든 모드에서 구조, 탐색, 상호작용은 HIG를 따릅니다. 브랜드는 플랫폼이 열어 둔 영역(틴트, 글꼴, 모션, 콘텐츠)을 통해 표현합니다.

## iOS 품질 검사

iPhone에 익숙한 사용자가 앱을 신뢰할까요, 아니면 명세를 벗어난 컨트롤에서 멈칫할까요? 흔한 징후는 “웹사이트를 포팅한 앱”처럼 보이는 것입니다. 탐색 막대를 새로 만들고, 뒤로 가기 제스처를 직접 구현하고, 웹 형태의 버튼이나 hover에 의존하는 기능을 사용합니다. 기본적으로 플랫폼 컴포넌트를 사용하고, 사용자가 고맙다고 느낄 이유가 있을 때만 벗어납니다.

## 레이아웃과 구조

- **안전 영역**: 안전 영역 inset 안에 레이아웃합니다. 노치, Dynamic Island, 홈 표시기, 둥근 모서리 아래에 컨트롤을 두지 않습니다.
- **시스템 탐색**: 최상위 섹션이 2~5개면 탭 바(동작이 아니라 섹션)를 사용하고, 위계를 탐색 stack으로, 자체 완결적인 과업을 sheet로 표현합니다. 사용자 지정 전역 탐색이나 혼합된 비유를 사용하지 않습니다.
- **가장자리에서 쓸어 뒤로 가기는 계속 작동해야 합니다.** 왼쪽 가장자리의 뒤로 가기 동작은 근육 기억입니다. 비활성화하거나 위에 다른 것을 덮지 않습니다.
- 최상위 화면에는 **큰 제목**을 사용하고 스크롤하면 인라인 제목으로 축소합니다. 깊은 상세 화면은 계속 인라인 제목을 사용합니다.

## 터치 영역

- 탭 가능한 컨트롤마다 최소 **44×44 pt**를 확보하고 대상 사이에 여유 공간을 둡니다.

## 타이포그래피

- **Dynamic Type**: 시스템 텍스트 스타일(Large Title부터 Caption)을 사용해 사용자의 읽기 크기 설정을 따릅니다. point 크기를 하드코딩하지 않습니다.
- **San Francisco로 UI를 구성합니다.** 본문, 레이블, 컨트롤은 SF Pro / SF Compact를 사용하고, 브랜드 글꼴은 디스플레이 순간에만 사용할 수 있습니다.
- 최소 글자 크기는 11 pt이며 본문은 17 pt입니다.

## 색상과 재질

- **의미 기반 시스템 색상**(label, secondaryLabel, systemBackground, separator, tint)을 사용합니다. 다크 모드와 대비 증가에 자동 대응합니다. 원시 hex는 이를 깨뜨립니다.
- **다크 모드도 정식 외관입니다.** 두 가지 외관 모두 설계하고 테스트합니다.
- 인터랙티브 요소의 색상은 틴트 하나로 통일합니다. 틴트를 장식용으로 쓰지 않습니다.
- 막대와 sheet 뒤의 blur / 반투명에 **시스템 재질**을 사용합니다. 직접 만든 glassmorphism은 사용하지 않습니다.

## 컴포넌트와 컨트롤

- **플랫폼 컨트롤**을 사용합니다. 스위치, 분할 컨트롤, stepper, 시스템 선택기, action sheet, alert, context menu, swipe action 등이 있습니다. 개성을 위해 이를 다시 만드는 것이 네이티브 UI에서 흔히 생기는 실수입니다.
- 아이콘은 기준선 정렬, Dynamic Type 대응, 굵기 및 크기 변형이 있는 **SF Symbols**를 사용합니다. 웹 아이콘 세트를 섞지 않습니다.
- **모달 방식은 의도적으로 사용합니다.** 초점이 필요한 닫을 수 있는 하위 과업에는 sheet, 몰입 경험에는 전체 화면 cover를 사용합니다. Cancel/Done을 분명하게 두고 데이터 손실을 막아야 하는 경우가 아니면 스와이프 닫기를 허용합니다.
- 설정 형태의 콘텐츠는 그룹 / inset 목록으로 표시하고 별도의 카드 묶음을 만들지 않습니다.

## 모션

- **시스템 전환**: push는 옆으로 이동하고 sheet는 위로 나타나며 닫을 때는 반대로 움직입니다. 탐색 모델과 충돌하는 사용자 지정 전환은 혼란을 줍니다.
- **Reduce Motion을 따릅니다.** 시차 효과나 큰 슬라이드 대신 crossfade를 사용합니다.

## 빌드 검증

- **스크린샷은 브라우저가 아니라 Simulator에서 가져옵니다.** 빌드하고 실행한 뒤 `xcrun simctl io booted screenshot <path>`로 캡처합니다. 여러 기기가 실행 중이면 `xcrun simctl list devices booted`에서 대상 UDID를 얻어 `booted` 대신 사용합니다. 표시 이름은 중복될 수 있지만 UDID는 고유합니다. 앱을 출시하는 모든 기기 종류를 캡처합니다. 최소 iPhone 한 대를 포함하고 iPad를 대상으로 하면 iPad도 한 대 포함합니다. 검토 흐름에서 찾을 수 있는 위치에 저장합니다.
- **다크 모드와 Dynamic Type도 검토합니다.** 여러 기기가 부팅되었으면 같은 UDID를 지정해 `xcrun simctl ui booted appearance dark`를 사용합니다. Dynamic Type을 큰 크기로 설정해 고정 레이아웃이 감추는 잘림을 확인합니다.
- Simulator는 다양한 화면을 확인하기 좋지만 기기 자세, 제스처, 성능은 실제 하드웨어가 필요합니다. 어떤 기기에서 근거를 얻었는지 말합니다.
