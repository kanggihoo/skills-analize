# Read 모드

`impeccable concept-seed --mode read`는 아래 두 절을 MODE RULES 블록으로 출력합니다. Read 화면에서 방문자는 내용을 이해하려고 오므로 페이지는 무엇을 다루는지 알 수 있는 문서여야 하고 시각 세계는 그 바깥 틀을 만듭니다.

## 방향

독자의 질문이 흐름을 이끌며 어느 지점에서도 이해와 길 찾기가 온전히 유지되어야 합니다. 문서는 문서답게, 안내서는 안내서답게, 글은 글답게, 변경 기록은 변경 기록답게 읽혀야 합니다. 시각 세계가 프레임을 소유하고 읽기 열을 보조합니다. 프레임은 masthead, 탐색 rail, 바탕, 제목과 섹션 시작점, 코드·표·callout의 배치 방식으로 구성됩니다. 이 영역에 시각 세계의 팔레트, 글꼴, 시그니처 동작을 충분히 반영해 어느 제품에도 속할 수 없는 페이지가 되도록 합니다. 그 안의 읽기 열은 차분해야 합니다. 읽기 좋은 글꼴, 실제로 확보된 대비, 적절한 행 길이를 사용하고 텍스트 뒤에서 표현을 과시하지 않습니다. 시각 세계가 읽기 순서를 정하거나 독자가 새로 배워야 하는 탐색 방식으로 기존 탐색을 대체하면 안 됩니다. 문서는 문서답게, 안내서는 안내서답게, 글은 글답게 계속 읽혀야 합니다.

시각 세계 자체의 출판 전통에서 가져온 후보가 잘 맞습니다. 참고서, 활자 표본, 시간표, 현장 안내서, 기술 매뉴얼, 학술 장치, 신문의 길 찾기 방식 등이 있습니다. 독자가 사용하는 도구나 장비, 가상 인터페이스를 가져오면 독서용 화면을 의상처럼 꾸미게 됩니다. 다른 후보로 대체하거나 글꼴, 팔레트, 정보 밀도, 시그니처 동작으로 옮길 수 있는 요소만 활용합니다. 카탈로그의 시각 세계가 인터페이스 언어를 기반으로 해도 한계는 같습니다. 글꼴, 정보 밀도, 팔레트, 시그니처 동작 하나만 가져오고 탐색과 컨트롤은 플랫폼 표준을 유지합니다.

각 방향의 첫 viewport는 먼저 문서 프레임으로 씁니다. 탐색과 독자의 현재 위치, 독자의 질문에 답하거나 질문의 맥락을 잡아 주는 제목과 도입, 읽기 열, 다음에 읽을 곳을 안내하는 목차·섹션 제목·이전/다음 항목을 배치합니다. 그 뒤 프레임에서 세계를 드러낼 곳과 시그니처 동작을 둘 곳을 명시합니다. masthead, 색상 rail, running head, 여백 체계, 번호 체계, 코드나 표의 표시 방법 등이 그 예입니다. 도전 방향을 결합할지 판단할 때 독자가 얼마나 빨리 답을 찾아 이해하는지도 제품의 명료성에 포함합니다.

## Comp

comp는 독자가 문서를 처음 만났을 때의 화면이어야 합니다. 확정 팔레트와 글꼴을 사용해 시각 세계가 소유하는 프레임을 만들고, 실제 길이의 차분한 읽기 열로 둘러쌉니다(웹에서는 본문 약 16px, 행 길이 약 60~75자, 네이티브 앱에서는 플랫폼 본문 스타일과 읽기 좋은 너비). 제목은 분명한 위계를 가져야 하며 독자가 이동할 길도 보여 줍니다. 본문은 실제 배경 대비가 있는 읽기용 글꼴을 사용합니다. monospace는 코드, 매개변수, 짧은 레이블에만 쓰고, 본문이나 제목의 기본 글꼴로 사용하지 않습니다. 코드, 표, 메모, 그림은 독자가 익숙한 표준 형태로 두고 시각 세계의 글꼴과 팔레트를 적용합니다. 시그니처 동작은 필요한 곳에만 사용하는 하나의 시스템입니다. 모든 요소를 프레임으로 감싸지 않습니다. 시각 세계가 읽기 순서를 대신하지 않으므로 문서는 포스터, 잡지 표지, 펼쳐진 책 사진처럼 보이면 안 됩니다.

실제 자료를 prompt에 넣습니다. 실제 제목, 실제 도입 문단, 실제 섹션 이름, 해당 화면이 담는 가장 어려운 콘텐츠의 예(코드 샘플, 참고 표, 도식)를 포함하고 채우기용 문구는 쓰지 않습니다.

두 번째와 세 번째 comp는 읽기 열이 아니라 읽기 구조와 프레임이 시각 세계를 담는 방식을 바꿉니다. 탐색 모델(사이드바 트리, 상단 탭, 인라인 목차), 열과 여백 체계, 참고 자료의 정보 밀도, 시그니처 동작의 위치를 바꿉니다. thumbnail 크기에서도 첫 comp와 분명히 달라야 합니다. prompt를 읽어야만 구별되는 변형은 선택지를 늘리지 않습니다. 시각 세계의 재료를 읽기 열 안으로 밀어 넣어 읽기를 어렵게 하면 잘못된 방향입니다.

렌더링을 볼 때마다 자체 검토합니다. 독자가 현재 위치와 다음 이동 지점을 알 수 있나요? 본문을 편하게 읽을 수 있나요? 그 다음 이름을 가리고 봅니다. 다른 제품의 문서처럼 보일 수 있나요? 그렇다면 프레임이 시각 세계를 충분히 담지 못한 것입니다. masthead, rail, 바탕, 섹션 시작점을 더 강하게 표현합니다. 세계의 결과물처럼 먼저 읽히면 세계가 읽기 열까지 들어온 것입니다. 다시 프레임으로 돌립니다.
