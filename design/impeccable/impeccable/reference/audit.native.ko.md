네이티브 앱(`ios` / `android` / `adaptive`)에서 체계적인 **기술 품질** 검사를 수행하고 종합 보고서를 작성합니다. 문제를 직접 고치지는 말고 다른 명령이 해결할 수 있도록 기록합니다.

이는 디자인 비평이 아니라 코드 수준의 감사입니다. 소스(SwiftUI / UIKit / Compose / React Native / Flutter)를 기준으로 감사하며 브라우저 도구나 `impeccable detect`는 적용되지 않습니다. 플랫폼 참조([ios.md](ios.md) / [android.md](android.md))를 기준으로 점수를 매깁니다. `adaptive`이면 두 문서를 모두 적용합니다. Setup 단계에서 읽지 않았다면 점수를 매기기 전에 해당 문서를 읽습니다. 보고서 골격은 [audit.md](audit.md)와 같은 구조입니다. 변경할 때 두 문서를 함께 맞춥니다.

## 진단 검사

아래 다섯 가지 영역을 종합적으로 확인합니다. 각 영역은 0~4점으로 평가합니다.

### 1. 접근성(VoiceOver / TalkBack)

**확인 항목**:
- **레이블 누락**: 접근성 레이블, 특성 / 역할, 상태 안내가 없는 인터랙티브 요소
- **읽기와 초점 순서**: 비논리적인 이동 순서, 도달할 수 없는 컨트롤, 탐색 중 사라지는 초점
- **텍스트 크기 조정**: Dynamic Type(iOS)을 막는 고정 point 크기 또는 Android에서 sp 대신 px 사용, 큰 글자 크기에서 잘리거나 겹치는 레이아웃
- **터치 영역**: 44 pt(iOS) / 48 dp(Android) 미만이거나 간격 없이 빽빽하게 배치됨
- **Reduce Motion 무시**: 대체 crossfade 없이 시차 효과와 큰 슬라이드 적용
- **대비**: 라이트 또는 다크 등 한쪽 외관에서 대비 기준에 미달하는 텍스트

**점수 0~4**: 0=스크린 리더를 사용할 수 없음, 1=큰 공백(레이블이 없는 컨트롤, 크기 조정 불가), 2=일부 적용(레이블은 있으나 순서나 크기 조정이 깨짐), 3=양호(작은 공백), 4=우수(레이블과 순서가 정확하고 크기 조정이 자연스러우며 Reduce Motion 준수)

### 2. 성능

**확인 항목**:
- **느린 시작**: 첫 프레임 전 실행되는 무거운 작업
- **가상화되지 않은 목록**: FlatList / LazyColumn / List 재활용 없이 긴 콘텐츠를 표시
- **메인 스레드 끊김**: 스크롤이나 제스처 경로에서 동기 작업, 60/120Hz에서 프레임 손실
- **낭비되는 렌더링**: 불필요한 재렌더(React Native) 또는 재구성(Compose), memoization / key 누락
- **이미지 처리**: thumbnail에 원본 크기 이미지를 디코딩, 캐시 없음
- **앱 용량**: 비대해진 JS bundle이나 바이너리, 사용하지 않는 의존성

**점수 0~4**: 0=전반적으로 끊김, 1=큰 문제(가상화되지 않은 목록, 느린 시작), 2=일부 문제, 3=양호(작은 개선 가능), 4=우수(빠른 시작, 부드러운 스크롤, 가벼운 구성)

### 3. 외관과 테마

**확인 항목**:
- **색상 하드코딩**: 의미 기반 시스템 색상(iOS) / Material 색상 역할(Android) / 디자인 토큰 대신 원시 hex 사용
- **깨진 다크 모드**: 어두운 변형 누락, 다크 모드의 낮은 대비, 빠르게 반전한 색상
- **Dynamic Color(Android 12 이상)**: 정적 대체 테마가 없거나 적합한 경우에도 무시
- **플랫폼과 맞지 않는 재질**: 시스템 재질이나 tonal elevation이 적합한데 직접 그린 시각 재질 사용

**점수 0~4**: 0=모든 색상을 하드코딩, 1=토큰을 아주 조금만 사용, 2=일부 적용(토큰은 있으나 일관되지 않게 사용), 3=양호(일부 하드코딩 값만 남음), 4=우수(전반적으로 의미 토큰 사용, 두 테마가 모두 우선순위 있게 구현)

### 4. 플랫폼 준수(중요)

불필요하게 관습을 거스르는 디자인을 찾는 테스트를 포함해 로드한 플랫폼 참조 문서에 따라 점수를 매깁니다. 다음을 확인합니다.
- **깨진 시스템 제스처**: 가장자리 쓸기 뒤로 가기를 비활성화(iOS), 예측형 Back을 가로챔(Android)
- **inset 위반**: 노치, Dynamic Island, 홈 표시기, 상태 표시줄, 키보드 아래로 콘텐츠가 들어감
- **플랫폼과 맞지 않는 탐색**: 사용자 지정 전역 탐색, 지나치게 많은 탭 바 기능, Android에 iOS 패턴 적용 또는 그 반대
- **웹 형태의 컨트롤**: HTML 버튼처럼 보이는 동작, 사용자 지정 토글, hover에 의존하는 조작 안내
- **아이콘 체계 불일치**: SF Symbols / Material Symbols 대신 여러 아이콘 집합을 섞음
- **시스템과의 괴리**: 제품, 플랫폼, 기존 디자인 시스템과 충돌하는 편법이나 장식 패턴 반복

**점수 0~4**: 0=웹 포팅(네이티브 요소가 없음), 1=심각한 위반(3~4종), 2=눈에 띄는 위반 1~2종, 3=대체로 준수(미묘한 문제), 4=완전한 네이티브 경험(플랫폼에 익숙한 사용자도 모든 화면을 신뢰함)

### 5. 적응성

**확인 항목**:
- **늘어난 휴대전화 레이아웃**: 태블릿 / iPad에서 size class / window size class를 쓰지 않고 휴대전화 UI를 확대해 표시
- **화면 방향 문제**: 가로 모드에서 잘림, 가로 모드 무시, 이유 없이 화면 방향 고정
- **키보드 / IME 처리**: 키보드 뒤에 입력 필드가 숨거나 inset 조정 없음
- **멀티태스킹**: iPad Split View / Android 다중 창에서 레이아웃 깨짐
- **폴더블**: Android에서 자세 변경 시 힌지를 고려하지 않은 레이아웃

**점수 0~4**: 0=한 가지 화면 크기에서만 작동, 1=큰 문제(가로 또는 태블릿에서 깨짐), 2=일부 적용, 3=양호(작은 예외만 있음), 4=우수(크기, 방향, 창 구성에 적응)

### 심각도별 상세 발견 사항

모든 문제에 **P0~P3 심각도**를 지정합니다.
- **P0 차단**: 과업을 완료할 수 없음. 즉시 수정.
- **P1 주요**: 사용에 큰 어려움이 있거나 플랫폼 지침 위반. 출시 전 수정.
- **P2 경미**: 불편하지만 우회 방법이 있음. 다음 개선 때 수정.
- **P3 마무리**: 수정하면 좋지만 실사용 영향은 거의 없음. 여유가 있을 때 수정.

각 문제는 다음 내용을 기록합니다.
- **[P?] 문제 이름**
- **위치**: 화면, 파일, 줄
- **분류**: 접근성 / 성능 / 테마 / 준수 / 적응성
- **영향**: 사용자에게 미치는 영향
- **지침**: 위반하는 HIG / Material 규칙(해당되는 경우)
- **권장 사항**: 해결 방법
- **권장 명령**: 사용할 명령(가능하면 `$impeccable adapt`, `$impeccable animate`, `$impeccable audit`, `$impeccable bolder`, `$impeccable clarify`, `$impeccable colorize`, `$impeccable critique`, `$impeccable delight`, `$impeccable distill`, `$impeccable document`, `$impeccable harden`, `$impeccable layout`, `$impeccable onboard`, `$impeccable optimize`, `$impeccable overdrive`, `$impeccable polish`, `$impeccable quieter`, `$impeccable shape`, `$impeccable typeset` 중 선택)

### 반복 패턴과 시스템 문제

한 번의 실수가 아니라 시스템의 공백을 나타내는 반복 문제를 확인합니다.
- “15개가 넘는 화면에서 색상을 하드코딩했습니다. 의미 기반 색상을 사용해야 합니다.”
- “탭 바와 목록 행 곳곳에서 터치 영역이 계속 44pt보다 작습니다.”

### 긍정적인 발견 사항

잘 작동하는 점과 계속 유지하고 다른 곳에도 적용할 좋은 관행을 기록합니다.

## 권장 조치

P0부터 P1, P2 순으로 권장 명령을 나열합니다.

1. **[P?] `$command-name`**: 간단한 설명(감사에서 발견한 구체적 맥락)
2. **[P?] `$command-name`**: 간단한 설명(구체적 맥락)

**규칙**: 다음 명령만 권장합니다. `$impeccable adapt`, `$impeccable animate`, `$impeccable audit`, `$impeccable bolder`, `$impeccable clarify`, `$impeccable colorize`, `$impeccable critique`, `$impeccable delight`, `$impeccable distill`, `$impeccable document`, `$impeccable harden`, `$impeccable layout`, `$impeccable onboard`, `$impeccable optimize`, `$impeccable overdrive`, `$impeccable polish`, `$impeccable quieter`, `$impeccable shape`, `$impeccable typeset`. 발견 사항에 가장 적합한 명령을 연결합니다. 수정할 항목이 있다면 마지막 단계는 `$impeccable polish`로 마무리합니다.

요약을 제시한 뒤 사용자에게 다음과 같이 안내합니다.

> 한 번에 하나씩, 모두 한꺼번에, 또는 원하는 순서대로 실행하도록 요청할 수 있습니다.
>
> 수정한 뒤 `$impeccable audit`를 다시 실행하면 점수 변화를 확인할 수 있습니다.
