# Shape

무엇을 만들어야 하며 어떻게 동작해야 하는지 파악한 뒤, 코드 없이 확인된 디자인 브리프를 작성합니다.

## 1단계: 발견 인터뷰

아직 코드를 쓰거나 시각 방향을 선택하지 않습니다.

### 질문의 흐름

- 사용할 수 있다면 구조화된 질문 도구를 사용합니다. 없으면 질문을 한 다음 멈춥니다.
- 한 번에 서로 관련된 질문을 두세 개씩 하고 답을 기다립니다. 답변에서 중요한 공백이 드러날 때만 두 번째 질문 차례를 추가합니다.
- 설문지를 한꺼번에 던지거나, 이미 정해진 사실을 반복하거나, 명백한 사실을 선택지로 만들지 않습니다. 가능성 높은 해석을 먼저 말하고 수정을 요청합니다.
- 정보가 적은 요청은 질문을 한 차례 이상 진행합니다. 정확한 요청은 짧게 확인하는 것으로 충분할 수 있습니다.

### 첫 번째 차례: 목적, 사용자, 결과

결과를 가장 크게 바꿀 질문 두세 개를 선택합니다.

- 이 화면이나 기능은 무엇을 위한 것이며 해결해야 할 문제는 무엇인가요?
- 구체적으로 누가 어떤 상황과 마음 상태로 찾아오나요?
- 사용자가 이해하거나 실행해야 할 핵심은 무엇인가요? 성공은 어떤 모습인가요?
- 주변 제품이나 일반 템플릿은 주장할 수 없지만 이 제품만 사실로 말할 수 있는 내용은 무엇인가요?

### 두 번째 차례: 자료, 동작, 경계

중요한 결정이 실제로 남아 있는 경우에만 질문합니다.

- 경험에 반영해야 할 실제 콘텐츠, 근거, 데이터, 에셋은 무엇인가요? 최소 / 일반 / 최대 범위는 어떻게 되나요?
- 중요한 상태와 전환은 무엇인가요? 최초 사용, 빈 상태, 로딩, 오류, 성공, 권한, 넘침, 전문가 사용 등이 있습니다.
- 목표 완성도, 범위, 상호작용 수준은 어느 정도인가요? 아이디어 탐색, 출시할 화면, 전체 흐름, 더 큰 화면인가요?
- 그대로 둬야 하는 것은 무엇인가요? 화면이 잘 다듬어졌더라도 무엇이 있으면 잘못된 결과인가요?
- 플랫폼, framework, 성능, 접근성, 현지화, 전달 제약 중 반드시 지켜야 하는 것은 무엇인가요?

CSS 값을 묻거나 미리 정해진 미적 방향을 제안하지 않습니다. 시각 세계와 개념은 new-work가 담당합니다.

## 2단계: 디자인 방향 확정

새 화면, 브랜드 확장, 대체 디자인이면 시각적 권위, 세계관 워크숍, 개념 선택을 포함해 [new-work.md](new-work.md)를 따릅니다. 인터뷰에서 얻은 정보를 재사용하고, 계약·문서화·구현 단계에 들어가기 전에 돌아옵니다. 기존 세계 안에서 작업하되 구성이나 상호작용이 중요한 수준으로 열려 있을 때만 해당 세계의 개념 절차를 사용합니다.

## 3단계: 브리프 작성

필요한 만큼만 간결하게 씁니다.

1. **과업과 사용자**: 누가 어떤 상황과 필요를 갖고 방문하는지, 방문자 모드.
2. **결과와 근거**: 주요 과업 / 동작, 성공 기준, 실제 근거, 제품 고유 사실.
3. **선택한 방향**: 시각적 권위, 구조 / 상호작용 핵심 가설, 순서, 초점 순간, 구현에 따르는 결과.
4. **범위와 경계**: 완성도, 폭, 상호작용, 지정 대상, 손대지 않을 것, 명시적 비목표.
5. **상태와 범위값**: 현실적인 콘텐츠 / 데이터 범위와 중요한 상태.
6. **상호작용과 레이아웃**: 위계, topology, 반응형 동작, affordance, 피드백, 전환. CSS가 아니라 의도를 기록합니다.
7. **제약과 미결정 사항**: 플랫폼, 전달 방식, 접근성, 현지화, 재사용 컴포넌트, 빌더가 지어내면 안 되는 선택.

과업이 정리되어 있으면 세~다섯 개 글머리표로 작성합니다. 모호하거나 여러 화면을 다루거나 계획 자체가 요청된 경우에만 전체 구조를 사용합니다. 대화를 그대로 반복해서 적지 않습니다.

## 확인 후 멈춤

브리프를 보여 주고 명시적인 승인이나 한 차례 수정 답변을 받은 뒤 멈춥니다. Shape는 코드를 작성하거나 방향 계약서를 만들지 않습니다.

사람이나 구조화된 답변 방법을 사용할 수 없는 경우에는 가정을 명확히 적고 브리프를 반환한 뒤 멈춥니다.
