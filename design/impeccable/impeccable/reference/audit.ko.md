체계적인 **기술 품질** 점검을 수행하고 종합 보고서를 작성합니다. 문제를 직접 고치지는 말고 다른 명령이 해결할 수 있도록 기록합니다.

이는 디자인 비평이 아니라 코드 수준의 감사입니다. 구현에서 측정하고 검증할 수 있는 항목을 확인합니다.

**웹 전용입니다.** 네이티브 플랫폼(`ios` / `android` / `adaptive`)은 [audit.native.md](audit.native.md)로 연결됩니다. 프로젝트가 네이티브라면 지금 해당 문서로 전환합니다.

## 진단 검사

아래 다섯 가지 영역을 종합적으로 확인합니다. 각 영역은 다음 기준에 따라 0~4점으로 평가합니다.

### 1. 접근성(A11y)

**확인 항목**:
- **대비 문제**: 텍스트 대비율이 4.5:1 미만, 큰 텍스트는 3:1 미만(AAA는 7:1 미만)
- **모션 민감도**: `prefers-reduced-motion`은 상태 변화와 위계를 유지하는 의도된 대체 동작을 제공해야 합니다. 유용한 피드백을 없애는 전역 `0.01ms` 차단, 기준을 넘는 깜박임, 초점·읽기·과업 완료를 방해하는 모션을 표시합니다.
- **ARIA 누락**: 올바른 역할, 레이블, 상태가 없는 인터랙티브 요소
- **키보드 탐색**: 초점 표시 누락, 비논리적인 탭 순서, 키보드 trap
- **시맨틱 HTML**: 잘못된 제목 위계, landmark 누락, 버튼 대신 div 사용
- **대체 텍스트**: 이미지 설명이 없거나 부정확함
- **양식 문제**: 레이블 없는 입력, 부족한 오류 안내, 필수 표시 누락

**점수 0~4**: 0=접근 불가(WCAG A 실패), 1=큰 공백(ARIA 레이블이 거의 없고 키보드 탐색 불가), 2=일부 적용(접근성을 고려한 흔적은 있으나 큰 문제가 남음), 3=양호(WCAG AA를 대체로 충족, 작은 공백), 4=우수(WCAG AA를 모두 충족하고 AAA에 근접)

### 2. 성능

**확인 항목**:
- **레이아웃 thrashing**: 반복문에서 레이아웃 속성을 읽고 씀
- **비용이 큰 애니메이션**: 이유 없이 레이아웃 속성을 애니메이션하거나, 제한 없는 blur/filter/shadow를 사용하거나, 프레임이 눈에 띄게 떨어지는 효과
- **최적화 누락**: 지연 로딩이 없는 이미지, 최적화되지 않은 에셋
- **`will-change` 남용**: 넓은 영역에 적용하거나 정지 상태에서도 유지(`will-change`는 기본 요구사항이 아니라, 비용이 큰 애니메이션이 확실할 때 주는 제한적 힌트입니다.)
- **번들 크기**: 불필요한 import, 사용하지 않는 의존성
- **렌더링 성능**: 불필요한 재렌더, memoization 누락

**점수 0~4**: 0=심각한 문제(레이아웃 thrash, 최적화되지 않은 항목이 전반적으로 많음), 1=큰 문제(지연 로딩 없음, 비용이 큰 애니메이션), 2=일부 최적화했으나 공백이 남음, 3=양호(대체로 최적화됐고 작은 개선 가능), 4=우수(빠르고 가벼우며 충분히 최적화됨)

### 3. 테마

**확인 항목**:
- **하드코딩된 색상**: 디자인 토큰을 사용하지 않는 색상
- **깨진 다크 모드**: 다크 모드 변형 누락, 어두운 테마에서 낮은 대비
- **일관성 없는 토큰**: 잘못된 토큰이나 서로 다른 유형의 토큰을 혼용
- **테마 전환 문제**: 테마를 바꿔도 갱신되지 않는 값

**점수 0~4**: 0=테마 시스템이 없음(모두 하드코딩), 1=토큰을 아주 조금만 쓰고 대부분 하드코딩, 2=일부 적용(토큰은 있지만 일관되지 않게 사용), 3=양호(토큰을 사용하며 하드코딩 값은 일부만 남음), 4=우수(토큰 시스템이 온전히 갖춰지고 다크 모드도 완벽하게 작동)

### 4. 반응형 디자인

**확인 항목**:
- **고정 너비**: 모바일에서 깨지는 하드코딩된 너비
- **터치 대상**: 44x44px보다 작은 인터랙티브 요소. WCAG AA(SC 2.5.8)는 예외(간격, 동등한 컨트롤, 인라인 텍스트, 사용자 에이전트 스타일, 필수 크기)가 적용되지 않는 경우 최소 24x24 CSS px를 요구합니다. 대상의 경계 상자 중앙에 24 CSS px 원을 놓았을 때 다른 대상과 겹치지 않고, 크기 미달 대상의 원과도 겹치지 않으면 간격 예외를 충족합니다.
- **깨진 터치 상호작용**: 기본 제스처가 터치에서 작동하지 않는 사용자 지정 슬라이더, 드래그 표면, 스크롤 가능한 컨트롤 띠. 페이지 스크롤을 가로채거나 드래그가 스크롤에 빼앗기거나 제스처가 중단된 뒤 상태가 고정되는 경우도 포함합니다. 코드 징후: 마우스 전용 handler, pointer-event 드래그 표면에 `touch-action` 없음, 취소 / 포인터 capture 손실 / 창 흐림 때 지워지지 않는 드래그 상태. 브라우저 도구가 터치 입력을 만들 수 있다면 제스처를 직접 실행합니다(렌더링된 viewport는 레이아웃을 입증하지만 제스처 동작까지 입증하지 않음). 어떤 증거를 만들었는지(에뮬레이트 viewport, 입력을 합성한 터치, 엔진, 실제 기기)와 확인하지 못한 사항을 적습니다.
- **가로 스크롤**: 좁은 화면에서 콘텐츠가 넘침
- **텍스트 확대**: 글자 크기를 키웠을 때 레이아웃이 깨짐
- **중단점 누락**: 모바일 / 태블릿 변형 없음

**점수 0~4**: 0=데스크톱 전용(모바일에서 깨짐), 1=큰 문제(일부 중단점만 있고 여러 실패), 2=일부 적용(모바일에서 작동하지만 거친 부분이 남음), 3=양호(반응형이며 작은 터치 대상이나 넘침 문제만 있음), 4=우수(모든 viewport에서 유동적으로 작동하고 터치 영역 및 제스처가 터치 입력에서도 적절함)

### 5. 구현 무결성(중요)

포함된 탐지기를 실행하고 발견 사항을 각각 맥락 속에서 확인합니다. 반복되는 구현 편법, 디자인 시스템과의 괴리, 오해를 부르는 콘텐츠나 장식성 콘텐츠, 다른 제품에도 그대로 쓸 수 있는 구조를 살펴봅니다. 결정론적 탐지 결과와 시각적 판단을 분리하고 오탐을 표시합니다.

**데스크톱 앱**(Electron, NW.js, CEF, WebView2): 로컬 DevTools 포트로 앱을 실행합니다(`--remote-debugging-port=9222`, WebView2는 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`; 127.0.0.1에만 열고 외부에 노출하지 않음). 감사할 상태를 준비하고 창을 화면에 보이게 둡니다(숨겨진 창에서는 픽셀 대비 측정을 건너뜀). 그런 다음 `.agents/skills/impeccable/scripts/impeccable detect --cdp 9222 --target <part of the page URL or title> --json`을 실행합니다. URL 검사와 같은 JSON을 반환하고 창 상태를 그대로 둡니다. harness의 CDP 도구로 스크린샷을 찍고 작업 뒤에도 창을 원래 상태로 둡니다. macOS의 Tauri(WKWebView)와 Linux의 Tauri(WebKitGTK)는 CDP를 제공하지 않습니다. 이 경우 소스를 검사하고 렌더링 검사는 실행하지 않았다고 적습니다.

**점수 0~4**: 0=시스템 전반에 걸친 괴리, 1=큰 실패가 반복됨, 2=검증된 문제 여러 개, 3=고립된 작은 문제, 4=일관되고 의도가 분명함

### 심각도별 상세 발견 사항

모든 문제에 **P0~P3 심각도**를 지정합니다.
- **P0 차단**: 과업을 완료할 수 없음. 즉시 수정.
- **P1 주요**: 사용에 큰 어려움이 있거나 WCAG AA 위반. 출시 전 수정.
- **P2 경미**: 불편하지만 우회 방법이 있음. 다음 개선 때 수정.
- **P3 마무리**: 수정하면 좋지만 실사용 영향은 거의 없음. 여유가 있을 때 수정.

각 문제는 다음 내용을 기록합니다.
- **[P?] 문제 이름**
- **위치**: 컴포넌트, 파일, 줄
- **분류**: 접근성 / 성능 / 테마 / 반응형 / 구현 무결성
- **영향**: 사용자에게 미치는 영향
- **WCAG/표준**: 위반하는 표준(해당되는 경우)
- **권장 사항**: 해결 방법
- **권장 명령**: 사용할 명령(가능하면 `$impeccable adapt`, `$impeccable animate`, `$impeccable audit`, `$impeccable bolder`, `$impeccable clarify`, `$impeccable colorize`, `$impeccable critique`, `$impeccable delight`, `$impeccable distill`, `$impeccable document`, `$impeccable harden`, `$impeccable layout`, `$impeccable onboard`, `$impeccable optimize`, `$impeccable overdrive`, `$impeccable polish`, `$impeccable quieter`, `$impeccable shape`, `$impeccable typeset` 중 선택)
