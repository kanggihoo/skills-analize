이메일과 URL에는 `example.com`, `example.org` 또는 `.test` 도메인을 사용해 실제 받은 편지함이나 사이트를 가리키지 않도록 합니다.

## 숫자와 금액

| 값 | 문제를 일으키는 점 |
| --- | --- |
| `0` | 0 상태입니다: “회원 0명”, 비어 있는 진행 막대, 퍼센트 계산에서 0으로 나누기. |
| `1` | 복수형 처리입니다: “1 members”, “1 days ago”. |
| `1284` | 천 단위 구분자가 필요합니다: `1,284`. |
| `1000000` | 개수 배지 너비를 확인합니다. 정밀도가 중요하지 않다면 `1M` 같은 축약형을 고려합니다. |
| 통화 형식의 `12345678.9` | `$12,345,678.90`으로 표시되어 합계 열에서 넘칠 수 있습니다. |
| `-42.5` | 음수 기호, 빨간색 표시 로직, 회계 형식의 괄호를 확인합니다. |
| `0.1 + 0.2` | 원시 값으로 표시하면 `0.30000000000000004`가 렌더링됩니다. |
| `142%` / `-3%` | 범위를 벗어난 진행 막대와 계기판을 확인합니다. |
| `null` / `undefined` / `NaN` | 값이 그대로 화면에 표시됩니다. |
| `de-DE`에서 `1.284`, `en-US`에서 `1,284` | 로케일별 숫자 형식입니다. 구분자를 하드코딩하면 세계 절반에서 틀립니다. |
| 실시간으로 바뀌는 값(`99` → `100`) | `tabular-nums`가 없으면 너비가 바뀌며 흔들립니다. |

## 컬렉션

| 값 | 문제를 일으키는 점 |
| --- | --- |
| 항목 0개 | 빈 상태가 있는지, 어떻게 보이는지 확인합니다. |
| 항목 1개 | 카드 하나만 있을 때 그리드가 깨져 보이는지, “1 of 1” 표기를 확인합니다. |
| 페이지 크기와 정확히 같거나 페이지 크기 + 1개 | “Showing 40 of 40”의 off-by-one 오류, 비어 있는 2페이지를 만드는 페이지네이션을 확인합니다. |
| 페이지네이션 없이 항목 1,000개 이상 | 스크롤 성능, 렌더링 시간, 메모리뿐 아니라 “Showing 40 of 1,284” 문구도 확인합니다. |
| 다른 항목보다 10배 큰 항목 하나 | Masonry 및 그리드 행이 가장 높은 항목 크기로 늘어납니다. |
| 이름이 같은 항목 | 이름만으로 구별하는 목록에서 문제가 됩니다. |

## 시간

| 값 | 문제를 일으키는 점 |
| --- | --- |
| 지금 | “방금 전” 대신 “0 seconds ago”라고 표시될 수 있습니다. |
| 12일 전, 11개월 전, 3년 전 | 상대 시간 임계값을 확인합니다. 보통 일주일쯤 지나면 절대 날짜로 전환합니다. |
| 미래 날짜 | “3일 후” 대신 “-3 days ago”가 표시될 수 있습니다. |
| `1970-01-01` | 타임스탬프 0이 실제 날짜로 표시됩니다. |
| `2025-12-31T23:30:00-08:00` | UTC와 사용자 시간대에서 서로 다른 날짜로 보입니다. |
| 매우 긴 기간(`1,284 hours`) | 시간이 며칠 단위로 넘어가지 않는 기간 형식을 확인합니다. |

직접 문자열을 만들지 말고 `Intl.RelativeTimeFormat`과 `Intl.DateTimeFormat`을 사용합니다.

## 이미지와 미디어

| 값 | 문제를 일으키는 점 |
| --- | --- |
| 404를 반환하는 아바타 URL | 이니셜 대체 표시 대신 깨진 이미지 아이콘이 나타납니다. |
| 아바타 없음 | 대체 표시 자체를 확인합니다: 이니셜, 색상, 실제 아바타와의 크기 일치. |
| 아바타나 커버에 4000×200 파노라마 이미지 | `object-fit: cover`가 없으면 이미지가 찌그러집니다. |
| 200×4000 세로로 긴 이미지 | 같은 문제의 반대 방향이며 카드 높이를 과도하게 키울 수 있습니다. |
| 투명 PNG 로고, 어두운 모드에서 어두운 로고 | 배경 위에서 보이지 않을 수 있습니다. |
| 로딩이 느린 이미지 | 크기나 `aspect-ratio`를 고정하지 않으면 레이아웃이 이동합니다. |

## 상태

| 값 | 문제를 일으키는 점 |
| --- | --- |
| 로딩 중 | 최종 레이아웃과 맞지 않는 스켈레톤, 콘텐츠를 밀어내는 스피너. |
| API 오류 | 오류 상태가 없거나 원시 오류 메시지(`TypeError: Cannot read properties of undefined`)가 표시됩니다. |
| 일부 데이터만 있음 | 같은 목록에서 선택 필드는 채워지고 나머지는 비어 있어 행 정렬이 어긋납니다. |
| 모든 상태가 한꺼번에 있음 | 한 목록에서 모든 enum 값(`active`, `invited`, `expired`, `suspended`)을 보여 배지 너비가 달라집니다. |
| 권한 없음 | 동작을 비활성화했을 때 행 레이아웃이 그대로 유지되는지 확인합니다. |
| 목록에 현재 사용자가 있음 | “You” 레이블, 본인에게 적용되면 안 되는 동작을 확인합니다. |

## 환경

데이터는 아니지만 같은 방식으로 검사합니다. 최악의 조건으로 바꾸고 아래 사항을 확인합니다.

| 조건 | 문제를 일으키는 점 |
| --- | --- |

| 좁은 사이드바 안에 배치 | 전체 너비로 설계한 컴포넌트를 280px 열에서 재사용할 때 문제가 생깁니다. |
| 너비 2560px | 줄이 너무 길어 읽기 어렵고 콘텐츠가 한쪽에 몰립니다. |
| 브라우저 확대 200% / 큰 글꼴 설정 | 글자는 커져도 높이를 고정한 상자는 늘어나지 않아 잘립니다. |
| 다크 모드 | 하드코딩한 색상, 보이지 않는 테두리와 로고. |
| `dir="rtl"` | 아이콘, 꺾쇠, padding, 끝에 배치한 동작 버튼 순서가 틀어집니다. |
| 터치 기기 | 호버해야만 나타나는 동작(호버 시 나타나는 •••)에 접근할 수 없습니다. |
