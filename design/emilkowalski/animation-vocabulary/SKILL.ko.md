# 애니메이션 용어

## 첫 응답

이 스킬이 구체적인 질문 없이 처음 호출되면 다음 문장만 응답합니다.

> I'm ready to put a name to any motion effect you describe, my knowledge comes from Emil Kowalski's animation philosophy.

사용자가 질문하기 전까지 다른 정보를 제공하지 않습니다.

움직임이나 효과에 대한 막연한 설명을 정확한 용어로 바꿔, 사용자가 무엇을 요청해야 할지 알 수 있도록 합니다.

## 빠른 시작

사용자가 효과를 대략 설명하면 다음 형식으로 해당 용어를 알려 줍니다.

```
**Stagger** — Animate several items one after another with a small delay between each, creating a cascade.
```

여러 용어가 맞을 수 있으면 가장 적합한 용어를 먼저 쓰고, 차이를 한 줄로 덧붙여 다른 후보를 1~2개 제시합니다.

## 지침

1. **키워드가 아니라 의도를 읽습니다.** 사용자는 기술 용어 대신 자신이 *보고 느낀 것*을 설명합니다(“스프링처럼 튄다”, “미끄러져 나간다”, “스스로 그려져 나타난다”). 그 감각을 아래 용어집과 연결합니다.
2. **용어집의 설명을 그대로 인용합니다.** 용어집의 설명을 기준 문구로 삼고, 바꿔 쓰지 않습니다.
3. **비슷한 용어는 구분해 줍니다.** (*Clip-path*와 *Mask*, *Pop in*과 *Bounce*, *Shared element transition*과 *Layout animation*처럼) 둘 다 가능한 경우 차이를 설명해 사용자가 고를 수 있게 합니다.
4. **정확히 맞는 항목이 없다면** 가장 가까운 용어를 제시하고 근사치라고 분명히 말하거나 용어집 표현으로 효과를 설명합니다(예: “그건 *scale-in* 진입에 시차를 준 *stagger*입니다”).
5. **이 용어집 안에서 답합니다.** 필요한 용어가 정말 없다면 없는 용어라고 말하고 지어내지 않습니다. 다만 용어집의 표현을 사용해 개념을 설명할 수는 있습니다.
6. **간결하게 답합니다.** 이름을 묻는 질문에는 용어를 먼저 제시하고 에세이처럼 길게 쓰지 않습니다. 사용자가 요청할 때만 설명을 확장합니다.

## 예시

**예시 1 — 느낌을 설명하는 경우**
사용자: “팝오버가 자기 중앙에서 커지는 게 아니라 클릭한 버튼에서 자라나는 듯 보이는 동작은 뭐라고 하나요?”
응답:
```
**Origin-aware animation** — An element animates out of its trigger, like a popover growing from the button that opened it instead of from its own center which is the default in CSS.
```

**예시 2 — 용어 구분**
사용자: “한 이미지가 다른 이미지로 바뀌는 동작이요.”
응답:
```
**Morph** — One shape smoothly turns into another shape, e.g. Dynamic Island.

Close alternates:
- **Crossfade** — if they simply fade over each other in the same spot.
- **Shared element transition** — if an element travels and transforms from one position into another.
```

**예시 3 — 물리적인 느낌**
사용자: “iOS에서 너무 멀리 잡아당기면 저항하다가 튕겨 돌아오는 스크롤이요.”
응답:
```
**Rubber-banding** — Resistance and snap-back when you drag past a boundary (the iOS overscroll feel).
```

## 용어집

_프로젝트의 `/vocabulary` 페이지와 내용이 일치하도록 관리하는 선별 용어 목록입니다. 어느 한쪽이 바뀌면 둘을 함께 갱신합니다._

### 진입과 퇴장 — 요소가 나타나고 사라지는 방식
- **Fade in / Fade out** — 투명도를 바꿔 요소를 나타내거나 사라지게 합니다.
- **Slide in** — 요소가 화면 밖에서(왼쪽, 오른쪽, 위, 아래) 미끄러져 들어옵니다.
- **Scale in** — 요소가 작게 시작해 나타나는 동안 원래 크기로 커집니다. 흔히 페이드 효과와 함께 씁니다.
- **Pop in** — 살짝 목표 지점을 넘어갔다 돌아오며 튀어 오르듯 나타납니다.
- **Reveal** — 보통 clip-path나 mask를 애니메이션해 콘텐츠를 점진적으로 드러냅니다.
- **Enter / Exit** — 요소가 화면에 추가되거나 화면에서 제거될 때 실행되는 애니메이션입니다.

### 순서와 타이밍 — 여러 요소나 순간의 움직임을 맞추는 방법
- **Keyframes** — 브라우저가 중간 상태를 채울 수 있도록 애니메이션의 지점(0%, 50%, 100%)을 지정합니다.
- **Interpolation / Tween** — 시작 값과 끝 값 사이의 모든 프레임을 계산해 움직임을 이어 줍니다.
- **Stagger** — 여러 항목 사이에 짧은 지연을 두고 하나씩 애니메이션해 연쇄적으로 나타나게 합니다.
- **Orchestration** — 여러 애니메이션의 타이밍을 의도적으로 맞춰 하나의 조화로운 움직임처럼 느끼게 합니다.
- **Delay** — 애니메이션이 시작되기 전의 대기 시간입니다.
- **Duration** — 애니메이션에 걸리는 시간입니다.
- **Fill mode** — 애니메이션 시작 전이나 종료 후에 요소가 첫 프레임 또는 마지막 프레임의 스타일을 유지할지 정합니다(예: forwards).
- **Stepped animation** — 카운트다운 타이머처럼 애니메이션을 구분된 단계로 나눕니다.

### 이동과 변형 — 요소의 위치, 크기, 각도를 바꾸는 방식
- **Translate** — 요소를 X축이나 Y축을 따라 이동합니다.
- **Scale** — 요소를 확대하거나 축소합니다.
- **Rotate** — 한 점을 중심으로 요소를 회전합니다.
- **Skew** — 요소를 X축이나 Y축을 따라 기울여 직사각형 형태를 비틀어 변형합니다.
- **3D tilt / Flip** — 3D 공간에서 회전(`rotateX` / `rotateY`)해 깊이를 더합니다.
- **Perspective** — 3D 효과의 강도를 정합니다. 값이 낮을수록 보는 사람이 가까이 있는 것처럼 깊이가 과장됩니다.
- **Transform origin** — 확대나 회전이 시작되는 기준점입니다.
- **Origin-aware animation** — 팝오버가 자기 중심에서 커지는 대신 팝오버를 연 버튼에서 자라나듯, 요소가 트리거에서부터 애니메이션됩니다. CSS 기본 동작은 요소 자체의 중심을 기준으로 합니다.

### 상태 간 전환 — 상태, 화면, 요소를 서로 연결하는 방식
- **Crossfade** — 같은 위치에서 한 요소가 페이드아웃되는 동안 다른 요소가 페이드인합니다.
- **Continuity transition** — 전후 상태를 시각적으로 연결해 사용자가 맥락을 잃지 않게 하는 변화입니다. 예를 들어 같은 직사각형의 크기를 키우거나 줄입니다.
- **Morph** — 하나의 형태가 다른 형태로 부드럽게 바뀝니다(예: Dynamic Island).
- **Shared element transition** — 썸네일이 카드로 커지는 것처럼 요소가 한 위치에서 다른 위치로 이동하면서 형태도 바뀝니다.
- **Layout animation** — 요소의 크기나 위치가 바뀔 때 새 위치로 순간 이동하지 않고 애니메이션하며 이동합니다.
- **Accordion / Collapse** — 섹션의 높이를 부드럽게 늘이거나 줄여 콘텐츠를 표시하거나 숨깁니다.
- **Direction-aware transition** — 앞으로 이동할 때 한 방향으로, 뒤로 이동할 때 반대 방향으로 콘텐츠를 움직여 내비게이션에 방향 감각을 줍니다.

### 스크롤 — 스크롤이나 화면 간 이동에 연결된 움직임
- **Scroll reveal** — 요소가 화면에 들어올 때 페이드되거나 미끄러져 나타납니다.
- **Scroll-driven animation** — 애니메이션 진행도가 스크롤 위치에 직접 연결됩니다.
- **Parallax** — 스크롤 중 배경과 전경이 서로 다른 속도로 움직여 깊이감을 만듭니다.
- **Page transition** — 페이지나 경로를 이동할 때 실행되는 애니메이션입니다.
- **View transition** — 브라우저가 공유 요소를 연결해 두 상태나 페이지 사이를 변형합니다.

### 피드백과 상호작용 — 사용자 동작에 반응하는 방식
- **Hover effect** — 커서가 요소 위에 올라갔을 때 나타나는 시각적 변화입니다.
- **Press / Tap feedback** — 요소를 눌렀을 때 살짝 축소해 물리적으로 눌리는 느낌을 줍니다.
- **Hold to confirm** — 사용자가 버튼을 누르고 있는 동안 진행 표시가 채워집니다.
- **Drag** — 요소를 잡아 옮깁니다. 손을 떼면 관성이 이어질 수 있습니다.
- **Drag to reorder** — 목록에서 항목을 끌어 순서를 바꾸면 다른 항목이 자리를 내주며 이동합니다.
- **Swipe to dismiss** — 드로나 토스트처럼 요소를 화면 밖으로 끌어 닫습니다.
- **Rubber-banding** — 경계를 넘어 끌 때 저항이 생기고 원래 위치로 되돌아옵니다(iOS의 오버스크롤 느낌).
- **Shake / Wiggle** — 오류나 거부된 입력을 나타내기 위해 짧게 좌우로 흔듭니다.
- **Ripple** — 탭한 지점에서 원이 퍼져 눌렀음을 확인시킵니다.

### 이징 — 애니메이션 중 속도가 바뀌는 방식
- **Easing** — 애니메이션이 빨라지거나 느려지는 속도 변화를 정합니다.
- **Ease-out** — 빠르게 시작해 천천히 끝납니다. 대부분의 UI와 사용자 입력에 반응하는 움직임의 기본값입니다.
- **Ease-in** — 천천히 시작해 빠르게 끝납니다. 보통 피하며, 굼뜬 느낌을 줄 수 있습니다.
- **Ease-in-out** — 천천히 시작하고 빨라졌다가 다시 천천히 끝납니다. 이미 화면에 있는 요소가 A에서 B로 이동할 때 적합합니다.
- **Linear** — 일정한 속도로 움직입니다. UI에는 잘 쓰지 않고 스피너나 마퀴에 사용합니다.
- **Cubic-bezier** — 정밀한 제어를 위해 직접 정의하는 사용자 지정 이징 곡선입니다.
- **Asymmetric easing** — 가속과 감속의 정도가 서로 다른 곡선입니다. 대칭 곡선보다 생동감이 느껴집니다.

### 스프링 애니메이션 — 고정 지속 시간 이징의 대안인 물리 기반 움직임
- **Spring** — 정해진 지속 시간이 아니라 장력, 질량, 감쇠와 같은 물리 요소로 움직임을 계산합니다.
- **Stiffness / Tension** — 스프링이 목표 지점으로 끌어당기는 힘입니다. 값이 클수록 빠릿하게 느껴집니다.
- **Damping** — 스프링이 얼마나 빨리 안정되는지 정합니다. 감쇠가 낮으면 더 많이 튀고 진동합니다.
- **Mass** — 움직이는 요소가 얼마나 무겁게 느껴지는지 정합니다. 질량이 클수록 느리고 둔하게 움직입니다.
- **Bounce** — 목표 지점을 지나친 뒤 안정되며 장난스러운 느낌을 더하는 스프링 움직임입니다.
- **Perceptual duration** — 미세하게 계속 안정되는 움직임이 남아 있어도, 사용자가 애니메이션이 끝났다고 느끼기까지 걸리는 시간입니다.
- **Momentum** — 특히 드래그하거나 움직임을 중단했을 때 속도가 이어지는 성질입니다.
- **Velocity** — 요소가 어느 방향으로 얼마나 빠르게 움직이는지 나타냅니다. 중단된 뒤 스프링 애니메이션으로 이어지면 튕긴 요소가 기존 속도를 유지합니다.
- **Interruptible animation** — 먼저 끝날 때까지 기다리지 않고 진행 중에 부드럽게 방향을 바꿀 수 있는 애니메이션입니다.

### 반복과 주변 움직임 — 스스로 재생되는 애니메이션
- **Marquee** — 텍스트나 콘텐츠가 반복해서 계속 스크롤됩니다.
- **Loop** — 지정한 횟수만큼 또는 무한히 반복하는 애니메이션입니다.
- **Alternate (yoyo)** — 시작점으로 순간 이동하지 않고 반복할 때마다 앞으로 재생한 뒤 반대로 재생합니다.
- **Orbit** — 요소가 다른 요소를 중심으로 계속 원을 그리며 움직입니다.
- **Pulse** — 주의를 끌기 위해 크기나 투명도를 부드럽게 반복해서 바꿉니다.
- **Float** — 정적인 요소를 가볍고 생동감 있게 보이도록 위아래로 부드럽게 움직입니다.
- **Idle animation** — 요소가 상호작용을 기다리며 가만히 있을 때 재생되는 미세한 움직임입니다.

### 마무리와 효과 — 좋은 결과를 더 돋보이게 하는 작은 요소
- **Blur** — 요소를 부드럽게 하거나 작은 결점을 가리는 블러 필터입니다.
- **Clip-path** — 요소를 특정 모양으로 잘라내며, 노출 효과, 마스크, 전후 비교 슬라이더에 사용합니다.
- **Mask** — clip-path와 비슷하게 모양이나 그라데이션으로 요소의 일부를 숨기거나 드러냅니다. 가장자리를 부드럽게 페이드할 수 있습니다.
- **Before / after slider** — 겹쳐 놓은 두 이미지를 비교하도록 드래그 가능한 경계선을 움직입니다.
- **Line drawing** — 보이지 않던 펜이 SVG 경로를 따라 그리듯 선이 나타납니다.
- **Text morph** — 텍스트가 바뀔 때 글자 단위로 움직여 새 값에 주의를 모읍니다.
- **Skeleton / Shimmer** — 콘텐츠가 로드되는 동안 표시하는 자리표시자에 빛이 지나가는 효과를 더합니다.
- **Number ticker** — 숫자가 굴러가거나 목표 값까지 올라갑니다.
- **Tabular numbers** — 숫자가 바뀌어도 위치가 흔들리지 않도록 각 숫자의 너비를 고정합니다. 숫자 표시기, 타이머, 카운터에 필수적입니다.
- **Typewriter** — 타이핑하는 것처럼 글자가 한 번에 하나씩 나타납니다.

### 성능 — 움직임을 끊김 없이 유지하는 방법
- **Frame rate (FPS)** — 초당 그리는 프레임 수입니다. 부드러운 움직임의 기준은 60fps이며 최신 화면은 120fps를 지원합니다.
- **Jank** — 브라우저가 애니메이션을 제때 처리하지 못해 프레임을 놓치면서 생기는 눈에 보이는 끊김입니다.
- **Dropped frame** — 브라우저가 그리기 마감 시간을 놓쳐 움직임에 짧은 걸림이 생기는 프레임입니다.
- **Compositing** — 레이아웃이나 페인트를 다시 수행하지 않고 GPU가 자체 레이어에서 요소를 이동하거나 페이드하도록 합니다.
- **will-change** — 요소가 곧 애니메이션될 것이라고 브라우저에 알려 미리 별도 레이어로 올릴 수 있게 하는 CSS 힌트입니다.
- **Layout thrashing** — `width`, `height`, `top`, `left`처럼 프레임마다 레이아웃을 다시 계산하게 만들어 애니메이션을 끊기게 하는 속성을 움직이는 현상입니다.

### 알아둘 원칙 — 애니메이션을 언제, 어떻게 할지 결정하는 개념
- **Purposeful animation** — 움직임은 장식에 그치지 않고 방향 안내, 피드백, 관계 표시 같은 기능을 해야 합니다.
- **Anticipation** — 움직임이 시작되기 전에 반대 방향으로 살짝 준비 동작을 넣어 다음 동작을 예고합니다.
- **Follow-through** — 주요 움직임이 멈춘 뒤에도 요소의 일부가 조금 더 움직이고 가라앉아 무게감을 더합니다.
- **Squash & stretch** — 움직이는 요소를 변형해 무게, 속도, 유연성을 표현합니다.
- **Perceived performance** — 적절한 애니메이션으로 실제보다 인터페이스가 더 빠르게 느껴지게 합니다.
- **Frequency of use** — 사용자가 애니메이션을 자주 볼수록 지속 시간은 짧고 움직임은 미묘해야 합니다.
- **Spatial consistency** — 상태가 바뀌어도 요소의 정체성과 위치를 연결해 사용자가 요소의 이동 경로를 놓치지 않게 합니다.
- **Hardware acceleration** — `transform`과 `opacity`를 애니메이션하면 GPU가 움직임을 부드럽게 유지할 수 있습니다.
- **Reduced motion** — 사용자의 `prefers-reduced-motion` 설정을 존중해 움직임을 줄이거나 없앱니다.
