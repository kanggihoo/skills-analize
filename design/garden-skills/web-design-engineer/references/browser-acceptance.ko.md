## 1. 트리거 게이트

사용자가 승인/验收, 브라우저 QA/테스트/浏览器测试, 반응형 검증/响应式检查, 브라우저 간 검사, 시각적 회귀, 상호 작용 테스트 또는 이에 상응하는 실행 가능 검증을 명시적으로 요청하는 경우에만 이 하네스를 실행하십시오.

단지 사용자가 코드 빌드, 구현, 다듬기, 완료, 검토 또는 작업 확인을 한다고 해서 실행하지 **마세요**. 브라우저 실행이 명시적으로 지정되거나 틀림없이 요청되지 않는 한 이러한 요청은 간단한 전달 전 자체 검사를 받습니다.

사용자가 디자인 비평만 요청하는 경우 제공된 렌더링이나 아티팩트를 검사하고 `critique-guide.md`를 사용하세요. 브라우저 수용으로 자동 확장하지 마십시오.

## 2. 수락 계약 체결

질문하기 전에 요청과 프로젝트에서 추론하세요.- 항목 URL 또는 로컬 명령
- 중요 경로/스크린
- 기본 상호작용 경로
- 필수 뷰포트
- 대상 브라우저(지정된 경우)
- 사용자가 증거, 수리 또는 보고 전용 QA를 원하는지 여부

프로젝트의 기존 dev 명령과 종속성을 사용합니다. 필요하거나 승인되지 않은 경우 스택을 교체하거나 새 테스트 프레임워크를 설치하지 마십시오.

사용자가 반응형 수락을 요청했지만 대상을 제공하지 않은 경우에만 기본 뷰포트:

| 이름 | 뷰포트 |
|---|---|
| 소형 모바일 | 390×844 |
| 태블릿 | 768×1024 |
| 소형 노트북 | 1280×720 |
| 데스크탑 | 1440×900 |

고정된 16:9 아티팩트의 경우 의도한 내부 캔버스와 하나 이상의 작은 외부 뷰포트를 테스트하여 왜곡되지 않는 배율 동작을 확인합니다.

## 3. 안전하게 시작하세요1. `package.json` 및 프로젝트 문서에서 의도한 명령을 검사합니다.
2. 가능한 경우 이미 실행 중인 서버를 재사용합니다.
3. 필요한 최소한의 로컬 프로세스를 시작하고 실제 준비 신호를 기다립니다.
4. 실제 URL과 빌드/개발 모드를 기록합니다.
5. 프로덕션 서비스나 외부 데이터를 수정하지 마십시오.

## 4. 자동 패스

해당 환경에서 사용 가능한 브라우저 제어 또는 테스트 도구를 사용하십시오. 합의된 범위를 확인하세요.

### 런타임

- 치명적인 오류 없이 페이지가 로드됩니다.
- 콘솔에는 실행 가능한 새로운 오류가 없습니다. 관련 없는 제3자 소음을 숨기지 않고 분류합니다.
- 로컬 자산, 글꼴, 이미지 및 기본 네트워크 요청이 성공합니다.
- 수화 또는 프레임워크 불일치가 나타나지 않습니다.

### 레이아웃

- 의도하지 않은 수평 오버플로가 발생하지 않습니다.
- 탐색, 기본 CTA, 주요 콘텐츠, 대화 상자 및 컨트롤에 계속 접근할 수 있습니다.
- 텍스트가 잘리거나 충돌하거나 읽을 수 없을 정도로 좁아지지 않습니다.
- 이미지는 의도한 자르기와 초점을 유지합니다.
- 고정 캔버스 아티팩트는 왜곡 없이 확장됩니다.

### 상호 작용- 기본 링크와 버튼은 의도한 작업을 수행합니다.
- 키보드 포커스가 표시되며 합리적인 순서를 따릅니다.
- 양식에는 해당하는 경우 레이블, 유효성 검사, 오류 및 제출 피드백이 표시됩니다.
- 오버레이는 사용자를 가두거나 잃지 않고 열고 닫을 수 있습니다.
- 로드 중, 비어 있음, 오류 및 비활성화 상태는 범위 내에 있고 안전하게 도달할 수 있을 때 실행됩니다.

### 모션 및 환경설정

- 애니메이션이 완료되고 상호작용을 차단하지 않습니다.
- 움직임 감소 동작으로 콘텐츠와 작업 완료가 유지됩니다.
- 아티팩트에서 필요할 경우 자동 재생 또는 반복 동작을 일시 중지할 수 있습니다.

## 5. 비주얼 패스

요청된 각 뷰포트와 위험 상태에서 증거를 캡처합니다. 스크린샷에서 다음 사항을 검사하세요.

- 계층 구조 및 초점 순서
- 간격 리듬 및 정렬;
- 디자인 토큰 드리프트;
- 반복되는 레이아웃 공식;
- 대비 및 가독성;
- 어색한 접힘, 고아 컨트롤 및 대규모 우발적 공백;
- 제공된 참조 또는 기준선과의 시각적 차이.공식적인 기준선이 존재하는 경우 이를 비교하십시오. 그렇지 않은 경우 패스를 "시각적 회귀"가 아닌 "시각적 수용"이라고 부릅니다.

## 6. 수리 루프

사용자가 구현을 승인하거나 승인 실패를 수정하도록 요청한 경우:

1. 고장 및 재현 상태를 기록합니다.
2. 최소한의 원인 복구를 수행하십시오.
3. 동일한 뷰포트/상태에서 실패한 검사를 다시 실행합니다.
4. 변경으로 인해 다른 지역이 퇴보할 수 있는 경우 인근 연기 경로를 다시 실행하십시오.
5. 계약 통과 후 정지하거나 콘크리트 차단제를 신고하세요.

보고서 전용 QA의 경우 파일을 편집하지 마세요. 심각도에 따라 정렬된 증거 기반 조사 결과를 제공합니다.
