# 디자인 방향 조언자 — 확장 참조

요청이 모호하고("좋은 것을 만들어주세요", "내가 원하는 스타일이 무엇인지 모르겠습니다") 디자인 컨텍스트가 존재하지 않는 경우 이 내용을 읽어보세요. 기본 `SKILL.md`는 이미 **메커니즘**(3가지 차별화된 방향, 명명된 디자이너 참조, 동일 학교 선택에 대한 엄격한 규칙)을 다루고 있습니다. 이 파일은 **학교 분류**를 제공합니다. 즉, 각각 명명된 앵커와 이를 추천하는 데 사용하는 샘플 사본이 포함된 6개의 높은 수준의 철학적 렌즈입니다.

> **용어 잠금**: 이 파일은 **학교**(6개의 상위 수준 렌즈) 및 **앵커**(학교별 명명된 스튜디오/브랜드/디자이너)를 다룹니다. 동반 폴더 `style-recipes/`에는 구체적이고 바로 붙여넣을 수 있는 구성을 갖춘 25개의 **레시피** 파일(앵커당 하나의 파일)이 포함되어 있습니다. 사용자가 여기에서 학교를 선택하면 구체적인 팔레트/타이포그래피/간격 값에 대한 해당 학교의 레시피 파일에 전달합니다. 실제로 필요한 레시피 파일만 로드하세요. 카탈로그 색인은 `style-recipes/INDEX.md`에 있습니다.

---## 이 파일을 사용하는 방법

1. 사용자의 요청과 4가지 포지셔닝 질문(서사적 역할/시청 거리/시각 온도/용량)을 읽습니다.
2. 아래의 **다양한 행에서 사용자의 상황에 꼭 맞는 학교 3개**를 선택하세요.
3. 각각 추천: 디자이너/스튜디오 이름 + "이것이 당신에게 적합한 이유" 2~3줄 + 시그니처 시각적 큐 3~4개 + (선택 사항) 유명한 시금석 작품 1개
4. 사용자가 하나를 선택하거나 두 개를 리믹스할 때까지 기다립니다.
5. **사용자가 학교를 선택한 후 → 해당 학교의 `style-recipes/`에서 2~3개의 레시피 파일을 읽습니다**(예: *Information Architecture* 선택 → `style-recipes/pentagram.md` + `style-recipes/bloomberg-terminal.md` + `style-recipes/tufte-dataink.md` 읽기). 레시피 파일에는 구체적인 값이 들어 있습니다. 이 파일은 그것들을 복제하지 않습니다.
6. 선택한 레시피가 설계 컨텍스트가 됩니다. 이를 `brand-spec.md`에 작성하고 기본 워크플로우로 진행합니다.

### 6. 최신 도구/빌더 SaaS

**바이브**: 도구를 위한 조용한 고급스러움, 헤어라인 디테일, 따뜻한 어둠 + 고정 공간 액센트
**최적의 용도**: 개발자 도구, B2B SaaS, AI 도구, 인프라/플랫폼 제품, 생산성 앱
**효과가 있는 이유**: 자신감 있는 구속은 '마케터가 만든 것'이 아니라 '도구를 사용하는 사람이 만든 것'으로 읽혀집니다. 헤어라인 테두리, 고정폭 단축키 칩, 단일 악센트 색상은 소리 지르지 않고도 공예가 주도하는 문화를 나타냅니다. 이는 AI 기본 출력에서 ​​가장 서비스가 부족한 학교입니다. 모든 모델은 대신 보라색-분홍색-파란색 그라데이션에 도달하기를 원합니다.| 앵커 | 무엇을 빌릴까 |
|---|---|
| **선형** | 가는선 1px 테두리, 따뜻하고 어두운 바탕, 선택적 보라색 액센트 < 5% 픽셀, 키보드 우선 칩 |
| **Vercel** (최근) | *하나*의 깃털 그라디언트 메쉬로 인해 검정 + 흰색 정밀도가 깨졌습니다. 영웅의 배포 로그 현실감 |
| **레이캐스트** | 영웅으로서의 유리 명령 팔레트; 작은 액센트로 사용되는 확장명별 컬러 도트 |
| **노션**(AI 이전 시대) | 친숙한 세리프 헤드라인 + 크림색 표면에 아이콘으로 표시된 이모티콘; 구조가 먼저, 따뜻함이 두 번째 |

**구체적인 시작점**(각각은 `style-recipes/`의 단일 파일입니다. 하나 읽기): [`linear`](./style-recipes/linear.md) · [`vercel-mesh`](./style-recipes/vercel-mesh.md) · [`raycast`](./style-recipes/raycast.md) · [`notion-pre-ai`](./style-recipes/notion-pre-ai.md) — 각각 팔레트를 운반합니다. 타이포그래피, 띄어쓰기, 시그니처는 3단계에 바로 붙여넣기 위해 이동합니다.**추천 시 샘플 사본**:

## 사용자가 선택(또는 리믹스)할 때

일반적인 사용자 응답:- **"2번으로 가겠습니다."** → 방향 확정. `brand-spec.md`에 씁니다. 이를 설계 컨텍스트로 사용하여 2단계로 진행합니다.
- **"A의 색상은 마음에 드는데 C의 레이아웃은 마음에 듭니다."** → 리믹스를 서면으로 확인("그래서: 미니멀한 편집 팔레트 + 모션 주도 레이아웃 안무. 그렇죠?") 후 진행합니다.
- **"이것들 중 어느 것도 옳지 않다고 생각합니다. 더 보여주세요."** → 범위를 좁히기 위해 하나의 목표 질문("형식적/제도적 또는 장난기/표현적에 더 가깝습니까?")을 묻고 이전에 표시하지 않은 행에서 3가지 새로운 방향을 제시합니다.
- **"모르겠어요. 고르세요."** → 가장 안전한 것(보통 Editorial/Minimalist)을 선택하고, 이유를 설명하고, 커밋하기 전에 검증할 수 있는 5분 v0를 제안합니다.

## AI 프롬프트 템플릿(방향을 지원하는 이미지 생성 시)

형식: `[philosophy DNA] + [content description] + [technical params]`✅ **좋음**(특정 특성):
> "80% 여백, 단일 음소거 테라코타(#C04A1A) 액센트, GT Sectra 세리프 헤드라인, 따뜻한 황백색(#F2EFE8) 바탕에 단일 제품 영웅, 부드러운 하향식 조명, 3:2 화면비를 갖춘 케냐 하라의 영향을 받은 미니멀리즘"

❌ **나쁜** (DNA가 없는 스타일 이름):
> "미니멀리스트 스타일, 프리미엄 느낌, 하이퀄리티"

항상 다음을 포함하십시오:
- 색상 HEX("따뜻함" / "시원함" 아님)
- 종횡비 및 크기
- 구성 규칙(삼등분 법칙, 중앙 정렬, 비대칭)
- *피해야 할* 사항(예: "보라색 그라데이션 없음, 이모티콘 없음, 둥근 카드 없음")

> `style-recipes/`의 각 레시피 파일은 해당 레시피의 DNA에 맞춰 미리 작성된 **AI 프롬프트 시드**를 제공합니다. 프롬프트를 처음부터 작성하는 대신 사용 중인 것부터 시작하세요.

## 방향 추천의 안티 패턴

❌ **같은 행에서 3개 선택 추천** — 사용자는 이들을 구별할 수 없습니다. '방향 차별화' 포인트 전체가 무너져❌ **'미니멀리즘' / '모던' / '클린'**을 방향 이름으로 추천합니다. 이는 방향이 아니라 AI 기본 단어입니다. 항상 지명된 디자이너/스튜디오를 기준으로 삼으세요.

❌ **"이것이 당신에게 적합한 이유" 없이 추천** — 사용자는 객관식 퀴즈가 아닌 *안내*를 원했습니다. 각 옵션은 상황(대상, 목적, 예산, 브랜드 성숙도)에 적합한지 설명해야 합니다.

❌ **5개 이상의 방향 표시** — 선택 마비. 3이 가장 좋은 지점이다. 처음 3개 항목이 모두 누락된 경우 좁혀지는 질문 하나를 하고 새로운 질문 3개를 제공합니다.

❌ **사용자에게 각 방향을 1~10점으로 평가하도록 요청** - 이는 권장 사항을 사용자에게 다시 오프로드하는 것입니다. 추천을 해주세요. 사용자는 동의하거나 반발할 것입니다.
