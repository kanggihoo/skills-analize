# 기존 UI 및 리디자인 프로토콜

기존 시각적 제품을 수정하기 전에 이 참조를 읽어보세요.

## 내용

1. 모드 분류
2. 편집 전 감사
3. 보호되는 계약
4. 현대화 명령
5. 다이얼 안내
6. 전후 계획
7. 검증

## 1. 모드 분류

### 확장

현재 시스템 내부에 경계 요소를 추가하거나 변경합니다. 기존 어휘를 일치시킵니다. 관련 없는 표면을 "개선"하지 마십시오.

### 재설계 · 보존

신원, 정보 아키텍처, 콘텐츠 음성, 행동 계약을 유지하면서 현대화합니다. 표적 진화를 선호합니다.

### 재설계 · 정밀 검사

합의된 제품, 콘텐츠 및 기술 계약을 유지하면서 새로운 시각적 언어를 도입합니다. 정밀검사는 모든 것을 다시 작성하는 권한이 아닙니다.

보존과 정밀 검사로 인해 결과가 실질적으로 변경되고 요청이 모호한 경우 하나의 집중적인 질문을 하세요.

## 2. 편집 전 감사

프로젝트 노트나 간결한 재설계 개요에 현재 상태를 기록하세요.### 시각 시스템

- 색상 역할 및 실제 사용 비율
- 유형군, 규모, 가중치 및 줄 길이
- 간격 리듬 및 컨테이너 너비
- 반경, 테두리, 그림자 및 고도 규칙
- 아이콘, 일러스트레이션, 사진 및 이미지 처리
- 모션 지속 시간, 완화, 트리거 및 피드백 스타일

### 제품 및 콘텐츠

- 페이지 트리, 탐색, 주요 여정 및 전환 경로
- 기존 콘텐츠 블록과 그 목적
- 브랜드 보이스, 법률 카피, 현지화, 실제 데이터
- 로드 중, 비어 있음, 오류, 비활성화 및 권한 상태

### 기술 계약

- 경로, 슬러그, 앵커 및 딥 링크
- 양식 필드 이름, 순서, 유효성 검사 및 자동 완성 기대치
- 분석 이벤트, 데이터 속성, 테스트 선택기 및 실험 후크
- 구성 요소 API 및 다운스트림 소비자
- 접근성 의미, 키보드 동작, 포커스 순서 및 공지 사항
- SEO 메타데이터, 표준 URL, 구조화된 데이터 및 소셜 카드

### 품질 부채

관찰 내용을 다음과 같이 구분합니다.- **보존**: 인식 가능하거나 계약에 중요한 강점
- **개선**: 취약한 계층 구조, 간격, 대비, 반응성 또는 기술
- **제거**: 지원되지 않는 혼란, 깨진 패턴, 작동하지 않는 상호 작용 또는 조작된 콘텐츠

## 3. 보호되는 계약

다음 항목을 자동으로 변경하지 마세요.

- 경로 구조, 슬러그, 앵커 ID 또는 기본 탐색 라벨
- 브랜드 로고, 워드마크 또는 아이덴티티에 중요한 자산
- 양식 필드 이름/주문 또는 제출 동작
- 법률, 동의, 개인 정보 보호, 가격 책정 또는 규정 준수 사본
- Analytics 이벤트, 선택기 및 실험 식별자
- 기존 접근성이 승리합니다.
- 공개 구성 요소 API 또는 영구 상태 키
- 이용자가 제공한 콘텐츠 및 실제 데이터

요청한 결과에 실제로 보호 계약 변경이 필요한 경우 승인을 요청하세요.

## 4. 현대화 순서

문제를 해결하는 가장 위험도가 낮은 수단을 적용한 후 다음을 재평가하세요.1. 기능 및 접근성 오류를 수정합니다.
2. 계층구조와 타이포그래피를 수정하세요.
3. 간격, 정렬 및 반응 동작을 표준화합니다.
4. 토큰을 통합하고 불량 스타일을 제거합니다.
5. 상태 및 상호 작용 피드백을 개선합니다.
6. 정당화된 모션을 추가합니다.
7. 영웅 또는 핵심 섹션을 재구성하십시오.
8. 수리할 수 없는 경우에만 전체 블록을 교체하십시오.

보존 모드에서는 브리핑이 만족되면 중지하세요. 증분 작업을 포트폴리오 재설계로 전환하지 마십시오.

## 5. 다이얼 안내

- **확장**: 기존의 모든 다이얼과 일치합니다. 브랜드 충실도를 10으로 설정합니다.
- **보존**: 밀도와 자산을 안정적으로 유지합니다. 요청하지 않는 한 최대 한 지점까지 변화/움직임을 변경합니다.
- **정밀 검사**: 개요에서 새로운 변화/모션을 도출하되 정보가 손실되지 않도록 콘텐츠 밀도 맵을 유지합니다.

## 6. 전후 계획

사소한 재설계의 경우 다음과 같이 명시하십시오.

```text
Mode:
Preserve:
Improve:
Remove:
Protected contracts:
Design Read + dials:
Highest-risk change:
Rollback / fallback:
```이것은 긴 디자인 에세이가 아닌 결정 기록입니다.

## 7. 확인

기본 제공 전 자체 점검은 검사를 통해 요청된 범위와 보호된 계약을 확인합니다. 사용자가 명시적으로 요청할 때만 실행 가능한 브라우저 승인을 실행하십시오. 그런 다음 `browser-acceptance.md`를 사용하고 보존된 여정에 대한 회귀 검사를 포함합니다.
