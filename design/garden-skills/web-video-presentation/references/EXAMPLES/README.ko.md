# 예시 — 완성된 챕터 / 주제별 기준점

> ## ⚠️ 이 문서는 **구조 예시**이며, 그대로 베끼는 템플릿이 아닙니다.
>
> 이 예시들은 **복사해서 쓰라는 뜻이 아닙니다**. 역할은 “완성된 챕터의 대략적인 형태, 애니메이션의 레이어 구성, CSS 토큰, outline 모양”을 살펴보는 데 있습니다.
>
> **올바른 사용 순서**:
>
> 1. [`../CHAPTER-CRAFT.md`](../CHAPTER-CRAFT.md)의 Part 0에서 다섯 가지 질문에 먼저 답합니다.
> 2. “이 챕터 전체 구조를 어떻게 잡아야 하지?”에서 막혔을 때만 EXAMPLES를 살펴봅니다.
> 3. 이 예시의 “형태”(step을 나누는 방식, 글자 크기 관계, 레이아웃 원칙)는 유지하되, **현재 프로젝트의 주제와 내용에 맞춰 동작을 고릅니다.**
>
> 반대로 EXAMPLES부터 보고 하나를 끝까지 그대로 따라 하면 [`../CHAPTER-CRAFT.md`](../CHAPTER-CRAFT.md) Part 5의 8번, “한 챕터에 하나의 등장 애니메이션만 사용”이라는 동질화 방지 원칙을 어기게 됩니다. 모든 사용자의 영상이 같은 템플릿을 조금씩 바꾼 것처럼 보이게 됩니다.

두 종류의 참고 자료를 제공해 에이전트가 챕터를 작성할 때 구체적인 형태를 참고하고, 처음부터 모두 설계해야 하는 부담을 줄입니다.

> **반드시 따라야 하는 것은 아닙니다.** 막힐 때 참고하고, 적극적으로 시도할 때는 과감하게 벗어나도 됩니다.

## 목차

### A. 챕터 구조 기준점(주제 무관)

| 예시 | 적합한 상황 | 파일 |
|---|---|---|
| [`hook-chapter/`](hook-chapter/) | **후크형 오프닝** — 여러 이미지를 하나씩 보여준 뒤 히어로 화면으로 전환 | `chapter.tsx` + `chapter.css` |
| [`list-reveal/`](list-reveal/) | **목록 순차 공개** — 내레이션이 “세 가지 / N개 특성”을 말하고 각 항목을 한 step씩 공개 | `chapter.tsx` + `chapter.css` |

각 예시는 모두 **완성된 챕터**입니다. **내용에 맞는 주도 동작**과 필요한 보조 동작을 사용합니다. 지속적인 미세 움직임을 반드시 붙일 필요는 없으며, [`../CHAPTER-CRAFT.md`](../CHAPTER-CRAFT.md) Part 0 원칙 7에 따라 절제합니다. 실제 소재를 사용하고(자리표시 카드가 아님), 글자 크기는 강한 대비를 두며, 예시에서는 `newsroom` 테마를 적용했습니다.

### B. 주제별 사례 기준점(특정 주제와 연관)

| 예시 | 주제 | 파일 |
|---|---|---|
| [`case-tech-review/`](case-tech-review/) | 기술 리뷰 / 실사용 비교 / 성능 영상 | README + outline 발췌 |

> 주제 사례는 **실제 outline이 어떻게 생겼는지**(article 보충 정보를 채우는 법, 챕터 구분을 결정하는 법)를 보여줍니다. 특정 사례와 비슷한 주제의 요청을 받으면, 자신의 outline을 작성하기 전에 먼저 읽어 보세요.

## 사용 방법

### 챕터 구성이 막힐 때

1. 지금 챕터와 구조가 가장 비슷한 기준점(후크형, 목록형 또는 기타)을 찾습니다.
2. `README.md`에서 예시의 설계 의도와 리듬을 확인합니다.
3. `chapter.tsx`에서 JSX 구조, `step` 구분, 사용한 컴포넌트와 클래스명을 확인합니다.
4. `chapter.css`에서 애니메이션에 사용한 keyframes와 토큰, `infinite` 미세 움직임을 어디에 넣었는지 확인합니다.
5. 자신의 챕터에는 기준점의 “형태”를 유지하면서 현재 내용과 주제 분위기에 맞는 애니메이션을 고릅니다.

### 테마를 바꿀 때

각 예시 README의 끝에는 다른 테마로 바꾸는 방법이 있습니다. 보통 주도 동작의 표현만 바꾸면 됩니다(`newsroom`의 도장 찍기 → `terminal`의 타자기 효과 → `chalk`의 분필 자필 효과). 구조, step 구분, 글자 크기 관계는 그대로 둡니다.

---

## ⚠️ 두 기준점은 “최저 기준”이지 “최고 한계”가 아닙니다

두 예시에는 도장 찍기, stagger, 포인트 색상의 빨간 막대가 들어 있지만, **비교적 절제된 버전**입니다. 더 과감하고 영상다운 표현을 시도해 보세요.

### 확장 아이디어(원하는 대로 조합)

| 요소 | 두 기준점의 시작점 | 더 확장할 수 있는 방향 |
|---|---|---|
| 배경 레이어 | 단색 surface | + SVG turbulence 필터로 종이 질감을 만들고 사선 방향으로 계속 흐르게 하기 |
| 주도 동작 | mask reveal + 도장 찍기 | + Canvas 입자가 화면 밖에서 모여 히어로 글자가 되게 하기 |
| 보조 동작 | 포인트 빨간 막대의 scaleX | + SVG path의 stroke-dashoffset으로 밑줄·장식 무늬 직접 그리기 |
| 지속적인 미세 움직임 | 포인트 색상 후광의 호흡 효과 | + 여러 입자 레이어의 이동 / scanline / ken burns로 천천히 당기기 |
| 숫자 히어로 | 숫자를 바로 표시 | + `requestAnimationFrame`과 easeOutQuart를 사용해 JS 숫자 굴리기 |
| 과정 / 구조 | 텍스트만 나열 | + SVG path로 흐름도를 직접 그리고 선마다 stroke-dashoffset 시작 시차 주기 |
| 비교 그래프 | 텍스트 두 구간 | + SVG 막대 두 개를 직접 그리고 차이 숫자를 굴리기 |
| 전환 | 챕터 경계에서 바로 자르기 | + clip-path inset으로 가로 방향 닦아내기 전환 |

→ 자세한 도구 모음은 [`../CHAPTER-CRAFT.md`](../CHAPTER-CRAFT.md) Part 2의 “시각 표현 전체 도구 상자”(CSS / SVG / Canvas / JS 4개 층)를 참고하세요.

### 실제 적용 원칙

챕터를 작성할 때는 먼저 [`../CHAPTER-CRAFT.md`](../CHAPTER-CRAFT.md) Part 0의 다섯 질문으로 주도 동작을 고르고, 기준점과 비슷한 기본 수준을 구현해 실행해 봅니다. 분위기가 맞는지 확인한 다음 보조 동작이나 지속적인 미세 움직임을 추가할지 결정합니다.

**판단 기준**:
- 각 step의 주도 동작이 충분히 다양하다면(Part 0 원칙 7의 PPT 경고 확인) 지속적인 미세 움직임을 더할 필요가 없습니다.
- 챕터 전체의 주도 동작이 지나치게 단조롭다면 “지속적인 미세 움직임 추가”로 보완하지 마세요. [`../CHAPTER-CRAFT.md`](../CHAPTER-CRAFT.md) Part 1의 다섯 질문으로 돌아가 주도 동작을 다시 고르는 것이 맞습니다(Part 5의 8번 “한 챕터에 하나의 등장 애니메이션만 사용” 참고).

## EXAMPLES에 없는 챕터 유형

- **숫자형 히어로**(“+47%” → “거의 두 배 빨라짐”)
- **비교형**(전후 비교 / 막대 그래프 2개)
- **마무리 링크 카드**

이런 장면에 필요한 시각 요소는 [`../CHAPTER-CRAFT.md`](../CHAPTER-CRAFT.md) Part 3의 시각 도구 모음(CSS / SVG / Canvas / JS 전체)에 있습니다. 기준점의 “형태”를 활용해 조합하세요.
