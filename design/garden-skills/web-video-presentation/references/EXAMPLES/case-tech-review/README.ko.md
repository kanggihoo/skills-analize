# 사례: 기술 리뷰

AI / 도구 / 제품을 **실제로 사용해 비교하는** 글을 7개 챕터, 36개 step으로 구성한 6분 30초 영상의 실제 사례입니다.

> ## ⚠️ 구조 예시이자 과거 사례이며, 그대로 베끼는 템플릿이 아닙니다.
>
> 이 디렉터리의 목적은 에이전트에게 **“리뷰 영상의 챕터를 어떻게 나누는지, 정보 풀에서 무엇을 추출하는지, 챕터 길이를 어떻게 정하는지”** 보여주는 것입니다. 여기에 포함된 구체적인 애니메이션 설명(예: “1.5s ease-out의 느린 blur clear / 글자당 80~100ms 타자기 효과”)은 과거 버전에 속합니다. 최신 outline에는 **애니메이션이나 지속 시간을 쓰지 않습니다**([`../../OUTLINE-FORMAT.md`](../../OUTLINE-FORMAT.md) 참고). 새 outline에는 화면에 표시할 내용, 관계 이름의 접두어, 챕터 단위 정보 풀만 적고, 애니메이션은 챕터 구현 단계에서 [`../../CHAPTER-CRAFT.md`](../../CHAPTER-CRAFT.md) Part 0의 다섯 질문으로 정합니다.
>
> **이 사례에서 배울 내용**:
> 1. 리뷰 영상을 7개 챕터로 나누는 방법(후크 → 장점 → 사용 장면 → 심화 → 마무리)
> 2. 챕터 길이를 정하는 방법(피로를 막기 위해 챕터마다 4~6 step)
> 3. 두 출처 원칙을 적용하는 방법(hero는 script에서, 데이터 보조 표시는 article에서 가져오기)
>
> **배우지 말아야 할 내용**: 애니메이션 선택, CSS 구현, 지속 시간 숫자(이 내용은 chapter 단계로 옮겨졌습니다).

## 적합한 상황

- AI 모델 / 제품 / 도구의 실제 사용 후기
- 여러 제품 비교(A 대 B 대 C)
- 벤치마크 / 성능 측정 / 사용자 투표 데이터 기반 콘텐츠
- “무엇이 강점인가 / 어떻게 쓰는가 / 더 잘 쓰는 법” 형식의 구조

## 핵심 결정 사항

| 요소 | 이 사례의 선택 | 일반적인 시사점 |
|---|---|---|
| 테마 | `midnight-press`(영화 같은 느린 장면, blur clear, 따뜻한 오렌지 포인트, scanline) | 기술 리뷰에는 절제되고 무게감 있는 어두운 색조가 적합합니다. 장난스럽거나 사탕처럼 밝은 색은 피합니다. |
| 챕터 구분 | 7개: 도입의 긴장감 / 강점 / 쓰임새 / 잘 쓰는 법 / Skill 소개 / Skill 모드 / 마무리 | 리뷰의 일반적인 구조는 후크 → 장점 → 사용 장면 → 심화 → 마무리입니다. |
| 챕터 길이 | 챕터마다 4~6 step | 리뷰는 정보 밀도가 높으므로 시청자 피로를 막기 위해 챕터당 6 step을 넘기지 않습니다. |
| 두 출처 적용 | hero 문구는 script에서, 화면에 표시할 세부 수치(점수 / 투표 수 / 타임스탬프)는 article에서 가져옵니다. | 리뷰 article에는 데이터가 많습니다. 모노 큐 / 작은 보조 표시 / 데이터 오버레이로 보여 주세요. |
| 애니메이션 스타일 | 느린 blur clear / 타자기 / ken burns로 천천히 당기기 | `midnight-press`의 어두운 인쇄 분위기를 유지하되, 챕터 구현 단계에서 테마에 맞춰 자유롭게 선택합니다. |

## 파일

- [`outline-snippet.md`](outline-snippet.ko.md) — 첫 두 챕터의 전체 발췌(각 5 step). outline에 두 출처 원칙을 적용한 방식을 보여줍니다.

> 전체 7개 챕터 outline은 이 Skill을 사용하는 실제 프로젝트의 `gpt-image2-video/outline.md`에 있습니다. Skill 저장소에 넣지 않은 이유는 특정 프로젝트 내용이 Skill 명세에 섞이는 것을 피하기 위해서입니다.

## 이 사례에 나오지 않는 상황

리뷰 영상에는 보통 다음이 필요하지 않습니다.
- 느린 롱테이크(영화 분위기의 오프닝이나 여행 브이로그에 적합)
- 따뜻한 손글씨(교육·육아·레시피에 적합)
- 많은 일러스트(디자인 시안이나 공예품에 적합)
