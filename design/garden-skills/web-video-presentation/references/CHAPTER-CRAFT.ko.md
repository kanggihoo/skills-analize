# 장 개발 지침 (각 장을 만들 때 필수로 읽기)

---

## 이것은 PPT가 아니라 영상입니다

만드는 것은 **영상 웹 페이지**입니다 — 발표자가 클릭하고 내레이션을 더해 화면 녹화한 뒤 관객에게 보여줍니다. 각 단계가 제대로 만들어졌는지 판단하는 기준은 간단합니다.

- **PPT처럼 보이지 않아야 함** — 관객이 페이지 넘김 슬라이드가 아닌 영상을 보는 느낌을 받아야 함 (페이지에 머리글과 바닥글을 두지 않고 핵심 시각 요소를 강조)
- **편안하게 보여야 함** — 색상, 글꼴, 리듬이 편안해야 함. 순수 텍스트를 많이 보여주지 말고 너무 작은 글자를 쓰지 않음
- **시각적 충격이 있어야 함** — 화면에서 사건이 벌어져야 하며 글자만 쌓아서는 안 됨. 모든 요소를 한꺼번에 나열하지 말고 핵심 요소를 진행에 따라 단계적으로 드러냄

---

## CSS / SVG / Canvas / JS로 시각 연출을 적극 구현해야 함

> **최소 요구 사항입니다.**
>
> 모든 장에 움직이는 그래픽이나 시연 요소를 **최소 1–2개** 포함해야 합니다.
> **장 전체가 텍스트뿐이면 검수를 통과하지 못하며 다시 만들어야 합니다.**

영상 같은 느낌은 설명하는 대상을 관객이 **화면에서 직접 보며 경험할 때** 강해집니다.

- 숫자가 증가하거나 막대가 자라거나 순위가 바뀜
- 흐름 노드가 차례로 켜지고 연결선이 그려짐
- 비교 화면을 칼로 가르듯 나누거나 스포트라이트가 지나가거나 형태가 변형됨
- 입자가 모여 형상을 만들거나 노이즈 배경이 흐르거나 글자 비가 떨어짐
- 터미널 상호작용 모의 화면
- AI 대화 창 모의 화면
- 파일 디렉터리 트리 모의 화면

**어떤 방식으로 조합해도 되지만 모든 장에 반드시 적용해야 합니다. 장 전체가 텍스트만인 결과물은 허용되지 않습니다.**

---

## 단계별 공개, 한 번에 모두 보여주지 않기

페이지 내용은 **전역 `step` 카운터**가 제어합니다 — 빈 곳을 클릭하거나 → 키를 누르면 한 단계 이동합니다. 각 단계를 설계할 때 **“이번 단계에서는 무엇을 보여주고 다음 단계에서는 무엇을 보여줄까?”**를 생각합니다.

**가장 중요한 규칙:**

> 내레이션이 “첫째는 X, 둘째는 Y, 셋째는 Z”처럼 **목록**을 읽을 때는 X / Y / Z를 하나의 step에서 전부 stagger 애니메이션으로 보여주는 것을 **엄격히 금지합니다.**

올바른 방법:

- 항목 하나당 step 하나
- X는 자기 step에서 혼자 강조
- Y를 말할 때는 X를 회색으로 남겨 맥락을 유지하고 Y를 강조
- Z를 말할 때는 X / Y를 회색으로 바꾸고 Z를 강조

**판단 기준**: 발표자가 하나씩 읽을까요? 그렇다면 반드시 순서대로 하나씩 공개합니다.

## 콘텐츠 선별: 핵심을 잡고 원문을 그대로 옮기지 않기

영상은 **소리 + 화면**입니다.

- **내레이션**은 정보를 순차적으로 명확히 설명
- **화면**은 박자의 핵심을 확대해 리듬을 강조

각 step의 화면에는 해당 박자에서 **강조할 가치가 가장 큰 요소 1–3개만** 둡니다 — hero 슬로건 하나 / 숫자 하나 / 대비 한 쌍 + 필요한 시각 시연.

원문의 모든 글자를 화면에 옮기려 하지 않습니다. 그것은 논문 읽기이지 영상이 아닙니다.

---

## 이중 출처: 리듬은 내레이션, 세부 정보는 원문

> **리듬 / 순서 / 박자 분할**은 **`script.md` 내레이션 원고**를 따릅니다 — **중요한 순서는 바꾸지 않습니다.**
> **화면 디테일 / 데이터 / 인용 / 사례**는 **`article.md` 원문**에서 가져옵니다.

`outline.md`는 각 장의 첫 부분에서 참고용 “정보 풀”을 추출합니다. 하지만 **장을 구현할 때는 `article.md`에서 해당 장의 원문 단락도 다시 확인해야 합니다.** 내레이션 원고보다 더 많은 구체적 수치, 직접 인용, 사례 관점, 출처 날짜가 있습니다. 이런 내용을 화면에 더해 **화면의 정보 밀도를 내레이션보다 높게** 만듭니다.

> **내레이션 원고 내용만 화면에 썼다면**, 화면은 내레이션을 글자로 다시 쓴 셈이고 — 이것은 영상이 아니라 PPT입니다.
>
> 장을 구현할 때 번거롭더라도 원문에서 디테일을 가져옵니다.

---

## 글꼴 / 색상 / 애니메이션 / 여백 — 영상 시연의 기본 미학

영상 관객은 화면에서 멀고 주의가 분산될 수 있으므로:

- **글자는 크게** — hero 텍스트는 최소 80px부터 시작해야 멀리서도 읽힘
- **여백은 넉넉히** — 무대 네 가장자리에 큰 여백을 두고 화면을 꽉 채우지 않음
- **색상은 편안하게** — **색상과 글꼴 패밀리는 테마 토큰을 사용** (테마 변경 시 깨지지 않게 함). 글자 크기 / 간격 / 길이는 콘텐츠에 맞춰 장마다 자유롭게 설정 (아래 “코드 레이어 최소 제약” 참고)
- **애니메이션은 편안하면서도 멋지게** — 등장과 정지는 깔끔해야 하고 시선을 빼앗지 않아야 함. 멋은 **설계의 기발함** (콘텐츠 기반 시연 애니메이션)으로 만들고 **과도한 속도**나 **잦은 점멸**로 만들지 않음

## AI 티 제거

AI 생성 웹 페이지에는 흔한 “시각적 지문”이 있습니다. **전부 피합니다.**

- 보라·분홍 / 파랑·보라 대각선 그라데이션 배경
- 둥근 카드 + 색깔 있는 왼쪽 테두리 장식
- 그라데이션 버튼 + 크게 둥근 알약 모양
- 아이콘 대신 이모지 사용
- 가짜 데이터 / 가짜 로고 / 가짜 “사용자 수 만 명”
- 장의 N개 step이 모두 같은 등장 애니메이션 (전부 fade / 전부 blur)
- 모든 step에 ken burns / 광륜 호흡 / 지속 점멸 적용
- 모든 화면 오른쪽 아래에 모노스페이스 배지 / 번호 표시

없는 것은 **없다고 인정합니다** — 실제 비율에 맞춘 placeholder 카드 (예: “image · 16:9 설명”이라고 적힌 카드)를 둡니다. 이모지로 얼버무리지 말고, 관련 없는 이미지를 찾거나 수치를 만들어내지 않습니다. **없다고 밝히는 것이 가짜보다 백 배 낫습니다.**

## 프레임워크에 이미 포함된 기능 (이해만 하고 다시 만들지 않기)

- **16:9 고정 무대**: 콘텐츠는 1920×1080에서 설계하고 바깥 transform scale이 모든 뷰포트에 맞춤. 가장자리 레터박스는 검정 — **반응형 중단점은 없음**
- **중앙 무대 + 넉넉한 여백**: 위아래좌우에 최소 80px 안전 영역 확보
- **숨겨진 진행 표시줄**: 화면 아래에 기본 완전 투명. 마우스를 아래쪽 가장자리로 옮기면 표시되고 장 이동 클릭을 지원 (녹화 영상에는 UI 장식이 보이지 않음)
- **전역 step 제어**: 무대 빈 곳 클릭 / 키보드 ←/→로 진행. 장은 `step`의 순수 함수이며 타이머나 명령형 상태가 없음

## 코드 레이어 최소 제약

반드시 지켜야 하는 금지선 외에는 자유롭게 구현합니다.

### 토큰 필수 사용 (테마 변경 시 깨지지 않게 하는 기본 규칙)

- **색상**: `--shell` / `--surface` / `--surface-2` / `--surface-3` / `--text` / `--text-2` / `--text-mute` / `--text-faint` / `--rule` / `--accent` / `--accent-soft` / `--accent-glow` — **hex / rgb / 색상 이름을 하드코딩하지 말 것**
- **글꼴 패밀리**: `--font-display-cn` / `--font-display-en` / `--font-body` / `--font-mono` — **글꼴 이름을 하드코딩하지 말 것**
- **테마 성격 시그니처**는 primitive class로 자동 적용됩니다. **장 CSS에서 다시 정의하지 않습니다.**
  - `.hero-num` (hero 숫자 스타일 — 세리프 / 모노스페이스 / 굵은 산세리프를 테마가 결정)
  - `.rule` (구분선 — 1px 실선 / 4px 실선 / 2px 점선을 테마가 결정)
  - `.card` (카드 — 모서리와 그림자의 성격을 테마가 결정)
  - `.stage-frame` (무대 바탕색 / 모서리 / 그림자 / 장식 패턴 / 비네팅을 모두 자동 적용하므로 장 코드에서 별도 작업 불필요)

### 하드코딩 / 토큰 사용 모두 가능, 콘텐츠에 따라 자유롭게 결정 (장별 설계 허용)

- **글자 크기**: 80px가 필요하면 80px로, `var(--t-h1)`을 써도 됨
- **간격 / padding / margin**: 화면 리듬에 맞춰 직접 지정
- **애니메이션 시간 / easing / keyframe**: 애니메이션 의도에 맞게 직접 지정 (`theme.json`의 `mood`에서 **리듬 분위기**를 참고 — 느린 테마에 200ms 빠른 애니메이션을 쓰지 않음)
- **테두리 두께 / 성격 토큰이 아닌 모서리 / 자간**: 직접 지정 가능
- **gap / grid 레이아웃 크기**: 구도에 맞춰 작성

### 기타 엔지니어링 금지선

- 애니메이션을 구동하는 `setTimeout` / `setInterval`을 사용하지 말고 CSS keyframes를 사용합니다.
- 장 안의 인터랙티브 요소 (버튼 / 사용자 지정 컨트롤)에 `data-no-advance`를 추가합니다. 그렇지 않으면 클릭이 무대에 의해 step 진행으로 잘못 처리됩니다.
- 장 코드의 물리적 경계를 분리합니다: 장마다 독립 폴더와 독립 CSS 클래스 접두어를 사용하고 장끼리 import하지 않습니다.
- **각 장에는 `narrations.ts`가 반드시 있어야 합니다** (`<Chapter>.tsx`와 같은 디렉터리):
  - 배열 길이 **=** 장 코드의 `if (step === N)`에서 가장 큰 N + 1
  - 각 요소는 해당 step에서 재생할 내레이션 문구 ( `script.md`의 대응 단락에서 가져옴. **의미가 일치해야 함** — TTS에 맞춰 구두점 / 문장 나누기를 조금 조정할 수 있지만 핵심 구절은 빠뜨릴 수 없음)
  - 오디오가 전혀 없는 전환 step은 빈 문자열 `""` 사용. Auto 모드가 글자 수에 따라 시간을 추정해 진행함
  - 이 파일은 **오디오 합성과 Auto 모드 자동 진행의 유일한 원본**입니다. 잘못 쓰거나 빠뜨리면 녹화 타이밍이 어긋납니다.
- **애니메이션 길이는 step 내레이션 길이보다 짧거나 같아야 합니다.** Auto 모드는 오디오가 끝나는 순간 다음 단계로 진행하며 “애니메이션이 끝날 때까지 대기”하지 않습니다. 애니메이션이 너무 길면 세 가지 중 하나를 선택합니다: **내레이션을 늘리기 / step 나누기 / 애니메이션 속도 조정**. 자세한 동작은 [`AUDIO.md`](AUDIO.md)를 참고합니다.

## 완료 검수 (각 장 작성 후 **반드시 실행**, 건너뛸 수 없음)

> ⚠️ **필수 절차**: 장 구현 후 아래 자체 검수 → 수정 → 보고의 세 단계를 **반드시 완료**합니다. **“구현 완료 → 사용자에게 바로 보고”는 금지합니다.**
>
> **수행 방식** (기능에 따라 선택):
>
> 1. **Agent Teams 우선**: 별도의 reviewer agent를 열어 이 장 코드 경로와 이 문서의 “완료 검수” 체크리스트를 전달하고 **항목별 확인 + 결론**을 요청합니다 (통과 / 실패 항목 + 근거).
> 2. **subAgent 차선**: 현재 agent에 Teams 기능은 없지만 subagent 실행 기능이 있으면 같은 절차로 검토합니다.
> 3. **둘 다 없음**: 현재 agent가 직접 **항목별로 엄격히** 확인합니다. 대충 훑고 통과시키지 않습니다.
>
> **자체 검수 결과를 받은 뒤**: 실패 항목부터 **코드를 수정하고 나서** 사용자에게 “완료 + 검수 결과 + 수정 사항”을 보고합니다. **원래 결과만 보고하고 수정하지 않으면 규칙 위반**입니다.

한 장을 작성하고 브라우저에서 전체를 클릭해 본 뒤 항목별로 확인합니다.

- [ ] **각 장에 CSS / SVG / Canvas / JS 시각 연출이 최소 1–2개 있음** — 없으면 추가
- [ ] **step마다 주도 동작이 다름** — 장 전체에서 애니메이션 하나만 반복하면 다시 제작
- [ ] 글자가 크고 여백과 색상이 편안함
- [ ] 목록을 한 항목씩 공개하며 **항목 하나 = step 하나**
- [ ] 화면 정보가 내레이션보다 많음 (원문으로 돌아가 디테일을 추출해 화면에 추가)
- [ ] 보라·분홍 그라데이션 / 둥근 컬러 테두리 / 이모지 / 가짜 데이터 / 가짜 로고가 없음
- [ ] 부족한 소재를 가짜 이미지로 대체하지 않고 placeholder로 표시
- [ ] **색상과 글꼴 패밀리를 모두 토큰으로 사용** (하드코딩 hex / 글꼴 이름 없음). hero 숫자 / 카드 / 구분선 / 무대는 primitive class를 통해 테마 성격을 적용 — 둘 중 하나라도 어기면 테마 교체 시 깨짐
- [ ] 장을 전달할 때 **필요한데 아직 없는 소재를 사용자에게 먼저 알림**
- [ ] 작은 글자와 텍스트만 가득한 화면이 없음 (있으면 수정)
- [ ] 머리글·바닥글을 어떤 형태로든 두지 않고 핵심 내용만 표시 (있으면 수정)
