# 글을 말하기 편한 대본으로 바꾸는 스타일 가이드

글로 쓴 글을 **입으로 읽어도 어색하지 않은** 내레이션 대본으로 바꿉니다. 기본 스타일은 **Bilibili(B站)**입니다. 다른 플랫폼의 스타일 변형은 문서 끝에 있습니다.

> **절대 지켜야 할 세 가지**(하나라도 어기면 대본 전체를 다시 씁니다):
>
> 1. **정보를 60% 이상 보존**(자세한 내용은 다음 절 참고) — 내레이션 대본은 “요약”이 아니라 “다른 표현으로 바꾸기”입니다. 군더더기와 수식은 줄여도 되지만 사실 / 데이터 / 사례 / 논증 흐름을 삭제하면 안 됩니다.
> 2. **AI 말투 제거** — 문장을 짧고 구어체로 바꾸고 청자를 “당신”으로 불러도 AI 특유의 말투(억지 공감 / 억지로 깊은 척하기 / 자기 과시 / 만능 문구 / 과도한 병렬 나열)가 남을 수 있습니다. **글보다 말에서 AI 말투가 더 두드러집니다.**
> 3. **원문의 언어 유지** — 사용자가 명시적으로 번역을 요청하지 않는 한 `script.md`는 입력한 주 언어를 유지해야 합니다. 영어 글은 영어 대본으로, 중국어 글은 중국어 대본으로 바꿉니다. 중국어와 영어가 섞인 경우 원문의 용어, 인용, 제품명, 코드, 고유명사를 그대로 둡니다. “Bilibili 스타일 / YouTube 스타일 / 구어체”는 리듬, 구조, 표현의 자연스러움만 바꾸며 **언어를 바꾸지 않습니다.**
>
> 여덟 가지 원칙은 **형식**을 다루고, “AI 말투를 없애는 다섯 가지 유형”은 **문장의 분위기**를 다룹니다. 둘 다 가장 중요한 제약인 “정보 보존율”을 바탕으로 합니다.

## 최우선 원칙: 정보 보존율 60% 이상(40% 넘게 줄이지 말 것)

> 이 원칙은 아래의 여덟 가지 원칙과 AI 말투 제거 기준보다 **우선합니다**. 형식과 분위기를 다듬기 전에 정보가 빠지지 않았는지 먼저 확인하세요.

**판정 기준**:

- `len(script.md) ÷ len(article.md) ≥ 0.6`(중국어는 글자 수로 계산하며 코드 블록 / Markdown 표기 / 인용 출처는 계산에서 제외)
- 핵심 사실(수치 / 이름 / 시점 / 주장)을 **항목별로 대조**하며, 한 단락 전체가 사라지면 안 됩니다.
- 글의 **논증 흐름**(전제 → 결론 / 인과 / 비교)은 표현을 바꾸더라도 중간 단계를 건너뛰지 말고 보존해야 합니다.

**크게 줄여도 되는 항목**: 상투적인 도입 / 반복되는 요약 / 학술적인 배경 설명 / 인용 출처의 전체 서지 형식 / 형식적인 맺음말.

**줄이면 안 되는 항목**:

- 핵심 데이터와 숫자(“느낌”으로 풀어 말하더라도 원래 숫자를 주석으로 남깁니다.)
- 구체적인 사례 / 예시 / 이야기
- 여러 단계로 된 논증의 중간 단계
- 반대 의견 / 제한 조건 / 예외(특히 AI가 흔히 통째로 지워 버리는 항목)

**원문이 너무 긴 경우**(예: 5,000자 이상 글을 3분 영상으로 만들 때)에는 억지로 압축하지 않습니다. 사용자에게 다음처럼 알립니다. “원문은 X자입니다. 정보 보존율 60%를 유지하려면 영상이 최소 ~Y분이어야 합니다. 영상을 늘리거나 여러 편으로 나눠야 합니다.” 내용을 30%로 줄이고 완성한 것처럼 처리하지 마세요.

## Bilibili 스타일의 여덟 가지 원칙(형식)

### 1. 구어체: 글말을 읽어도 어색하지 않은 말로 바꾸기

| 글말 | 말하기 편한 표현 |
|---|---|
| 종합하면 | 그러니까요 |
| 비범한 의미가 있다 | 이건 정말 중요해요 |
| … 측면에서 크게 향상되었다 | …에서 확실히 좋아졌어요 |
| 해당 도구는 …을 위해 설계되었다 | 이 도구는 …에 쓰는 거예요 |
| 필자는 생각한다 | 저는 이렇게 봐요 |
| 이로부터 알 수 있다 | 그렇죠 / 그래서 그런 거예요 |
| 이와 반대로 | 반대로요 |
| 관련 자료에 따르면 | 제가 찾아보니 |
| 자세한 내용은 참조 | 자세한 건 직접 확인해 보세요 |

판단 기준: **직접 읽었을 때 “왜 이렇게 딱딱하게 말하지?”라는 생각이 드나요?** 그렇다면 고칩니다.

### 2. 짧은 문장: 한 문장 20자 이하

긴 문장을 짧게 나눕니다. 복합문보다 쉼표로 끊는 편을 우선합니다.

| 원문 | 바꾼 문장 |
|---|---|
| “텍스트 렌더링이 크게 개선되었지만 일부 복잡한 상황에서는 여전히 오류가 발생한다.” | “텍스트 렌더링은 확실히 좋아졌어요. 그래도 복잡한 상황에서는 아직 문제가 생겨요.” |
| “비교 테스트 결과, 이 모델의 지시 이행 능력은 이전 세대보다 크게 우수했다.” | “비교 테스트를 해 봤어요. 지시를 따르는 능력은 이전 세대보다 훨씬 좋아졌어요.” |

말하는 사람은 숨이 차지 않아야 합니다. 화면을 보는 사람도 마찬가지입니다.

### 3. 2인칭: “사용자 / 독자”보다 “당신 / 우리”를 더 자주 쓰기

| 원문 | 바꾼 문장 |
|---|---|
| 사용자는 이 인터페이스로 …을 구현할 수 있다 | 이 인터페이스를 호출하기만 하면 돼요 |
| 독자는 …을 발견하게 된다 | 여러분도 알게 될 거예요 |
| 개발자는 주의해야 한다 | 작성할 때 조심하세요 |
| 이 글에서는 …을 소개한다 | 같이 살펴볼게요 |

화면 앞의 사람이 공지문을 듣는 게 아니라 **당신과 대화한다고 느끼게** 하세요.

### 4. 도입부에 후크 넣기(cold open)

첫 문장은 반드시 **사람의 관심을 붙잡아야** 합니다. 보편적인 후크 세 가지:

- **궁금증**: “이게 진짜일까요?” / “무슨 일이 있었는지 아세요?” / “버그인 줄 알았는데, 알고 보니…”
- **대비**: “예전엔 3시간 걸렸는데 지금은 30초면 돼요.” / “지난주엔 다들 칭찬했는데 오늘은 완전히 망가졌어요.”
- **이익**: “이 영상 하나 보면 플러그인 살 돈을 아낄 수 있어요.” / “이 방법만 알면 회의 때 지목될까 봐 걱정하지 않아도 돼요.”

**금지**(앞의 두 항목은 PPT 같고 뒤의 두 항목은 억지 공감으로 AI 말투가 납니다):

- ❌ “안녕하세요, 오늘은 …에 대해 이야기해 보겠습니다” 같은 자기소개로 시작
- ❌ “이번 영상에서는 …을 살펴보겠습니다” 같은 PPT 제목식 도입
- ❌ “시작하기 전에 먼저 배경을 알아보겠습니다”처럼 배경 설명을 길게 늘어놓기
- ❌ “요즘 X 때문에 고민이 많으시죠? / 이런 기분 느껴 보셨죠?” 같은 억지 공감 후크
- ❌ “지금부터 할 말이 여러분의 생각을 바꿀지도 모릅니다” 같은 자기 중요도 부풀리기

후크는 **3초 안에** 시청자에게 꽂혀야 합니다. 친근한지는 시청자가 듣고 판단할 일이지, 첫마디부터 친하다고 선언할 일이 아닙니다.

### 5. 리듬과 쉼: 완결된 생각 사이에 `---` 넣기

집중된 생각 하나를 말한 뒤 = 하나의 step 경계 = `---` 하나입니다. 한 줄에 생각 하나씩 적고 여러 생각을 쌓지 않습니다.

```markdown
그러니까 이건 정말 대단해요.

---

예를 하나 들어 볼게요. 며칠 전에 포스터를 하나 그려 달라고 했더니 3초 만에 나왔어요.

---

그런데 제일 놀라운 게 뭔지 아세요? 이미지 안의 중국어 글자도 정확했어요.
```

`---` 사이의 내용이 나중에 `outline.md`의 하나의 step이 됩니다.

### 6. 숫자를 체감되는 말로 바꾸기

구체적인 비율과 큰 숫자를 들으면 시청자는 **집중을 놓치기 쉽습니다.** 숫자 자체가 핵심이 아니라면(예: 충격을 주기 위한 “20배 상승”) 체감되는 표현으로 바꿉니다.

| 원문 | 바꾼 문장 |
|---|---|
| 정확도가 47% 향상되었다 | 거의 두 배 빨라졌어요 |
| 120개 국가 / 지역에서 이용 | 사실상 전 세계 어디서나 쓰여요 |
| 사용자 수가 1억 2천만 명을 돌파 | 이제는 누구나 아는 앱이 됐어요 |
| 추론 속도가 3.4배 향상 | 예전보다 훨씬 빨라서 기다릴 필요가 없어요 |

예외: **핵심적인 충격 숫자**는 남기고 강조합니다(“전후 차이가 100배”, “3초 대 3시간”).

### 7. 구조 표현과 만능 문구를 반복하지 않기

“첫째 / 둘째 / 마지막으로” 또는 “간단히 말해 / 본질적으로 / 근본 원리는” 같은 말을 반복하면 내레이션에서 기계적인 느낌이 확연해집니다.

**금지**(구조 표현):

- ❌ “첫째 / 둘째 / 마지막으로”
- ❌ “이제 세 가지를 살펴보겠습니다”
- ❌ “정리하면 이번 영상에서는 …을 다뤘습니다”
- ❌ “두 번째 부분으로 넘어가겠습니다”

**금지**(만능 문구 — AI가 자주 쓰는 표현, AI 말투 제거 4번 참고):

- ❌ “간단히 말해 …” / “본질적으로 …” / “근본 원리는 …”
- ❌ “한 문장으로 요약하면 …” / “결국 …” / “다시 말해 …”

**대신 이렇게 합니다**: 표현을 자연스러운 연결 문장에 녹이거나 **그냥 삭제합니다.**

- “첫째, 텍스트 렌더링은” → “먼저 텍스트 렌더링부터 볼게요”
- “두 번째로 살펴볼 것은” → “다른 하나도 볼게요”
- “정리하면” → “그러니까요”
- “간단히 말하면 X입니다” → “X입니다”
- “한 문장으로 요약하면 Y” → 바로 Y라고 말합니다.

시청자는 영상 outline이 몇 부분으로 되어 있는지 알 필요가 없습니다. **구조는 지시 문구가 아니라 내용의 리듬으로 느껴져야 합니다.**

### 8. 추상적인 말보다 구체적인 사례를 우선하기

**추상적인 설명**은 집중을 흐리고, **구체적인 설명**은 사람을 붙잡습니다.

| 추상적인 표현 | 구체적인 표현 |
|---|---|
| 강력한 기능을 제공한다 | 고양이 사진을 주고 사이버펑크 스타일로 바꿔 달라고 하면 3초 만에 나와요 |
| 성능이 우수하다 | 5년 된 제 컴퓨터에서도 돌아가요 |
| 사용자 경험이 좋다 | 엄마가 처음 써 봤는데 5분 만에 익혔어요 |
| 활용 분야가 넓다 | 포스터, PPT, 스티커, PR용 이미지 묶음까지 만들 수 있어요 |

**예를 들 때는 “나”의 경험에서 시작합니다.** “제가 테스트해 봤어요”, “제가 그림을 부탁했어요”, “제 컴퓨터에서는”이 “사용자는”, “일반적으로”보다 훨씬 친근합니다.

## AI 말투 제거: 꼭 걷어내야 할 다섯 가지 유형(문장 분위기)

형식만 갖췄다고 AI 말투가 사라지는 것은 아닙니다. 다음 다섯 유형은 AI 내레이션 대본에 가장 꾸준히 나타나는 “지문”입니다. **초안을 쓴 뒤 한 번 더 살펴보며 하나씩 없애세요.**

> 유일한 판단 기준: **실제 사람이 이 말을 입으로 할까요?** 아니라면 고칩니다.

### 1. 억지 공감: 말을 시작하자마자 “당신을 이해한다”고 연기하기

AI는 본론에 들어가기 전에 먼저 감정을 달래는 도입을 즐겨 씁니다. 하지만 내레이션에서 처음부터 친한 척하면 느끼하고 부자연스럽습니다. 시청자는 아직 당신을 모르는데 “당신을 이해해요”라고 하면 영업처럼 들립니다.

❌ 흔한 표현:

- “요즘 X 때문에 고민이 많으시죠?”
- “이런 기분 느껴 보신 적 있나요?”
- “오늘 영상은 계속 …하던 분들을 위한 것입니다.”
- “마음이 어떤지 이해해요.”
- “여러분의 감정은 존중받고 있습니다.”

✓ 고치는 법: 원칙 4처럼 사실이나 후크를 바로 던집니다. 친근한지는 시청자가 듣고 판단합니다. 원문에 공감 표현이 꼭 필요하다면 구체적이고 정보가 있는 방식으로 말합니다. “저도 그 함정에 빠져 봤어요”가 “당신의 기분을 알아요”보다 열 배는 진짜처럼 들립니다.

### 2. 억지로 심오한 척하기: “오히려 / 반대로 / 바로”로 평범한 의견을 포장하기

AI는 전환 표현을 이용해 깨달음처럼 보이게 만드는 데 능합니다. 하지만 그런 말을 빼도 의미가 똑같고, 오히려 더 분명한 경우가 많습니다.

❌ 흔한 표현:

- “모델이 커서 강하다고 생각하시죠? 정반대입니다……”
- “오히려 이게 진짜 무서운 부분입니다.”
- “바로 단순하기 때문에 …할 수 있습니다.”
- “정말 정확히 보셨어요.”
- “X 때문이 아니라 당신이 너무 Y하기 때문입니다.”

✓ 고치는 법: 전환 표현을 걷어내고 결론을 바로 말합니다. **자체 검토 방법**: “오히려 / 반대로 / 바로”가 들어간 문장을 빼도 뜻이 달라지나요? 달라지지 않으면 지웁니다. 빼고 나니 의견이 평범하게 들린다면 **원래 평범한 의견**이었던 것입니다. 수사로 덮지 말고 내용을 보충하세요.

### 3. 자기 과시: 본론 전에 자기 말에 무게를 더하기

AI는 핵심을 말하기 전에 말을 고르며 시청자에게 “이제 대단히 중요한 말을 하겠다”고 느끼게 하는 것을 좋아합니다. **내레이션에서는 더 거슬립니다.** 시청자의 시간을 붙잡아 두려는 모습이기 때문입니다.

❌ 흔한 표현:

- “정말 진지하게 한마디 해야겠어요.”
- “이 이야기는 자세히 설명해야겠습니다.”
- “지금부터 할 말이 여러분의 생각을 바꿀지도 모릅니다.”
- “이 부분은 꼭 끝까지 들어 주세요.”
- “마음을 조금 가라앉혀 줄 말씀을 드릴게요.”
- “피하지도, 숨기지도, 돌려 말하지도 않고 오늘 X를 확실하게 짚겠습니다.”

✓ 고치는 법: **바로 말합니다.** 좋은 의견에는 예열이 필요 없습니다. 시청자가 넘길까 걱정된다면 “중요하다”고 강조하지 말고 짧은 문장과 후크로 리듬을 잡으세요.

### 4. 만능 템플릿: 듣자마자 AI가 썼다고 알 수 있는 말버릇

AI 대본의 지문입니다. 너무 자주 나와서 시청자는 눈을 감고도 다음 말을 맞힐 수 있습니다.

| 위치 | ❌ AI 템플릿 | ✓ 내레이션 표현 |
|---|---|---|
| 도입 | “간단히 말하면 …” / “본질적으로 …” / “근본 원리는 …” | 곧장 “X예요”라고 말합니다. |
| 전환 | “한 문장으로 요약하면 …” / “다시 말해 …” / “결국 …” | 예고하지 말고 그 문장을 바로 말합니다. |
| 포장 | “어떤 의미에서는” / “어느 정도는” | 의미가 없다면 삭제합니다. |
| 마무리 | “이상으로 이번 영상 내용을 마치겠습니다” / “도움이 되었길 바랍니다” / “시청해 주셔서 감사합니다” | “링크는 댓글 상단에 고정해 둘게요” / “다음 영상에서 봐요”처럼 구체적인 CTA를 씁니다. |
| 참여 유도 | “X도 계속 이야기해 볼까요?” / “댓글로 알려 주세요” | “GitHub에서 X를 검색해 보세요” / “어떤 문제를 겪었는지 댓글로 나눠 주세요”처럼 구체적으로 요청합니다. |

> **주의**: 이 유형은 원칙 7의 “구조 표현을 반복하지 않기”와 겹칩니다. 원칙 7은 형식 차원의 경고이고, 여기서는 문장 분위기 차원에서 경고합니다. **두 기준을 모두 통과해야 합니다.**

### 5. 병렬 표현을 쌓기: 구조가 똑같은 문장을 연속해서 세 번 쓰기

AI는 중국어를 쓸 때 지나치게 반듯한 대구를 좋아합니다. **글보다 말에서 병렬 표현이 더 거슬립니다.** 구조가 같은 짧은 문장 세 개를 들으면 시청자는 집중을 끊습니다.

**판단 기준**: 구조가 같은 짧은 문장이 3개 이상 이어지고, 몇 문장을 빼도 뜻이 바뀌지 않습니다.

❌ 예시:

- “피하지도, 숨기지도, 돌리지도, 도망가지도 않겠습니다.”
- “그림도 그리고, 글도 쓰고, 포스터도 만들고, PPT도 만들어요.”
- “당신의 아픔을 이해하고, 당신의 피로를 알고, 당신의 노력을 기억합니다.”
- “효율적이고, 정확하고, 강력합니다.”

✓ 고치는 법: 정보가 가장 많은 표현 한두 개만 남기고 나머지는 지우거나, 구체적인 사례 하나로 바꿉니다.

- “그림도 그리고, 글도 쓰고, 포스터도 만들고, PPT도 만들어요.” → “그림도 그려요. 어제 만든 고양이 사이버펑크 버전도 바로 이 도구가 만든 거예요.”

> 실제 사람은 모든 단락을 대구처럼 반듯하게 만들려고 하지 않습니다. 다소 거칠어도 괜찮습니다. 연결 문장은 자연스럽게 넘어가는 역할만 하면 됩니다.

## **피해야 할** 세부 표현

- ❌ **emoji**: 사용자가 명시적으로 요청하지 않는 한 내레이션 대본에 넣지 않습니다. emoji는 글로 된 댓글이지 말이 아닙니다.
- ❌ **괄호 보충**: “이 모델(transformer 기반 구조의 한 종류)은 대단합니다”처럼 괄호 안의 내용은 소리 내어 말하기 어렵습니다. 본문에 넣거나 삭제합니다.
- ❌ **책 제목 괄호 / 따옴표를 붙인 나열**: “『XX 보고서』에 따르면 XX” 대신 “보고서 하나를 봤는데 이렇게 되어 있더라고요”라고 말합니다.
- ❌ **“하하하” 등 말버릇을 남발**: 가끔 한 번은 효과가 있지만 단락마다 넣으면 경련처럼 보입니다.
- ❌ **유행어 과다 사용**: 유행어는 반년이면 수명이 끝납니다. 반년 뒤 보면 민망해집니다. 주제가 그 유행어 자체인 경우가 아니라면 피합니다.

## 주제별 말투 미세 조정

주제마다 기본 말투를 다르게 잡습니다.

- **기술 / 튜토리얼**: 약간 딱딱해도 되지만 구어체를 유지합니다. “가정해 봅시다”보다 “같이 해볼게요”를 더 자주 씁니다.
- **리뷰 / 비교**: 분명하게 말합니다. “이건 별로예요”, “저건 과장됐어요.” 중립적인 리뷰는 지루합니다. 단, **분명하게 말하기와 자기 과시는 다릅니다.** “일주일 써 봤는데 별로였어요”는 분명한 표현이고 “정말 진지하게 말하는데 별로예요”는 자기 과시입니다.
- **뉴스 / 정보**: 리듬을 빠르게 하고 핵심 문장을 분명하게 씁니다. 첫 문장에 가장 강한 사실을 둡니다.
- **제품 / 마케팅**: 과장하지 않습니다. “완벽하다”, “판을 뒤집는다” 대신 “일주일 써 봤는데 확실히 편하더라고요”라고 말합니다.
- **문화 / 역사 / 과학 교양**: 속도를 늦추고 “상상해 보세요”로 시작할 수 있습니다.

## 대본을 고쳐 쓴 뒤 할 일

### 1. 파일로 저장하고 박자 나누기

결과를 `script.md`에 저장하고 원문은 `article.md`에 보관합니다. 한 단락이 5문장 이상인데 `---`로 나누지 않았다면 나눕니다. `---`는 이후 step 경계가 되므로 적게 나누는 것보다 많이 나누는 편이 낫습니다(합치는 것이 쪼개는 것보다 쉽습니다).

> ⚠️ **자체 검토는 필수 절차입니다.** `script.md`를 쓴 뒤 아래의 세 단계(형식 / 문장 분위기 / 소리 내어 읽기)를 모두 진행하고, 수정한 뒤에만 다음 단계로 넘어갑니다. 검토 없이 바로 outline을 만들지 마세요.
>
> **역량에 따라 다음 순서로 진행**:
>
> 1. **Agent Teams 우선**: 별도 reviewer agent를 열고 `script.md`와 이 절의 세 단계 점검표를 전달합니다. 항목마다 확인하고 실패 항목, 근거, 수정 제안을 보고하게 합니다.
> 2. **다음은 subAgent**: Teams를 쓸 수 없지만 subagent를 열 수 있으면 같은 절차를 진행합니다.
> 3. **둘 다 쓸 수 없음**: 직접 항목별로 엄격히 확인합니다. 특히 실제로 소리 내어 읽습니다.
>
> 검토 결과의 실패 항목을 먼저 고치고 outline을 만듭니다.

### 2. 형식 점검(여덟 가지 원칙)

- [ ] **정보 보존율이 60% 이상**(**최우선**, 미달이면 전체 대본을 다시 씀). `wc -m script.md` / `wc -m article.md`로 비율을 계산하고 핵심 숫자 / 사례 / 논증 흐름이 원문과 맞는지 항목별로 확인합니다. 한 단락 전체가 빠지면 안 됩니다.
- [ ] emoji / 원문의 책 제목 괄호 《》 / 괄호 보충 / “XX 보고서에 따르면” 같은 인용 형식이 없음(내레이션으로 읽기 어렵기 때문)
- [ ] Bilibili 기준 한 문장이 20자 이하인가?
- [ ] 2인칭을 사용했는가?
- [ ] 첫 3초 안에 후크가 있는가?
- [ ] 숫자를 체감되는 말로 바꿨는가?(**핵심 충격 숫자는 원래 값으로 유지해야 함**)
- [ ] “첫째 / 둘째 / 마지막으로” 같은 구조 표현이 없는가?
- [ ] 추상적인 설명보다 구체적인 사례를 썼는가?

### 3. 문장 분위기 점검(AI 말투 제거 다섯 유형) — **가장 중요**

한 번 훑으면서 확인합니다. 하나라도 통과하지 못하면 다시 고칩니다.

- [ ] 전체에 “간단히 말해 / 본질적으로 / 근본 원리 / 오히려 / 반대로 / 바로 …이기 때문에 / 결국 / 어느 정도” 같은 **AI가 자주 쓰는 표현**이 남아 있는가?
- [ ] 첫 문장이 후크인가? **“당신을 이해한다”는 억지 공감**으로 시작하지 않는가?
- [ ] “진지하게 말하자면 / 자세히 말해야겠어요 / 생각을 바꿀 수도 있어요 / 꼭 끝까지 들으세요” 같은 **자기 중요도 부풀리기**가 있는가?
- [ ] 같은 구조의 문장이 3개 이상 이어지는 **병렬 나열**이 있는가? 세 번째 문장을 읽을 때 스스로 지루하지 않은가?
- [ ] 끝맺음이 구체적인 CTA인가? **“도움이 되었으면 합니다 / 이상입니다 / 시청해 주셔서 감사합니다” 같은 상투어**는 아닌가?
- [ ] “오히려 / 반대로 / 바로”로 포장한 문장이 있는가? **이 말을 빼면 뜻이 바뀌는가?** 바뀌지 않으면 삭제합니다.

### 4. 소리 내어 읽기(최종 기준)

단락 세 개를 아무거나 골라 읽습니다. 마음속으로 읽지 말고 **실제로 입을 열어 읽습니다.**

- “이 말은 못 하겠다”고 느낀 문장이 있으면 그 문장이 AI 말투입니다.
- 건너뛰고 싶은 문장이 있으면 그 단락에 병렬 나열이나 자기 과시가 있습니다.
- 내용이 웃겨서가 아니라 느끼해서 웃음이 나는 문장이 있으면 억지 공감입니다.

고친 뒤 다시 읽습니다. 세 단락을 자연스럽게 읽을 수 있을 때까지 반복합니다.

### 5. 같은 작업에서 outline 만들기

`script.md`를 저장하고 검토를 마친 뒤 **사용자를 기다리며 바로 멈추지 말고** [`OUTLINE-FORMAT.md`](OUTLINE-FORMAT.md)에 따라 같은 흐름 안에서 `outline.md`도 만듭니다(챕터 구분 + step별 화면 내용 + 챕터 단위 정보 풀). 그런 다음 Checkpoint Plan으로 넘어가 원고 / outline / 테마 / 소재 / 개발 모드 다섯 가지를 사용자가 한 번에 확인하게 합니다.

> **흐름 변경 안내**: 예전 흐름은 script와 outline을 두 checkpoint로 나눴지만 새 버전은 하나로 합쳤습니다(SKILL.md의 “Phase 1.2 한 번에 만들기” 참고). outline에서 애니메이션을 다루지 않으므로 이제 필요한 것은 원고의 박자 구분과 article의 정보 풀 추출뿐입니다. 두 작업을 원고와 함께 끝낼 수 있습니다.

---

> **핵심**: AI 말투를 없애는 것은 품질을 낮추는 일이 아닙니다. “AI가 낭독하는 말”을 “사람이 대화하는 말”로 바꾸면서 정보는 하나도 빼지 않고 말투를 전부 바꾸는 것입니다. 바꾼 뒤 내용이 어리석게 느껴진다면 **원래 내용이 어리석었던 것**입니다. AI 말투 제거 탓이 아니라 내용을 보충해야 합니다.
