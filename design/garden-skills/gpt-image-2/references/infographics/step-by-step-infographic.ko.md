# 단계 / 절차 인포그래픽 템플릿

이 문서는 "단계 / 절차 / how-to / 튜토리얼" 스타일의 인포그래픽을 만들 때 사용합니다.

- 레시피 / 베이킹 단계 이미지
- 사용 방법 / 앱 사용 절차
- 운동 동작 분해 설명
- 메이크업 / 스킨케어 순서
- 여행 / 비용 정산 / 신청 절차
- 육아 / DIY 작업 단계

특징:

- 각 단계에 분명한 번호가 붙습니다.
- 각 단계에 간단한 일러스트 / 아이콘을 배치합니다.
- 단계 사이를 안내 화살표 / 연결선으로 잇습니다.
- 보통 3~7단계이며 최대 9단계입니다.
- 일러스트 느낌이 있고 따뜻하며 이해하기 쉬운 스타일입니다(**공학적으로 정밀한 순서도와 분명히 다릅니다**).

## 적용 범위

- 레시피 / 작업 / 튜토리얼 안내
- "X단계로 배우기..." 형태의 콘텐츠
- DIY / 수공예 / 개조 과정
- 육아 / 운동 / 뷰티 단계 안내
- 사용자 안내 / 입문 가이드

## 사용 시점

- 사용자가 "단계 / 절차 / how-to / 튜토리얼 / X단계 / 사용 안내 / 레시피 / 메이크업 순서"를 언급할 때
- 독자가 "한 단계씩 따라 하길" 원할 때
- 일러스트 느낌에 따뜻하고 이해하기 쉬운 시각물을 원할 때(공학적인 느낌은 아님)

다음에는 사용하지 마세요.

- 공학적으로 정밀한 순서도(마름모 결정 노드, Yes/No 분기)를 원하는 경우 → `technical-diagrams/flowchart-decision.md` 사용
- 만화 콘티를 원하는 경우 → `storyboards-and-sequences/recipe-process-flowchart.md` 사용
- 방법 파이프라인 논문 그림을 원하는 경우 → `academic-figures/method-pipeline-overview.md` 사용
- 벤토 그리드 고밀도 정보를 원하는 경우 → `infographics/bento-grid-infographic.md` 사용

## 누락 정보 확인 우선순위

1. 주제 + 단계 수(예: "파스타 만들기 3단계 / 개발 환경 설정 5단계 / 매일 스킨케어 7단계")
2. 각 단계의 구체적인 내용(제목 + 설명 한두 문장)
3. 색상 방향(따뜻한 음식 / 산뜻한 스킨케어 / 카툰 튜토리얼 / 칠판 수업)
4. 배치 방식(세로형 / 가로형 / 구불구불한 경로 / 원형 순환)
5. 표지 / 완성 이미지가 필요한지 여부(시작에 "완성 이미지" 한 장 또는 끝에 "완성 결과" 한 장)
6. 비율(샤오홍슈 3:4 / 공식 계정 16:9 / 1:1)

### 매개변수 전략

- **반드시 질문**: `step_count`, 각 단계의 제목(즉 `items_example`의 실제 내용)
- **기본값 지정 가능**: `background`, `palette`(주제에 따라 선택 — 음식은 따뜻한 주황색, 스킨케어는 마카롱, 기술 튜토리얼은 민트), `layout_style`(기본값 vertical-zigzag), `connector_style`
- **무작위 지정 가능**: 단계별 일러스트 모양, 연결선을 화살표 또는 점선으로 할지, 장식(재료 튀는 모양 / 별점 / 작은 라벨)

### 자동 완성 전략

- 사용자가 주제만 제시하면(예: "파스타 만들기 5단계") 구체적인 단계 5개를 자동으로 채우고 따뜻한 음식 색상 팔레트와 완성 이미지 미니어처를 추가합니다.
- 사용자가 "샤오홍슈 스타일"을 원하면 손그림 장식 + 마카롱 색상을 추가합니다.
- 사용자가 "메이크업 / 스킨케어"를 원하면 팔레트를 더스티 핑크 + 크림색으로 바꿉니다.
- 사용자가 "운동"을 원하면 팔레트를 민트 + 코랄로 바꾸고 사람의 동작 일러스트를 사용합니다.
- 사용자가 "DIY / 수공예"를 원하면 도구 이모지 / 재료 목록을 추가합니다.
- 사용자가 "기술 튜토리얼"을 원하면 팔레트를 민트 + 슬레이트로 바꾸고 스크린샷 프레임 일러스트를 사용합니다.

## 피해야 할 사항

- 단계가 9개보다 많거나 3개보다 적음
- 단계별 일러스트 스타일 혼합(한 단계는 손그림, 다음은 평면)
- 단계마다 번호 배지 디자인이 달라짐
- 시각적 연결이 없어 단계가 흩어진 카드처럼 보임
- 공학 도면의 마름모 결정 노드 / 직각 화살표 사용 → 일러스트의 따뜻함이 사라짐
- Helvetica / Arial처럼 차가운 글꼴 사용
- 단계 설명이 3줄을 넘어 긴 글이 되어 인포그래픽 특성을 잃음
- 이 템플릿으로 "순서도"를 만들지 않습니다(순서도는 `technical-diagrams/flowchart-decision.md` 사용).
