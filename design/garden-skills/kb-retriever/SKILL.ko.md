# 로컬 지식베이스 검색 Skill (kb-retriever)

## 지식베이스 디렉터리 설명

- 지식베이스는 하나의 루트 디렉터리 아래에 있으며, 여러 종류의 파일(예: `.md`/`.txt`, `.pdf`, `.xlsx` 등)을 포함합니다. 보통 파일 유형이나 업무 용도에 따라 여러 단계의 하위 디렉터리로 나뉘어 있습니다.
- **계층형 디렉터리 색인 파일**을 사용합니다:
  - 루트 디렉터리에는 `data_structure.md`가 있으며, 주요 「도메인 디렉터리」와 그 용도를 설명합니다.
  - 각 도메인 디렉터리 아래에도 자체 `data_structure.md`가 있을 수 있으며, 그 안에 어떤 하위 디렉터리/파일이 있고 각각 무엇에 쓰이는지 설명합니다.
  - 더 깊은 하위 디렉터리에도 계속 `data_structure.md`가 있을 수 있어, 다단계 색인 트리를 이룹니다.
- 지식베이스 루트 디렉터리 규칙:
  - 기본적으로 지식베이스는 현재 프로젝트 루트의 `knowledge/` 디렉터리에 있다고 가정합니다.
  - 사용자가 대화에서 다른 경로를 명시하면(예: 「제 지식베이스는 /data/kb에 있습니다」 또는 「./docs 디렉터리를 지식베이스로 사용하세요」), 사용자가 지정한 경로를 루트로 사용합니다.
  - 기본 경로 `knowledge/`가 없거나 접근에 실패하면, 임의로 추측하지 말고 실제 지식베이스 루트 위치를 사용자에게 확인합니다.
- 단일 업무 파일은 클 수 있습니다:
  - 파일 전체를 Read로 직접 읽지 마십시오.
  - PDF와 Excel은 해당 Skill로 구조화 처리한 뒤, grep/부분 읽기로 세밀하게 검색하십시오.

### `knowledge` 루트 디렉터리 찾기

- 루트 디렉터리는 사용자의 지정을 우선합니다: 사용자가 경로(예: `./docs`, `./knowledge-personal`)를 주면 그 경로를 그대로 사용합니다.
- 기본 루트 디렉터리: 그렇지 않으면 현재 프로젝트의 `knowledge/`를 루트로 간주합니다.
  - 셸에서 디렉터리 존재 여부를 명시적으로 확인하십시오. 우선 `test -d knowledge`를 사용하고, 여의치 않으면 `ls -d knowledge`를 사용합니다.
  - 주의: `Glob "knowledge" in .` 같은 패턴으로 디렉터리 존재 여부를 판단하지 마십시오. `Glob`은 파일 경로만 반환하고 디렉터리 자체는 반환하지 않으므로, 빈 결과로는 「디렉터리가 없음」과 「디렉터리는 있으나 비어 있음」을 구분할 수 없습니다.
- 루트 디렉터리가 `test -d` 등으로 존재가 확인된 후에만 Glob으로 그 디렉터리 안의 내용을 검색하며, 디렉터리를 `path`로 지정합니다. 예:
  - 색인 파일: `pattern="**/data_structure.md"`, `path="knowledge"`
  - 모든 Markdown: `pattern="**/*.md"`, `path="knowledge"`
- 기본 `knowledge/`가 없으면(`test -d` 실패): 다른 디렉터리를 추측하지 말고, 기본 루트 디렉터리를 찾지 못했다고 명확히 알린 뒤 사용자에게 실제 지식베이스 경로를 지정해 달라고 요청합니다.

## 핵심 원칙: 먼저 학습하고, 그다음 처리한다

**PDF 또는 Excel 파일을 만났을 때의 필수 체크리스트**:

- [ ] ✅ 해당 references 문서를 읽어 처리 방법을 익혔다
- [ ] ✅ 추천 도구와 명령을 이해했다
- [ ] ✅ 파일 처리(추출/변환)를 완료했다
- [ ] ⏭️ 이제 검색을 시작할 수 있다

**금지 행동**:
- ❌ pdf_reading.md를 읽지 않고 PDF 처리를 바로 시도하기
- ❌ excel_reading.md를 읽지 않고 Excel 처리를 바로 시도하기
- ❌ 처리 단계를 건너뛰고 원본 PDF/Excel을 바로 검색하기

## 전체 흐름

1. 사용자 요구 이해하기
   - 사용자 질문을 읽고 다음을 추출합니다:
     - 주제/분야 키워드(예: 「판매 보고서」「시스템 아키텍처」「인터페이스 문서」)
     - 기간 또는 범위 제한(예: 「2023년 1분기」「최신 버전」)
     - 필요한 출력 유형(설명, 요약, 구체적인 필드 값 등)
   - 지식베이스 루트 디렉터리를 정합니다:
     - 먼저 사용자가 질문에서 지식베이스 경로를 지정했는지 확인합니다.
     - 그렇지 않으면 기본 루트 디렉터리 `knowledge/`를 사용합니다.
     - 기본 루트 디렉터리가 없거나 구조가 비정상이면, 스스로 가정하지 말고 사용자에게 확인합니다.

2. 계층형 디렉터리 색인 `data_structure.md` 살펴보기
   - 「현재 작업 디렉터리」 개념을 사용합니다:
     - 기본적으로 사용자가 지정한 지식베이스 루트에서 시작하며, 사용자가 지정하지 않았다면 현재 디렉터리를 사용합니다.
   - 현재 작업 디렉터리에 `data_structure.md`가 있으면:
     - Read로 파일 앞부분 몇 줄을 읽습니다(예: limit=300). 필요하면 여러 번 나누어 계속 읽습니다.
     - 목표:
       - 현재 디렉터리에 어떤 하위 디렉터리와 파일이 있는지 파악
       - 각 하위 디렉터리/파일의 용도 설명 이해
     - 사용자 질문을 바탕으로 **가장 관련 있는 몇 개의 하위 디렉터리 또는 파일**을 골라 후보 집합을 만듭니다.
   - 후보 하위 디렉터리에 대해:
     - 그 하위 디렉터리로 재귀적으로 들어가 새로운 「현재 작업 디렉터리」로 삼고, 그 안의 `data_structure.md`를 찾아 위 과정을 반복합니다.
     - 재귀 과정에서는 모든 분기를 한꺼번에 깊이 파고들지 말고, 질문과 가장 관련 있는 경로를 우선해서 아래로 내려갑니다.
   - 후보 업무 파일(md/텍스트, PDF, Excel 등)에 대해:
     - 필요한 디렉터리 계층 탐색을 마친 뒤, 이 파일들을 최종 **검색 대상 목록**으로 모읍니다.
   - 우선순위를 정할 때:
     - 용도 설명이 질문 주제와 매우 잘 맞는 도메인 디렉터리와 파일을 우선합니다.
     - 그다음으로 색인에 드러나 있다면 기간/버전 같은 제약을 고려합니다.
     - README.md, 전체 설계 문서처럼 일반적인 설명 문서는 뒤쪽 우선순위에 둡니다.

3. 파일 처리 방법 학습하기(PDF/Excel을 만나면 반드시 실행)
   - **PDF 파일을 처리하기 전에**:
     - **반드시 먼저 읽어야 합니다**: [references/pdf_reading.md](references/pdf_reading.md) (이 디렉터리는 지식 디렉터리가 아니라 Skills 디렉터리 아래에 있습니다). 처리 방법을 학습하십시오.
     - 중점 파악: pdftotext 명령, pdfplumber 사용법, 표 추출 방법
   - **Excel 파일을 처리하기 전에**:
     - **반드시 먼저 읽어야 합니다**: [references/excel_reading.md](references/excel_reading.md) (읽기 방법 학습)
     - **반드시 먼저 읽어야 합니다**: [references/excel_analysis.md](references/excel_analysis.md) (분석 방법 학습)
     - 중점 파악: pandas 읽기, 열 선택, 데이터 필터링
   - **목적**: 올바른 도구와 방법을 쓰도록 보장하여, 무작정 검색하는 것을 피합니다.

4. 파일 유형별 처리 및 검색 실행
   - 학습한 방법으로 파일을 처리합니다(추출, 변환, 구조화).
   - 각 후보 파일 유형에 대해 아래의 「Markdown/텍스트」「PDF」「Excel」 전략에 따라 실행합니다.
   - 전체 원칙:
     - 가장 관련 있고 정확한 파일부터 시작합니다.
     - 각 파일 안에서도 점진적으로 부분 검색하며, 전체 내용을 한꺼번에 불러오지 않습니다.
     - 현재 파일에서 만족스러운 정보를 얻지 못하면 다음 후보 파일로 넘어갑니다.

5. 반복 검색
   - 모든 파일 유형은 공통된 「다단계 반복 검색 메커니즘」(위의 공통 검색 원칙 참고)을 사용합니다.

6. 답변 구성 및 출처 표기
   - 여러 번의 검색으로 얻은 맥락을 종합해 사용자 질문에 답합니다.
   - 가능한 한:
     - 명확하고 직접적인 답을 제시합니다.
     - 사용한 파일 이름을 밝힙니다(필요하면 대략적인 위치도 함께, 예: 장/절 또는 대략적인 행/페이지 번호).
   - 답이 추론에 기반하거나 정보가 불완전한 경우:
     - 가정과 불확실성을 명확히 표시합니다.
     - 더 구체적인 파일 범위나 키워드를 제공해 달라고 사용자에게 안내합니다.

## 공통 검색 원칙

### 키워드 선택 전략
- 사용자 질문에서 3–8개의 키워드를 추출합니다(가능한 영문 약어, 동의어, 상위/하위 개념 포함).
- 단어 조합도 가능합니다(예: "판매 보고서", "API 인터페이스 타임아웃").
- 필요하면 업무 용어, 기술 용어, 흔한 약어를 포함합니다(예: "uv", "pv", "GMV").

### grep 검색 기본 원칙
- 항상 가능한 한 정확한 include와 path를 지정하여 디렉터리 전체 검색을 피합니다.
- pattern은 질문의 핵심 명사와 용어를 우선 시도하고, 그다음 동의어를 시도합니다.
- 각 일치 항목에 대해서는 일치 부분 근처의 국소 영역(위아래 몇 줄)만 읽습니다.
- 「파일 이름 + 위치 정보 + 텍스트 조각」을 저장합니다.

### 다단계 반복 검색 메커니즘(최대 5회)
모든 파일 유형은 다음과 같은 통일된 반복 전략을 사용합니다:
1. **반복 제어**
   - 「검색 시도 횟수」를 세며, 최대 5회입니다.
   - 검색할 때마다 횟수를 1씩 누적합니다.
2. **반복 한 회차의 절차**
   1. 질문을 바탕으로 검색 키워드를 생성하거나 갱신합니다(동의어, 확장어 포함 가능).
   2. 아직 충분히 검색하지 않은 파일이나 파일 일부를 선택합니다.
   3. 검색을 실행합니다(grep/국소 읽기/전용 Skill 호출).
   4. 얻은 문맥 조각을 분석합니다.
   5. 질문에 답하기에 충분한지 판단합니다.
3. **종료 조건**
   - 질문에 답하기에 충분한 근거 문맥을 찾았거나; 또는
   - 5회 시도에 도달했지만 적절한 정보를 찾지 못한 경우
4. **정보가 부족할 때의 처리**
   - 정보가 없거나 현재 지식베이스에 없을 수 있다고 사용자에게 명확히 알립니다.
   - 찾은 가장 가까운 정보를 제공하고, 불확실성을 설명합니다.
   - 범위를 좁히는 방법을 안내합니다(더 구체적인 파일 이름, 키워드, 기간 범위 등).

### 주의 사항

- 처음부터 `Glob "knowledge" in .` 또는 Glob으로 디렉터리 존재 여부를 판단하려는 호출을 하지 마십시오. 디렉터리 존재 여부는 `test -d` 같은 셸 명령으로 확인해야 합니다.
- 이 Skill로 지식베이스를 조회할 때는 웹 검색 등 다른 도구로 지식을 얻지 마십시오.

## 파일 유형별 구체 전략

### 1. Markdown / 텍스트 파일(.md, .txt, .log 등)

1. **후보 파일 선택**
   - `data_structure.md`와 파일 이름, 경로를 바탕으로 관련도를 판단합니다.
   - 제목과 목차 성격의 파일(요약 문서, 설계 개요 등)을 우선 검색합니다.

2. **grep으로 위치 찾기 및 국소 읽기**
   - Grep 도구로 지정한 후보 파일을 검색하며, include는 구체적인 확장자로 제한합니다(예: "*.md").
   - 일치하는 파일에 대해서는 Read로 일치 부분 근처의 국소 영역만 읽습니다:
     - 줄 번호 오프셋과 limit을 사용해 제어합니다(예: 일치 줄의 앞뒤로 수십 줄씩 읽기).
     - 파일 전체를 읽는 것을 피합니다.

3. **특수 처리**
   - 내용이 목차나 제목뿐이라면, 링크나 절 이름을 따라 더 깊은 내용을 찾아갑니다.
   - 「다단계 반복 검색 메커니즘」(위의 공통 검색 원칙 참고)을 적용합니다.

### 2. PDF 파일 검색 전략

**작업 흐름**:

1. **먼저: 처리 방법 가이드 읽기**
   - 어떤 PDF든 처리하기 전에 **반드시 먼저 읽어야 합니다**: [references/pdf_reading.md](references/pdf_reading.md) (이 디렉터리는 Knowledge 디렉터리가 아니라 Skills 디렉터리 아래에 있습니다)
   - 중점 파악: pdftotext 명령, pdfplumber 사용법, 표 추출 방법, 빠른 결정표

2. **후보 PDF 선택**
   - `data_structure.md`의 설명을 바탕으로 가장 관련 있는 1–3개 파일을 고릅니다.
   - 사용자가 구체적인 PDF 파일을 지정했다면 그 파일을 우선 사용합니다.

3. **학습한 방법으로 텍스트 추출**
   - pdf_reading.md에서 추천한 도구를 사용합니다(우선 pdftotext 또는 pdfplumber).
   - **중요**: `pdftotext input.pdf output.txt`로 텍스트를 파일에 추출하십시오. 표준 출력(stdout)으로 직접 내보내지 마십시오(토큰을 많이 차지합니다).
   - 표가 필요하면 pdfplumber의 표 추출 기능을 사용합니다.

4. **추출 결과에 대해 검색 실행**
   - 추출된 텍스트에 grep으로 키워드 검색을 합니다.
   - 각 일치 항목에 대해 일치 부분 근처의 문맥(위아래 수십 줄 또는 인접한 몇 페이지)을 추출합니다.
   - 「파일 이름 + 페이지 번호/대략적인 위치 + 텍스트 조각」을 저장합니다.
   - 「다단계 반복 검색 메커니즘」(위의 공통 검색 원칙 참고)을 적용합니다.

- **Grep**: 키워드로 지정한 파일에서 행 번호와 일치 조각을 찾는 데 사용합니다. 항상 가능한 한 정확한 include와 path를 지정하십시오.
- **Read**: 파일의 국소 부분만 읽는 데 사용합니다. 항상 적절한 limit(예: 200–500행)과 적당한 오프셋을 설정하십시오.

  - 처음부터 끝까지 읽는 것을 금지합니다.

## 답변 스타일과 오류 처리

- 답변 스타일
  - 가능한 한 사용자가 질문한 언어(중국어/영어 등)로 답합니다.
  - 결론을 먼저 제시한 뒤 간단한 근거를 덧붙입니다.
  - 필요하면 뒤에 인용한 파일과 대략적인 위치를 나열합니다. 예:
    - 출처: design/api_gateway.md 100행 근처
    - 출처: reports/2023_Q1_sales.xlsx Summary 워크시트
- 정보가 없거나 불확실할 때
  - 현재 지식베이스에서 완전히 일치하는 정보를 찾지 못했거나 부분적으로만 답할 수 있다고 명확히 말합니다.
  - 사실을 지어내지 않습니다.
  - 사용자가 범위를 좁힐 수 있는 방법을 안내합니다:
    - 더 구체적인 디렉터리/파일 지정
    - 더 정확한 키워드나 필드 이름 제공
    - 시간/버전 범위 지정
