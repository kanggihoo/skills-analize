# 장편 영화: 장, 구성 및 검토

2분 이상 최대 20분까지의 동영상에 사용할 수 있습니다. 단편 영화는 여전히 원본 단일 페이지와 `build.sh`를 사용하므로 새로운 기능을 위해 프로젝트 복잡성을 늘릴 필요가 없습니다.

## 먼저 콘텐츠를 기획한 후, 여러 장으로 나누어 보세요

수요를 확인할 때 총 기간과 부동 허용 여부를 명확히 하십시오. 실제 구두 방송 시간이 목표와 일치하지 않는 경우 먼저 확인하시기 바랍니다. 1200초를 초과하면 자동으로 끊어지지 않습니다. TTS는 사용자 원본을 사용해야 합니다. 말이 없어도 비트 구동이 가능하며 기존 스타일과 합성 엔진은 모두 유지됩니다.

간략한 장 제목, 길이, 응집력, 요소를 통해 적어보세요. 장편 영화는 여러 초점을 가질 수 있으며 20분 동안 지속되는 단편 영화의 밀도가 빠르게 변할 필요는 없습니다. 글꼴, 색상 및 그래픽 의미는 일관되게 유지되며 변경 사항은 스토리를 전달하는 데 도움이 됩니다. 스타일 프레임은 주요 프로세스를 따릅니다. 즉, 결정된 스타일을 위한 세 개의 프레임과 결정되지 않은 스타일을 위한 세 개의 방향입니다. 확인 후 각 챕터별 대표 프레임에 대한 셀프 테스트를 추가할 수 있으며, 추가 추가하지 않을 경우에는 반드시 정지 후 확인을 하셔야 합니다.

콘텐츠 경계에 따라 장을 나누십시오. 일반적으로 건물 단위당 30~90초입니다. 이는 내러티브 규칙이 아닌 렌더링 및 오디오 메모리를 제어하기 위한 제안입니다. 각 장은 `render(0)`부터 시작하여 독립적인 프로젝트 디렉토리와 로컬 타임라인을 사용합니다. 총 영화 시간 = 이전 챕터의 지속 시간 + 챕터 내 시간의 합입니다. 캐시에서 외부 변경 사항이 누락되는 것을 방지하려면 공유 디자인 토큰, 재료 및 빌드 종속성을 각 장의 `inputs`에 나열해야 합니다.

건물 단위는 시각적 단락과 동일하지 않습니다. 이 장의 `render(0)`는 피사체, 위치 및 움직임을 재설정하는 것을 의미하지 않습니다. 슬라이스에서 동일한 작업을 수행할 때는 일반적인 전체 영화 시간/궤적 또는 명시적인 연결 자세를 사용하세요. 내러티브 단락 전환을 통해 의도적인 하드 컷이 가능하며, 기술적인 슬라이싱으로 인해 무작위 일시 중지 및 공간 점프가 발생하지 않습니다. 음성 세그먼트에는 문장별 잘라내기가 필요하지 않습니다.

## 재구성 가능한 챕터 목록

프로젝트 루트에 `chapters.json`를 작성하고 모든 경로는 이 파일을 기준으로 합니다. 지속 시간은 초 단위로 측정되며 챕터는 배열 순서대로 연결됩니다.

```json
{
  "version": 1,
  "duration": 180,
  "size": "1920x1080",
  "fps": 30,
  "chapters": [
    { "id": "intro", "project": "chapters/intro", "start": 0, "duration": 60, "audio": "chapters/intro/audio/final.wav" },
    { "id": "explain", "project": "chapters/explain", "start": 0, "duration": 60, "audio": "chapters/explain/audio/final.wav" },
    { "id": "end", "project": "chapters/end", "start": 0, "duration": 60, "audio": "chapters/end/audio/final.wav" }
  ],
  "render": { "workers": 3 }
}
```

`start`는 최종 영상의 시작 시간이 아닌 소스 페이지의 챕터에 있는 프레임의 시작 지점입니다. 여러 챕터가 동일한 페이지를 참조하고 다른 `start`를 사용할 수도 있지만, 공유 소스 코드가 변경되면 이러한 챕터가 함께 유효하지 않게 됩니다. 챕터 기간은 프레임 경계에 속해야 하며 합계는 승인 기간과 동일해야 합니다.

```bash
node <skill>/scripts/build-long.mjs <slug>/chapters.json
```

동일한 명령을 다시 실행하면 확인된 챕터 캐시가 재사용됩니다. 챕터 소스 파일이나 렌더링 사양을 변경한 후에는 유효하지 않은 챕터만 다시 작성됩니다. `.showreel-cache/`를 유지하고 캐시를 지우는 이유로 일반 인터럽트를 사용하지 마십시오. 내부 캐시는 기술적인 인공물이며 소스 코드, 개요 및 원본 오디오를 대체하지 않습니다.

- 각 장은 독립적인 오디오 트랙을 유지합니다. `chapters[].audio`를 사용하면 오디오 트랙이 누락된 장은 동일한 길이의 무음으로 채워집니다. 챕터 오디오 트랙 길이가 충돌하는 경우 오류가 보고됩니다.
- 기존 전체 칩 오디오 믹스: 대신 최상위 `audio`를 사용하여 전체 칩 오디오를 가리키고 더 이상 `chapters[].audio`를 설정하지 않습니다. 확인의 총 기간과 일치해야 합니다.
- 영화 전체가 무음입니다. 오디오 트랙 필드도 설정되지 않습니다. 기술 검사에는 오디오 트랙이 필요하지 않습니다. 단편영화는 `AUDIO=none`에 해당합니다. 무성 WAV를 음량 검사를 통과해야 하는 사운드 필름으로 취급하지 마십시오.
- `--skip-qa`는 드래프트 전용이므로 납품용으로 제작할 수 없습니다. 최종 승인은 완전한 사양으로 이루어져야 합니다.

## 오디오도 챕터별로 제작됩니다

내장된 신시사이저와 Tone.js는 모두 전체 샘플 메모리를 할당합니다. 20분 동안의 전체 칩에 대해 여러 개의 Float32 버스를 설정하지 말고 더 많은 메모리를 추가하여 수행해 보십시오.

오리지널 사운드, 효과 및 클릭 도구를 사용하여 각 장에서 나만의 `timeline.js`, `score.mjs` 또는 `score.tone.js`를 작성해 보세요. 먼저 `audio.mjs build`를 사용하여 이 장의 음악/음향 효과를 만든 다음 `narration.md`를 눌러 이 장의 음성 단어와 혼합하여 이 장의 `audio/final.wav`를 얻습니다. 이는 최종적으로 장 빌더에 의해 스트리밍되고 연결됩니다.

사용자가 전체 구두 방송을 제공하는 경우 실제 문장의 타임스탬프를 먼저 얻은 다음 자연스러운 휴지 시간에 챕터를 여러 챕터로 나눕니다. 분할은 단어를 잃거나 속도를 변경해서는 안 되며, 모든 장 간격은 확인된 전체 콘텐츠를 포함해야 합니다. 원본 녹음은 유지됩니다. 사용자의 원본 원고가 매우 긴 경우 TTS는 세그먼트별 합성 및 캐싱 기능을 제공합니다. 해당 세그먼트는 챕터별로 선택되어 이미지를 생성합니다. 보컬 중복을 방지하기 위해 전체 오디오 트랙을 최상위 레이어에 보관할 수 있습니다.

사운드트랙은 챕터 경계에서 계속되거나, 페이드 아웃되거나, 숨쉬도록 미리 설계되었습니다. 챕터 스플라이싱은 음악을 임의로 끊는 이유로 사용될 수 없습니다. 연속적인 음악은 스트리밍 ffmpeg를 먼저 연결하고 마지막으로 함께 마스터링할 수 있습니다. 조용해야 하는 챕터를 동일한 음량으로 강제하지 마십시오. 보컬 중 회피 및 최종 믹스에 대해서는 `narration.md`를 참조하세요.

## 장 수용 및 전체 영화 수용

빌드하기 전에 각 장에서 `render.mjs --determinism`를 실행하세요. 각 챕터별로 스틸 프레임, 텍스트 프레임, 모션, 휴대폰 크기 등을 확인하고 자료를 `qa/<chapter-id>/`로 저장하세요. 반복되는 프레임, 누락된 프레임, 텍스트 점프 및 오디오 이음새를 확인하려면 각 절단 지점 전후의 연속 프레임을 살펴보세요.

빌더는 전체 영화에서 `inspect.mjs qa`를 실행하여 크기, 프레임 속도, 총 지속 시간, 프레임 수 및 최종 오디오 트랙을 확인합니다. 전체 영화에서 프레임을 추출하는 것은 단지 목차일 뿐이며 장별 검사를 대체할 수는 없습니다. 구두 방송은 `narration.mjs check`에서 진행되며 원본 원고, 사운드 및 그림을 문장별로 확인합니다. 전체 영화의 청취 경험은 최종 검토를 위해 여전히 사용자의 몫입니다. 챕터 목록, 캐시 재사용 방법, 재구성 명령, 기술 결과 및 알려진 문제를 제공하며 프레임 추출에만 기초하여 전체 영화를 보거나 들었다고 주장하지 않습니다.
