## 1. 페이지 계약

```js
window.DUR = 16;                  // 秒，render.mjs 用它算总帧数（timeline.js 导出）
window.render = (t) => { ... };   // 画出第 t 秒；确定性；可以返回 Promise（比如要等视频帧解码）
window.READY = true;              // 字体、图片、模型、纹理全部加载完以后再设置
```

- 렌더링 도구는 HTTP 서비스 프로젝트 디렉터리(ES 모듈, 글꼴 및 glTF를 로드할 수 있도록), viewport = `--size`, DPR = `--dpr`를 사용합니다. 페이지는 `?w=&h=`부터 `stageSize()`까지 읽고 이 크기에 따라 형식이 지정됩니다.
- 페이지 또는 필수 스크립트의 JS 오류가 404인 경우 도구는 즉시 종료되고 오류를 인쇄합니다. 선택적 파일 404는 경고만 합니다.
- 미리보기: `npx serve <slug>` 또는 기타 정적 서비스, `index.html?w=1920&h=1080`를 열고 콘솔에서 `render(3.2)`를 호출하여 3.2초를 확인하세요. 일시적으로 `?play=1` 분기를 추가하고 rAF를 사용하여 `render(performance.now()/1000 % DUR)`를 구동하여 디버깅을 용이하게 할 수도 있지만 **이 분기는 렌더링 중에 실행할 수 없습니다**.

### 소리와 함께 미리보기

`preview.mjs`는 프로젝트 소스 파일을 수정하지 않고 메모리에 컨트롤을 추가하며 이전 프로젝트를 직접 사용할 수 있습니다. 새로운 스캐폴딩에는 일반 정적 서비스를 통해 쉽게 미리 볼 수 있는 `preview.js`도 포함되어 있습니다. 수동으로 접근할 때 파일을 복사하고 `<script type="module" src="./preview.js"></script>`를 `body`에 추가하세요. 컨트롤은 `render=1`가 아닌 `?preview=1`일 때만 실행되며 페이지의 `render(t)`를 변경하지 않습니다.```bash
node <skill>/scripts/preview.mjs <slug> --size 1920x1080 --fps 30
# 指定项目内音轨（路径相对项目）：
node <skill>/scripts/preview.mjs <slug> --size 1080x1920 --audio audio/final.wav
```

인쇄된 로컬 주소를 열고 재생을 클릭하세요. 프레임별로 일시 중지, 드래그, 왼쪽 및 오른쪽 및 두 배 속도 미리보기를 지원합니다. 오디오 트랙이 있으면 `audio.currentTime`를 사용하여 화면을 구동하고, 오디오 트랙이 없으면 미리보기 시계를 사용합니다. 오디오 트랙이 지정되지 않은 경우 `audio/final.wav`, `audio/narration.wav`, `audio/music.wav`로 검색하세요. 자동 동작 미리보기를 수행하기 위한 오디오 트랙이 아직 생성되지 않았으므로 오디오와 비디오가 정렬되었다고 주장할 수 없습니다.

화면은 지정된 너비와 높이 비율에 따라 창에 맞춰 조정되며 컨트롤을 위한 공간이 남습니다. 창 크기를 조정해도 프레임 크기는 변경되지 않습니다. 장면 레이아웃은 여전히 ​​페이지 계약에 따라 `stageSize()`를 사용하므로 미리보기 창의 `innerWidth` 또는 `vw/vh`에 의존하지 마세요.

미리보기 제어 및 실시간 상태는 `render(t)` 호출에만 책임이 있으며 공식 렌더링은 여전히 ​​결정적인 시간에 프레임을 사용합니다. `?render=1`를 사용하면 플레이어, 컨트롤 또는 애니메이션 루프가 생성되지 않습니다. 배속은 미리보기에만 영향을 미치며 원본, 오디오 파일 또는 내보내기 사양은 변경되지 않습니다. 대표적인 연속 클립을 사용하여 피사체 상태, 연속 촬영, 키워드 이벤트를 확인하고, 룩앤필 검토를 대체하기 위해 프레임 속도 수치를 사용하지 마십시오.

## 2. 확실성

렌더러는 순서와 횟수에 관계없이 `render(t)`를 호출합니다. 즉, 병렬로 실행되는 여러 작업자, 단일 프레임 미리 보기, 단 하나의 세그먼트만 다시 렌더링, 모션 블러 처리된 서브프레임 등이 있습니다. 이전 프레임에 약간의 상태가 숨겨져 있는 한 다시 렌더링된 그림은 달라집니다.| 금지 | |로 변경 |
|---|---|
| `Math.random()` | `rng(seed)`(렌더링 시 고정 시드로 새로 생성됨) 또는 `hash(i, seed)` |
| `Date.now()` / `performance.now()` / rAF / `setTimeout` | 매개변수 t |
| CSS `transition` / `animation` / 웹 애니메이션 | render(t) |에서 직접 스타일(변환, 불투명도, 클립 경로...)을 작성합니다.
| 프레임별 위치 및 속도 누적(`x += v`) | 분석식 `x(t)`; 스프링용 `spring` / `springTo` |
| 물리/유체를 축적해야 하는 시뮬레이션 | 고정된 단계로 0에서 t로 푸시하거나(캐싱할 수 있지만 단일 프레임도 올바르게 계산해야 함) 배열에 미리 구워집니다 |
| `<video>` 요소가 자연스럽게 재생됨 | `video.currentTime = t`를 설정하고 `seeked` 이벤트를 기다리거나(렌더링이 약속을 반환함) 먼저 ffmpeg를 사용하여 이미지 시퀀스로 분할 |
| 뷰포트에 따른 무작위 레이아웃 | W/H에만 시드되어 의존 |

주요 변경이 있을 때마다 `render.mjs <slug> --determinism`를 실행합니다.

## 3. 화면별 기술 선택

**그림 스타일을 먼저 결정한 다음 이 스타일을 만들 수 있는 가장 간단한 기술을 선택하십시오. **한 가지 유형을 사용할 수 있다면 세 가지 유형을 혼합하지 마십시오. 혼합하려면 "콘텐츠 레이어 → 텍스처 레이어"를 눌러 쌓으세요. 각 레이어를 독립적으로 실행하고 확인할 수 있습니다.| 기술 | 잘한다 | 잘하지 못한다 |
|---|---|---|
| 캔버스 2D | 픽셀, 평면 그래픽, 기하학, 타이포그래피, 입자(수천 개 이내), 손으로 그린 ​​선; 일반 그리드가 있는 의사 3D 블록(`camera3d` + `drawBoxes`, recipe.md 섹션 15) | 수만 개의 입자, 픽셀별 텍스처, 산재된 3D 개체 |
| DOM/CSS/SVG | 인터페이스 애니메이션, 실제 텍스트 레이아웃, SVG 스트로크, 제품 스크린샷 카드 | 수천 개의 요소, 복잡한 질감 |
| WebGL 조각 셰이더 | CRT, 입자, 색차, 하프톤, 리퀴드, 노이즈 필드, SDF 그래픽 | 콘텐츠 및 텍스트 직접 그리기(일반적으로 Canvas로 먼저 그린 다음 셰이더에 텍스처로 보냅니다.) |
| Three.js | 3D 장면, 돌출된 텍스트, 인스턴스 배열, 유리 금속 재료, 우주 렌즈 | 현실적인 캐릭터 |
| p5.js + p5.brush | 컬러 연필, 수채화, 크레용 스트로크 | 렌더링 속도(브러시가 매우 느림. 먼저 단일 프레임의 시간 소모를 테스트) |
| 원격/하이퍼프레임 | 다중 장면 장편 영화, 사용자가 이미 사용 중이거나 사용하려는 경우 | 10초가 넘는 단편영화(단일 HTML이 더 빠름), 적극적으로 소개하지 않음 |

## 4. 캔버스 2D- `setupCanvas(canvas, W, H)` 캔버스 크기를 DPR로 설정하고 컨텍스트를 CSS 픽셀로 조정합니다. **각 프레임을 `setTransform(1,0,0,1,0,0)`가 아닌 `ctx.save()` / `ctx.restore()`로 래핑합니다**. 그렇지 않으면 왼쪽 상단 모서리의 1/4만 `--dpr 2`로 채워집니다.
- 먼저 각 프레임의 전체 배경을 채웁니다(`clearRect` 이후 투명 배경에 의존하지 마세요).
- 텍스트: 먼저 `await loadFonts([...])`, `ctx.font`의 글꼴 크기 단위는 CSS 픽셀입니다. `measureText`는 문자 너비를 얻어 문자 간격을 정렬할 수 있습니다.
- 픽셀 스타일: 오프스크린 캔버스 + `imageSmoothingEnabled = false` + 정수 배율 + 좌표 반올림.
- 흐림 및 발광: `ctx.filter = 'blur(8px)'`를 사용할 수 있지만 속도가 느립니다. WebGL을 사용하여 넓은 면적의 후광을 만듭니다.
- 복합 모드(마스킹용 `globalCompositeOperation`: `multiply`, `screen`, `destination-in`)는 마스크 조판을 위한 강력한 도구입니다.
- **텍스트 금지 영역**: 큰 문자와 복잡한 콘텐츠(3D 블록, 파티클, 콜라주, 배열)가 동일한 화면에 있는 경우 먼저 `measureText`를 사용하여 문자의 직사각형(오름차순/내림차순 포함, 글꼴 크기 약 0.15배 확장)을 계산하고 콘텐츠가 들어갈 수 없는 영역으로 처리합니다. 카메라 프레이밍 센터(`cx / cy`), 피사체의 윤곽선(섬, 마스크) 또는 레이어 순서로 콘텐츠를 차단할 수 있습니다. 동일한 색상의 바쁜 그래픽에 단어를 누르면 썸네일은 왜곡된 문자로 읽혀지며 자체 검사 중에 글꼴 또는 코드 오류로 쉽게 오인될 수 있습니다. 큰 캐릭터가 포함된 각 샷에 대해 특히 캐릭터의 가장자리를 보면서 적어도 하나의 스틸 프레임을 렌더링합니다.

## 5. DOM / SVG- 모든 스타일은 render(t): `el.style.transform = ...`에 직접 작성됩니다. CSS 전환에 의존하지 마십시오.
- **크기가 조정되고 텍스트를 포함하는 요소에 `will-change: transform`를 추가하지 마십시오**. 그렇지 않으면 텍스트가 래스터화된 다음 크기가 조정되어 흐려집니다.
- SVG 스트로크 애니메이션: `pathLength="1"` + `stroke-dasharray="1"` + 렌더링에서 `stroke-dashoffset = 1 - k` 설정.
- 형상 변형 : 동일한 `<div>`가 `width`, `height`, `border-radius`, `background`로 변경됩니다. (변형 용기 내부의 내용물이 들어가고 나가도록 별도로 배열되어 있습니다.)
- DOM의 텍스트 서식 품질(합자, 커닝, 중국어 구두점 돌출)이 가장 우수하여 많은 양의 텍스트에 적합합니다.
- 스크린샷 자료는 `<img>`, `decode()`를 미리 사용해주세요.

## 6. WebGL 후반 작업

방법: 콘텐츠를 2D 캔버스에 그린 후 → 각 프레임을 텍스처로 업로드 → 전체 화면 삼각형이 프래그먼트 셰이더를 실행 → 디스플레이 캔버스로 출력합니다. 전체 템플릿을 보려면 recipe.md의 "WebGL Post"를 참조하세요.

- `getContext('webgl2', { preserveDrawingBuffer: true, antialias: false })`, 각 프레임이 그려진 후 `gl.finish()`를 호출합니다.
- 시간 관련 효과의 경우 `t`를 균일하게 전달하고 노이즈의 경우 `hash(uv + floor(t * fps))`와 같은 결정적 쓰기를 사용합니다.
- **쉐이더가 실제로 적용되는지 확인하기 위해 먼저 한 프레임을 렌더링한 다음**(컴파일이 실패하면 화면이 검게 표시되거나 원본 내용만 표시됨) 전체 영화를 렌더링합니다.
- 소프트웨어 렌더링(SwiftShader)이 매우 느립니다. macOS의 렌더링 도구는 기본적으로 Metal을 사용합니다.

## 7. Three.js- 프로젝트에 설치: `cd <slug> && npm i three`, `index.html`에서 importmap 사용:
  ```html
  <script type="importmap">{ "imports": { "three": "./node_modules/three/build/three.module.js", "three/addons/": "./node_modules/three/examples/jsm/" } }</script>
  ```
  렌더링을 위해 CDN에 의존하지 마십시오.
- `new THREE.WebGLRenderer({ antialias: true, preserveDrawingBuffer: true })`, `setPixelRatio(devicePixelRatio)`, `setSize(W, H)`.
- `render(t)`에서: 카메라 위치 및 방향, 객체 변환, 재료 매개변수, 조명 설정 → `renderer.render(scene, camera)`. `THREE.Clock`를 사용하지 마십시오. 애니메이션 편집에는 `mixer.setTime(t)`를 사용하세요.
- 포스트 프로덕션(EffectComposer, Bloom, Depth of Field)을 사용할 수 있으나 추가되는 레이어마다 프레임 시간을 확인해야 합니다.
- glTF/Texture/HDRI 로딩 시 `await`가 모두 완료된 후 READY로 설정하세요.

## 8. p5.js

- `window.render = t => { T = t; p.redraw(); }`에서 구동되는 인스턴스 모드 + `noLoop()`를 사용합니다. `draw()`는 `T`만 읽습니다. `randomSeed` 및 `noiseSeed`는 매 프레임마다 고정된 값으로 재설정됩니다.
- p5.brush가 매우 느립니다. 먼저 단일 프레임이 지속 시간과 프레임 속도를 결정하는 데 걸리는 시간을 측정합니다. 스트로크의 임의 시드로 `floor(t * 12)`를 사용합니다. 스트로크는 초당 12번만 변경됩니다. 손으로 그린 ​​애니메이션처럼 보이며 렌즈는 매 프레임마다 여전히 부드럽습니다.

## 9. 글꼴- **자체 호스팅**: `.woff2`를 `fonts/`에 넣고 `@font-face`로 선언하고 `loadFonts()`는 로드될 때까지 기다린 후 READY됩니다. 렌더링할 때 Google Fonts를 연결하지 마세요.
- 풀 오픈 소스 글꼴: `https://github.com/google/fonts/tree/main/ofl/<family>`(OFL 승인).
- **중국어**: 완전한 CJK 글꼴의 범위는 몇 MB에서 12MB까지입니다. 사용된 단어를 기반으로 하위 집합을 만들 수 있습니다. Google Fonts CSS API는 `&text=` 매개변수를 사용하고 `https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@900&text=<URL 编码的文字>`와 같이 이러한 단어의 글리프만 반환합니다. `fonts/`를 가리키는 글꼴 파일을 다운로드하고 로컬로 로드합니다. 카피라이팅이 변경되면 하위 세트를 다시 작성해야 합니다. 네트워크가 없는 경우 시스템 글꼴: `"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`를 사용하십시오(다른 기계의 렌더링 결과는 다를 수 있으므로 배송 지침에 이를 명시하십시오).
- 디지털 점프에는 `font-variant-numeric: tabular-nums`를 사용하세요(캔버스에서 고정폭 숫자의 글꼴을 선택하세요).

## 11. 멀티 프레임

- 모든 레이아웃은 `W`, `H`에서 파생됩니다: 단위 `U = Math.min(W, H) / 1080`, 스케일 또는 그리드를 사용한 위치.
- 9:16 및 16:9는 단순한 자르기가 아닙니다. 세로 화면 문자는 더 크고 세로로 배열되어야 하며 상단과 하단에 안전 영역의 약 12%를 남겨 두어야 합니다(플랫폼 UI가 이를 덮습니다). 여러 프레임을 제작할 때 동일한 타임라인을 사용하고 각 프레임의 레이아웃을 개별적으로 조정한 다음 별도로 렌더링합니다(`--size 1080x1920`).
- 16:9 완성된 필름을 세로 모드로 직접 자르지 마십시오.## 12. 성능 및 렌더링 시간

`long-form.md`의 챕터 빌더를 사용하면 2분 이상, 최대 1200초입니다. 원본 `render.mjs --start --duration`는 프레임 가져오기 도구로 유지됩니다. `build-long.mjs`는 그 위에 지속적인 캐싱, 재시도 및 중단점 복구를 제공합니다. 오디오 합성도 규정에 따라 수행되며 여러 개의 풀 칩 PCM 버스는 메모리가 부족할 수 없습니다. 음성 방송이 있는 경우 `narration.md`를 눌러 실제 오디오와 문장 시간을 준비한 다음 촬영 타임라인을 작성하세요.

- 렌더링 도구는 각 샘플의 밀리초 수를 인쇄합니다. 예상: **총 시간 ≒ 단일 프레임 시간 × 프레임 수 × 서브프레임 수 ¼ 작업자 수 × 1.2**.
- 참조 스케일(Apple Silicon, 1080p): 캔버스 2D 단순 장면 15~40ms/프레임, DOM 레이아웃 30~60ms, WebGL 포스트 +20~80ms, Three.js 포스트 80~300ms.
- 기본 작업자 수는 3개이며, CPU 코어가 더 많으면 작업자 수를 4~6개까지 늘릴 수 있습니다. WebGL이 많은 페이지의 경우 작업자가 너무 많으면 속도가 느려집니다.
- 저화질 샘플(960×540, 모션 블러 없음)로 시작하여 리듬을 설정한 후 마지막으로 `--subframes`, `--dpr`, 60fps를 재생합니다.
- 렌더링 오류가 있는 경우 `--start 6 --duration 3 --out out/seg.mp4` 섹션만 다시 렌더링하세요. 전체 조각을 렌더링하기 전에 문제가 없는지 확인하십시오.
