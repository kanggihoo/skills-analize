# 간략한.md 템플릿

`brief.md`에는 두 가지 목적이 있습니다. 이 프로덕션에서는 이를 엄격히 따르십시오. 향후 테마를 변경하거나 도구를 변경할 때 완전한 구조화된 프롬프트가 될 것입니다. XML 태그를 사용하여 부품을 분리함으로써 Claude는 어떤 부분이 요구 사항인지, 어떤 부분이 재료인지, 어떤 부분이 제약 사항인지 더 정확하게 구분할 수 있습니다.

1. 단편 영화의 경우 단일 HTML 파일을 유지하십시오(또는 Three.js / p5가 필요한 이유를 설명하십시오). 장편 영화의 경우 장을 long-form.md로 분리하세요. 콘텐츠 레이어:…, 텍스처 레이어:….
2. 페이지 노출 window.DUR / window.render(t) / window.READY; 그림은 t에 의해서만 결정되고 난수에는 고정된 시드가 있으며 타이머가 사용되지 않고 CSS 애니메이션이 사용되지 않으며 프레임 간에 상태가 저장되지 않습니다.
3. 모든 시점은 timeline.js에 기록되고 여기에서 페이지와 Score.mjs를 가져옵니다. 샷 목록은 SHOTS에 기록됩니다. 입으로 방송하지 않는 경우 공개 온(촬영 지점, 지속 시간, 공개 지점)을 사용하여 전환 시작 지점을 반전시킵니다. 음성 방송이 있을 경우 실제 오디오를 먼저 합성하거나 분석한 후 장면에 문장 시간을 스탬프 처리하므로 시간을 추정하고 맞춰진 척할 필요가 없습니다.
4. 렌더링: render.mjs 프레임별 스크린샷 → ffmpeg; 매개변수: --fps … --size … [--subframes 4] [--dpr 2] [--grain …].
5. BGM과 효과음은 각각 확인된 소스에서 가져오며, 첫 번째 파일인 Score.mjs / 두 번째 파일인 Score.tone.js가 유지됩니다. narration.md를 사용하여 음성 사운드를 준비하세요. 독립 트랙에 narration.mjs 믹스를 사용하면 최종 믹스에서 음량과 피크 값이 통합됩니다. 음향 효과가 있는 액션은 액션의 틀에 속합니다. 음성 방송이 있을 때 오케스트레이션과 음향 효과가 수렴됩니다. 세 트랙이 모두 꺼진 후에 'Silence'를 썼습니다. 장편 길이의 오디오는 장별로 구성되므로 분할 처리 대신 전체 영화 Float32 합성이 필요하지 않습니다.
6. 각 샷에 대해 3개의 스틸 프레임 렌더링을 확인합니다. 주요 상태 변경 및 렌즈 조인트에 대한 연속 데모를 보고, 오디오 미리 보기를 사용하여 이벤트 동기화 및 동작 연속성을 확인하세요. 모든 작업이 완료되면 --determinism을 실행하고 저화질 데모를 만들어 리듬을 확인한 후 장편영화를 제작합니다.
7. 승인: sh build.sh (FPS / SIZE / AUDIO / LOOP 는 build.sh 상단에 작성되며 기간은 timeline.js 의 DUR 입니다), 이는spect.mjs qa --expect-size ... --expect-fps ... --expect-duration ... --audio require|none [--loop]; 기술적 확인은 모두 PASS이고 NOT CHECKED는 없습니다. HOLDS(고의적 체류) 및 DROPS(다시 호흡하기)는 timeline.js에 선언됩니다. build.sh는 또한 텍스트 프레임 장면(qa/text.json)과 샷별 모션 보고서를 생성합니다. 이 두 가지는 리뷰 자료이므로 각각 읽어야 합니다.
8. 혼합 오디오 트랙의 경우 AUDIO=file AUDIO_FILE=audio/final.wav sh build.sh를 사용하십시오. 장편 영화의 경우 챕터 캐시를 유지하려면 build-long.mjs Chapters.json을 사용하세요. 구두 방송이 있는 경우 narration.json과 실제 오디오 지속 시간, 문장별 이미지 대응, 원본 원고의 완성도를 확인하세요. 장편 영화의 경우 장별로 확인하고 이음새를 검토하세요.
