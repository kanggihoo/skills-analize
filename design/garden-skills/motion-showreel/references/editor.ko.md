# 기본 편집 워크스페이스

모든 제작은 먼저 여기서 미리보고 독립 트랙의 소리를 조정하며, 사용자가 현재 미리보기가 통과되었다고 확인한 뒤에야 MP4를 생성한다. 에이전트는 서비스를 능동적으로 시작하고 워크스페이스를 열어야 한다. 브라우저를 열 수 없으면 로컬 링크를 제공하고 사용자의 피드백을 기다린다. 소리가 없는 영상, 나레이션이 없는 영상, 짧은 영상, 루프 영상 모두 이 절차를 따르며, 긴 영상은 아래 설명에 따라 챕터별로 미리본다. 사용자가 워크스페이스를 따로 열어 달라고 요청할 필요는 없으며, 기본적으로 프록시 MP4를 생성하지 않는다.

사용자가 「导出视频」(영상 내보내기) 버튼을 클릭하거나, 대화에서 현재 버전을 내보내도 된다고 말하면 이것이 내보내기 확인이다. 같은 질문을 반복하지 않는다. 내용을 수정했다면 사용자가 다시 확인하도록 한다. 사용자가 미리보기를 건너뛰고 바로 내보내라고 명시적으로 요청했다면, 그 지시에 따라 실행하고 기록한다. 기존 `preview.mjs`는 가벼운 디버깅용이며, `build.sh`, 챕터별 빌드, 검수는 확인 후 내보내기 도구로 계속 쓴다. 애니메이션과 소리의 구현은 바뀌지 않는다.

사용자가 요구사항 단계에서 제작 과정을 보고 싶다고 표현했다면, 같은 진입점을 `--progress` 옵션으로 일찍 열고, 단계마다 화면 스타일 프레임, 음색 짧은 샘플, 재생 가능한 결과물을 발행한다. 자세한 내용은 [`progress.md`](progress.md)를 참고한다. 제작 단계에서는 읽기 전용으로 동작하며, 최종 짧은 영상에 `review --final`을 발행한 뒤에도 이 페이지에서 확인과 내보내기를 한다. 요청이 없다면 이 문서의 기본 최종 미리보기 흐름을 그대로 유지한다.

## 기존 프로젝트 열기

```sh
node <skill>/scripts/editor.mjs <project> --size 1920x1080 --fps 30
```

터미널에 출력되는 로컬 주소를 연다. 크기와 프레임레이트는 이 영상의 확정 사양과 반드시 같아야 한다. 길이는 프로젝트 `timeline.js`의 `DUR`에서 읽으며, `--duration <seconds>` 또는 `editor.json`의 `duration`으로도 지정할 수 있다. 장면의 실제 `window.DUR`과 다르면 오류로 알린다. MP4를 먼저 렌더링할 필요가 없고, TTS를 호출하거나 음악을 합성하지도 않는다. 프로젝트에 오디오가 없으면 소리 없이 미리볼 수 있다.

`--audio audio/final.wav`로 원본 믹스를 명시할 수 있다. 기존 내보내기 품질 설정으로 `--workers`, `--subframes`, `--shutter`, `--dpr`, `--grain`, `--crf`를 함께 넘길 수 있다. 실시간 미리보기는 내보내기 도구의 서브프레임 블렌딩, DPR 슈퍼샘플링, ffmpeg 그레인을 모사하지 않으며, 화면에도 이 점을 표시한다. 이 값들이 픽셀 단위로 일치한다고 주장하지 않는다.

## 워크스페이스 레이아웃

화면과 타임라인은 하나의 워크스페이스를 공유한다. 기본적으로 믹싱과 제작 진행 패널은 접혀 있어 화면 공간을 확보하며, 필요하면 상단 버튼으로 연다. 미리보기 툴바는 창에 맞추기, 비율 확대/축소, 확대 후 드래그, Ctrl/⌘ 휠 확대/축소, 최대화를 지원하고, Esc로 원래대로 돌아간다. 화면과 타임라인 사이의 가로 구분선을 드래그해 상하 공간을 나눌 수 있으며, 구분선은 방향키와 더블클릭 초기화도 지원한다. 트랙이 많으면 타임라인 내부에서 스크롤한다. 모든 표시 조작은 미리보기 레이아웃만 바꾸며, 원래 장면 크기, 타임라인, 내보내기 매개변수는 그대로 유지한다.

## 첫 버전에서 지원하는 작업

- 원본 장면은 고정된 너비와 높이의 독립 iframe 안에서 같은 `render(t)`를 실행한다. 화면 트랙에는 `SHOTS`가 표시되고, 재생 헤드를 드래그할 수 있으며, 프레임 단위 이동, 타임라인 확대/축소, 루프 구간 재생을 지원한다. 복잡한 장면은 실시간에서 프레임이 떨어질 수 있지만, 오프라인 내보내기의 프레임 수는 바뀌지 않는다.
- 실제 오디오 파형은 프로젝트 원본 파일에서 생성하여 캐시한다. 나레이션, BGM, 효과음은 각각 따로 표시된다. 음소거와 트랙 게인은 내보내기에 반영된다. 게인은 트랙 간 비율을 조정하며, 편집 후 최종 믹스는 원래 검수 기준대로 −14 LUFS로 통일된다.
- BGM과 효과음 클립은 드래그, 분할, 자르기, 제거가 가능하며, 소스 시작점, 길이, 클립 게인, 페이드인과 페이드아웃을 설정할 수 있다. 분할점이 페이드 구간 안에 있으면 조정하라고 알려 주어, 분할로 인해 소리의 엔벨로프가 의도치 않게 바뀌지 않도록 한다. 클립끼리 겹치는 것은 허용되며, 겹친 부분은 더해진다.
- 나레이션과 기존 전체 믹스의 시간 위치는 고정된다. 게인을 조정하거나 음소거할 수 있지만, 글자를 자르거나 옮기거나 속도를 바꿀 수 없다. 화면, 자막, 의미 타임스탬프는 계속 연결된다. 루프 구간은 미리듣기 전용이며, 최종 내보내기를 자르지 않는다.
- 실행 취소, 다시 실행, 자동 저장, 새로고침 후 복원을 지원한다. 저장 파일은 `.showreel-editor/session.json`이며, 애니메이션, 사용자 원고, 오디오 원본은 수정하지 않는다. 원본 소스 오디오가 바뀌면 이전 편집을 자동으로 적용하지 않는다. 원본 파일과 이전 세션은 디스크에 남는다.
- 오디오를 수정한 뒤에는 「更新试听」(미리듣기 갱신)을 누르거나, 바로 재생하면 자동으로 갱신된다. 오디오만 다시 믹싱하며 영상은 렌더링하지 않는다. 재생되는 것은 내보내기에 사용될 것과 같은 WAV 파일이며, 브라우저의 근사 믹싱을 따로 쓰지 않는다. 긴 영상은 믹싱에 시간이 걸리며, 결과는 편집 내용과 원본 파일 서명을 기준으로 캐시된다.

## 트랙은 어디서 오는가

먼저 프로젝트 루트의 `editor.json`에 명시된 트랙 설정을 읽는다. 없으면 `audio/mix.json`의 입력 트랙, 게인, 나레이션 회피 구간을 읽는다. 새로 생성된 mix 기록에는 게인이 포함되며, 오래된 기록에 게인이 없으면 화면에서 기본값을 알려 주고, 필요하면 `editor.json`에 원래 값을 채운다. **편집하지 않은 상태에서는 항상 원본 최종 믹스를 그대로 재생하며, 다시 처리하지 않는다.**

`audio/final.wav`나 합성된 `audio/music.wav`만 있으면 하나의 믹스된 트랙으로 표시된다. 나레이션, BGM, 효과음을 따로 복원한다고 주장할 수 없다. 오디오를 생성할 때 독립 파일을 보존하고 아래처럼 명시적으로 설정해야 한다.

```json
{
  "duration": 60,
  "size": "1920x1080",
  "audio": "audio/final.wav",
  "tracks": [
    {"id": "voice", "kind": "voice", "file": "audio/narration.wav", "gain": 1},
    {"id": "bgm", "kind": "bgm", "file": "audio/bgm.wav", "gain": 0.35},
    {"id": "sfx", "kind": "sfx", "file": "audio/sfx.wav", "gain": 0.5}
  ]
}
```

트랙 종류는 `voice`, `bgm`, `sfx`, `mix`이며, 경로는 프로젝트 디렉터리 기준 상대 경로다. 내장 합성기의 `audio.mjs build score.mjs --stems`는 버스 단위 분리 트랙을 내보낼 수 있다. 다만 버스가 BGM/SFX와 반드시 같지는 않으며, 리버브와 마스터링이 전체 믹스에 집중되어 있을 수도 있다. 실제 내용에 맞게 설정해야 하며, 분리 트랙을 더한 결과를 원래 믹스를 복원했다고 주장해서는 안 된다. 워크스페이스는 최대 32개 트랙, 256개 오디오 클립을 지원한다.

첫 버전은 `render(t)` 페이지 하나를 대상으로 한다. 여러 페이지로 된 긴 영상은 챕터별로 워크스페이스를 열어 미리보고, 인접 챕터의 이어짐을 확인한 뒤, 사용자가 확인하면 원래 챕터 빌더를 실행한다. 여러 페이지를 가로지르는 전편 연속 재생이나 여러 챕터 오디오 편집의 자동 취합은 지원한다고 하지 않는다. 같은 페이지의 서로 다른 구간이 여러 챕터를 이루는 경우에는 그 페이지를 열고 루프 구간으로 각 챕터를 찾는다. `--duration`을 줄여 장면 길이를 바꾸지 않는다. 워크스페이스에서 한 소리 편집은 실제 내보내기에 쓰이는 믹스와 검증 기록에 동기화되어야 하며, 긴 영상을 이어 붙일 때 원래 믹스로 되돌아가서는 안 된다. 자세한 내용은 `long-form.md`를 참고한다.

## 내보내기와 호환성

인터페이스에서 「导出视频」를 클릭해야만 원래의 `render.mjs`가 실행된다. 먼저 결정성을 확인하고, 내보내기 후 전체 사양의 `inspect.mjs qa`를 실행하며, 텍스트 검수 자료를 생성한다. 단계, 실제 프레임 진행률, 오류는 화면에 표시되고, 취소를 지원한다. 실패하거나 취소된 작업은 완성 영상을 발행하지 않는다. 사용자가 대화에서 내보내기를 확인하면 에이전트가 이 버튼을 조작할 수 있다. 워크스페이스에서 소리를 편집하지 않았다면, 확정된 사양의 원래 빌드 명령을 실행해도 된다. 이미지는 여전히 `review.md`에 따라 검수해야 하며, 기술 검사가 사용자의 최종 확인을 대신하지 않는다.

출력은 새 파일 `out/editor-<task-id>.mp4`이며, `out/final.mp4`를 덮어쓰지 않는다. 해당 작업의 편집 스냅샷, 검수 결과, 검수 자료는 `.showreel-editor/exports/<task-id>/`에 저장된다. 원래의 `build.sh`는 워크스페이스 편집을 자동으로 읽지 않는다. 편집판을 다시 빌드하려면 워크스페이스에서 다시 내보내야 한다. 편집 믹스를 다른 빌드에 쓰려면 오디오 경로와 유효한 믹스 검증 기록을 함께 동기화해야 한다. `AUDIO_FILE`만 바꾸면 원래 `audio/mix.json`과 맞지 않아 검증을 통과하지 못하며, 검증을 건너뛸 수 없다.

워크스페이스 내보내기는 프로젝트의 `timeline.js`를 검수 도구에 명시적으로 전달한다. 따라서 `SHOTS`, `HOLDS`, `DROPS`의 검수 근거가 유지된다. 검수 출력은 작업 디렉터리의 `qa.log`에 저장되며, `receipt.json`에는 로그 위치와 타임라인 사용 여부가 기록된다. 타임라인이 없는 이전 프로젝트는 기존 방식으로 계속 내보낼 수 있다.

서버는 로컬 주소에서만 수신한다. 터미널에서 서버를 끄면 접근이 중단된다. 소스 파일, 코드, 편집 기록은 모두 프로젝트 디렉터리에 남으며, 원격 계정이나 새 npm 패키지는 필요하지 않다. 회귀 테스트는 다음과 같다.

```sh
node --test <skill>/scripts/test/editor-model.test.mjs <skill>/scripts/test/editor.test.mjs
```
