# 디지털 글리치 (glitch-digital)

> 디지털 신호가 오류를 일으킨다: 픽셀이 늘어나고 데이터 블록이 어긋나며 압축 손상이 번지고 문자가 깨졌다 다시 배열된다. 무너졌다 복구되는 데이터 흐름처럼 보인다.
> 참고 (문법만 참고): 글리치 아트, 데이터벤딩과 데이터모시 작품, 픽셀 정렬, 해체주의 그래픽 디자인, 전자 음악 비주얼. 특정 작품을 복제하지 않는다.

## 본질 / 본질이 아닌 것
- 본질: **디지털 매체 자체에서 비롯된 오류.** 압축 블록, 인코딩 불일치, 비트 반전, 메모리 읽기 오류 등 디지털 신호의 물리적 특성에서 글리치가 생긴다. 글리치는 구조와 리듬이 있고 박자에 맞춰 나타나며 오류 자체가 침입, 재작성, 업그레이드 같은 내용을 말한다.
- 본질이 아닌 것: 아날로그 TV의 스캔라인과 VHS 노이즈 (`crt-vhs`에 해당), 매 프레임 무작위로 흔들리는 “사이버” 필터.

## 식별 신호: 영상마다 2–3개 선택
| 신호 | 어떤 모습인가 | 적합한 주제 |
|---|---|---|
| 블록 어긋남 | 화면이 가로 줄이나 사각 블록으로 나뉘어 각각 옆으로 어긋남 | 충격, 침입 |
| 픽셀 정렬 | 영역 안의 픽셀을 밝기 순으로 긴 막대처럼 늘임 | 용해, 시간 흐름, 예술성 |
| 압축 손상 | 8×8 모자이크 블록, 색상 양자화 계단 | 저화질, 데이터 손상 |
| 데이터모시 | 이전 장면의 움직임이 다음 장면을 끌고 감 | 전환, 기억 혼란 |
| RGB 채널 분리 | 세 채널이 각기 어긋나며 가장자리가 딱딱함. 흐릿한 색수차와 다름 | 충격, 디지털 |
| 깨진 문자의 재배열 | 문자가 무작위로 바뀌다 정확한 단어로 정착 | 디코딩, 공개, 제목 |
| 비트 패턴 | 0과 1, 16진수, 메모리 덤프로 배경을 채움 | 저수준, 코드, 해커 |
| 불량 픽셀 | 고정된 밝은 점이나 불량 라인 몇 개 | 화면, 불완전함 |
| 데이터벤딩 색상 | 부자연스럽게 채도가 높은 색면과 반전색 | 환각적, 음악 |
| 해체된 레이아웃 | 글자를 자르고 회전·중첩하며 그리드를 의도적으로 깸 | 반항, 태도 |
| 로딩과 재구성 | 저해상도 화면이 단계별로 선명해지거나 위에서 아래로 다시 만들어짐 | 복구, 업그레이드 |

규칙:
- 영상마다 2–3개를 고르고, 그중 하나 이상은 아래의 “가장 진부한 버전”에 없는 신호로 선택한다.
- 신호는 주제에 맞춰 선택하며 순서대로 전부 쓰지 않는다.
- 글리치는 배경 무늬가 아니라 사건이다. 평소에는 깨끗한 화면을 유지하고 강박, 전환, 핵심 단어에서만 몇 프레임에서 0.5초 정도 사용한다.

## 이 스타일의 가장 진부한 버전
- 화면: 검은 바탕, 마젠타·시안 색수차가 계속 떨리고 가로줄이 무작위로 어긋남, 글자가 계속 깨지고 “ERROR”와 16진수가 곳곳에 보임.
- 사운드: 계속되는 bitcrush 노이즈와 무작위 전자 삑 소리.
- brief의 style 항목에 이번 영상에서 뒤집은 규칙이나 고전적인 표현을 유지한 이유를 쓴다. 유지한다면 구도, 카메라, 리듬 또는 예상 밖의 기억에 남는 순간에 공을 들인다.

## 적합성
- 용도: 오프닝, 비트에 맞춘 문구, 전자음악 비주얼, 제품 출시의 “재구성 / 업그레이드” 구간, 포트폴리오 클라이맥스.
- 콘텐츠: 사이버 보안, AI, 개발자 도구, 전자 음악, 게임, 트렌드 브랜드, 규칙을 깨는 주제.
- 부적합: 신뢰나 따뜻함이 필요한 주제, 긴 글을 읽어야 하는 구간 (글리치가 읽기를 방해).

## 기술 구현
먼저 Canvas 2D로 깨끗한 원본 콘텐츠를 그린 뒤 WebGL 후처리로 글리치를 만든다. 블록 어긋남은 `floor(uv.y * rows)`별로 무작위 오프셋을 가져온다. RGB 분리는 채널별로 따로 샘플링한다. 픽셀 정렬은 CPU에서 선택한 작은 영역을 밝기 순으로 정렬한다 (영역이 크면 느려짐). 압축 손상은 8×8 블록의 평균색과 양자화로 표현한다. 모든 무작위성은 `hash(블록 인덱스, floor(t * fps))`를 사용하고 글리치 강도는 timeline의 이벤트로 구동한다. 프레임마다 무작위로 켜고 끄지 않는다.

## 재질과 렌더링
- 블록 어긋남: 가로줄 높이는 4–60px로 다르게 두고 강도에 따라 오프셋을 바꿈. 가끔 한 줄 전체를 이전 프레임이나 다음 장면의 내용으로 교체.
- RGB 분리: 흐림 없이 날카롭게, 픽셀 단위 오프셋 (2–12px).
- 픽셀 정렬: 특정 밝기 구간의 픽셀을 골라 행이나 열 방향으로 정렬해 길게 늘임.
- 깨진 문자: 문자 집합 (A–Z, 0–9, 기호, 블록 문자) 안에서 글자를 바꾸다 점차 빈도를 낮추고 마지막에 한 글자씩 올바른 단어로 정착.
- 재구성: 처음에는 16×9 모자이크를 보여준 뒤 2배씩 선명하게 하거나 위에서 아래로 한 행씩 디코딩.

## 색상
아래 색상은 예시다. 방향만 참고하고 그대로 베끼지 않는다.
- 흑백 + 오류색 하나: 검정 `#0A0A0A` / 흰색 `#F2F2F2` / 오류 빨강 `#FF2A2A`
- 데이터 컬러: 거의 검정 `#0B0C10` / 형광 초록 `#39FF14` / 마젠타 `#FF00A8` / 전기 파랑 `#00B3FF`
- 밝은 해체 스타일: 종이 흰색 `#EDEDE8` / 잉크 `#111` / 형광 오렌지 `#FF6A00`
- 색상 도출: 평소의 깨끗한 화면에는 브랜드나 주제의 색을 사용하고 글리치 때만 “오류색” (분리된 원색 채널, 반전색, 고채도색)을 보인다. 마젠타와 시안 색수차가 가장 흔한 조합이지만 오류색 하나만 쓰거나 밝은 배경과 검은 글자의 글리치도 강한 인상을 줄 수 있다.

## 글꼴
데이터와 깨진 문자에는 모노스페이스 (JetBrains Mono, IBM Plex Mono, Space Mono). 제목에는 굵은 그로테스크체나 좁은 글꼴 (Archivo Black, Space Grotesk, Anton)을 쓰며 잘라내거나 어긋나게 하고 겹칠 수 있다.

## 움직임
- 글리치는 순간적으로 사용: 2–8프레임의 강한 오류를 강박에 맞추고 빠르게 깨끗한 상태로 복귀.
- 깨끗한 상태로 복귀하는 것도 움직임이다. 어긋난 블록은 `snap`으로 제자리에 놓고 채널은 빠른 스프링 `{4, 0.9}`으로 합친다.
- 깨진 문자가 왼쪽에서 오른쪽으로 한 글자씩 정착하며 글자당 30–60ms 간격.
- 가끔 “정지 + 프레임 고정”을 사용: 한 프레임을 3–4회 반복한 뒤 계속 진행.

## 화면에 생동감 더하기
- 평소에는 깨끗하게 둔다. 불량 픽셀 한두 개나 아주 가는 어긋난 선 하나가 가끔 깜빡이는 정도만 허용.
- 배경의 비트 패턴이나 16진수는 밝기를 낮추고 천천히 흐르게 함.
- 큰 글리치는 강박에만 사용. 평소 움직임이 적을수록 글리치의 충격이 커진다.

## 카메라 문법
| 카메라 움직임 | 표현하는 것 | 적합한 콘텐츠 |
|---|---|---|
| 하드 컷 + 2프레임 글리치 | 충격, 전환 | 비트 편집 |
| 모자이크 블록으로 전진하고 그 안에 다음 장면이 있음 | 데이터 내부 진입 | 전환 |
| 화면이 “멈춘” 뒤 다음 장면으로 점프 | 중단, 의외성 | 반전 |
| 데이터모시로 끌어가는 전환 | 기억, 혼란 | 구간 전환 |
| 단계적으로 선명해지며 후퇴 | 복구, 공개 | 엔드카드 |

## 사운드 팔레트
화면의 글리치 프레임에 맞춰 `glitch`, `blip`, 짧은 노이즈 파열음을 사용한다. 음악 버스는 평소 깨끗하게 두고 글리치 순간에 `crush` (4–8 bit)를 갑자기 강하게 적용한다. `kick`과 `snare`에 drive를 더할 수 있다. 1단계 합성이 잘 맞는다.

리듬과 화성 (예시이며 한 가지로 한정하지 않음): IDM 파편 리듬, breakcore, 또는 글리치가 끊어 놓는 깨끗한 four-on-the-floor (같은 오디오의 짧은 구간을 3–4회 반복하는 “테이프” 식 반복 절단). 음 뭉치, 온음 음계, Phrygian. 전체를 조용한 환경음으로 두고 글리치 때 날카로운 디지털 노이즈만 넣을 수도 있다. 소리와 화면 글리치는 같은 프레임에 맞춘다.

## 이 매체만의 표현
- 깨진 문자가 재정렬되어 제목이 됨: 오프닝과 엔드카드의 “디코딩”에 적합.
- 화면이 모자이크로 부서지고 그 안에서 다음 장면이 재구성됨: 업그레이드와 재구성에 적합.
- 데이터모시로 이전 장면의 움직임이 다음 장면의 픽셀을 끌고 감: 전환과 기억 혼란에 적합.
- 픽셀 정렬로 화면이 흐르는 막대처럼 “녹아내림”: 시간의 흐름과 용해에 적합.
- 영상 내내 색수차와 가로줄이 떨림: 고전적인 기법이자 가장 진부한 버전.

## 변주 여지
- 구조: 시스템 침입 → 붕괴 → 복구, 이미지를 계속 압축해 알아볼 수 없게 했다가 복원, 한 문장이 깨진 문자에 먹혔다가 한 글자씩 되살아남.
- 도입: 깨끗한 화면이 갑자기 두 프레임 멈춤, 검은 화면의 깨진 문자 한 줄이 첫 단어로 정착.
- 끝맺음: 글리치가 모두 사라져 유난히 깨끗한 화면과 고정된 로고가 남음, 마지막 프레임에서 한 번 더 글리치.

## 함정
- 글리치가 계속되어 눈이 피로하고 내용이 안 보임: 글리치는 사건으로만 쓰고 평소에는 깨끗하게 둔다.
- 매 프레임 무작위여서 인코딩 후 뭉개지고 파일이 커짐: 프레임 번호를 기준으로 고정 시드를 쓰고 글리치 영역에 구조를 준다.
- RGB 분리가 흐릿한 색수차처럼 됨: 디지털 글리치는 날카로운 경계와 정수 픽셀 이동으로 표현한다.
- 광과민성: 초당 3회가 넘는 전체 화면의 고주파 명암 점멸은 불편을 유발할 수 있으므로 연속적인 전체 화면 흰색 점멸을 피한다.
- 글리치 속에서 글자를 읽을 수 없음: 핵심 문구는 글리치가 끝난 뒤 충분히 깨끗하게 유지한다.
