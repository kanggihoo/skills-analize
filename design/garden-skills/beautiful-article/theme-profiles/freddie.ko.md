# Theme Profile · freddie(Mailchimp의 따뜻한 노랑 / 친근함)

> 이 문서는 **AI가 글을 쓸 때 읽는** authoring profile이지 CSS가 아닙니다. CSS 토큰은 컴포넌트 라이브러리의 runtime theme(`data-theme="freddie"`)에서 관리합니다. 이 파일은 테마를 고르고 사용하는 법을 안내합니다. 자세한 기준 문서는 `src/theme/themes/freddie/freddie.md`에 있습니다(코드 / 공식 / 미디어 / Raw 작성 전에 읽을 것).

- **runtime theme id:** `freddie`(`<ThemeProvider theme="freddie">`)
- **분위기:** 따뜻한 휴머니즘(Mailchimp). 순백색 종이, 거의 검정에 가까운 Peppercorn 잉크, Cavendish 밝은 노랑은 **형광펜 / 색면**으로만 사용(텍스트 색상 금지). 장난스럽고 부드러운 세리프 제목(Fraunces)을 깔끔한 고딕 본문(Hanken) 위에 얹습니다. 재치 있고 친근하며 사람 냄새가 나지만 전문성을 유지합니다. 구조 규율은 그대로 따릅니다.

## 적합한 글 유형 / 적합하지 않은 글 유형

- **적합:** 제품 소개, `tutorial` / 시작 안내, changelog 서사, 기능 `explainer`, FAQ, 친근한 마케팅 어조의 장문. 일반 사용자를 대상으로 따뜻함과 유머가 필요한 콘텐츠.
- **부적합:** 학술 논문(`knuth`), 차가운 시스템 사양(`vignelli`), 어두운 엔지니어링 현장(`shannon`), 극도로 밀도 높은 데이터 보고서(`tufte`), 부드럽고 치유하는 분위기(`andy`), 슬라이드.

## 타이포그래피 분위기

- 제목은 Cooper / Means를 연상시키는 부드럽고 장난스러운 Fraunces, 본문 / 레이블은 Graphik을 연상시키는 Hanken Grotesk를 씁니다.
- 본문은 약 17px, 행간은 1.65. 제목은 `display: 600`과 부드러운 가변 축으로 강조하고 지나치게 굵게 만들지 않습니다. 이탤릭 강조는 금지합니다(프로토콜 수준에서 금지).
- **노랑은 잉크가 아니라 형광펜입니다.** 링크는 검은 글자 + 노란색 highlight(호버 시 채움)로 표시하고 섹션 번호는 검은 글자 + 살짝 기울인 노란 스티커 모양으로 표현합니다.

## Raw 스타일

친근하고 손으로 만든 듯한 제품 설명 일러스트 한 장처럼 보이게 합니다.

- 제한하는 것은 매체가 아니라 **분위기**입니다(검정 / 흰색 / 노랑, 적당히 둥근 모서리, 넉넉한 여백, 약간의 인간적인 따뜻함).
- 일반적인 요소: 단계 / 흐름도, 비교 도식, 노란 highlight 주석, 친근한 소형 데이터 그래프, 펼쳐 볼 수 있는 FAQ.
- 여백을 넉넉하게 두고 노랑은 강조용, 모서리는 적당히 둥글게 처리합니다. 색상은 `--ra-*`만 사용하고 노랑에는 `--mc-yellow`을 씁니다.
- 짧고 약간 튀는 전환은 허용합니다. 무한 반복 장식은 피합니다.

## 미디어(이미지 / 비디오 / 오디오) 스타일

- 잘 어울리는 요소: 둥근 마스코트 / blob 일러스트, 따뜻한 사진, 부드러운 오렌지 그라데이션 배경, 둥근 친근한 아이콘.
- 여백을 넉넉하게 두고 주제를 분명하게 배치합니다. 약간의 불규칙함으로 손맛을 더할 수 있습니다. 캡션은 간결하게 쓰고 alt를 반드시 제공합니다.
- 검정 / 흰색 / 노랑 계열을 사용하고 강조는 노란 면으로 표현합니다. 보라·분홍의 차가운 그라데이션은 넣지 않습니다.

## 코드 / 공식 스타일

- `CodeBlock`은 친근한 코드 샘플처럼 보이게 합니다. 따뜻하고 밝은 surface + 가는 선 + 적당히 둥근 모서리. 어두운 코드 에디터 창은 사용하지 않습니다.
- Prism token은 레이블 / 함수를 잉크색이나 따뜻한 빨강으로, 키워드는 위험 빨강, 문자열은 초록으로 표시합니다. **노랑은 구문 색상으로 사용하지 않습니다.**
- `Formula`는 본문 속 친근한 주석처럼 절제되고 정렬된 형태로 만듭니다. 아주 옅은 둥근 surface를 둘 수 있습니다.

## 금지

- Cavendish 노랑을 텍스트 / 링크 / 구문 색상으로 사용(읽기 어렵고 테마 정체성도 깨짐).
- 보라·분홍 그라데이션, 네온, Tailwind 기본 스타일, 이모지 / 아이콘을 장식처럼 사용.
- 큰 모서리 반경 + 큰 그림자로 카드 더미를 만들지 않습니다(그 부드러움은 `andy`의 영역). 이탤릭으로 강조하지 않습니다.

## 정보 밀도별 표현 제안(권고이며 제한 아님)

- `100% explainer / tutorial`: 친근한 장문 + 단계 카드 + 노란색 callout, 본문을 중심으로 구성.
- `60-80% 产品介绍`: 주요 절차와 스크린샷을 유지하고 노란색으로 포인트를 줍니다.
- `40% briefing`: Raw는 친근한 도식 위주로, 텍스트는 짧게 하되 제품의 친근한 분위기는 유지합니다.
