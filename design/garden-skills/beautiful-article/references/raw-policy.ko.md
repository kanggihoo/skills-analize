# Raw 정책

Raw는 Beautiful Article의 핵심적인 표현 수단이지만 반드시 **테마**와 **글의 형식**을 따라야 합니다. Raw를 작성하기 전에 선택한 테마의 `theme-profiles/<id>.md`에서 Raw 스타일을 확인합니다.

## Raw는 “SVG 그리기”가 아니라 완전한 Web 플랫폼입니다

**Raw 안에서는 임의의 HTML / CSS / JS / React 컴포넌트를 쓸 수 있습니다. 전체 Web 플랫폼을 사용할 수 있습니다.** SVG는 선택 가능한 방법 중 **하나**일 뿐이며 기본값이나 유일한 방법이 아닙니다. Raw를 “인라인 그림 그리기”로만 생각하면 웹의 표현 가능성이 크게 제한됩니다. “이 문단을 가장 잘 설명하는 매체는 무엇인가?”를 기준으로 자유롭게 고릅니다.

- **인터랙션:** 슬라이더 / 토글 / 접기 / 단계 조절기 / 계산기 / 작은 조정 가능 모델 / 가정 시뮬레이션.
- **레이아웃과 타이포그래피:** 나란히 비교, 타임라인, 카드 그리드, 다단 배치, 큰 인용문, 특수한 제목 리듬(HTML + CSS).
- **모션:** CSS transition / `@keyframes` / 스크롤 노출 / 상태 전환 애니메이션.
- **데이터 시각화:** HTML/CSS 막대와 히트맵, `<canvas>`, 필요한 경우에만 `<svg>` 선 그래프 / slopegraph.
- **임베드와 조합:** 표 + 컨트롤 + 텍스트를 결합한 일회성 소형 도구, 복사 가능한 코드 조각, 비교 패널.

판단 기준은 한 문장입니다. **이 문단의 이해 / 논증 / 리듬을 가장 잘 돕는 구현은 무엇인가?** 반사적으로 SVG를 그리지 말고 그 방법을 사용합니다.

## 핵심 원칙

- **재사용 위젯이 아니라 이 글만을 위해 작성합니다.** 모든 Raw는 주변 문단에 맞춰 새로 만들어야 합니다. 토큰 비용을 설명한다면 작은 슬라이더를 만들고, 두 방식을 비교한다면 비교 패널을 만들며, 용량 추세를 설명할 때만 선 그래프를 고려합니다. **Raw를 글마다 재사용하는 고정 위젯 모음으로 만들지 않습니다**(같은 파이프라인 / 같은 팔레트를 곳곳에 사용). 그러면 자유 표현 레이어가 또 하나의 제한된 컴포넌트 묶음으로 바뀝니다.
- **자유롭게 구성하되 테마는 일관되게 따릅니다.** Raw 안에서는 임의 HTML / React 컴포넌트, `<style>`과 `@keyframes`, 인라인 스타일, `<canvas>`, 필요에 따른 `<svg>`, 일회성 인터랙션을 자유롭게 사용합니다. 단, 색상 / 글꼴 / 간격은 테마 토큰(`var(--ra-color-accent)`, `var(--ra-font-body)`, `var(--ra-space-4)` 등)을 사용합니다. 그러면 각 블록이 독창적이면서도 테마 전환을 따라갑니다.

## 허용

문단에 실제로 도움이 되는 모든 HTML / CSS / JS / React를 쓸 수 있습니다. 가벼운 인터랙티브 설명, 조정 가능한 소형 도구, 사용자 지정 레이아웃과 타이포그래피, 나란히 비교, 개념 애니메이션, 읽는 리듬을 위한 시각적 쉼, 필요한 SVG / canvas 도식 등이 해당합니다. 현재 문단에 맞춘 일회성 구현이어야 합니다.

## 금지

복잡한 양식, 드래그 작업대, 완전한 대시보드, 글과 무관한 애니메이션, 테마와 독립된 팔레트, 고정 소형 위젯을 자유 표현인 것처럼 재사용하는 행위.

## Raw 예시(매번 새로 작성하며 고정 위젯을 재사용하지 않음)

> 아래는 흔히 쓰는 기법(SVG / CSS 애니메이션 / React 인터랙션) 몇 가지 예시일 뿐입니다. **전체 목록이나 우선순위가 아닙니다.** 레이아웃, 타이포그래피, 비교 패널, `<canvas>`, 임베디드 소형 도구도 사용할 수 있습니다. “이 문단을 가장 잘 설명하는 방법”을 선택합니다.

```tsx
// 1) 需要曲线时，才为这个数据点手画一条内联 SVG（不是默认手段）
<Raw title="构建体积走势">
  <svg viewBox="0 0 300 80" width="100%">
    <polyline points={pts} fill="none" stroke="var(--ra-color-accent)" strokeWidth="2" />
  </svg>
</Raw>

// 2) 带一次性 CSS / @keyframes 的 HTML 字符串（内联进产物）
<Raw html={`
  <style>@keyframes ra-rise{from{height:0}to{height:var(--h)}}</style>
  <div style="display:flex;gap:8px;align-items:flex-end;height:80px">
    <i style="--h:60%;flex:1;background:var(--ra-color-accent);animation:ra-rise .6s ease"></i>
    <i style="--h:90%;flex:1;background:var(--ra-color-accent);animation:ra-rise .8s ease"></i>
  </div>
`} />

// 3) 只为这篇文章定义的一个小交互组件
function TokenScale() {
  const [n, setN] = useState(50);
  return (
    <div>
      <input type="range" value={n} onChange={(e) => setN(+e.target.value)} />
      <span style={{ color: "var(--ra-color-accent)" }}>{n}%</span>
    </div>
  );
}
<Raw title="拖动感受差距"><TokenScale /></Raw>
```


한 글 안에서 기법을 바꿔 보세요. 서로 다른 매체, 레이아웃, 인터랙션을 활용해 두 Raw 블록이 똑같아 보이지 않게 합니다. 변화는 좋지만 **테마 분위기를 어기면 안 됩니다.** `tufte` 테마의 Raw는 발광하는 마케팅 대시보드처럼 보이면 안 됩니다. `press` 테마의 Raw도 차가운 네온 터미널이 되면 안 됩니다(테마 문서에서 명시적으로 허용한 경우 제외).

## Raw 자체 점검

- 이 Raw를 삭제하면 글의 이해가 어려워지는가?
- 어느 문단 / 논지를 돕는가?
- `--ra-*` 토큰을 사용하는가? 테마 문서를 따르는가?
- 글보다 앱처럼 느껴지는가? 그렇다면 삭제하거나 읽기를 돕는 설명용 시각 요소 / 타이포그래피로 줄입니다.
