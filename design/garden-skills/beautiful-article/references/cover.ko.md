# 글 표지(Cover) — 디자인 가이드

## 표지란?

Beautiful Article의 각 글에는 TOC와 본문 위에 **책 표지처럼 보이는 표지 이미지**가 배치됩니다. HTML 글을 출판물처럼 시작하게 하는 페이지 상단의 독립 영역으로, 책 표지 / 잡지 커버 / 음반 재킷에 해당합니다. 한눈에 **“이 글은 무엇을 다루며 어떤 분위기인가”**를 전달해 독자가 계속 읽을지 결정하게 합니다.

표지는 Hero와 **다릅니다.**

| 역할 | Hero | Cover |
| --- | --- | --- |
| 위치 | `<Article>` 안, TOC 옆 | `<Article>` **밖**, TOC **위** |
| 형태 | 제목 + 부제 + 메타데이터(텍스트 영역) | 3:4 이미지와 텍스트를 결합한 구성 |
| 기능 | 주제와 독자가 얻을 것을 설정 | 시각적 훅 + 스타일 분위기 설정 |
| 정보 비중 | 텍스트 중심 | **이미지 중심, 텍스트 보조** |

두 요소는 **서로 보완합니다.** 표지는 관심을 끌고 Hero는 글을 고정합니다. **같은 일을 반복하게 만들지 않습니다.**

## 크기 · 화면에서는 3:4 한 화면에 완전히 표시 / PDF에서는 첫 페이지 단독 사용

- **화면:** `aspect-ratio: 3 / 4`를 유지합니다. 너비에는 **두 가지 상한 중 작은 값**을 적용해 3:4 표지 전체가 **스크롤 없이 한 화면 안에** 보여야 합니다.
  1. `48rem`(768px) — 하드 상한. 그보다 크면 책 표지가 아니라 광고판처럼 보입니다.
  2. `calc((100vh - 8rem) * 3 / 4)` — 뷰포트 높이에서 너비를 계산하고 상단 바 / 컨테이너 여백 / 위아래 여유 공간을 위해 8rem(128px)을 남깁니다.

  즉 `max-width: min(100%, 48rem, calc((100vh - 8rem) * 3 / 4))`로 설정합니다. 세로가 짧은 화면에서는 표지가 같은 3:4 비율로 자동 축소되고, 1024px보다 높고 넉넉한 화면에서는 768×1024로 유지됩니다.
- **PDF:** `@media print`에서도 기본적으로 화면과 같은 3:4 구성을 유지하고 표지 뒤에서 페이지를 나눠 PDF 첫 페이지를 표지만으로 채웁니다. 표지를 강제로 한 장 높이에 맞추기 위해 일반적인 `height: 100vh`에 의존하지 마세요. Chromium 인쇄는 복잡한 표지 내부 레이아웃을 안정적으로 처리하지 못합니다.

A4 비율(1:√2 ≈ 0.707)이 아니라 3:4를 쓰는 이유:

| 비율 | 값 | 인상 |
| --- | --- | --- |
| 16:9 | 1.78 | 너무 넓어 배너처럼 보임 |
| A4(1:√2) | 0.707 | 너무 길어 보고서 내지처럼 보임 |
| **3:4** | **0.75** | **책 표지처럼 보이며 A4와 Letter 중간 비율** |
| 2:3 | 0.667 | 소설 표지처럼 폭이 좁음 |

3:4 표지는 A4 PDF에서 위아래로 약 4%, Letter PDF에서 약 3%의 흰 여백이 생깁니다. PDF 렌더링을 안정적으로 유지하기 위해 이 비율 차이는 기본으로 둡니다.

**디자이너에게 미치는 영향:** 기본 PDF에서 표지 비율을 바꾸지는 않지만 내부 레이아웃은 반응형이어야 합니다. 백분율 / `aspect-ratio` / `inset: 0` / `grid` / `flex`로 요소를 배치합니다. **요소 위치를 절대 픽셀 값으로 고정하지 않습니다.** 그렇지 않으면 뷰포트나 인쇄 배율이 바뀔 때 어긋날 수 있습니다.

## 하드 제약(5개 · 타협 불가)

1. **화면의 3:4 비율 + PDF 첫 페이지 단독 사용(외부 프레임은 수정 금지).** `Cover.tsx`의 `aspectRatio: "3 / 4"`와 max-width / margin / border를 바꾸지 않습니다. `pdf-print-overrides.css` C 구간은 표지 다음 페이지로 넘어가게 하는 용도입니다. **내부 요소에는 백분율 / 상대 단위만 사용하고** 픽셀로 높이를 고정하지 않습니다.
2. **이미지와 텍스트를 함께 사용합니다.** **텍스트만 있는 표지는 금지합니다.** 반드시 다음 두 요소가 있어야 합니다.
   - **시각적 주 요소**(기술은 자유롭게 선택 가능. 아래 참고)
   - **텍스트 레이어**: 최소 제목 하나. 필요하면 부제 한 줄, 작은 레이블(type / date / kicker) 추가 가능.
3. **테마 준수 · `--ra-*` 토큰만 사용.** 색상 / 글자 크기 / 굵기 / 테두리 / 모서리 반경 / 간격은 모두 `var(--ra-color-fg)`, `var(--ra-color-accent)`, `var(--ra-text-3xl)` 등으로 지정합니다. **금지:** 고정 hex 색상, 고정 글꼴 이름, 픽셀 단위 고정 글자 크기. 테마를 바꾸면 표지까지 함께 깨집니다.
4. **내용과 일치합니다.** 시각적 주 요소는 장식이 아니라 **본문의 핵심 주제와 연결되어야** 합니다. 표지를 본 독자가 글이 어떤 분야인지, 어떤 주장을 하는지 짐작할 수 있어야 합니다. 예를 들면:
   - “프롬프트 캐싱이 전부다”를 다루는 글 → 캐시 적중률 곡선 / 중복 토큰을 강조하는 띠를 표현.
   - “Codex 에이전트 루프”를 다루는 글 → 화살표가 있는 순환 도식(USER → MODEL → TOOL).
   - “색상 충돌”을 다루는 글 → 서로 보색인 두 색면을 기하학적으로 콜라주.
5. **오프라인 우선.** **엄격히 금지되는 유일한 항목은 외부 이미지**입니다. `<img src="https://...">`, Google Fonts 동적 로드, 외부 도메인을 사용하는 CSS background URL은 오프라인에서 동작하지 않습니다.
   **base64 래스터 이미지**는 Plan Checkpoint의 이미지 모드가 `user-assets` / `ai-generated`일 때만 허용하며 문서에 인라인으로 포함해야 합니다.

## 시각 기법 · 모델이 자유롭게 선택

표지의 시각적 주 요소에 사용할 기술은 **모델이 결정합니다.** SVG / CSS / Canvas / WebGL / 글꼴 / 이모지 / 복잡한 React 컴포넌트 / mask / clip-path / filter / 다층 합성 / 자유로운 조합 모두 가능합니다. **정해진 “우선 기법”은 없으며**, 해당 글과 테마에 가장 잘 어울리는 방식을 고릅니다.

사용 가능한 기법 예시(전체 목록은 아님):

- **인라인 SVG:** 격자 / 곡선 / 노드-엣지 도식 / 흐름 화살표 / 벡터 삽화 / pattern fill / mask. 어떤 크기에서도 선명하며 `currentColor`가 테마를 자동으로 따릅니다.
- **CSS 기하 형태 / gradient / clip-path / backdrop-filter:** 화면 분할 색면, 유리 질감, 빛, 추상적인 타이포그래피. 포스터나 그래픽 디자인 느낌의 표지에 적합합니다.
- **`<canvas>` + JS:** 입자 / 유체 / 노이즈 / 절차적 텍스처 / ASCII 아트. 데이터 / 기술 / 생성형 아트 분위기에 적합합니다. Canvas는 PDF에서 **첫 프레임만** 렌더링하므로 애니메이션의 첫 프레임 자체가 완성된 이미지여야 합니다.
- **복잡한 React 컴포넌트:** grid와 조건부 렌더링으로 “목차형 표지”를 만들거나 React로 제목 글자를 재배치하는 등 자유롭게 구성합니다.
- **글꼴 / 타이포그래피 자체를 이미지처럼 활용:** 매우 큰 글자, 자간 / 행간 실험, 글자 겹치기, 이모지 콜라주, 기하학 유니코드 문자(`◐ ▲ ◆ ╳`), 따옴표 / 장 번호를 크게 배치해 페이지를 채우기.
- **다층 합성:** 배경 레이어(gradient) + 중간 레이어(SVG) + 전경 레이어(텍스트) + 장식 레이어(아이콘 / 레이블).
- **혼합:** 위 기법을 여러 개 겹쳐 사용할 수 있습니다. 표지는 한 번 만드는 디자인이므로 단일 기술 스택에 얽매일 이유가 없습니다.

**허용되지 않는 유일한 기법은 외부 이미지입니다**(하드 제약 5 참고). 나머지는 **모두 자유롭게 선택할 수 있습니다.**

**판단 기준:** 3초 동안 눈을 가늘게 뜨고 봅니다(이미지가 괜찮은가? 분위기가 맞는가? 테마를 바꿔도 유지되는가? 인쇄해도 어긋나지 않는가?). 네 가지 모두 통과하면 구현 기술은 자유입니다.

## 반례( **금지** )

- **텍스트만 있는 표지**(제목만 중앙에 있고 시각적 주 요소가 없음).
- **외부 이미지 사용**(`<img src="https://...">`, `background-image: url(https://…)`) — 오프라인에서 열리지 않음.
- **색상 / 글꼴 / 픽셀 값을 고정**(`color: #ff0066` / `font: 24px Helvetica`) — 테마를 바꾸면 깨짐.
- **3:4에서 위치를 절대 픽셀로 고정**(`top: 384px`) — 뷰포트나 인쇄 배율이 바뀌면 어긋남.
- **Hero 내용을 표지에 그대로 반복**(제목, 부제, 날짜, 작성자를 전부 표지에 넣기) — Hero와 중복됨.
- **요소를 너무 많이 배치**(제목 + 부제 + 작은 태그 세 개 + 메타 정보 + Lead + TOC 미리보기 + 큰 삽화 + QR 코드) — 정보가 과밀해져 표지가 아니라 대시보드처럼 보임.
- **내부 요소가 컨테이너를 벗어남**(absolute 자식 요소를 3:4 경계 밖으로 배치) — PDF에서 잘릴 수 있음.
- **표지에 본문을 넣음**(첫 단락의 핵심 내용을 표지에 적기) — 표지는 본문이 아니라 독자를 끄는 요소.
- **시간이 지나야 보이는 Canvas 애니메이션에 의존**(PDF는 첫 프레임만 캡처해 검은 화면이 될 수 있음) — 첫 프레임만으로도 완성도 있어야 함.

## 자체 점검( **필수 통과 5개** )

표지를 만든 뒤 다음 다섯 항목을 확인합니다. 하나라도 실패하면 고친 뒤 제출합니다.

1. **이미지와 텍스트를 모두 사용:** 텍스트 레이어를 가려도 시각적 주 요소가 남는가? 시각 레이어를 가려도 텍스트가 남는가? 둘 다 있어야 합니다.
2. **테마 충실도:** `theme-profiles/index.json`의 다른 테마로 전환해도(`main.tsx` 한 줄 변경) 표지의 색상 / 글꼴이 **자동으로 바뀌고 형태가 무너지지 않는가?** 값을 고정했다면 통과가 아닙니다.
3. **내용 충실도:** 표지를 5초 봤을 때 글이 무엇을 다루는지 짐작할 수 있는가? “예쁜 그림”만 보이고 본문과 관계가 약하면 실패입니다.
4. **비율 적응성:** 컨테이너를 3:4(화면)에서 약 3:4.2(A4) / 3:3.9(Letter)로 바꿔도 요소가 넘치거나 어긋나거나 큰 빈 공간이 생기지 않는가?(`position:absolute; inset:0` + `grid` / `flex`로 요소를 배치하고 픽셀 위치를 고정하지 않으면 자연히 통과합니다.)
5. **Hero와 중복하지 않기:** 표지 텍스트와 Hero 텍스트가 다른가?(표지는 훅, Hero는 기준점입니다.)

## PDF 표시

`scripts/pdf-print-overrides.css`의 C 구간은 표지에 다음을 적용합니다.

- **3:4 표지 프레임 유지** — Chromium 인쇄에서 강제로 늘릴 때 내부 레이아웃이 잘리지 않도록 합니다.
- **`break-after: always` 적용** — TOC가 두 번째 페이지부터 시작합니다.

결과: PDF 1페이지는 3:4 표지만 단독 표시되고, 2페이지부터 TOC와 본문이 시작됩니다.

> **페이지 전체를 채우는 표지가 필요할 때:** 해당 글에서 `.ra-cover` 전용 print 스타일을 추가할 수 있지만, PDF를 내보내 직접 눈으로 확인해야 합니다. 페이지 전체로 늘이는 방식을 일반 기본값으로 사용하지 마세요.

---

## 표지를 끄는 경우(`--no-cover`)

대부분(99%)의 경우 표지를 사용해야 합니다. 끌 수 있는 드문 경우:

- **briefing**(의사 결정 요약 / 바쁜 독자를 위한 글): 사용자가 “열자마자 핵심을 보고 싶다”고 하면 표지가 방해가 될 수 있습니다.
- **dialogue**(대화 / 인터뷰): 대화 흐름이 중심이므로 표지의 역할이 크지 않습니다. 생략할 수 있습니다.
- **사용자가 명시적으로 끄도록 요청:** 요청을 따릅니다.

끄는 방법:

- 스캐폴딩할 때: `bash scripts/scaffold.sh <dir> --theme=<id> --no-cover`.
- 이미 생성된 프로젝트: `article/main.tsx`에서 `<Cover />` import와 렌더링을 지웁니다. 필요하면 `Cover.tsx`도 삭제합니다.
