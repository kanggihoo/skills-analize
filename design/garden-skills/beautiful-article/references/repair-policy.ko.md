# 수정 정책(최소 범위)

가능한 한 작은 단위로 수정합니다. 실제로 수정이 있는 경우에만 `review/repair-log.md`를 작성합니다(한 번에 통과하거나 수정이 없으면 파일을 만들지 않음).

## 금지

- 사용자가 한 문제만 지적했는데 **글 전체를 다시 작성**하지 않습니다.
- 시각적 문제를 고치려고 **이미 확인된 글의 구조를 변경**하지 않습니다.
- 정보를 압축하기 위해 사용자가 **반드시 보존하라고 지정한** 내용을 삭제하지 않습니다.

## 최소 수정 단위

| 문제 | 최소 수정 범위 |
| --- | --- |
| 정보 누락 | 해당 Section / Table / CodeBlock |
| 정보가 지나치게 빽빽함 | 해당 Section의 문단과 로컬 Raw |
| 테마가 맞지 않음 | `plan/plan.md`의 Theme 단락 + 해당 token / Raw |
| 이미지가 맞지 않음 | 해당 이미지와 `plan/plan.md`의 Assets 단락 |
| 첫 화면이 맞지 않음 | Hero / Lead / Summary |
| Raw가 방향을 벗어남 | Raw block 하나 |
| 모바일 문제 | 해당 CSS / 컴포넌트 레이아웃 |
| 빌드 오류 | 오류가 난 파일과 행 |

## repair-log.md 형식

```markdown
## <日期> <谁反馈 / 哪个 Reviewer>
- 问题：<一句话>
- 定位层：<节奏 / 视觉 / 内容 / 构建>
- 最小修复单位：<Section 03 / raw-blocks/02 / main.tsx 主题 ...>
- 改动：<改了什么>
- 验证：<dev 预览 / npm run html 通过 / 控制台无错>
```


먼저 어느 층의 문제인지(콘텐츠 / 구조 / 시각 / 빌드) 확인한 다음 가장 작은 범위만 수정합니다. **글 전체를 다시 만들지 않습니다.**
