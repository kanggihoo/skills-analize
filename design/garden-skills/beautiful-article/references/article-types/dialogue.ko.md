# 글 유형 · 대화

대화 / Q&A / 인터뷰 / 팟캐스트 녹취 / AMA / 라운드테이블 등 **여러 화자가 번갈아 말하는** 모든 콘텐츠 형식입니다.

- **권장 정보 보존율:** 80%(군더더기, 반복, 인사말은 삭제하되 핵심 내용은 보존하고, 의견을 삭제하거나 어조를 바꾸지 않습니다).
- **전형적인 구조:** `Hero`(주제 + 게스트 + 진행자 + 날짜 / 출처) → `Lead`(배경 / 대화하는 이유) → 여러 `Section`(각 절마다 하나의 주제나 질문, 발언자를 명시하고 `Quote`를 충분히 사용해 대화 리듬을 살림) → 선택적 `Summary`(핵심 의견 요약을 글의 시작이나 끝에 배치) → `Conclusion`(요점 / 추가 읽을거리).
- **컴포넌트 선택:**
- 본문 **각 문단의 첫 부분에 발언자를 표시**합니다(예: `**A**：…` / `**主持**：…`). 누가 말하는지 혼동되지 않게 합니다.
  - `Quote`를 충분히 사용합니다. 게스트의 인상적인 문장, 원문 발언, 핵심 정의를 인용문으로 강조합니다.
  - 정의 / 데이터 / 개념 설명에는 `Aside tone="principle"`을 씁니다.
  - 빠르게 읽는 독자도 핵심을 파악하도록 처음에 `Summary`로 “핵심 의견 3–5개”를 제시할 수 있습니다.
  - `Table` / `CodeBlock`은 드물게 사용합니다(대화에 구조화된 기술 콘텐츠가 있는 경우가 많지 않습니다. 필요하다면 게스트의 원문 그대로 코드 블록에 담습니다).
  - 선택적인 부연 / 주석은 `Detail`로 접어 둡니다.
- **Raw 사용 기준:** 주제 지도(섹션 탐색 / 타임라인), 핵심 개념의 시각화(게스트가 설명하는 메커니즘을 Raw 도식으로 표현), 인용 카드에 사용할 수 있습니다. 장식용 댓글 흐름이나 애니메이션 아바타는 만들지 않습니다.
- **이미지 성향:** 게스트 사진 / 현장 사진 / 언급한 스크린샷은 `user-assets`를 사용하고, 텍스트 중심 대화라면 `none`을 선택합니다. 분위기용 `ai-generated` 이미지는 적게 씁니다.
- **테마 성향:** `press`(출판 편집 감각, 긴 대화 / 인터뷰에 적합), `bodoni`(잡지식 인터뷰), `freddie`(활기 있는 팟캐스트 분위기).
- **자체 점검:**
  - 누가 말했는지 명확해 독자가 혼동하지 않는가?
  - 대화의 리듬이 보존됐는가? “한 목소리의 요약문”으로 뭉뚱그리지 않았는가?
  - 핵심 의견을 30초 안에 Summary에서 파악할 수 있는가?
  - 편집 후에도 게스트의 의도가 바뀌거나 잘못 전달되지 않는가?
  - 모바일에서도 발언자 표시가 분명한가?

> **향후 확장:** reacticle 컴포넌트 라이브러리에 `Dialogue` / `Speaker` 전용 컴포넌트가 추가되면 우선 사용해야 합니다. 현재는 `Quote`와 본문 내 명시적 발언자 표시로 충분합니다.
