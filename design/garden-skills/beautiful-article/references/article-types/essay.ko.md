# 글 유형 · 에세이

의견, 논평, 서사, 리뷰(제품 / 책 / 논문 / 영화), 수필, 칼럼, 선언문처럼 **관점 중심의 논픽션 글**입니다.

- **권장 정보 보존율:** 60–80%(논증의 흐름과 가장 강한 사례는 남기고 곁가지, 지나치게 긴 인용, 같은 말을 바꿔 반복하는 부분은 삭제).
- **전형적인 구조:** `Hero`(개성이 분명한 제목) → `Lead`(**긴장감 / 모순 / 반직관적인 질문을 던져** 독자의 관심을 끔) → `Section`: 도입 → 주장 → 사례 → 전환 → 마무리. 구조는 **서사 리듬에 맞추며 대칭적일 필요가 없습니다.** 에세이는 리듬에 따라 섹션 3개일 수도 7개일 수도 있습니다.
- **컴포넌트 선택:** 본문이 **절대적인 중심**입니다. 인용문, 원문 발언, 반대 의견은 `Quote`로 강조합니다. 여백 설명 / 개인 의견 / 반대 입장에는 `Aside tone="aside"`를 사용합니다. `Table` / `RiskList` 같은 데이터 컴포넌트는 서사 감각을 깨므로 **적게 사용합니다.** 긴 에세이에서만 `Summary`를 추가합니다.
- **Raw 사용 기준:** 이야기 전개를 돕는 표현력 있는 시각적 쉼(리듬 도표 / 개념 비교 / 감정 곡선)을 가끔 사용합니다. 메커니즘 설명이 아니라 서사를 돕도록 합니다. 밀도는 낮게 유지합니다. 에세이에는 Raw 블록 1–3개면 충분합니다.
- **이미지 성향:** `press`의 따뜻한 편집 사진 / 삽화 / 원고 이미지를 사용합니다. 분위기를 뒷받침하되 **텍스트보다 앞서지 않게** 합니다. 리뷰형 에세이에서는 제품 / 책 / 영화의 스크린샷 등 `user-assets`를 활용할 수 있습니다.
- **테마 성향:** `press`(출판 편집 스타일), `bodoni`(칼럼 / 특집), `andy`(부드러운 서사), `sottsass`(활기 있는 문화 논평).
- **자체 점검:**
  - **명확한 논증 / 서사 흐름**이 있는가? 독자가 이 글의 핵심 주장을 한 문장으로 다시 말할 수 있는가?
  - 사례가 설득력 있는가? 막연한 주장 대신 구체적인 예시를 최소 두 개 제시했는가?
  - 어조가 일관되고 **사람이 쓴 글처럼** 느껴지는가(AI 티나 틀에 박힌 전개가 없는가)?
  - Lead가 배경만 미지근하게 설명하는 대신 실제로 긴장감을 만드는가?
  - 결말에서 독자에게 생각할 거리를 남기는가(꼭 결론일 필요는 없으며 새로운 질문 / 관점도 가능)?

> **에세이를 사용하지 말아야 할 때:**
>
> - **엔지니어링 결과물**(PR / 계획 / 사고)을 검토하는 경우 → `review`.
> - 독자가 결정을 내려야 하는 경우 → `briefing`.
> - 메커니즘을 분명하게 설명해야 하는 경우 → `explainer`.
> - 대화 / 인터뷰를 정리하는 경우 → `dialogue`.
