# 글 유형 · 종합 보고서

연구 보고서, 공식 분석, 기술 평가, 연간 회고, 설문 보고서에 사용합니다. 원본에 “요약 + 주요 결과 + 데이터 + 위험 + 권고” 구조가 있거나 그 구조로 재편할 수 있어야 합니다.

- **권장 정보 보존율:** 80%(원자료를 소화해 보고서로 구성합니다. 중복되는 추론, 추가 읽을거리, 부록 세부 사항은 생략하되 **요약 / 핵심 발견 / 데이터 / 위험 / 권고**는 모두 유지합니다.) 사용자가 원본 보고서 전체를 그대로 보존하려는 경우에만 100%로 설정하고 `plan/plan.md`의 Brief 단락에 “비표준 조합”으로 기록합니다.
- **전형적인 구조:** `Hero`(제목 + 보고 기간 / 범위 / 작성자 / 조직) → `Summary`(**필수: 실행 요약 / 핵심 결론을 먼저 제시**) → `Section`: 배경과 방법 → 주요 결과 → 데이터와 근거 → 위험과 한계 → 권고와 다음 단계 → `Conclusion`(핵심 결론 재진술 + 의사 결정 제안). **`TOC`는 반드시 켭니다.**
- **컴포넌트 선택:** `Summary`에는 “핵심 결론 + 핵심 데이터”를 넣어 빠르게 읽는 사람도 30초 안에 요점을 파악하도록 합니다. 데이터 / 비교는 `Table`, 위험과 상충 요소는 `RiskList` / `Decision` / `Tradeoff`, 기술적 근거는 `CodeBlock` / `Formula`, 권고 목록은 `ActionList`를 사용합니다. 논증 과정은 본문으로 전합니다.
- **Raw 사용 기준:** 데이터 차트, 추세, 비교 매트릭스, 위험 히트맵, 의존 관계 등은 Raw 자유 형식(HTML / CSS 차트와 매트릭스, 간단한 상호작용, 필요한 경우 SVG / canvas)으로 표현합니다. **근거를 전달하고 장식을 절제합니다.** 애니메이션이 주의를 빼앗거나 분위기용 그라데이션을 쓰지 않게 합니다.
- **이미지 성향:** `none` 또는 실제 데이터 차트 / 보고서 스크린샷을 우선합니다(`tufte` 스타일). **분위기용 이미지나 읽기를 방해하는 삽화는 피합니다.** 제품 스크린샷은 구체적인 결론 하나를 뒷받침해야 합니다.
- **테마 성향:** `tufte`(데이터), `knuth`(학술), `vignelli`(중립적 사양 / 표준 보고서), `fuller`(시스템 설계 / RFC 스타일).
- **자체 점검:**
  - 결론을 글의 첫 30초 안에 파악할 수 있는가?
  - 데이터 / 위험 / 권고가 모두 근거와 함께 있는가(각 권고가 어떤 발견을 바탕으로 하는가)?
  - 마케팅 페이지나 장문 수필이 아니라 **공식 보고서**처럼 보이는가?
  - `Table` / `RiskList` / `Decision`이 내용에 필요해서 사용됐는가, 아니면 “전문적으로 보이기 위해” 억지로 넣었는가?

> **full-report를 사용하지 말아야 할 때:**
>
> - 원본이 연속된 논증 / 서사 중심 장문임 → `longform`.
> - 사용자가 완전한 보고서가 아니라 “상사에게 보여 줄” 의사 결정 요약을 원함 → `briefing`.
> - 구체적인 PR / 계획 / 사고를 검토함 → `review`.
