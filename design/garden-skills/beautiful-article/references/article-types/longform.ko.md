# 글 유형 · 장문

전체 분량의 장문, 아카이브, 심층 읽기에 사용합니다. **기본 유형**입니다. 원본이 일관된 논증 / 서사 / 리뷰이며 사용자가 원문 수준으로 내용을 보존하기 원할 때 선택합니다.

- **권장 정보 보존율:** 100%. 원문의 핵심 내용을 누락하지 않습니다. 명백한 반복 문단과 정보 없는 연결 문장만 삭제할 수 있습니다.
- **전형적인 구조:** `Hero` → `Lead`(주제를 설정하는 도입) → 선택적 `Summary`(TL;DR / 결론 먼저 제시) → 여러 `Section`(필요하면 `Subsection`) → 핵심 개념 주변에 `Raw`로 보강 → `Conclusion`. 섹션이 10개를 넘거나 예상 읽는 시간이 15분을 넘으면 `TOC`를 켭니다.
- **컴포넌트 선택:** 본문 단락이 **압도적인 중심**이어야 하며 글 대부분을 차지합니다. 핵심 직관 / 역사적 주석 / 반대 의견은 `Aside`, 인용이나 원문은 `Quote`, 2차원 데이터는 `Table`, 기술 내용은 `CodeBlock` / `Formula`에 넣습니다. **연속적인 문단을 카드 더미로 쪼개지 않습니다.** 장문의 가장 흔한 형태 변질입니다.
- **Raw 사용 기준:** 핵심 개념, 데이터 추세, 메커니즘 옆에 Raw 자유 형식(간단한 상호작용 / 사용자 지정 레이아웃 / 모션 / 필요한 경우 SVG)을 넣어 리듬과 숨 쉴 공간을 줍니다. 각 블록은 구체적인 문단을 보조하고 `--ra-*` 토큰을 사용합니다. Raw는 **보강 요소이지 중심이 아닙니다.** 주요 정보를 Raw가 맡기 시작했다면 `explainer` 또는 `interactive-explainer`를 고려합니다.
- **이미지 성향:** `none` / `placeholders`를 우선합니다. 기술 / 근거 중심 글에는 실제 데이터 차트(`tufte` 스타일)를 사용할 수 있습니다. 서사형에는 `press` 분위기 이미지를 소량 추가할 수 있습니다.
- **테마 성향:** `tufte`(기술 / 근거), `knuth`(학술 / 논문), `press`(서사 / 리뷰), `bodoni`(칼럼 / 특집).
- **자체 점검:**
  - 본문이 여전히 중심인가? 문단을 카드로 쪼개지 않았는가?
  - 장 사이의 연결이 자연스러워 다음 절을 읽고 싶게 하는가?
  - Raw가 핵심 개념을 빛내는가, 아니면 읽는 흐름을 끊는가?
  - 정보 100%를 보존하면서 원문 복사본이 아니라 세련되게 편집된 장문으로 읽히는가?
  - 독자가 위치를 찾도록 돕는 `TOC` + `Summary`가 있는가?

> **longform을 사용하지 말아야 할 때:**
>
> - 원본이 실행 요약 + 위험 + 권고가 있는 정리된 보고서임 → `full-report`.
> - 메커니즘 / 개념을 설명하며 약 20%를 줄일 수 있음 → `explainer`.
> - 논문 / 장문을 인터랙티브 학습 페이지로 만들고 싶음 → `interactive-explainer`.
> - 바쁜 독자가 결정을 내리기 위한 문서임 → `briefing`.
