# 글 유형 · 튜토리얼

교육, 단계별 안내, 시작 가이드, 설치 / 설정, 마이그레이션 매뉴얼에 사용합니다. 독자가 **따라 하면** 실제로 완료할 수 있는 내용입니다.

- **권장 정보 보존율:** 80–100%. (**단계는 생략하면 안 됩니다.** 빠지면 독자가 따라 할 수 없습니다. 삭제할 수 있는 것은 장황한 배경, 선택적인 심화 내용, 완료에 영향을 주지 않는 “왜” 설명뿐입니다.)
- **전형적인 구조:** `Hero` → `Lead`(무엇을 할 수 있게 되는가 / 사전 조건 / 예상 시간) → 선택적 `Summary`(전체 경로 개관) → `Section`(단계마다 한 절, 절 안에는 목표 → 단계별 절차 → 예시 → 완료 확인 → 흔한 함정) → 선택적 `Section`(연습 / 확장) → `Conclusion`(요약 + 다음 학습 주제).
- **컴포넌트 선택:** 각 단계의 코드는 **정확하고 복사해 실행할 수 있게** `CodeBlock`에 둡니다. 단계와 완료 확인에는 `ActionList` / `Checkpoint`, 함정 / 주의에는 `Aside tone="warning"`, 선택적 심화 설명 / 대안에는 `Detail`, 매개변수 / 옵션 / 설정 비교에는 `Table`, 여러 플랫폼 / 언어 예시에는 `Tabs`를 사용합니다.
- **Raw 사용 기준:** 흐름도, 상태 변화(before / after), UI 단계 그림, 명령 실행 전후 비교에는 Raw 자유 형식(HTML 단계 레이아웃 / 가벼운 인터랙션 / 필요한 경우 SVG)을 사용해 절차를 시각화하고 비교합니다. **모든 단계에 Raw를 넣을 필요는 없습니다.** 코드와 스크린샷으로 충분히 설명되면 추가하지 않습니다.
- **이미지 성향:** `user-assets`를 우선하며 **실제 스크린샷**을 각 핵심 단계에 활용합니다. 순수 명령줄 튜토리얼이라면 `none`을 선택할 수 있습니다.
- **테마 성향:** `vignelli`(중립적 사양 / 문서), `freddie`(활기찬 시작 안내), `fuller`(시스템 설정 / RFC 스타일), `tufte`(정보 밀도가 높은 기술 튜토리얼).
- **자체 점검:**
  - 독자가 따라 했을 때 **실제로 완료할 수 있는가?** 단계가 생략되지 않았고 코드에 “…”을 넣어 완성된 듯 위장하지 않았는가?
  - 단계가 완전하고 순서가 맞는가? 각 단계에 성공 여부를 확인할 기준이 있는가?
  - 코드가 import / 환경 설명 누락 없이 **바로 복사해 실행 가능한가?**
  - 버전 불일치 / 권한 부족 / 플랫폼 차이 같은 함정을 표시했는가?
  - 모바일에서 코드 블록이 넘치지 않고 가로 스크롤할 수 있는가?

> **tutorial을 사용하지 말아야 할 때:**
>
> - 원본이 조작 절차가 아니라 메커니즘을 설명함 → `explainer`.
> - 독자가 **실제로 만들어 보기**보다 **직접 조작해 이해하기**를 원함 → `interactive-explainer`.
> - 원본이 API 문서 / 완전한 사양임 → 참고 문서에 적합한 `longform` + 강제 `TOC`를 사용합니다. 튜토리얼은 참고 매뉴얼로 적합하지 않습니다.
