# 글 유형 · 브리핑

바쁜 사람(의사 결정자 / 동료 / 투자자)이 **빠르게 판단**하도록 작성합니다. 독자는 **글 전체를 읽지 않을 것**이므로 모든 문단이 판단에 도움이 되어야 합니다.

- **권장 정보 보존율:** 40–60%(핵심 결론, 중요 근거, 주요 상충 관계, 다음 단계만 남기고 도입 / 추론 과정 / 배경 / 역사는 제거).
- **전형적인 구조:** `Hero`(제목 = 한 문장 결론) → `Summary`(**결론을 먼저 제시하고 핵심 사실 3–5개**를 나열하는 가장 중요한 부분) → `Section`: 핵심 근거 → 상충 관계 / 위험 → 다음 단계 / 실행 항목. **짧고 밀도 있게 작성해 전체 읽는 시간을 3–5분으로 제한**합니다. `Summary`에서 이미 결론을 말했다면 `Conclusion`은 없어도 됩니다.
- **컴포넌트 선택:** 여전히 **prose-first**를 지킵니다. 본문은 짧고 직접적으로 쓰며(문단당 3문장 이내 권장) `Summary`를 핵심으로 둡니다. 브리핑의 중심입니다. 나머지는 필요할 때만 추가합니다.
  - `Table`: 항목 N개를 나란히 비교해야 할 때만 사용합니다.
  - `Decision` / `Tradeoff`: 실제로 “X vs Y”의 선택 관계를 보여 줘야 할 때 사용합니다.
  - `ActionList`: 다음 단계와 담당자 / 기한을 나열할 필요가 있을 때 사용합니다.
  - **브리핑이라는 이유만으로 컴포넌트를 쌓지 않습니다.** 간결함이 중요하며 컴포넌트가 많으면 오히려 장황해 보입니다.
- **Raw 사용 기준:** 적지만 효과적으로 사용합니다. 핵심 비교 그림 / 추세 / 선택 매트릭스 / 의사 결정 트리 하나면 충분합니다. 시각 자료를 쌓지 않습니다. 보통 브리핑 하나에 Raw 블록 0–2개가 적당합니다.
- **이미지 성향:** `none` 또는 **핵심 이미지 한 장**(데이터 차트 / 중요한 스크린샷)을 사용합니다. `tufte`의 근거 중심 표현이나 `press`의 간결한 편집 디자인이 어울립니다.
- **테마 성향:** `tufte`(데이터 기반 브리핑), `vignelli`(중립적인 사양), `press`(편집 리듬).
- **자체 점검:**
  - 30초 안에(Hero + Summary만 읽고) 결론을 파악할 수 있는가?
  - 모든 문단이 **의사 결정에 도움이 되는가**(이 문단을 삭제하면 결정에 영향을 주는가)?
  - 불필요한 설명, 배경이나 역사, “그 이유는…” 식의 문단이 없는가?
  - 실행 항목을 수행할 수 있는가(담당자 / 기한 / 완료 확인 방법)?
  - 전체 읽는 시간이 실제로 3–5분인가? 더 길면 브리핑이 아닙니다.

> **브리핑을 사용하지 말아야 할 때:**
>
> - 빠른 판단이 아니라 독자가 **전체 내용을 이해**해야 하는 경우 → `longform` / `full-report` / `explainer`.
> - 구체적인 결과물을 평가하는 경우 → `review`.
> - 독자가 개념을 **배우도록** 하는 경우 → `explainer` / `interactive-explainer`.
