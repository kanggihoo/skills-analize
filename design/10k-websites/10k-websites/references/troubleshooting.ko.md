# Troubleshooting: Symptom → Cause → Fix

이 항목들은 모두 실제 빌드에서 일어난 일이다. 가설로 사용하고, 승인된 작업을 바꾸기 전에 실제 원인을 확인한다.

## Generation

| Symptom | Cause | Fix |
|---|---|---|
| 생성기가 생성 대신 프리셋을 제안한다 | 프롬프트를 특정 하우스 스타일로 잘못 매칭했다 | 그 제안을 거절하고 원래 프롬프트로 다시 시도한다. 설계된 샷이 하우스 스타일보다 낫다 |
| 생성 이미지에 실제 로고나 브랜드 마크가 나타난다 | AI가 상표를 슬쩍 넣었다 | 애니메이션을 만들기 전에 요청되지 않은 마크를 제거하되, 승인된 실제 제품 로고와 정체성은 보존한다 |

| 피사체가 얼어붙거나 생기가 없어 보인다 | 경로를 보호하려고 프롬프트가 과하게 안정화했다 | 경로는 고정하고 몸은 풀어 준다. 궤적은 엄격하게 두되, 피사체에는 자연스러운 움직임을, 장면에는 주변의 생동감을 요구한다 |
| 경계 통과(물속으로, 유리를 통과)가 가짜처럼 보인다 | 통과가 너무 깨끗했다 | 렌즈에서 일어나는 물리적 순간을 프롬프트에 쓴다. 물보라, 렌즈 위 물방울, 짧은 흐림 |
| 히어로 제품이 플레이스홀더처럼 읽힌다 | 거리에서 보이는 일반적이고 브랜드 없는 물체다 | 애니메이션 전에 이미지 편집으로 브랜드 마크를 적용하거나, 디자인이 전달되기에 충분히 가깝게 끝나도록 엔딩을 쓴다 |
| 한 컨셉에서 영상 세 개가 실패한다 | 프롬프트 문제가 아니라 컨셉 문제다 | 원인을 진단할 만큼 지출을 멈춘다. 선택한 수준에서 가격과 함께 표적화된 방법, 모델, 스토리 변경을 제안한다. 첫 시도에 성공이 보장되는 컨셉은 없다 |
| 샷은 강하지만 엔딩이 멈추지 않는다(끝에서 피사체가 다시 움직이기 시작한다) | 모델이 도착 구도를 넘어서 계속 애니메이션했다 | 모션이 다시 시작되는 지점을 확인한다. 승인된 속도와 내용을 보존하고, 승인된 행동을 바꾸지 않을 때만 자르기를 제안한다. 그렇지 않으면 수정된 편집이나 재렌더에 대한 합의를 받는다 |
| 연결된 체인이 세그먼트 접합부에서 튄다 | 세그먼트 인코딩 매개변수가 동일하지 않았거나, 세그먼트 사이에서 모션 벡터가 끊겼다 | 모든 세그먼트를 정확히 같은 scrub 명령으로 다시 인코딩한 뒤 다시 concat한다. 모션 자체가 튄다면 다음 세그먼트의 프롬프트가 이전 방향과 속도를 이어받지 못한 것이다 |
| 필름이 스토리가 아니라 부드러운 카메라 이동처럼 느껴진다 | 키프레임이 서로 거의 복사본이거나, 중간 프레임이 차분하다 | 앞선 키프레임을 새 샷으로 다시 만들고(`shots.md`의 스크린샷 테스트), EVENT 프레임을 가장 극적인 그림으로 만들며, 에너지 있는 속도 단어를 쓴다 |
| 모든 키프레임이 같은 사진처럼 보인다 | 레퍼런스가 정체성과 함께 구도까지 복사했다 | 구도, 레퍼런스 강도, 또는 레퍼런스 역할을 바꾼다. 정체성이 텍스트만으로도 살아남을 수 있으면 텍스트 전용 생성을 쓴다. 필요한 제품 레퍼런스는 자동으로 버리지 않는다 |
| 반복되는 그림이 채우기용처럼 느껴진다 | 한 섹션이 새 목적 없이 에셋을 재사용했다 | 반복의 역할을 검사한다. 의도된 모티프나 유용한 비교는 유지하고, 스토리에 필요할 때는 새 구도를 만든다 |
| 체인된 두 세그먼트가 만나는 곳에 보이는 컷이 있는데 모션은 이어진다 | 각 생성이 시작 프레임에서 미세한 질감을 새로 상상하므로, 특정 질감(직조, 입자, 피부)에서의 REST-to-REST 접합부가 컷처럼 보인다 | 다음에는 모든 이음새를 모션이나 질감 새로고침 순간으로 스토리보드한다(`prompt-laws.md`의 seam law). 기존 체인은 먼저 매칭 컷과 중복 끝점을 검사한다. 짧은 블렌드는 검사에서 이중 가장자리 없이 이음새를 개선할 때만 쓴다 |
| 무해한 추상 샷이 nsfw로 표시되어 반려된다 | 안전 필터가 추상적인 감각 언어(빛나는 형태, 형태를 감싸는 흐르는 액체)를 잘못 읽었다 | 먼저 `openart_account_get`으로 잔액을 확인한다. 그다음 같은 시작 프레임을 일반적인 상업 제품 사진 용어로 다시 쓴 프롬프트로 재생성한다. 제품 이름을 앞쪽에 쓰고, 감각이 아니라 사물을 묘사하며, 같은 샷 설계를 유지한다 |

## The hero

보고된 재생 문제는 실제 페이지 URL/스킴, 배포된 버전, 브라우저/기기, 화면에 보이는 상태로 시작한다. 가능하면 사용자의 관련 탭을 확인하고, 없는 정보는 요청한다. 호환성 변경을 제안하기 전에 공개 HTTPS, 제공되는 로컬 미리보기, 직접 연 `file:` 문서를 구분한다. 직접 파일 접근은 브라우저 출처 규칙 때문에 엔진의 영상 가져오기를 막을 수 있다. 브라우저 보안을 약화하는 대신 제공된 URL을 연다.

그다음 hero 클래스, 네트워크 응답, 콘솔, 비디오 준비 상태와 오류를 사용해 의도된 정적 상태(예: 모션 축소), 로딩, 미디어 실패를 구분한다. 가능하면 영향받은 브라우저에서 재현한다. 다른 브라우저에서 통과했다고 사용자의 원인이 식별되지는 않는다. 성공한 seek 중에 취소된 로컬 Blob 읽기는 HTTP 다운로드 실패가 아니다. 접근성 설정이나 브라우저 보호 기능을 추측에 기반한 수정으로 끄지 않는다.

엔진(`scene.js`, `scene.css`)은 부분 다운로드를 지원하지 않는 호스트, 쌓인 seek, 오류 후 얼어붙은 seek, 회전에 대한 휴대폰 게이트, 안정되면 쉬는 렌더 루프를 처리한다. 의심되는 엔진 회귀를 조사하기 전에 프로젝트가 제공된 엔진 파일을 쓰는지 확인하고, 그다음 시연된 실패를 분리한다.

| Symptom | Cause | Fix |
|---|---|---|
| 스크러빙이 끊긴다 | 클립이 스크러빙용으로 인코딩되지 않았거나 매우 크다 | 원본 클립에 `encode.mjs`를 다시 실행한다. 약 12MB를 넘으면 시각 검사로 해상도/CRF를 조정한다. 바이트 목표를 맞추려고 승인된 행동을 자르지 않는다 |
| 히어로에 정지 이미지만 보인다 | 의도된 정적 모드, 미완료 로딩, 또는 실패한 미디어 요청이다 | 먼저 정확한 URL과 상태를 확인한다. 공개 HTTPS URL이나 안전하게 제공되는 로컬 미리보기(`node .10k/tools/preview.mjs site --port 8080`)를 쓴다. `k-media-failed`라면 선택된 `data-src`, 응답, 콘솔을 확인한다. 의도된 모션 축소 동작은 보존한다. |
| 깊이 장면이 가까운 물체 주변에서 번진다 | 가까운 디테일이 얇거나 강도가 너무 크다 | `data-strength`를 낮추거나 `--blur 4`로 `depth.mjs`를 다시 실행한다. 다음에는 더 깨끗한 전경을 계획한다 |
| 깊이 장면이 평평해 보인다 | 그림에 가까움, 중간, 먼 거리가 없다 | `data-strength`를 조금 올리거나, 시작 프레임을 전경 요소와 함께 다시 구성한다 |
| 깊이 히어로의 색이 바래거나 캔버스가 검다 | 그 브라우저에서 WebGL이 꺼져 있거나 이미지 로딩이 실패했다 | 엔진은 포스터로 대체한다. `data-image`와 `data-depth` 경로를 확인한다 |
| 단단한 수평선이 히어로를 가로질러 미끄러진다 | `data-k-layer` 평면이 이동 거리보다 짧다 | 이동 거리만큼 평면을 키우거나, 양 끝에서 페이드한다 |
| 캡션이 완전한 강도에 도달하지 않거나 빠른 플릭으로 건너뛸 수 있다 | 구간에 비해 band 범위가 너무 짧다 | band를 넓히거나, `data-k-span`을 올리거나, 이웃과 합친다 |
| 캡션이 겹친다 | 두 band 범위가 겹친다 | 한 band의 끝과 다음 band의 시작 사이에 약 0.08의 간격을 둔다 |
| 임베디드 미리보기의 스크린샷에서 히어로가 비어 있거나 얼어 있다 | 숨겨진 패널이 애니메이션 프레임을 멈추거나, 캡처가 비디오 레이어를 빠뜨릴 수 있다 | 보이는 표면에서 재생과 미디어 상태를 확인한다. 같은 제공 URL에서 `check.mjs`와 다른 브라우저로 비교한다. 이 비교는 진단 근거이지, 보고된 표면이 동작한다는 증명이 아니다 |
| `check.mjs`가 Chrome을 찾을 수 없다고 한다 | Chrome이나 Edge가 설치되어 있지 않다 | 사용자에게 Google Chrome 설치를 요청하거나, `CHROME`을 다른 Chromium 브라우저의 경로로 설정한다 |
| `.10k/tools`의 `npm install`이 다운로드에서 실패한다 | 패키지가 설치 중 추가 파일을 가져오려 했다 | `--ignore-scripts`를 붙여 다시 실행한다(기본 명령에는 이미 포함되어 있다) |
| `depth.mjs`가 첫 실행에서 멈춘 것처럼 보인다 | 깊이 모델(약 27MB)을 다운로드하는 중이다 | 1분 정도 기다린다. 이후 실행은 몇 초면 끝난다 |
| 필름에 고정된 단어가 빠른 스크롤 중에 표면에 대해 미끄러진다 | 타이프가 스크롤 진행률이나 자체 시계를 따르는데, 엔진의 seek는 뒤처진다 | 표시된 프레임에서 구동한다. `filmtype.js`가 그렇게 한다. 직접 작성한 코드는 `requestVideoFrameCallback` 미디어 시간과 `seeked`를 읽어야 한다. `typesync.mjs`로 확인한다 |
| 추적된 단어가 영상 위에서 표면을 벗어난다 | 추적이 스스로 움직이는 무언가를 따라갔거나, 모델이 그 움직임에 맞지 않는다 | `track.mjs proof` 시트를 연다. 스스로 움직이는 것은 마스킹하고, 더 선명한 영역이나 참조 프레임을 고르고, `--model`을 바꾸거나, `--from`/`--to`로 구간을 자른다 |
| 추적된 단어가 몇 픽셀씩 떨린다 | 질감이 적은 표면에서 측정이 고르지 않다 | 세부가 더 보이는 영역을 고르거나, `--smooth`를 올리거나, 더 단순한 모델을 쓴다. 출력되는 picture-check 수치를 확인한다 |
| 커지는 단어가 반짝이거나 맥박처럼 뛴다 | 라이브 텍스트는 크기마다 다시 렌더링되므로, 매 프레임 가장자리가 픽셀에 다시 맞춰진다 | `filmtype.js`가 그룹을 그리게 한다(약 15% 이상 커지면 자동, 또는 `data-ft-paint="on"`) |
| 먼 단어가 문이나 창틀 앞에 떠 있다 | 개구부를 통해 보이는 먼 표면이 더 가까운 프레임 위에 그려진다 | 개구부 자체의 표면에 `data-ft-window`를 쓰거나, 카메라가 통과한 뒤에야 단어를 페이드 인한다 |
| 단어가 개구부나 화면 밖 반쯤에서 일찍 나타난다 | 표면이 아직 명확히 보이지 않는 곳에서 페이드가 시작된다 | 표면이 분명히 보인 뒤 페이드를 늦춘다(`data-ft-fade`) |
| 휴대폰에서 단어가 잘못된 위치에 있다 | 휴대폰 클립이 다른 크롭이거나 별도의 필름이다 | `track.mjs crop`을 다시 실행한다. 클립이 크롭이 아니라고 하면 `--variant phone`으로 휴대폰 클립을 추적한다 |
| 단어가 한 프레임씩 끊기며 움직인다 | 클립에 반복 프레임이 있다(프레임 레이트 패딩) | 마스터가 아니라 페이지가 재생하는 인코딩된 클립을 추적한다. `track.mjs`는 반복 프레임을 정지시킨다. `encode.mjs`는 더 이상 24fps를 30fps로 바꾸지 않는다 |
| 이탤릭 제목이 기울어 보이고 싸구려처럼 보인다 | 업라이트 폰트 파일만 제공되어 브라우저가 이탤릭을 가짜로 만든다 | 실제 이탤릭 파일을 자체 `@font-face`(`font-style: italic`)와 함께 제공한다 |

## The page

| Symptom | Cause | Fix |
|---|---|---|
| 등장 애니메이션이 재생되지 않고 요소가 그냥 나타난다 | 더 나중의 규칙이 캐스케이드에서 이겨 애니메이션의 시작 상태를 덮었다 | 시작과 끝 상태에 컨테이너 클래스를 붙이고(`.card .part`, `.card.in .part`), 모든 등장이 재생되는지 증명한다 |
| 단계적으로 배치된 그리드의 2번째와 3번째 항목에서 등장이 끝난 뒤에도 호버 반응이 늦다 | stagger `transition-delay`를 0으로 만드는 정리 규칙의 명시도가 그것을 폐기하려는 nth-child 지연 규칙보다 낮다(`:nth-child`는 클래스로 계산된다). 그래서 조용히 적용되지 않는다 | 정리 선택자가 지연 규칙과 같거나 더 높게 맞도록 nth-child를 그 안에 반복하거나, `0s` 지연에 `!important`를 붙인다. 그다음 나중의 형제 요소에 호버해서 증명한다 |
| 스크롤 기반 스타일이 등장 후 반응을 멈춘다 | `animation-fill-mode: forwards`가 영구히 덮어쓴다 | 등장 애니메이션은 부모에, 동적 스타일은 자식에 둔다 |
| 배경 루프가 시작할 때 깜빡이거나 튄다 | 양수 animation delay | 음수 지연(예: `-1.2s`)을 써서 모든 루프가 첫 페인트에서 이미 중간 주기에 있게 한다 |
| 글자 꼬리(g, y, p)가 잘린다 | 마스크되거나 잘린 텍스트에 여유 공간이 0이다 | 마스크에 맞는 음수 margin과 함께 em 기반 padding을 준다 |
| 페이지를 옆으로 끌거나 밀 수 있다 | `overflow-x: hidden`만 쓰였거나, 장식이 가장자리를 넘어 튀어나왔다 | `html`과 `body` 둘 다 `overflow-x: clip`을 주고, 폴백으로 `hidden`을 먼저 쓴다 |
| 스크립트가 실행된 뒤 호버가 튀기 시작한다 | JavaScript가 `el.style.transition`을 덮어썼다 | 전체 결합 transition을 선언한 클래스를 토글한다 |
| 모션 축소를 켜면 모바일 요소가 화면 밖에 놓인다 | 블랭킷 `transform: none !important`가 위치 기반 transform을 지웠다 | 모션 축소 블록 안에서 브레이크포인트별로 위치 transform을 다시 적용한다 |
| 마퀴 루프 지점에 간격이 보인다 | 트랙이 지원되는 가장 넓은 화면보다 짧다 | 각 트랙이 약 2560px를 넘을 때까지 항목을 복제한다 |
| 탭이 숨겨져 있거나 섹션이 화면 밖일 때도 애니메이션이 돈다 | 자유롭게 도는 루프 | 애니메이션 규칙을 IntersectionObserver가 토글하는 클래스로 범위 지정한다. `visibilitychange`에서는 body 클래스 하나를 토글하고 `body.paused *, body.paused *::before, body.paused *::after { animation-play-state: paused !important }`를 쓴다. rAF 루프는 수렴하면 쉰다 |
| 컨테이너에 쓴 일시정지가 그 안의 애니메이션을 실제로 멈추지 않는다 | `animation-play-state`는 상속되지 않는 속성이라, 부모에 설정한 값(또는 중첩 규칙의 `inherit`)이 중첩 요소나 의사 요소에 도달하지 않는다 | 위의 body 클래스 패턴. 모든 요소와 의사 요소에 직접 적용된다 |

## Deploy

| 링크 미리보기에 이미지가 없거나 URL이 잘못 나온다 | og 태그에 여전히 플레이스홀더가 들어 있다 | `<!-- DEPLOY STEP -->` 주석 위치에서 `og:image`와 `og:url`을 라이브 절대 URL로 패치하고, 다시 압축해 재배포한다 |

| 스크립트로 찾아 바꾼 뒤 특수 문자가 깨진다(화살표와 서수 표기가 모지바케가 된다) | 셸 명령이 UTF-8 파일을 잘못된 기본 인코딩으로 읽고, 그 손상을 다시 썼다 | 셸의 일반 읽기/쓰기로 사이트 파일을 패치하지 않는다. og 패치와 모든 텍스트 변경에는 편집 도구를 쓰거나, 명시적 UTF-8로 읽고 쓴다. 이미 발생했다면 복구한다. 손상된 파일을 UTF-8로 읽고, 그 텍스트를 Windows-1252 바이트로 인코딩한 뒤, 그 바이트를 UTF-8로 디코딩하고, UTF-8로 저장하고, 문자를 확인하고, 재배포한다 |

## Setup

| Symptom | Cause | Fix |
|---|---|---|
| 설치 직후 `openart`가 "command not found"다 | 설치 프로그램이 이 셸이 아직 검색하지 않는 `~/.local/bin`에 넣었다 | 이번 세션의 나머지 동안 전체 경로(`~/.local/bin/openart`)로 호출한다. `openart --version`으로 확인한다 |
| OpenArt 로그인이 아무것도 열지 않거나 어디로도 가지 않는 것 같다 | 브라우저가 사용자가 평소 쓰는 브라우저와 다른 곳에서 열렸거나, 로그인 탭이 닫혔다 | 미리 경고하고, 사용자가 다른 브라우저를 확인하게 한 뒤 커넥터 로그인을 다시 실행한다(`codex mcp login openart`). `openart_account_get`으로 확인한다 |
| OpenArt가 작업을 거부한다: 동시에 실행 중인 생성이 너무 많다 | 요금제마다 동시 작업 수에 상한이 있다 | 클립을 먼저 제출하고, 섹션 이미지는 두 개씩 제출한다. 나머지는 앞선 작업이 끝나는 대로 같은 턴 안에서 제출한다 |
| 커넥터를 추가한 뒤 OpenArt 도구가 보이지 않는다 | 호스트가 도구 목록을 새로고침해야 하거나, 커넥터 설정이 불완전하다 | 설정을 확인하고, 실제 호스트가 문서화한 새로고침이나 재시작 경로를 따른다. 현재 채팅과 계획은 보존한 뒤 계정 읽기로 확인한다 |
| 고정한 끝 프레임이 무시되거나 끝에서 클립이 튄다 | 두 키프레임이 하나의 움직임으로 잇기에 너무 다르거나, 프롬프트가 다른 엔딩을 요구한다 | 모든 키프레임을 하나의 세계(같은 팔레트, 빛, 적힌 제품 설명)에 둔다. 중간 키프레임을 추가하거나 옮겨서 각 클립이 덜 이동하게 한다. 하나의 연속 카메라 움직임을 묘사하고, 프롬프트를 "ends exactly on the final frame"으로 끝낸다 |
| 요청하지 않은 물체(드론 프로펠러, 카메라 리그, 추가 손)가 나타난다 | 프롬프트가 카메라 장비(드론, FPV, 크레인)를 언급했다 | "the camera"라고 말하고 경로를 묘사한다. 장비 이름은 절대 쓰지 않는다 |
| `openart_account_get`에 크레딧이 없거나 생성이 잔액 오류로 실패한다 | 요금제나 체험 크레딧이 아직 없는 새 계정이다 | 실제 잔액을 보여 주고, 계획된 경로를 미리 점검하며, 요금제 OpenArt 링크를 공유한다(SKILL.md의 Sign-up links 중 2번 순간). 사용자를 대신해 크레딧을 구매하지 않는다 |
| 영상 모델이 설정(길이, 화면 비율, 해상도, 사운드)을 거부한다 | 그 설정은 모델마다 다르다 | `openart_model_form_get(<id>, "image2video")`을 읽고, 모델이 받지 않는 설정은 빼거나 바꾼다 |
| ChatGPT가 명령마다 승인을 요청한다 | 기본 승인 설정에서는 정상이다 | 사용자에게 설정 단계를 읽고 승인하라고 한 번 알려 준다. 안전 설정을 끄라고 요청하지 않는다 |

| 호스팅 탐색이 컨텍스트를 과하게 소모한다 | 불필요하게 넓은 카탈로그를 불러왔다 | 필요한 작업만 좁게 검색하고 그 스키마를 확인한다. 안정적인 동안에는 현재 채팅을 계속하고, 실제 컨텍스트 제약이 인계를 요구하면 승인을 보존한다 |

| Windows에서 Hostinger 커넥터가 시작되지 않는다 | `npx` 대신 `npx.cmd`가 필요하다 | 명령이나 설정에서 `npx.cmd`를 쓴다 |

| 새 빌드가 필수 요소 검증을 건너뛴다 | 설정이 된 것으로 가정되었다 | 설치된 스킬을 읽고, 실제 필수 요소를 확인하며, 빠진 설정을 완료한다. 이어서 하는 빌드는 저장된 상태에서 계속하고, 온보딩을 반복하지 않는다 |
| 호스팅 호출이 멈추고 로그인 탭이 계속 나타난다 | 커넥터가 인증을 잃었을 수 있다 | 로그인 상태를 확인하고 한 번 복구한다. 필요할 때만 앱을 재시작하고, 계정 읽기로 확인한다. 재시작이 모든 원인을 고친다고 약속하지 않는다 |

**반복되는 멈춤:** 연속된 두 번의 호출에 응답이 없으면 맹목적인 재시도를 멈추고, 인증, 도구 상태, 연결을 진단한다. 의미 있는 복구 단계 후에만 재시도하며, 이미 수락되었을 수 있는 생성이나 배포를 중복시키지 않는다. 진행률을 보고하는 렌더는 여전히 작업 중이다. 복구에 사용자의 입력이 필요하면 작업 ID, 승인된 작업, 다음 행동을 보존한다.

## Tool and workflow repairs

| Symptom | Check and response |
|---|---|
| 인라인 채팅 플레이어에서 필름이 사라진다 | 파일을 디코딩한 뒤 `review.mjs`에서 전체 재생과 탐색을 확인한다. 유효한 파일이라고 전달 표면이 동작한다는 증명은 되지 않는다. |
| 접합부에서 가장자리가 몇 프레임 동안 두 번 나타난다 | 인접한 원본 프레임을 검사하고, 매칭 컷을 시도한 뒤 확인된 중복 끝점 제거만 적용한다. 승인된 전체 흐름은 보존한다. |
| 포스터 인코딩은 실패했지만 영상은 성공했다 | 사용 가능한 WebP 경로를 감지한다. 인코더의 Sharp 대체 경로나 설치된 cwebp를 쓴다. 성공한 영상 결과는 유지하고, 유료 생성을 반복하지 않는다. |
| 공백이 있는 폴더에서 Report가 Lighthouse를 찾지 못한다 | `fileURLToPath(import.meta.url)`을 쓴다. 인코딩된 URL pathname을 파일 시스템 경로로 취급하지 않는다. |
| 로컬 미리보기에서 PHP 파일이 원시 텍스트로 보인다 | 그 미리보기를 멈추고 제공된 안전한 서버를 쓴다. `--seo-only`로 SEO를 생성하며, 백엔드를 일반 정적 서버로 노출하지 않는다. |
| 스크롤 아래 쪽의 약한 효과가 시작을 느리게 한다 | 스크립트와 그래픽 초기화를 측정하고, 가까워질 때까지 지연하거나 더 가벼운 효과를 고른다. 화면 밖 애니메이션을 멈춘다고 초기화가 싸지는 것은 아니다. |
| 분할된 텍스트에서 이탤릭이 사라지거나 ARIA가 잘못되었다 | 작성된 인라인 노드와 하나의 접근 가능한 이름을 보존한다. 제목뿐 아니라 일반 요소도 확인한다. |
| 사용량은 5시간이라고 하는데 며칠 뒤에 초기화된다 | 실제 창 길이를 확인한다. 기본 버킷은 주간일 수 있다. 위치로 기간을 추정하지 않으며, 오래된 초기화가 새로고침되었다고 주장하지 않는다. |
| SEO 점수는 높은데 Google이 차단된다 | 호스트의 실제 robots.txt, robots 태그, X-Robots-Tag 응답을 확인한다. 임시 호스팅은 업로드된 규칙을 덮어쓸 수 있다. |
| 재시작 후 미리보기가 멈춘다 | 이 프로젝트의 서버와 포트를 확인하고, 다시 시작하고, HTTP를 검증한 뒤 URL을 다시 연다. 다른 프로젝트의 리스너를 죽이지 않는다. |
