# $10K 체크리스트

첫 번째 작동 미리보기와 다듬어진 최종 결과를 아래 여덟 가지 항목으로 1점부터 10점까지 채점한다. 엄격하고 구체적으로 채점한다. 모든 제작 수준은 같은 기준을 공유한다. 생성 비용이 더 높다는 이유만으로 점수를 얻지 못한다. 전체 데스크톱과 휴대폰 경험을 사용하고, 스크린샷만이 아니라 실제 영상 재생과 작동하는 컨트롤을 증거로 쓴다.

| 항목 | 10점의 모습 |
|---|---|
| Point of view | 브랜드 세계의 아이디어에 바탕을 둔 분명한 개성이 있다. 이 시그니처 표현은 경쟁사에 그대로 옮겨 붙일 수 없다. |
| Typography | 자신감 있는 구도와 크기, 목적이 분명한 서체와 위계. 핵심 히어로 타입은 실제 영상 안에서 식별 가능한 단서와 함께 이동하거나, 크기가 바뀌거나, 방향이 바뀐 뒤 읽기 위해 자리 잡는다. 휴대폰용 연출은 따로 설계되어 있고, 의미 구조, 강조, 정적 대체 화면은 그대로 유지된다. 일반적인 등장 효과나 페이드만으로는 통과하지 못한다. |
| Color | 시각 세계에서 추출한 일관된 팔레트, 목적이 분명한 대비, 유용한 강조에만 쓰는 액센트. |
| Hierarchy | 모든 화면에 의도된 초점과 분명한 다음 행동이 있다. 페이지는 크기와 밀도를 바꾸고, 이유가 있을 때만 반복하며, 마지막까지 관심을 유지한다. |
| Imagery | 방향이 요구하는 곳에는 아트 디렉션이 적용된 이미지가 있고, 정체성, 빛, 재질이 일관된다. 의도하지 않은 중복, 얼룩, 명백한 생성 결함이 없다. 히어로는 카메라가 흔들리는 것만이 아니라 구성된 이야기를 전한다. 이미지가 적은 페이지는 이미지 수가 아니라 선택된 이미지의 목적과 품질로 판단한다. |
| Motion | 이미지, 타입, 상호작용이 하나의 경험처럼 느껴진다. 기록된 영상 단서와 타입의 관계가 데스크톱과 휴대폰 재생, 역방향 스크롤, 임의의 탐색(seek)에서도 같은 위치에서 같은 상태로 유지된다. 전체 영상과 연결 지점이 자연스럽게 흐르고, 보조 장면은 이야기를 압도하지 않으면서 뒷받침한다. 효과는 가볍게 로드되고 효율적으로 실행된다. |
| Mobile | 세로 방향의 전체 이야기가 구성되어 있고, 읽기 쉬우며, 도달 가능하다. 모든 장면과 연결 지점이 살아남고, 컨트롤은 쓰기 쉽고, 페이지는 실제 네트워크에서도 잘 로드된다. 자르기(crop)는 적절한 경우 전용 처리와 비교해 평가한다. |
| Polish | 빠른 로딩, 콘솔 오류와 레이아웃 흔들림 없음, 사실에 맞는 문구, 작동하는 내비게이션과 폼 상태, 키보드 접근성, 구성된 영상 실패/동작 감소(reduced-motion) 대체 화면. |

초기 시각 처리 검토 단계에서는 히어로, 하단 섹션, 휴대폰 화면이 해결하는 창작상의 질문을 기록한다. 첫 번째 전체 미리보기에서는 채점표를 보여 주고, 경험에 가장 큰 영향을 주는 가장 약한 세 항목을 고른다. 각 항목에 구체적인 개선안을 하나씩 제시한 뒤, 승인된 제작 계획 안에서 다듬기 작업을 마친다.

넓은 화면, 울트라와이드, 휴대폰 너비 등 관련 있는 너비에서 모든 하단 섹션의 안정된 자르기 화면을 포함한다. 폰트, 미디어, 등장 효과가 모두 끝난 뒤에 캡처한다. 각 섹션의 시각적 또는 설명적 초점과 다음 유용한 단계를 적는다. 모든 섹션에 장식이나 CTA를 요구하지 않는다. 검토자를 쓸 수 있으면 가장 약한 비히어로 섹션에 대한 독립적인 비평을 기록한다. 그렇지 않으면 별도의 비판적 자기 검토를 기록한다. 관련 있는 대안 하나와 선택한 처리의 이유를 함께 적는다. 개선은 승인된 범위 안에서 자율적으로 완료한다. 타이포그래피, 여백, 강한 히어로만으로는 높은 전체 점수를 정당화할 수 없다.

타이포그래피와 모션에 대해서는, 선택한 영상 버전과 관찰한 단서 시간을 해당 타입 움직임과 함께 적는다. 추적된 타입에 대해서는 `track.mjs` 증명 시트와 `typesync.mjs` 결과를 인용한다. 실제 동기화된 시퀀스와 읽기 정지 구간을 검토한다. 빠르거나 역방향인 탐색, 휴대폰 프레이밍, 정적 대체 화면도 포함한다. 스토리보드, 스크린샷, 애니메이션 텍스트만으로, 또는 통과한 체커만으로는 타입이 영상과 함께 움직인다고 인증할 수 없다. 시네마틱 경험이 완성되었다고 말하기 전에 빠지거나 깨진 관계를 고친다.

다듬기 후에는 두 열을 나란히 제시한다.

이 점수는 객관적인 인증이 아니라 디자인에 대한 판단이다. 스크린샷, 영상 검토, 관련 검사는 `review/`에 보관한다. 변하지 않은 점수는 솔직하게 설명한다. 임시 자산은 최종 승인된 결과물로 제시하지 말고 버전으로 식별한다. Lighthouse 점수는 측정된 범주에 대한 증거일 뿐이며, 창작의 질, 실제 이메일 전달, 검색 엔진 색인의 증명이 아니다. 실제 휴대폰 검증을 했다고 주장하지 않는다. 에뮬레이션만 가능했다면 그렇게 말한다. 기술적인 QA를 사용자가 직접 하지 않도록 하면서, 최종 실제 기기 반응은 사용자에게 요청한다.
