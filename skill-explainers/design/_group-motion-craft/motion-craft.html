Answer

emilkowalski의 모션 스킬 여섯 개는 한 줄로 이어진 파이프라인이 아니다. 각자 "나는 이것 하나만 한다"고 선언하고, 나머지 일은 이름을 대며 다른 스킬의 몫으로 돌린다. 실제로 다음 스킬을 쓰라고 권하는 곳은 find-animation-opportunities가 improve-animations plan을 안내하는 한 곳뿐이다(r10).12

  1. 여섯 스킬의 경계는 서로의 소개 문단에 적혀 있다. 예를 들어 animate는 감사는 improve-animations, 리뷰는 review-animations, React Native는 animate-expo의 몫이라고 한다(r03~r05).2
  2. review-animations는 기준점 역할을 한다. animate는 그 리뷰를 한 번에 통과하게 쓰라고 하고, improve-animations는 execute 모드에서 그 기준으로 diff를 판정한다(r01, r12).34
  3. 그런데 review-animations는 disable-model-invocation: true라 모델이 스스로 켜지 못한다. 리뷰를 받으려면 사용자가 직접 불러야 한다.5

여섯 스킬은 서로 어떻게 가리키나

Diagram structure
  • find-animation-opportunities find
  • improve-animations improve
  • review-animations review
  • animation-performance perf
  • animate anim
  • animate-expo expo
  • anim → review · 같은 기준
  • expo → anim · 웹은 여기
  • find → improve · plan 안내
  • improve → review · 같은 기준
  • perf → anim · easing은 여기
  1. find-animation-opportunities ↗

    움직이지 않는 곳 중 정말 필요한 곳만 골라 수치와 함께 제안한다. 코드는 고치지 않는다. 구현을 원하면 improve-animations plan <suggestion>을 예로 들며 넘긴다(r10, 제안). 그림에서 실선은 이 하나뿐이다.

  2. improve-animations ↗

    코드베이스의 모션 코드를 감사해 우선순위 목록과 구현 계획을 쓴다. execute <plan>이면 실행 서브에이전트가 격리된 worktree에서 구현하고, review-animations 기준으로 diff를 판정한다(r12).

  3. animation-performance ↗

    프레임이 떨어지는 원인을 찾는다. easing·duration·애니메이션 여부 결정은 animate, 리뷰는 review-animations의 몫이라고 한다(r07, r08).

  4. animate-expo ↗

    React Native·Expo의 모션을 구현한다. 웹 애니메이션은 animate를 쓰라고 한다(r06).

  5. animate ↗

    애니메이션을 정해진 결정 순서로 직접 구현한다. 끝내기 전에 review-animations에서 자동으로 막히는 항목으로 자체 점검한다(r01).

  6. review-animations ↗

    모션 코드를 높은 기준으로 리뷰해 Block 또는 Approve를 낸다. 명시 호출만 된다.

점선은 "그건 저 스킬의 몫" 또는 "같은 기준을 쓴다"는 참고 관계다. 판정: 요청에 따라 어느 스킬로 시작할지는 각 description이 정한다. 움직일 곳 찾기는 find-animation-opportunities, 전체 감사는 improve-animations, 새로 구현은 animate, 끊김은 animation-performance, React Native는 animate-expo다.678910

근거: 역할 구분 문장은 animate 16줄,2 animation-performance 16줄,11 find-animation-opportunities 16줄,12 improve-animations 18줄,13 animate-expo description이다.10 넘김 안내는 find-animation-opportunities 26·136줄,114 판정 결과는 review-animations 112~113줄이다.15

2

리뷰 기준점은 왜 자동으로 이어지지 않나

여러 스킬이 가리키는 review-animations는 사용자가 불러야 켜진다

animate, animation-performance, find-animation-opportunities, improve-animations, mobile-native, break-ui, prototype이 모두 리뷰를 review-animations의 몫으로 둔다(r01, r08, r11, r12, r15, r18, r19). 그러나 review-animations의 frontmatter는 disable-model-invocation: true다.5 판정: 그림의 점선은 "같은 기준을 쓴다"는 뜻이다. 다른 스킬이 끝난 뒤 리뷰가 저절로 실행된다는 뜻이 아니다. improve-animations의 execute도 스킬을 호출한다고 적지 않고 "그 기준으로" 판정한다고만 적는다.4

확인하지 못한 것
