Answer

variant, break, state-machine은 한 컴포넌트를 임시로 따로 세워 놓고 작업하는 스킬 세 개다. 세 스킬은 순서로 이어지지 않는다. 각자 "나는 이것만 한다"고 적고 나머지 일은 이름을 대며 서로의 몫으로 돌린다. 세 스킬 모두 사용자가 직접 불러야만 켜진다.123

  1. variant는 의도적으로 다른 버전 3개를 실제 페이지의 선택기 뒤에 만들고, 순위는 매기지 않는다(r106, r107 참고).4
  2. break는 컴포넌트를 닿을 수 있는 모든 시나리오로 임시 페이지에 그려 깨진 곳을 표시한다. 판단하지 않고 관찰한다.56
  3. state-machine은 컴포넌트가 가진 모든 상태를 mock 데이터와 전환기를 단 임시 페이지에 그린다. 리뷰가 아니라 작업대다.78
  4. 셋 중 무엇을 쓸지는 "무엇을 알고 싶은가"로 가른다. 대안이 필요하면 variant, 최악의 데이터가 필요하면 break, 상태별로 다듬으려면 state-machine이다. 리뷰나 다른 스킬로 돌리는 경계는 각 스킬의 소개 문단이 적는다.968

2

어떤 스킬로 시작하나

세 스킬 사이에 순서는 없다. 사용자가 알고 싶은 것에 따라 하나를 고른다. 아래 표는 각 스킬이 소개 문단에서 다른 스킬에 돌리는 경계다. 서로 실행하라는 지시는 없다.

하려는 일쓸 스킬근거rel-id
컴포넌트의 대안 디자인을 비교한다variantbreak와 state-machine이 대안 탐색을 variant의 몫으로 적는다68r114, r123
최악의 데이터로 컴포넌트를 깨 본다breakvariant와 state-machine이 스트레스 테스트를 break의 몫으로 적는다98r106, r122

끝난 변경을 리뷰한다interface-review·better-interface(묶음 밖)세 스킬이 모두 리뷰를 이 둘의 몫으로 적는다968r104, r105, r112, r113, r124

variant는 실제 페이지를 고집하고 break는 일부러 컴포넌트를 격리한다. break는 적대적 시나리오를 한 페이지에 쌓지만 state-machine은 제품 상태를 한 번에 하나씩 보여 준다. 이 두 대비는 각 스킬이 직접 적은 경계 설명이다.68

셋 다 임시 페이지를 남기고, 지우는 시점은 사용자가 정한다

break와 state-machine은 페이지를 보고서와 같은 turn에 지우지 않는다. 사용자가 끝났다고 말할 때 지운다. variant는 사용자가 하나를 고르면 그 버전을 제대로 만들고, 나머지·선택기·import를 지운다.141513 판정: 세 스킬의 임시 페이지는 모두 앱 안의 scratch route로 만든다. 지울 때 route와 fixture 이름을 검색해 남은 것이 없는지 확인하라는 지시가 break·state-machine·variant에 모두 있다. 공유 파일은 없고 각자 자기 폴더를 쓴다. 이 부분은 원문에 명시되어 있다.141513

4

그림을 넣지 않은 이유와 확인 범위

이 묶음에는 순서나 의존 관계가 없다. 서로 몫만 가르는 참고 관계라 그림은 넣지 않고 비교 표로 보여 준다. 판정: 다이어그램은 순서나 호출을 보여 줄 때만 그린다. 몫 구분을 화살표로 그리면 "다음에 이 스킬을 쓰라"는 뜻으로 읽힌다.
