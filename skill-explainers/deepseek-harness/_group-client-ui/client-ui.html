클라이언트 GUI 묶음(client-ui)은 어떻게 이어지나

Long image

A

Answer

이 묶음은 클라이언트 GUI를 설계하고 리뷰하며 증거를 남기는 스킬 다섯 개다. dsh-client-ui-ux가 판단 기준을 주고, 오류 보고는 dsh-error-handling에 위임하고, 반응형 세부는 dsh-responsive-ui를 참고하라고 가리킨다.12 공식 플러그인 그림(dsh-official-plugin-artwork)은 이와 다른 대상을 다루고, GUI PR의 데모 GIF는 record-browser-gif가 맡는다.34

  1. dsh-client-ui-ux는 실패를 보고할 때 dsh-error-handling의 보고 절을 적용하고, 그 뒤 메시지 수명에 따라 어디에 보일지 고른다(r31).1
  2. dsh-client-ui-ux는 반응형 레이아웃, 터치 판별, 말줄임, 제목 줄바꿈, 아이콘 전용 버튼, 폭 변화 중 포커스를 다룰 때 dsh-responsive-ui를 쓰라고 한다(r32).2
  3. 두 스킬 사이의 간선은 dsh-official-plugin-artwork → dsh-client-ui-ux 한 방향뿐이다. dsh-official-plugin-artwork는 액션 아이콘이 dsh-client-ui-ux 소관이라고 경계를 긋는다(r33). 반대 방향 참조는 없다.53
  4. dsh-official-plugin-artwork는 그림 작업이 GUI PR이면 record-browser-gif를 따른다(r34). dsh-client-ui-ux 원문에는 GIF 언급이 없다.67

  1. dsh-client-ui-ux ↗

    클라이언트 GUI 변경의 판단 기준을 준다. 토큰 재사용, 피드백 자리, 오버레이 안전, 플랫폼 창 적응이 대상이다. 스스로 완전한 체크리스트가 아니라 안내라고 밝힌다.

  2. dsh-error-handling ↗

    실패 분류, 처리 책임, 상태 보장, 사용자에게 보이는 오류 보고의 원칙을 준다. dsh-client-ui-ux는 이 스킬의 보고 절을 적용한 다음, 오류를 보일 자리를 고른다.

  3. dsh-responsive-ui ↗

    반응형 레이아웃, 터치 판별, 말줄임, 아이콘 전용 버튼, 폭 변화 중 포커스를 설계하고 리뷰한다.

  4. dsh-official-plugin-artwork ↗

    공식 플러그인 아이콘과 기능 미리보기 그림을 그리고 리뷰한다. 툴바·액션 아이콘은 대상이 아니다.

  5. record-browser-gif ↗

    GUI를 바꾸는 PR이면, 데모 GIF를 녹화하고 인코딩한다. 작업이 PR 첨부를 포함하면 gh --attach로 올린다.

화살표는 실행 순서가 아니라 참조 방향이다. 다섯 스킬을 순서대로 모두 거치라는 원문은 없다. 각 스킬의 내부 규칙과 수치는 deepseek-harness/dsh-client-ui-ux/dsh-client-ui-ux.html, deepseek-harness/dsh-error-handling/dsh-error-handling.html, deepseek-harness/dsh-responsive-ui/dsh-responsive-ui.html, deepseek-harness/dsh-official-plugin-artwork/dsh-official-plugin-artwork.html, deepseek-harness/record-browser-gif/record-browser-gif.html에 있다.

실선은 위임, 굵은 선은 넘김, 점선은 참고다. 아래 표에서 생략으로 표시한 행은 그림에 없다.

record-browser-gif와 dsh-official-plugin-artwork는 서로의 산출물을 읽지 않는다. dsh-official-plugin-artwork는 GUI PR이면 record-browser-gif를 따르라고만 적는다.6

GIF 필수 조건과 디자이너 승인은 다른 의무다

record-browser-gif는 제품 사용자에게 보이는 GUI 동작을 바꾸는 PR에 GIF 파일을 필수(MUST)로 요구한다. dsh-client-ui-ux는 UI나 상호작용을 눈에 띄게 바꾸는 PR에 디자이너나 제품 리뷰를 요구하고, dsh-official-plugin-artwork는 새 글리프를 병합하기 전에 디자이너 승인을 요구한다.

원문 인용: GIF는 record-browser-gif 12~14줄, 디자이너 리뷰는 dsh-client-ui-ux 77줄, 글리프 승인은 dsh-official-plugin-artwork 41줄이다.4166

이 분석의 범위와 한계

  • 읽은 파일: 묶음 스킬 5개의 SKILL.md와 경계 스킬 dsh-pr-description, dsh-speed-up-perf, dsh-code-review의 인용 줄. 모두 원본이다. 번역본은 이 컬렉션에 없다.
  • 원문 대조: r03, r04, r23, r30~r35의 출처 줄을 원문에서 다시 읽었다. 종류와 조건이 원장과 같다.
  • 원장 정정: 처음 원장의 묶음 그림 칸은 client-ui-ux 쪽 GUI PR 증거도 record-browser-gif로 모인다고 적었다. r34는 dsh-official-plugin-artwork → record-browser-gif뿐이고 dsh-client-ui-ux는 record-browser-gif를 부르지 않아, 조정자가 원장을 고쳤다. 이 페이지는 r34만 그렸다.
  • 실제로 실행해 보지 않았다. 페이지의 흐름은 모두 지시상 동작이다.
  • 분석 중 바뀐 파일: 없음.

확인하지 못한 것

dsh-official-plugin-artwork의 선택 사항인 기능 미리보기 규칙은 원래 저장소의 쿡북 문서가 소유하고, 이 저장소에 없어 열지 못했다. 이 페이지의 흐름에는 영향이 없다. dsh-code-review가 dsh-client-ui-ux를 본문 점검 항목에서 적용하는지는 원문에 명시 없음(r03).
