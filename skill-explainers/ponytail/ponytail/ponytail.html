ponytail은 새 코드를 줄이면서 어디까지 끝내게 하나?

Long image

A

Answer

ponytail은 필요한 변경을 끝까지 마치면서 새 코드를 최소화한다. 호출자와 테스트까지 영향 범위를 먼저 잡으므로, 줄 수를 줄이려고 필요한 수정을 빼먹지 못하게 한다.12

  1. 기존 코드, standard library, 설치된 dependency 순으로 재사용할 방법을 찾는다.3
  2. validation, 데이터 손실 방지, security, accessibility와 사용자 요구는 줄이지 못한다.4
  3. 세션 동안 유지되며 기본 수준은 full이다.56

1

언제 켜지고 언제 끝나나?

description은 모델이 호출 여부를 판단할 때 참고하는 설명이다. 특정 단어와 정확히 일치해야 켜진다는 뜻은 아니다. disable-model-invocation 필드는 이 원문에 명시되어 있지 않다.7

원문은 모든 코딩 작업에 사용하라고 한다. ponytail, be lazy, simplest solution, yagni와 과도한 설계에 대한 불만도 호출 맥락으로 든다.7

수준·종료에이전트의 행동
lite요청한 것을 만든다. 더 작은 선택지를 한 줄로 제시하고 사용자가 고르게 한다.6
full최소한의 완전한 변경 규칙을 적용한다. 기본 수준이다.6
ultra만들기 전에 필요가 뒷받침하지 않는 요구를 짚고 반대 의견을 낸다.6
변경·종료/ponytail lite|full|ultra로 수준을 바꾼다. stop ponytail, normal mode까지 세션에 유지된다. ponytail-help는 /ponytail off도 안내한다.58
2

어떤 순서로 구현 방법을 고르나?

에이전트는 먼저 호출자, 테스트, fixture, config, exports와 데이터 손실·노출 위험을 확인한다. 그 범위를 해결하는 첫 번째 선택지를 쓴다.13

  1. 필요 확인

    요청하지 않은 기능과 유연성을 빼고 무엇을 뺐는지 한 줄로 적는다.3

  2. 기존 코드

    저장소의 helper, component, service, 관례를 같은 방식으로 쓴다.3

  3. standard library

    프로젝트 자체 구현이 있으면 그것을 우선한다.3

  4. 설치된 dependency

    몇 줄을 위해 새 dependency를 추가하지 않는다.3

  5. 읽히는 한 줄

    한눈에 이해할 수 있을 때만 한 줄로 쓴다.3

  6. 최소 구현

    앞선 선택지로 해결되지 않을 때 필요한 코드만 쓴다.3

3

적게 쓰더라도 무엇을 지켜야 하나?

조건강제되는 행동
구현·수정깨진 호출자, 테스트, fixture까지 마친다. 기존 layer와 interface를 유지한다.2
bug fix수정 전에 모든 호출자를 검색하고 공유 코드에서 원인을 한 번 고친다.2
이동·병합error handling과 validation을 보존한다. 크기가 같으면 edge case에 맞는 쪽을 고른다.2
새 로직branch, loop, parser, 돈·security, 새 script·app에는 작은 테스트 1개 또는 assert 기반 self-check를 남긴다. 사소한 변경은 제외한다.2
주석코드가 보여 주지 못하는 이유만 한 줄로 쓴다. 한계가 있는 지름길에는 shortcut: <the limit>, <when to upgrade>를 남긴다.2
답변마지막 1~2줄에 생략했거나 확인하지 않은 일과 사용자에게 필요한 위험을 적는다.5

줄일 수 없는 요구

신뢰 경계의 validation, 데이터 손실을 막는 error handling, security, accessibility, 실제 hardware의 calibration과 사용자 요구는 생략하지 못한다.4

판정 · 코드 길이만 줄이려는 작업에는 이 스킬의 제약도 함께 적용해야 한다. 설명용 예시로, 함수 signature를 바꿨다면 함수 본문이 짧아져도 호출자 수정이 끝나야 완료다.12

실행으로 확인하지 않은 부분

호스트가 실제로 스킬을 활성화하거나 상태를 유지하는지는 실행으로 확인하지 않았다.

분석 중 원본은 수정하지 않았다. 분석 전 사용자 승인으로 컬렉션 7개 파일을 commit했다. 새 분석 초안과 HTML, 관계 원장, 색인, 검증 보고서를 작성했다. 원문의 명령과 설치·설정 변경은 실행하지 않았다.
