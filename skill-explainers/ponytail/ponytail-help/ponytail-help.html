ponytail-help는 모드를 바꾸나, 사용법만 보여 주나?

Long image

A

Answer

ponytail-help는 수준·스킬·명령을 한 번 안내한다. ponytail-help 자체는 모드나 flag를 바꾸거나 파일을 저장하지 않는다. 명령을 설명하는 것과 그 명령을 실행하는 경계를 분명히 둔다.12

  1. lite, full, ultra와 종료 표현을 알려 준다.34
  2. 여섯 스킬의 목적을 보여 주고 사용자가 고르게 한다.2
  3. 환경 변수·config·band·업데이트는 호스트의 기능으로 설명한다.5

1

언제 쓰고 어디서 끝나나?

description은 모델이 호출 여부를 판단할 때 참고하는 설명이다. 특정 단어와 정확히 일치해야 켜진다는 뜻은 아니다. disable-model-invocation 필드는 이 원문에 명시되어 있지 않다.6

원문은 /ponytail-help, ponytail help, 사용법 질문을 호출 맥락으로 든다. 참고 카드 표시 후 끝내며, 모드 변경·flag 파일 작성·지속 저장을 금지한다.61

2

수준과 호출 표현은 무엇인가?

사용 목적원문의 안내
lite/ponytail lite로 요청한 것을 만들고 더 작은 선택지를 한 줄로 알린다.3
full/ponytail의 기본이다. 완전한 최소 변경, 필요한 검사, 생략과 위험의 보고를 적용한다.3
ultra/ponytail ultra로 구현 전에 필요도 따져 반대 의견을 낸다.3
유지·종료수준을 바꾸거나 세션이 끝날 때까지 유지한다. stop ponytail, normal mode, /ponytail off로 끈다. /ponytail로 재개한다.34
호스트별 표기Codex CLI·IDE는 $ponytail:ponytail, $ponytail:ponytail-review, $ponytail:ponytail-help를 예로 든다. Claude Code·OpenCode는 slash 명령을 안내한다.2

설정 안내와 실제 변경은 어떻게 구분하나?

항목원문의 안내와 적용 경계
기본 수준매 세션 full 자동 활성화를 설명한다. PONYTAIL_DEFAULT_MODE 환경 변수가 가장 먼저이며, config 파일, full 순으로 해석한다고 적는다. off는 자동 활성화를 끈다.5
config 경로~/.config/ponytail/config.json, Windows의 %APPDATA%\ponytail\config.json을 안내한다. defaultMode에 lite 등을 넣는다. ponytail-help가 직접 쓰지는 않는다.51
bandClaude Code의 /ponytail band는 표시 전환, band on·band off는 직접 지정이다. 수준은 유지한다. band import는 과거 세션의 cost·agent time·tokens를 board에 더한다고 설명한다.5
업데이트/plugin의 Marketplaces에서 auto-update를 켜거나 /plugin marketplace update ponytail 후 /reload-plugins를 안내한다. /plugin을 인식하지 못하면 Claude Code 업데이트와 재시작을 안내한다. 다른 호스트는 자체 방식을 쓴다.5

판정 · ponytail-help를 호출했다고 ultra가 되거나 config가 생기지는 않는다. ponytail-help 원문이 표시만 하도록 제한하기 때문이다. 호스트 설정·band·업데이트의 실제 구현은 컬렉션에 없다.15

실행으로 확인하지 않은 부분

모드 자동 활성화, band, config 해석, plugin 업데이트는 원문이 설명한 동작이다. 외부 전체 문서와 호스트를 실행해 확인하지 않았다.

분석 중 원본은 수정하지 않았다. 분석 전 사용자 승인으로 컬렉션 7개 파일을 commit했다. 새 분석 초안과 HTML, 관계 원장, 색인, 검증 보고서를 작성했다. 원문의 명령과 설치·설정 변경은 실행하지 않았다.
