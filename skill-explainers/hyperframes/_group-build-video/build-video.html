HyperFrames로 새 영상 한 편을 만들 때 네 스킬은 어떻게 이어지나?

Long image

A

Answer

hyperframes가 계약과 작업 순서를 정하고, 명령 실행은 hyperframes-cli, 기성 효과는 hyperframes-registry, 음악·이미지·음성 같은 media는 media-use가 맡는다. 네 스킬을 고정된 순서로 모두 실행하라는 지시는 원문에 없다. 요청에 필요한 스킬만 부른다.12

  1. hyperframes는 이름 붙은 효과를 손으로 쓰기 전에 registry를 검색하고, 모든 media는 /media-use로 보내라고 한다.3
  2. hyperframes-cli는 catalog·add와 media-treatment·tts 같은 명령을 각각 /hyperframes-registry, /media-use 옆에 적어 두고, 실행법만 정한다.4
  3. 네 스킬은 assets/, compositions/, .hyperframes/ 같은 프로젝트 파일을 함께 쓴다. 파일을 통한 연결이라 선후 관계는 없다.567

Applies to스킬 4개SKILL.md 기준관계 R01·R02·R03·R09·R10·R24~R27·R29~R32폴더 밖 참조 대상은 읽지 않음

네 스킬은 어떤 관계로 이어지나?

Diagram structure

화살표는 원장의 넘김과 참고다. 앞 스킬이 뒤 스킬을 자동으로 실행한다는 뜻은 아니다. hyperframes가 hyperframes-cli로 가는 R01·R29는 참고라서 점선이고, 명령 이름만 지목하는 연결은 표에만 남겼다.34

  1. hyperframes ↗

    계약 12조와 작업 순서를 정하고 요청에 맞는 스킬로 안내한다.

  2. hyperframes-cli ↗

    lint, check, snapshot, preview, render 명령 사용법을 정한다.

  3. hyperframes-registry ↗

    이름 붙은 효과를 catalog로 찾고 add로 설치한다.

  4. media-use ↗

    음악·이미지·음성 같은 media를 resolve로 구해 assets/에 둔다.

각 스킬의 내부 규칙과 수치는 개별 페이지에 있다. 개별 페이지는 색인 기준 hyperframes/hyperframes/hyperframes.html 같은 경로로 찾는다.

어떤 파일과 상태를 공유하나?

파일·상태쓰는 스킬·주체읽는 스킬·조건
assets/media-use가 local 파일과 ledger 기록으로 둔다. 같은 원문 안에서 .media/<type>/로 적힌 곳도 있어 위치가 갈린다.5hyperframes가 media와 font는 assets/에 있다고 하고 경로를 assets/...로 정한다.1
compositions/hyperframes-registry의 add가 block을 compositions/<name>.html, component를 compositions/components/<name>.html에 쓴다.6hyperframes의 index.html이 compositions/의 sub-composition을 mount한다.1
hyperframes.json설치 경로를 정한다. 쓰는 주체는 hyperframes CLI다(지시상 동작).6hyperframes-registry가 설치 경로를 여기서 가져온다.6
.hyperframes/ historyhyperframes-cli가 턴 시작에 history begin, 끝에 history end를 하라고 한다. .hyperframes는 지우지 않는다.7hyperframes가 변경 전에 history --since mine --who <you>로 사용자 편집을 읽고 그 위에 만든다.10
.hyperframes/credit-limit.json사용자가 말한 credit 한도를 media-use가 쓴다.11유료 호출이 이 한도를 넘으면 거절된다(지시상 동작). style-sampling도 같은 파일에 쓴다.

어떤 순서가 강제되고 무엇이 선택인가?

판정 · 원문이 강제 순서로 적은 것은 hyperframes 안의 작업 루프뿐이다. 새 영화는 type 파일, story.md, SPEC.md를 거치고, 마지막 edit 뒤에 check를 돌린다. 렌더는 사용자가 preview를 승인하거나 파일을 요청하거나 멈추지 말라고 했을 때만 한다.10 나머지 세 스킬은 필요할 때 부르는 선택지다.

  • hyperframes-cli의 루프는 lint, check --json, snapshot, preview --background, render 순서이고, 확인이 통과했다는 이유만으로 렌더하지 않는다.12
  • 사용자 입력이 필요한 지점은 스킬 안에 있다. media 요청은 media-use가 HeyGen이 필요할 때마다 auth status를 먼저 돌리고 로그인되지 않았으면 사용자가 로그인을 마칠 때까지 기다리며,13 credit 한도는 사용자가 정하고,11 hyperframes-registry는 on-device 검색 다운로드를 사용자가 정하게 한다.8

확인하지 못한 것

이 페이지는 네 스킬의 SKILL.md와 원장만 근거로 썼다. 폴더 밖 참조 대상(hyperframes/references/*)과 CLI의 실제 동작은 이 페이지에서 다시 열지 않아 부분 분석이다.
