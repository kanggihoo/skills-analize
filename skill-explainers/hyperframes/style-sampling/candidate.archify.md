# style-sampling은 언제 켜지고 무엇을 강제하나? {#style-sampling-page}

`style-sampling`은 템플릿 5종 중 하나로 사용자 주제의 새 에피소드를 만든다. 시작할 때마다 `auth status`를 돌려 Pro인지 확인하고, 두 번 멈춰 사람 승인을 받는다. 템플릿 파일이 이 저장소에 없어서 이 페이지는 **부분 분석**이다.[](source:skill-intro)[](source:skill-start)[](source:remix-order)

- 템플릿은 HyperFrames Pro 기능이다. Free나 미로그인이면 pull하지 않고 명령을 사용자에게 입력하게 한다.[](source:skill-pro)[](source:skill-start)
- 템플릿을 기억·웹·다른 곳의 사본으로 다시 만들지 않는다. creator의 얼굴·목소리·footage·로고·쇼 이름도 쓰지 않는다.[](source:skill-pull)[](source:remix-never)
- 사람 몫의 정지점은 storyboard와 draft 두 곳이다.[](source:skill-make)[](source:remix-stop1)[](source:remix-stop2)
- 5개 템플릿에 없는 스타일은 pull하지 않고 `/reverse-any-video` 또는 `/hyperframes`를 제안한다.[](source:skill-nofit)

description은 모델이 호출 여부를 판단할 때 참고하는 설명이다. 특정 단어와 정확히 일치해야 켜진다는 뜻은 아니다. `disable-model-invocation` 필드는 이 원문에 명시되어 있지 않다.[](source:skill-front)

원문은 "an episode of", "in the style of", "sample this style" 같은 요청을 호출 맥락으로 든다. 한 편짜리 영상을 그대로 복제하려는 요청은 `reverse-any-video`의 몫이라고 description 끝에 적었다.[](source:skill-front)

표는 원문 그대로 옮긴 것이다.[](source:skill-table)

- 주제가 한 템플릿에만 맞거나 사용자가 템플릿을 지목하면 그대로 진행한다.
- 그렇지 않거나 사용자가 무엇이 있는지 물으면 5종을 이름·만드는 것·가져올 것으로 짧게 보여 주고, 맞는 것이 있으면 짚은 뒤 사용자의 선택을 기다린다.[](source:skill-which)
- 선택 전에는 확인도 pull도 결제도 하지 않는다.[](source:skill-which)

| 채널이나 영화를 이름으로 대면 한 줄로 그렇다고 알린다. 목록 대신 두 길을 제안한다. 짧은 영상을 프레임 단위로 다시 만들고 내용을 바꾸는 `/reverse-any-video`, 또는 그 스타일의 문법을 가져와 새 영화를 만드는 `/hyperframes`(`../hyperframes/references/look.md`의 "From a reference")다.[](source:skill-nofit) |

원문은 템플릿이 다루지 못하는 주제도 따로 정해 두었다. 템플릿의 `TEMPLATE.md`가 "good for / not good for" 주제를 적고, 맞지 않으면 한 줄로 그렇다고 알리면서 가장 가까운 각도를 같은 메시지에서 제안한다. 맞지 않는 주제를 그래도 만들어 주겠다는 제안은 하지 않는다.[](source:remix-read) `TEMPLATE.md`의 실제 판정 기준은 외부 템플릿이라 이 저장소에서 확인하지 못했다. 원문에 명시 없음.

## 시작 전에 무엇을 강제하나? {#start}

`SKILL.md` 첫머리의 두 줄이 먼저 있다. HyperFrames plugin 안에서 쓰면 plugin execution rules를 따르고, 스킬이 시작될 때 `npx hyperframes events --skill=style-sampling`을 한 번 돌린다. 후자는 스킬 이름을 CLI의 telemetry와 함께 보내며(로그인했으면 계정에 연결) 사용자의 opt-out을 따른다.[](source:skill-plugin)[](source:skill-beacon)

`auth status`는 이어 하기(resume)를 포함해 **매번** 가장 먼저 돌린다. 이 결과의 plan이나 credits 줄은 사용자에게 되풀이하지 않는다.[](source:skill-start)

pull은 크레딧을 쓰지 않고, 이미 받은 템플릿은 다시 내려받지 않는다. 템플릿은 `templates/<slug>/`에 들어온다. Pro 기능이라며 거절되면 `auth status`가 무엇이라 했든 Free 분기처럼 답한다. 다른 실패는 무엇이 실패했는지 말하고 멈춘다.[](source:skill-pull)

@callout level=warning title="템플릿을 기억에서 다시 만들지 않는다"
| 원문은 템플릿을 기억, 웹, 다른 곳에서 찾은 사본으로 재구성하는 것을 금지한다("Never rebuild a template from memory, the web or a copy found elsewhere").[](source:skill-pull) |
| 제작 중에는 pull된 `templates/`를 그대로 둔다. 템플릿에 없는 component는 가장 가까운 것을 쓰고 `GAPS.md`에 적는다.[](source:remix-footage) |

판정 · 로그인과 결제 명령을 에이전트가 직접 돌리지 않고 사용자에게 prompt 입력을 맡기는 구조다. 로그인·결제는 사람 몫으로 남는다.[](source:skill-start)

## 에피소드는 어떤 순서로 만들고 어디서 사람을 기다리나? {#make}

`remix.md`는 순서만 정하고 과정은 템플릿의 `series/<series>/REMIX.md`가 정한다. 둘이 충돌하면 템플릿이 이기지만, 사용자가 고른 길이(length)와 Pro·credits 규칙(`SKILL.md`)에서는 예외다.[](source:skill-make)[](source:remix-prec) 그 REMIX.md의 step table은 "건너뛰지 않고 순서대로" 따른다.[](source:remix-read)

판정 · 질문은 "한 번, 아직 열린 것만"이라는 규칙이 원문에 있다. 작업 중에는 정지점 2개와 실패한 job의 재시도 후 질문이 사람이 개입하는 곳이다.[](source:remix-ask)[](source:skill-credits)

## 숫자와 금지는 어떻게 정해져 있나? {#rules}

| 항목 | 값과 적용 조건 | 구분 |

| 길이 선택 | 약 1분(cold open, title beat, chapter 하나, 짧은 end card), 2~4분(REMIX.md의 short cut), 전체 에피소드(시리즈 자체 runtime). 사용자가 "90 seconds", "5 min"처럼 말하면 그 길이.[](source:remix-length) | 사용자 몫이 템플릿 runtime보다 앞선다 |
| 리뷰 횟수 | 1분 길이는 1회, 전체 에피소드는 2회.[](source:remix-length) | 길이에 맞춰 줄인다 |
| 목소리 clone | 사용자가 직접 읽은 30초에서 3분 분량으로 HeyGen에서 만든다.[](source:remix-voice) | 선택지 중 하나 |
| voice id 접두어 | 8자 접두어는 `media-use voices --limit 100`에서 전체 id를 찾고 맞는 것이 없거나 여럿이면 묻는다.[](source:remix-voice) | 조건 |
| 오디션 | 대본 전체 전에 한 문단으로 words per minute을 재고 `voice.speed`를 시리즈 속도에 맞춘다. instant clone은 voice 호출에 speed를 받지 않는다.[](source:remix-audition) | 의무(오디션) |
| 재촬영 | presenter take가 있는 뒤 대사가 바뀌면 take 전체를 다시 만든다. 아니면 입 모양이 어긋난다.[](source:remix-audition) | 의무 |
| 렌더 부하 | 한 번에 무거운 일 하나. render는 `--workers 1`, ffmpeg는 `-threads 2 -nostdin`.[](source:remix-checks) | 의무 |
| 오래 걸리는 렌더 | 20분을 넘을 듯하면 대략 걸릴 시간을 미리 알린다. 10분을 넘는 렌더는 detached로 시작해 log로 지켜본다. 클라우드 3D shot은 20분 동안 `rendering`에 있어도 끝날 수 있으니 그것만으로 끄지 않는다.[](source:remix-checks)[](source:remix-stop2) | 의무 |
| preview port | 기본 3002가 쓰이고 있으면 `--port <free port>`.[](source:remix-stop2) | 조건 |
| 실패한 job | 실패하거나 거절된 job은 한 번 더 시도한 뒤 묻는다.[](source:skill-credits) | 의무 |
| 막힌 사이트 | 403, 429, bot check는 우회하지 않고 다른 출처로 간다.[](source:remix-footage) | 금지 |

단위와 조건은 위 표 행 뒤 출처를 따른다. 위 값은 모두 원문의 지시이며 이 분석에서 실행하거나 측정하지 않았다.

@callout level=warning title="금지와 입 다물기"
| creator의 얼굴·목소리·footage·로고·쇼 이름은 에피소드에도, 사용자에게 하는 설명에도 쓰지 않는다. 원작자 감사 문구는 스킬 본문에만 있다. 사용자의 clone, 사용자의 녹음, 크레딧을 붙인 stock voice는 괜찮다.[](source:skill-intro)[](source:remix-never)|
