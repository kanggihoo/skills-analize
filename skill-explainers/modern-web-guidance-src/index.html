묶음

guide-authoring-pipeline

새로 나온 web 기능을 guidance와 평가 기준까지 완성한다
  • project-features 브라우저 launch마다 올라오는 new-feature 이슈가 guidance 대상인지 가려 내고 web-feature ID를 하나로 정해 분류한다
  • project-use-cases web 기능 하나를 개발자가 하려는 일(use case) 2~5개로 풀고 guide ID와 guide.md 틀을 만든다
  • project-guides 에이전트가 읽을 guide.md와 demo.html, expectations.md를 쓰고 검토하는 규칙
  • project-guide-validation 쓴 guide·demo·expectations를 DevTools MCP와 체크리스트로 검증하고 피드백 보고서를 낸다
  • project-discipline-guides 분야 전체를 안내하는 discipline guide에서 모델이 이미 아는 내용을 mirror와 비교해 걷어 낸다
  • baseline-status 웹 기능의 browser 지원과 Baseline 상태를 pnpm baselinestatus로 조회한다

eval-quality-loop

평가 도구(프롬프트·grader·nightly 결과)를 고친 뒤 회귀를 막거나 평가 결과를 진단한다
  • dev-prompt-canary gd dev 작성·채점 프롬프트를 고친 뒤 task.md와 grader.ts를 일부만 다시 만들어 퇴행을 확인한다
  • grader-replay grader나 공용 helper를 고친 뒤 과거 nightly의 agent 결과에 다시 채점해 결과가 뒤집힌 곳을 분류한다
  • nightly-eval-investigation 최근 nightly 평가 3종을 내려받아 문제 task를 표시하고 원인과 권고를 보고서로 쓴다

repo-upkeep

저장소 코드와 문서를 PR 전에 점검하고 정기 점검을 돈다
  • coherence-auditor 문서 일관성과 링크, git 상태를 서브에이전트로 읽기 전용 감사한다
  • project-maintenance vendored 의존성과 web-features 데이터셋 갱신 같은 정기 점검 항목을 모아 둔다
  • project-coding-standards 이 저장소의 TypeScript·CLI·dashboard 코드 규칙과 PR 검증 순서를 정한다
