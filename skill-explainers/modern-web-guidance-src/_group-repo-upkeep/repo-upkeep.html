PR 전에 코드와 문서를 어떻게 점검하고 정기 점검은 어디 있나?

Long image

A

Answer

이 묶음은 순서가 있는 흐름이 아니라 점검 도구 모음이다. 스킬 사이의 호출은 두 가지다. project-maintenance가 문서 점검 항목에서 coherence-auditor의 감사 스크립트를 실행하라고 안내하고(R29), coherence-auditor가 서브에이전트에 감사를 맡긴다(R30).123

  1. coherence-auditor는 서브에이전트 document-coherence-auditor를 띄워 읽기 전용 감사를 맡긴다. 보고를 받은 뒤 메인 에이전트가 깨진 링크와 어긋난 파일을 직접 고친다.3
  2. project-maintenance는 문서 점검 항목의 실행 빈도를 정하지 않는다. 머리말은 "some regularity"라고만 쓴다. 빈도가 적힌 것은 web-features 갱신 workflow(월·목 자동)뿐이다.45
  3. project-coding-standards는 다른 스킬과 직접 호출 관계가 없다. 같은 계열 관계(R26~R28)는 모두 추론이라 흐름으로 그리지 않았다.6

Applies to로컬 SKILL.md 3개관계 R26~R33명령 실행 없음원본 저장소의 docs·src 파일은 확인하지 못함

coherence-auditor가 서브에이전트에 위임하고 보고를 받아 직접 고치는 과정을 그렸다(R30). 서브에이전트가 읽는 project-* 스킬 목록은 R31이다.

  1. project-maintenance ↗

    정기 점검 항목 세 가지를 모아 두고, 문서 점검에서 감사 스크립트 실행을 안내한다.71

  2. coherence-auditor ↗

    서브에이전트에 감사를 맡기고 보고를 받아 깨진 링크와 어긋난 파일을 직접 고친다.38

  3. document-coherence-auditor ↗

    감사 스크립트를 돌리고 project-* 스킬을 읽어 모순을 보고한다. 저장소 파일은 수정하지 않는다.9

  4. project-coding-standards

    코드 규칙과 PR 통과 조건을 정한다. 다른 스킬을 호출하지 않는다.106

원장에 이 묶음의 공유 상태 관계는 없다. 같은 명령을 여러 스킬이 쓰는 경우만 표로 남긴다.

docs/CONTEXT.md와 .agents/skills/project-*/SKILL.md (R31)쓰는 스킬 없음. 서브에이전트는 수정하지 않는다.9document-coherence-auditor가 읽고 모순을 확인한다. 스크립트는 docs/CONTEXT.md가 있을 때 project-* 목록을 출력한다.14

4

어디까지 대조했고 무엇이 남았나?

이 페이지는 묶음 스킬 3개의 SKILL.md를 읽고 원장 R26~R33과 대조했다. project-maintenance(1267B)와 coherence-auditor(3454B)는 SKILL.md 전부와 coherence-audit.ts 71~98행을 읽었다. project-coding-standards와 관계 대상 스킬은 관계가 나온 줄만 읽었다.

관계 8개(R26~R33)를 모두 원문과 대조했다. 번역본은 이 컬렉션에 없어 열지 않았다. 구조·표본만 읽은 파일은 이 페이지에서 0개다. 스킬 내부 규칙과 수치는 스킬 페이지에서 다룬다.

미확인 범위

pnpm, node, define_subagent, invoke_subagent 호출은 읽기만 했고 실행하지 않았다. 상태는 지시상 동작으로만 적었다.3 docs/CONTEXT.md, src/ci/*.ts, src/authoring/guides-integrity.test.ts, .github/workflows/update-web-features.yml은 이 저장소에 없어 확인하지 못했다.

자동 검증은 HTML 구조와 출처 해석을 확인한다. 실제 효과와 독자의 이해는 별도로 확인해야 한다. 사람 검토는 미실시다.
