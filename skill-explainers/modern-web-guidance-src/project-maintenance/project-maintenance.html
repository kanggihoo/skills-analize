Long image

Answer

project-maintenance는 저장소에서 "어느 정도 주기로" 해야 할 점검 3가지를 모아 둔 목록이다. vendored 의존성 detect-agent 갱신 확인, web 표준·호환성 dataset 갱신, 문서 일관성·링크 점검이다. 얼마나 자주 하는지, 누가 하는지, 언제 끝나는지는 원문에 명시되어 있지 않다.1234

  1. vendored 코드는 upstream 버전과 비교해 오래됐으면 src/cli/telemetry/detect-agent.ts를 맞추고 테스트 2개를 돌린다.2
  2. web-features는 workflow가 월·목에 자동으로 갱신한다. 수동 갱신 뒤에는 CI 스크립트 2개를 더 돌린다.3
  3. 문서 점검은 coherence-auditor의 스크립트를 돌린다.4

언제 켜지고 무엇을 점검하나?

description은 모델이 호출 여부를 판단할 때 참고하는 설명이다. 특정 단어와 정확히 일치해야 켜진다는 뜻은 아니다. disable-model-invocation 같은 호출 제한 필드는 원문에 명시되어 있지 않다.5

본문 머리말은 "Things that should happen with some regularity"라고만 쓴다. 호출 시점이나 주기를 정하는 문장은 없다.1

판정 · 호출 조건이 따로 없으므로 이 스킬은 에이전트를 움직이는 절차라기보다 사람과 에이전트가 함께 참고하는 점검 목록이다.15

점검 항목에이전트의 행동확인 방법
vendored 의존성upstream @vercel/detect-agent 최신 버전과 vendored 버전을 비교한다. 새 릴리스가 있으면 src/cli/telemetry/detect-agent.ts에 변경을 반영하고 버전 주석을 올린 뒤 node --test src/cli/telemetry/detect-agent.test.ts src/cli/telemetry/clearcut-logger.test.ts를 돌린다.2vendored 버전은 파일 안의 detect-agent@<버전> 표기에서 grep으로 뽑는다.2
web-features.github/workflows/update-web-features.yml이 월·목에 자동 갱신한다. 수동으로는 pnpm update web-features를 돌리고 이어서 src/ci/generate-feature-to-groups.ts와 src/ci/validate-after-web-feature-update.ts를 돌린다.3CI workflow와 두 스크립트
compat·WebRef@mdn/browser-compat-data, @webref/css, @webref/elements, @webref/idl, caniuse-lite, mdn-data 6개를 "periodically" 올린다. 주기 수치는 원문에 명시 없음.3확인 명령 원문에 명시 없음
문서 일관성·링크coherence-auditor의 coherence-audit.ts를 실행한다.4스크립트 출력

원문이 보여 주는 명령 두 개다. 이 분석에서는 실행하지 않았다.

분석에서 실행하지 않은 명령

첫 명령은 npm info로 외부 registry를 조회한다. 이 분석에서는 어떤 명령도 실행하지 않았으므로 버전 비교와 테스트 결과는 확인하지 못했다.6

확인하지 못한 부분
