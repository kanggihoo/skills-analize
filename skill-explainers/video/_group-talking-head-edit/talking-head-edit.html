Answer

이 묶음의 세 스킬은 말하는 사람 영상을 가공하는 도구인데, 원문이 직접 이어 주는 연결은 하나뿐이다. sound-effects가 cue 목록을 만들 때 motion-broll의 plan.json을 소스 후보로 든다(r03). object-separation은 어느 스킬과도 연결이 없다(r05는 같은 계열 표시일 뿐이다).12

  1. 연결의 방향에 주의한다. plan.json을 읽을 수 있다고 말하는 쪽은 sound-effects다. motion-broll은 sound-effects를 부르지 않는다.13
  2. 권고형이다. 원문은 "구성 소스에서 가져올 수 있으면"이라고 쓰고, 안 되면 ffmpeg로 장면 전환을 감지하라고 한다. 필수 순서가 아니다.1
  3. 판정: motion-broll이 만드는 preview.mp4를 sound-effects의 입력으로 쓴다는 말은 원문에 명시 없음이다. 쓰면 코드가 입력 영상의 오디오를 버린다.4

세 스킬은 어떻게 이어지나

  1. 영상·자막 ↗

    사용자가 말하는 사람 영상과 자막(SRT·VTT)을 준다. 자막이 없으면 단어 시각을 음성에서 얻거나 SRT를 요청한다.

  2. motion-broll ↗

    인터뷰 한 번과 계획 승인 뒤, 말 한 마디에 맞춘 B-roll 클립과 미리보기를 만든다.

  3. plan.json ↗

    클립 목록과 시각을 담은 파일이다. motion/plan.json에 쓴다.

  4. sound-effects ↗

    cue 목록을 만들고 박자 격자를 확인한 뒤 효과음과 음악을 입혀 음량을 측정한다.

  5. 헤드폰 확인 5곳 ↗

    가장 위험한 타임스탬프 5개를 사용자에게 주어 직접 듣게 한다. 스킬은 "소리가 좋다"고 말하지 않는다.

  6. object-separation

    이 흐름과 연결이 없다. 영상에서 사람·제품·손을 분리해 초록색 강조 영상과 프레임별 마스크를 만든다.

그림의 점선은 sound-effects가 plan.json을 읽을 수 있다는 뜻이다. motion-broll이 sound-effects에 넘긴다는 뜻이 아니다.1

사람은 어디에서 개입하나

스킬사람 개입근거
motion-broll인터뷰는 한 번에 끝낸다. 계획 표를 보여 주고, 사용자가 승인하거나 고치기 전에는 코드를 쓰지 않는다910
sound-effects발행처(사용처)를 묻는다. 음악 출처와 라이선스를 묻고, 교체 보고서에서 선택을 받고, 마지막에 헤드폰으로 5곳을 확인하게 한다11612
object-separation지점이 여러 곳이다. 자세한 내용은 video/Barty-Bart/object-separation/object-separation.html에 있다7

두 스킬 사이에 사람이 중간에 넘겨 주는 지점(예: motion-broll 결과를 sound-effects에 넘기는 승인)은 원문에 명시 없음이다.

preview.mp4를 sound-effects에 넣으면 원본 음성이 사라질 수 있다

motion-broll의 preview.mp4는 원본 오디오를 유지한다.3 sound_pass.py는 입력 영상에서 영상 스트림만 가져오고 오디오는 새로 믹스한 것으로 바꾼다(-map 0:v -map 1:a).4 판정: 원문은 두 스킬 사이의 파일 연결로 plan.json만 말한다. 그러나 preview.mp4를 입력으로 쓰면 말하는 사람의 음성이 출력에서 빠진다. 스크립트 사용 예시는 입력을 silent.mp4로 적는다.5 코드는 실행하지 않았고 줄만 읽었다.

확인하지 못한 것

motion-broll의 최종 결과는 사용자가 자기 편집기에서 클립을 직접 배치해서 만든다. 그래서 sound-effects가 어느 판본의 영상에 소리를 입히는지는 원문에 명시 없음이다. motion-broll과 object-separation을 이어서 쓰는 방법은 원문에 없다. 설치 안내가 둘을 같이 고르게 할 뿐이다(r05).2 영상과 소리가 실제로 잘 나오는지는 확인하지 못했다. 세 스킬을 실행하지 않았다.
