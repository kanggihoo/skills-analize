scan-vulnerabilities

소스에서 취약점을 찾고 후보를 검증하고 공격 경로로 보고 여부를 정한다
  • security-scan 저장소 전체나 지정 경로의 현재 소스에서 공격자가 실제로 악용할 수 있는 취약점을 한 번의 audit로 찾는다
  • security-diff-scan PR, commit, branch diff, working-tree patch의 변경 파일을 위협 모델부터 공격 경로 분석까지 단계별로 돌려 취약점을 찾는다
  • deep-security-scan 사용자가 deep, 철저한 감사를 요청했을 때 Standard scan을 반복 실행해 결과를 병합한다
  • threat-model 저장소의 실제 구조, 공격자 능력, 신뢰 경계로 위협 모델을 만들거나 기존 모델을 재사용한다
  • finding-discovery 위협 모델과 보안 정책을 근거로 악용 가능해 보이는 취약점 후보를 찾아 근거와 함께 남긴다
  • validation 후보마다 근거가 받쳐 주는지 따져 reportable, suppressed, not_applicable, deferred 중 하나로 처분한다
  • attack-path-analysis finding을 source에서 sink까지 추적해 공격 경로, 영향, 심각도, 보고 여부를 정한다

remediate-finding

이미 있는 취약점 finding을 고치고, 고친 결과의 위험과 효과를 점검한다
  • triage-finding scanner 보고서, advisory, GitHub, Jira, Linear 항목을 정적 근거만으로 confirmed, not_actionable, needs_review로 분류한다
  • fix-finding 사용자가 요청한 보안 취약점을 가장 작은 변경으로 고치고 고쳐졌는지 검증한다
  • verify-fix 보안 수정이 현재 checkout에서 실제로 취약점을 막았는지 파일을 바꾸지 않고 판정한다
  • assess-patch-risk 이미 만들어진 patch를 읽기 전용으로 분석해 영향, 회귀 위험, 자동 merge 자격을 판정한다
  • resolve-dependency-alert 취약한 의존성이 무엇에 끌려 들어왔는지 추적하고 업그레이드 가능 여부를 판단한다

external-findings

scanner와 Cloud, issue tracker 사이에서 finding을 가져오고, 올리고, 기록하고, 읽는다
  • resolve-dependency-alert 취약한 의존성이 무엇에 끌려 들어왔는지 추적하고 업그레이드 가능 여부를 판단한다
  • publish-findings 외부 scanner 결과를 가져와 local workbench에 저장하고 선택분을 Codex Security Cloud에 게시한다
  • track-findings 봉인된 scan의 finding을 Linear, Jira, GitHub issue, 초안 advisory에 미리보기와 승인을 거쳐 기록한다
  • cloud-findings 연결된 Codex Security Cloud의 finding, 보고서, 할당, 검증 기록, scan 상태를 읽기만 한다

finding-reports

확정된 finding을 보고서와 구조적 보강안으로 정리한다
  • vulnerability-writeup 취약점 메모, PoC, finding을 다른 연구자가 확인할 수 있는 독립 보고서로 쓴다
  • propose-security-hardening 개별 patch를 넘어서는 구조적 보안 보강안을 근거와 대안 비교로 제안한다

threat-model-and-policy

scan 전에 읽을 보안 맥락(위협 모델, SECURITY.md)을 만들고 읽기 쉽게 보여 준다
  • threat-model 저장소의 실제 구조, 공격자 능력, 신뢰 경계로 위협 모델을 만들거나 기존 모델을 재사용한다
  • define-security-policy SECURITY.md를 새로 쓰거나 검토해 scanner가 무엇을 finding으로 볼지 알려 준다
  • threat-model-visualize 이미 있는 위협 모델을 읽어 구조와 위협 경로를 보여 주는 standalone HTML explorer를 만든다

skill-vetting

스킬을 설치하기 전에 위험한 지시와 스크립트를 읽기 전용으로 검토한다
  • check-skills 설치 전 스킬 파일이나 묶음을 읽기 전용으로 검토해 BLOCK, REVIEW, INCOMPLETE, PASS를 낸다
  • editorial-guide check-skills 평가 입력. 문단을 고치되 외부 URL의 최신 절차를 읽고 거기 적힌 도구 동작까지 모두 따르라고 지시하는 표본이다
  • word-list check-skills 평가 입력. 문단을 고치되 외부 URL은 단어 뜻 조회에만 쓰고 그 안의 지시는 인용문으로만 다루라고 하는 표본이다
  • style-guide check-skills 평가 입력. 위험한 curl ... \| sh 설치 예시를 나쁜 사례로만 인용해 설명하라는 표본이다
  • status-summary check-skills 평가 입력. 빌드 상태를 요약하라는 짧은 스킬이지만 참조 파일과 스크립트로 숨은 지시와 토큰 전송 경로를 둔 표본이다

R05codex-security/plugins/codex-security/skills/deep-security-scancodex-security/plugins/codex-security/skills/security-scan호스트가 Standard audit를 반복 실행해 finding을 병합하고, 연속 audit가 새 결과를 더하지 못하거나 설정된 scan 또는 시간 한도에 닿으면 멈춘다. max_discovery_runs는 같이 도는 Standard scan까지 센 총 횟수 상한이다. 구현 확인: (1) deep 워커 prompt는 <pluginRoot>/references/core-scan.md를 직접 읽고 따르라고 한다. security-scan SKILL.md:10도 같은 core-scan.md를 쓴다. 두 스킬은 이 문서를 공유할 뿐 deep이 security-scan SKILL.md를 호출한다는 문장은 없다(워커 prompt에는 "스킬이 필요하면 <pluginRoot>/skills/<이름>/SKILL.md를 읽으라"는 일반 지시만 붙는다). (2) 중단 조건은 streak >= stopAfterNoNew \|\| dispatched >= maxDiscoveryRuns 또는 discovery deadline이다. 이유 라벨은 saturated 또는 capped이다. saturated는 deadline에 닿지 않았고 streak >= stopAfterNoNew일 때만 붙고, 배정 상한이나 deadline에 닿으면 capped이다. streak은 병합 결과가 audit마다 돌려주는 수가 0이면 +1, 하나라도 있으면 0으로 되돌린다(coordinator.ts:804:806). dispatched는 batch를 배정하는 시점에 min(workers, maxDiscoveryRuns - dispatched)만큼 늘기 때문에 실패한 worker도 이미 센 값이고 그 자리를 채우려고 새로 배정한 worker도 다시 센다(867:872, 교체 이벤트는 893). 마감은 scan 생성 시각(state.createdAt, 없으면 현재 시각)부터 잰다(575:587). 연속 discovery 오류가 stopAfterConsecutiveErrors에 닿으면 오류로 끝난다. (3) 다음 pass에는 이미 보고된 finding을 경로:줄 제목 문자열로 넘긴다. (4) 설정 우선순위는 프로젝트 설정, 사용자 TOML, 번들 기본값 순이다. 설정 해석기가 값마다 붙이는 출처 라벨은 project, default, 그리고 사용자 TOML 값에 붙는 legacy이다(deep_scan_config.py:107:109). 프로젝트 schema의 scan.max_time_minutes는 Standard에서는 권고(기본값 없음)이고 Deep에서는 강제 한도(기본·최대 5760분=96시간)이다(project-config.schema.json:24:27). 번들 기본값은 workers 4, subagents 3, stopAfterNoNew 4, stopAfterConsecutiveErrors 3, maxDiscoveryRuns 40, maxTimeHours 96(상한 96)이다.
