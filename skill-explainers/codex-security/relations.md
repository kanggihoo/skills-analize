# codex-security 관계 원장
분석 커밋: a1d836f93ec897c67870ac042622e8aec36e5f6b

- **조사 상태 기준**: 표의 `조사 상태`는 이 컬렉션 안 스킬 폴더 파일을 얼마나 읽었는지만 뜻한다. 플러그인 루트 `references/`, `schemas/`처럼 컬렉션에 없는 필수 참조(R60~R64)를 읽지 못한 한계는 이 열과 별개로, 해당 스킬 페이지가 결론에 "부분 분석"으로 표시한다. `threat-model-visualize`만 폴더 안 렌더러 assets를 표본만 읽어 `부분`이다.

## 조사 메모
- 컬렉션은 git에 81개 파일이 커밋돼 있다(`git ls-files codex-security | wc -l`). SKILL.md 24개를 재귀로 모두 찾았다. `*.KO.md` 같은 번역본은 없었고 열지도 않았다. 이전 분석과 `.agents`는 제외했다.
- 동명 스킬 비교: 24개 이름을 저장소 전체의 SKILL.md 디렉터리명과 frontmatter `name:`으로 모두 찾았다. 겹치는 것은 `security-scan` 하나(`ecc/security-scan`)다. SHA-256이 다르고(`1e678be7...` / `74bc3006...`), 목적도 다르다. ecc 쪽은 `.claude/` 설정을 AgentShield로 점검하는 스킬이고 codex-security 쪽은 저장소 소스의 취약점을 찾는 스킬이다. 그래서 `동명·내용 다름`이다. 판본의 선후 관계는 근거가 없어 적지 않는다.
- 전제: 대부분의 SKILL.md가 `../../references/`(플러그인 루트)를 읽으라고 한다. 이 컬렉션은 `plugins/codex-security/skills/` 아래 스킬만 가져온 것이라 그 폴더가 없다. R60~R65는 끊긴 참조가 아니라 `범위 밖`이다. 이 문서들이 어떤 순서나 통과 조건을 더 정하는지는 이 분석에서 알 수 없다.
- 읽은 범위: SKILL.md 24개와 `skills-lock.json`은 전부 읽었다. `agents/openai.yaml` 20개도 전부 읽었다. `publish-findings`와 `track-findings`의 openai.yaml에만 `policy: allow_implicit_invocation: true`가 있고 SKILL.md frontmatter에는 호출 제한 필드(`disable-model-invocation` 등)가 어느 스킬에도 없다. 나머지 18개 openai.yaml에는 `policy`가 없다.
- `부분` 사유: `threat-model-visualize`는 파일 14개 241KB다.
