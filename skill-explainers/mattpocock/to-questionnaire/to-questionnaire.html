to-questionnaire 스킬은 에이전트를 어떻게 바꾸나

Long image

A

Answer

to-questionnaire를 쓰면 에이전트는 사용자가 혼자 답할 수 없는 결정을 질문지로 만든다. 질문지는 답을 아는 다른 사람이 비동기로 채우거나 회의에서 함께 채우는 Markdown 문서다.1

  1. 사용자에게는 주제가 아니라 "보내는 일"만 묻는다. 누구에게 보내는지, 무엇을 돌려받아야 하는지다.2
  2. 질문은 받는 사람이 아는 것과 사용자가 필요한 것 사이의 빈틈을 겨눈다.2
  3. 결과는 현재 폴더의 to-questionnaire-<slug>.md 파일 하나다. 에이전트는 그 경로를 알린다.3

1

언제 켜지나

disable-model-invocation: true라서 모델이 스스로 켜지 않는다.4 agents/openai.yaml도 allow_implicit_invocation: false다.5 사용자가 /to-questionnaire를 입력할 때 켜진다. 인자 힌트는 없다.

2

어떤 순서로 만드나

Diagram structure
  • 받는 사람 질문 who
  • 필요한 것 질문 need
  • 질문지 작성 write
  • need → write
  • who → need
  1. 받는 사람 질문 ↗

    한 번의 주고받기로 받는 사람의 역할, 전문 분야, 사용자와의 관계를 묻는다. 말투와 맥락의 양이 여기서 정해진다. 받는 사람이 누구이고 사용자가 모르는 무엇을 아는지 알면 끝난다.

  2. 필요한 것 질문 ↗

    한 번의 주고받기로 사용자가 혼자 풀 수 없는 결정이나 사실을 묻는다. 사용자가 무엇을 하거나 정할 수 있어야 하는지 구체적인 목록이 생기면 끝난다.

  3. 질문지 작성 ↗

    1~2단계의 빈틈을 겨눈 질문을 아래 틀대로 쓴다. 현재 폴더의 to-questionnaire-<slug>.md에 저장하고 경로를 알린다. 파일이 있고 2단계 항목이 모두 질문으로 덮이면 끝난다.

각 단계의 완료 조건은 원문 그대로다.3 슬러그(slug)는 주제에서 만든다. 사용자 질문은 1·2단계의 두 번뿐이고, 작성한 질문지를 승인받는 단계는 원문에 명시 없음.

이 분석의 범위와 한계

  • 읽은 파일: SKILL.md, agents/openai.yaml. 두 파일 모두 원본이다.
  • 제외한 파일: SKILL.KO.md. 원본이 있는 번역본이다.
  • 원문 비교: 다른 컬렉션에 이름이 같은 스킬이 없다(원장 기준). 원장에 이 스킬의 관계 행은 없다.
  • 실행하지 않았다. 질문과 파일 작성은 지시상 동작이다.
  • 분석 중 바뀐 파일: 없음.

확인하지 못한 것

마감과 품을 누가 정하는지, 같은 이름의 파일이 이미 있을 때 어떻게 하는지는 원문에 명시 없음.
