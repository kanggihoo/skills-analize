git-guardrails-claude-code 스킬은 에이전트를 어떻게 바꾸나

Long image

A

Answer

git-guardrails-claude-code를 쓰면 에이전트는 Claude Code에 PreToolUse 훅을 설치한다. 그 뒤로 Bash 명령에 위험한 git 패턴이 들어 있으면 훅이 종료 코드 2로 실행을 막는다.12

  1. 설치 전에 사용자에게 두 번 묻는다. 적용 범위(이 프로젝트/모든 프로젝트)와 막을 패턴의 추가·삭제다.34
  2. 막는 방식은 명령 문자열에 grep -E 패턴 9개를 대 보는 것이다. git 문법을 해석하지 않는다.5
  3. 판정: 문자열 비교라서 빈틈과 과잉 차단이 함께 있다. 예를 들어 git -C repo push는 통과하고, 커밋 메시지에 "git push"가 들어간 명령은 막힌다.5
  4. 완료 확인은 가짜 git push 입력을 스크립트에 넣어 종료 코드 2와 BLOCKED 메시지를 보는 것이다.6

1

언제 켜지나

frontmatter에 disable-model-invocation이 없다. 그래서 모델이 description을 보고 스스로 켤 수 있다.7 agents/openai.yaml에도 policy 블록이 없어서 암묵 호출을 막는 allow_implicit_invocation: false가 없다.8

description이 그리는 상황은 위험한 git 작업을 막고 싶을 때, git 안전 훅을 더하고 싶을 때, push나 reset을 막고 싶을 때다. 이 설명은 판단 참고용이다. 특정 단어가 나와야만 켜지는 것은 아니다.

  1. 범위 질문 ↗

    사용자에게 이 프로젝트만인지, 모든 프로젝트인지 묻는다. 답에 따라 아래 표의 경로가 갈린다.

  2. 훅 설치 ↗

    동봉된 block-dangerous-git.sh를 hooks 폴더로 복사하고 chmod +x로 실행 권한을 준다. 이어서 settings 파일의 hooks.PreToolUse에 matcher: "Bash" 항목을 넣는다. 파일이 이미 있으면 배열에 합치고 다른 설정은 덮어쓰지 않는다.

  3. 패턴 질문 ↗

    차단 목록에 패턴을 더하거나 뺄지 묻는다. 답에 맞춰 복사한 스크립트를 고친다.

  4. 시험 ↗

    git push origin main을 담은 JSON을 스크립트에 넣는다. 종료 코드 2와 stderr의 BLOCKED 메시지가 나와야 한다.

범위스크립트 위치설정 파일훅 명령
프로젝트.claude/hooks/block-dangerous-git.sh.claude/settings.json"$CLAUDE_PROJECT_DIR"/.claude/hooks/block-dangerous-git.sh
전역~/.claude/hooks/block-dangerous-git.sh~/.claude/settings.json~/.claude/hooks/block-dangerous-git.sh

위 표는 2·3단계 원문을 정리한 것이다.910 완료 조건은 5단계의 시험 결과 하나다. 실제 Claude Code 세션에서 훅이 걸리는지 보라는 지시는 원문에 명시 없음.6

사용자 설정 파일을 고친다

전역 범위를 고르면 ~/.claude/settings.json을 고친다. 이 파일은 모든 프로젝트에 영향을 준다. 원문은 기존 설정을 덮어쓰지 말고 합치라고만 한다. 백업 지시는 원문에 명시 없음.

3

스크립트는 정확히 무엇을 막나

스크립트는 표준 입력의 JSON에서 jq로 .tool_input.command를 꺼낸다.12 그다음 패턴을 차례로 grep -qE에 대 본다. 처음 걸린 패턴에서 stderr에 메시지를 쓰고 exit 2로 끝난다. 하나도 안 걸리면 exit 0이다.2

패턴(정규식)막히는 예판정: 빠지는 예
git pushgit push, git push --force, git pushxgit -C repo push, git push(공백 2칸)
git reset --hard / reset --hardgit reset --hard, git -C repo reset --hardgit reset --hard(공백 2칸)
git clean -fd / git clean -fgit clean -f, git clean -fdxgit clean -xfd, git clean --force
git branch -Dgit branch -D xgit branch --delete --force x
git checkout \.git checkout ., git checkout .env없음
git restore \.git restore .git restore --staged .
push --forcegit -C repo push --forcegit -C repo push -f

표의 "막히는 예"와 "빠지는 예"는 분석자가 패턴을 따로 grep -E에 대 본 결과다. 스크립트 자체는 실행하지 않았다.5

  • 판정: grep은 명령 전체 문자열에서 찾는다. 그래서 grep 'git push' notes.md나 메시지에 "git push"가 든 git commit도 막힌다.2
  • 판정: git checkout \.은 점으로 시작하는 파일 하나를 되돌리는 git checkout .env도 막는다.5
  • 판정: jq가 없으면 COMMAND가 빈 문자열이 되어 모든 명령이 exit 0으로 통과한다. jq 설치 확인은 원문에 명시 없음.12

SKILL.md는 막힐 때 Claude가 "이 명령을 쓸 권한이 없다"는 메시지를 본다고 쓴다.1 실제 스크립트 메시지는 "The user has prevented you from doing this."다.2 뜻은 같지만 문구가 다르다.

이 분석의 범위와 한계

  • 읽은 파일: SKILL.md, agents/openai.yaml, scripts/block-dangerous-git.sh. 세 파일 모두 원본이다.
  • 제외한 파일: 없음. 이 스킬 폴더에는 번역본이 없다.
  • 원문 비교: 다른 컬렉션에 이름이 같은 스킬이 없다(원장 기준).
  • 실행하지 않았다. 설치·질문·시험 실행은 모두 지시상 동작이다. 패턴 표는 패턴 문자열만 따로 grep -E로 확인했다.
  • 분석 중 바뀐 파일: 없음.

확인하지 못한 것

종료 코드 2를 받은 Claude Code가 도구 호출을 어떻게 처리하는지는 Claude Code 문서의 영역이다. 이 스킬 원문에 명시 없음. 이미 다른 PreToolUse 훅이 Bash에 걸려 있을 때 실행 순서도 원문에 명시 없음.
