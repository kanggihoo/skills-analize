setup-pre-commit 스킬은 에이전트를 어떻게 바꾸나

Long image

A

Answer

setup-pre-commit을 쓰면 에이전트는 현재 저장소에 Husky 커밋 전 훅을 설치한다. 훅은 스테이징된 파일에 Prettier를 돌리고, 이어서 타입 검사와 테스트를 돌린다.1

  1. 패키지 관리자는 잠금 파일로 고른다. 애매하면 npm을 쓴다.2
  2. 사용자에게 묻는 단계가 없다. typecheck나 test 스크립트가 없을 때만 그 줄을 빼고 사용자에게 알린다.3
  3. 마지막에 바뀐 파일을 모두 스테이징하고 직접 커밋한다. 이 커밋이 새 훅의 첫 시험이다.4
  4. 판정: 커밋 전에 사용자 확인을 받으라는 말이 없어서, 이 스킬이 켜지면 커밋까지 한 번에 간다.4

1

언제 켜지나

frontmatter에 disable-model-invocation이 없다. 그래서 모델이 description을 보고 스스로 켤 수 있다.5 agents/openai.yaml에도 policy 블록이 없다. 암묵 호출을 막는 allow_implicit_invocation: false가 없다는 뜻이다.6

description이 그리는 상황은 커밋 전 훅, Husky, lint-staged, 커밋 시점의 포맷·타입 검사·테스트를 더하고 싶을 때다. 이 설명은 판단 참고용이다.

  1. 관리자 감지 ↗

    package-lock.json이면 npm, pnpm-lock.yaml이면 pnpm, yarn.lock이면 yarn, bun.lockb이면 bun을 쓴다. 애매하면 npm이다.

  2. 의존성 설치 ↗

    husky, lint-staged, prettier를 개발 의존성으로 설치한다. 이어서 npx husky init으로 .husky/를 만들고 package.json에 prepare: "husky"를 넣는다.

  3. 설정 파일 작성 ↗

    .husky/pre-commit, .lintstagedrc를 쓴다. Prettier 설정이 하나도 없을 때만 .prettierrc를 만든다.

    아래 다섯 항목을 확인한다. 마지막 항목은 npx lint-staged를 직접 돌리는 것이다.

  5. 커밋 ↗

    바뀐 파일을 모두 스테이징하고 Add pre-commit hooks (husky + lint-staged + prettier) 메시지로 커밋한다. 새 훅이 이 커밋에서 처음 돈다.

3

언제 끝났다고 보나

위 목록은 7단계 원문 그대로다.11 8단계 커밋이 훅을 거쳐 성공하면 종단 시험까지 끝난다.4

커밋 범위와 확인 절차

8단계는 "바뀌거나 만든 파일을 모두" 스테이징한다. 판정: 작업 트리에 이 스킬과 무관한 변경이 있으면 그것도 같은 커밋에 들어갈 수 있다. 커밋 전 사용자 확인은 원문에 명시 없음.4

판정: 원문 안에 작은 불일치가 있다. 설치는 감지한 관리자로 하라고 하지만, npx husky init과 확인 단계의 npx lint-staged는 npx로 고정돼 있다.911 이미 있는 lint-staged 설정(예: package.json의 키)을 어떻게 할지도 원문에 명시 없음.
