환경 개선 묶음(env-improve)은 어떻게 이어지나

A

Answer

긴 목표를 밀고 가면서 에이전트가 일하는 환경을 계속 고치는 스킬 세 개다. chief-of-staff가 허브이고, 세션 일부를 retro로 돌아보며, retro는 문서 기준을 writing-for-agents에서 가져온다.12

  1. chief-of-staff는 서브에이전트 세션 약 5개 중 1개에 retro를 쓴다. Skill 도구가 아니라 ../retro/SKILL.md를 읽어 따른다.1
  2. retro는 1단계에서 Skill 도구로 writing-for-agents를 부른다.2
  3. 호출 방식이 다른 이유는 disable-model-invocation 필드다. 이 필드가 있는 스킬은 다른 스킬이 부를 수 없다.3
  4. 단독 retro는 후보를 사용자에게 내놓고 끝난다. chief-of-staff 안에서는 에이전트가 직접 고르고 실행한다.41

  2. retro ↗

    사용자가 /retro로 단독 실행할 수도 있다. 세션 기록에서 일곱 범주의 환경 개선 후보를 찾아 심각도 순으로 낸다.

    개선 내용을 스킬이나 AGENTS.md 같은 문서로 쓸 때의 기준을 준다.

    큰 작업이면 명세, 티켓, 구현 스킬을 파일로 읽어 따른다. 세 폴더가 이 저장소에 없다.

writing-for-agents의 SKILL-MECHANICS.md가 이 차이의 규칙을 적는다. 사용자 호출형 스킬은 사람이 이름을 입력해야만 켜지고, 다른 스킬은 부를 수 없다.3 모델 호출형 스킬은 다른 스킬이 부를 수 있고, 여러 스킬이 쓰는 참고 자료를 한 곳에 둘 수 있다.17

판정: 그래서 chief-of-staff는 retro를 Skill 도구로 부를 수 없고, 옆 폴더의 SKILL.md를 파일 경로로 읽는다(r01).18 writing-for-agents는 필드가 없어 retro가 Skill 도구로 부른다(r03).2 파일로 읽는 방식은 "사용자 호출형끼리 나눌 자료는 스킬 체계 밖의 일반 파일로 둔다"는 규칙과 같은 해법이다.19

이 분석의 범위와 한계

  • 읽은 파일: 묶음 스킬 3개의 SKILL.md, writing-for-agents/SKILL-MECHANICS.md, 세 스킬의 agents/openai.yaml. 관계 확인을 위해 setup-pre-commit, git-guardrails-claude-code의 머리말을 읽었다. 모두 원본이다.
  • 제외한 파일: chief-of-staff/SKILL.KO.stale.md, retro/SKILL.KO.md. 번역본이다.
  • 원문 비교: r01, r02, r03, r09, r10의 출처 줄을 원문과 대조했다. 종류와 조건이 원장과 같다.
  • 원장의 묶음 표는 to-spec 외 세 스킬을 "범위 밖"이라 부르지만, 관계 행 r02의 해석 상태는 "불명"이다. 이 페이지는 r02를 따라 불명으로 적었다.
  • 실제로 실행해 보지 않았다. 페이지의 흐름은 모두 지시상 동작이다.
  • 분석 중 바뀐 파일: 없음.

확인하지 못한 것

to-spec, to-tickets, implement-spec의 내용은 확인하지 못했다. 폴더가 이 저장소에 없다(r02). chief-of-staff 안에서 회고를 에이전트가 직접 하는지 서브에이전트에게 맡기는지는 원문에 명시 없음.
