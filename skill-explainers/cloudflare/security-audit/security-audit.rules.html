이 페이지는 ATTACK-CLASSES.md와 도메인 지침 열 개를 맡는다. 개요의 정찰이 어떤 파일을 고를지 정하고 사냥의 hunter 지시문이 그 원문을 복사한다. 원칙형이라 순서를 만들지 않고 규칙표와 선택 조건으로 보인다. 시작 입력은 정찰이 찾은 trust boundary이고, 끝 출력은 ledger unit의 selected_companion_blocks와 hunter 지시문 4번 부분이다.1

1

일반 attack class 아홉 개는 무엇을 보나

ATTACK-CLASSES.md의 일반 class는 시작점이다. 모든 class가 모든 codebase에 맞지는 않으므로 정찰이 앱 유형에 맞는 것을 고르고, 큰 codebase는 subsystem별로 나누며, 앱에 특화된 class를 더한다. 작업은 취약점을 찾고 검증하고 고치고 우선순위를 매기는 것으로 틀을 잡고, 검증은 소스 검토와 제한된 local fixture에 한정한다. payload 체인 개발, live 서비스 availability 시험, 공유 환경 조치는 하지 않는다.2

class보는 것특히 주의하는 점출처
Injection입력이 진입점에서 위험한 sink까지 가는 경로. sink는 앱 유형마다 다르다(web은 SQL·HTML·shell·template·파일 경로·redirect·deserialization, library는 검증 없는 caller 데이터 처리 등)직접 경로에서 멈추지 않는다. 안전하게 저장했다가 다른 코드가 위험한 맥락에서 쓰는 간접 injection, 값이 아닌 field 이름·key·header·metadata, 로그·cache·검색 index 같은 보조 시스템3
Access controlcaller가 권한 밖의 일을 못 하는지권한 검사가 있는지보다 올바른 자원에 올바른 메커니즘으로 올바른 권한을 검사하는지. 같은 상태 변경에 더 약한 권한을 검사하는 다른 경로, 요청 body 필드가 권한 설계를 덮는 경우, 인증만 있고 인가가 없는 endpoint, bulk·export·import의 항목별 권한. 복잡하면 auth bypass와 authorization logic으로 agent를 나눈다4
Resource and file handlingpath traversal(symlink·인코딩·null byte 포함), SSRF(redirect·DNS rebinding·URL parser 차이 포함), 안전하지 않은 deserialization·archive 추출·임시 파일, 해당하면 memory safety, 파일 연산의 TOCTOU확인과 사용 사이의 경쟁5
Cryptography and secrets약한 난수, 하드코딩된 secret과 로그·오류·URL·client 응답의 secret, 잘못된 key 파생, HMAC 검증 누락, nonce 재사용, secret 비교의 timing, 암호 primitive 오용crypto 연산이 실패할 때 오류 경로가 암호 없이 진행하는지6
Business logic주요 workflow마다 상태 기계 위반, 비즈니스 영향이 있는 경쟁, 수량·숫자 조작, 접근 경계 위반, 암묵적 신뢰 가정, 시간 기반 논리, 기본·fallback 동작일반 scanner가 못 찾고 영향이 큰 오류를 사람이 직접 찾는다. 단계 건너뛰기·되돌리기·재생, 중간 실패 시 rollback 여부7
Feature abuse and data leakage정상 기능을 의도하지 않은 목적에 쓰는 설계 버그. export·backup의 유출, import·restore의 주입, 검색·filter·정렬이 oracle이 되는 경우, 부작용을 통한 enumeration, preview·draft 유출, 알림·webhook을 통한 SSRF오류 메시지·응답 시간·크기·상태 코드 차이8
Chained vulnerabilities and trust boundaries각각은 허용되거나 억제된 동작이 다른 구성요소의 더 강한 보장 가정과 만나 취약점이 되는 경우. 다단계 경계 실패, 구성요소 간 신뢰 틈, 2차 사용, 범위·capability 확대, 시점·순서, rollback·복구구체적 출력만 이어 붙이고 전제는 하나씩 확인한다. 하류 효과를 가정하지 않는다9
Wildcard표준 class 밖의 취약점. 지루하거나 보안과 무관해 보이는 코드, 미완성·실험·호환·fallback 기능, frontend가 안 쓰는 API 사용법, 숨은 endpoint, 섞어 쓰도록 설계되지 않은 기능 조합, git 이력, 테스트가 다루지 않는 것이상한 부분은 안전 여부를 말할 수 있을 때까지 읽는다. 안전하다는 주석이 있으면 그 설명을 검증한다. 같은 구체적 경계와 검증 요건은 다른 class와 같다10
Obvious things기본 노출. 하드코딩된 secret, 보안 관련 TODO, debug·dev mode 게이트, 운영에서 통하는 test·seed credential, 보호 안 된 /debug·/admin 류 endpoint, 저장소에 들어간 .env·키 파일, .gitignore, 의존성 pin과 알려진 CVE, 동적 입력 eval·exec, CORS·cookie 속성, open redirect, TLS, 운영 오류의 stack trace창의적일 필요 없이 철저하고 문자 그대로 항목을 모두 확인하고 결과를 보고한다. 단, 보고하는 finding마다 전체 코드 경로를 확인해야 한다. flag는 finding이 아니고 영향을 추적해야 한다11

겹치는 영역은 어느 파일이 맡나

선택한 파일에서 hunter 지시문에 무엇이 복사되나

도메인 파일은 같은 뼈대를 가진다. When to use this file은 정찰이 파일을 고르는 근거이고, Core discipline은 영역의 핵심 원칙을 담은 코드 블록이다. 그 뒤로 영역별 attack class 묶음, Universal moves, Validation rules가 온다.13

hunter 지시문 4번 부분은 선택한 일반 class block 전체와, 각 companion에서 Core discipline, 고른 attack class 하위 절, Universal moves, Validation rules를 원문 그대로 복사한다. block 이름만 보내지 않는다. 일반 class block은 스스로 완결되어 있고 companion식 Core discipline·Universal moves·Validation rules 절이 없다.24

ledger unit이 이 block을 가리키는 형식은 FILE.md# 뒤에 그 파일에 굵게나 제목으로 쓰인 class 이름을 그대로 붙인 것이다. 렌더된 HTML anchor가 아니라 파일 텍스트와 대조하는 식별자다. companion 절은 괄호 앞의 제목 텍스트를 쓴다(예: Core discipline). 표시 label을 소문자로 바꾸거나 slug로 만들어 참조를 만들지 않는다.25

모든 도메인 파일의 Validation rules는 마지막 항목에서 같은 선택을 요구한다. 완전한 소스 trace와 의미 있는 결과가 있을 때만 confirmed를 돌려주고, 풀리지 않은 구체적 사실이 있으면 그 사실과 그것을 풀 제한된 local 또는 소유자 관찰 확인을 적어 needs_validation을 돌려준다. 예로 AI-AND-LLM.md의 여섯째 규칙이 이렇게 쓴다.26
