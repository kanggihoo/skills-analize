전체 감사 모드의 parent는 정찰 agent를 띄우기 전에 다섯 값, 프로필, 예산을 정하고, 정찰에서 architecture.md, 도메인 파일 선택, coverage-ledger.json을 만든다.12

  1. 예산이 정찰 호출 네 번, 마지막 critic 몫, verifier 최소 한 번을 감당하지 못하면 agent를 하나도 띄우지 않고 incomplete로 끝난다.3
  2. 정찰은 대상과 로컬의 빌드·설정 상태만 읽고 배포된 endpoint나 공유 서비스에는 접속하지 않는다.4

전체 감사 개요 페이지의 앞 세 단계를 자세히 본다. 전체 그림은 개요에 있다.

  1. 예산이 충분한가? ↗

    전체 감사로 정해지면 parent는 다섯 값(스킬 폴더, 대상 경로, repo 이름, 출력 폴더, 소스 ref)과 프로필(기본 standard), 예산(모든 단계를 합친 agent 호출 최대 횟수)을 정한다.15 그다음 정찰 호출 네 번, 마지막 critic 몫, verifier 최소 한 번이 예산에 들어가는지 확인한다.3

  2. incomplete로 중단 ↗

    예산이 이 최소를 감당하지 못하면 agent를 하나도 띄우지 않고 사용자에게 더 큰 예산, 좁은 범위, 다른 프로필 중 하나를 요청한다. 요청이 그대로이면 run_status: "incomplete"와 이유 budget_cannot_fund_reconnaissance_and_reserves를 기록하고 감사가 한 번도 돌지 않았다고 보고한다.34

  3. Phase 1 정찰 ↗

    RECONNAISSANCE.md를 읽는다. parent가 읽기 전용 research agent 네 개를 병렬로 띄운다. 1a는 스택과 빌드 명령, 1b는 낮은 신뢰 주체와 인증·인가 통제, 1c는 진입면과 싱크, 1d는 로컬 실행 가능성과 샌드박스 통제를 조사한다.6 결과로 parent가 architecture.md(약 1,000단어 상한)를 쓰고, 보인 경계에 맞는 도메인 파일을 고르고, 진입면·신뢰 경계·subsystem·attack class 조합마다 한 줄씩 coverage-ledger.json에 planned로 적는다.27 검증 스크립트가 통과해야 작업을 배정한다.8 정찰 중에는 배포된 endpoint나 공유 서비스에 접속하지 않는다.4

프로필은 무엇을 바꾸나

프로필은 hunter 반복과 verifier 구성만 바꾼다. 후보 통과 조건, 소스·로컬 실행 경계, needs_validation 규율, 스키마 검증, confirmed 기록의 독립 검증은 어느 프로필에서도 줄이지 않는다.5
