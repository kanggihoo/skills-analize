Answer

typescript-best-practices를 쓰면 에이전트는 .ts나 .tsx 파일을 읽거나 고칠 때 규칙 16개를 적용한다. 핵심은 잘못된 상태를 타입으로 만들 수 없게 하고, 외부 데이터는 경계에서 한 번 검증하는 것이다.1

  1. 먼저 principle-type-system-discipline 원칙을 적용하라고 한다. 이 스킬은 그 원칙을 TypeScript 문법으로 옮긴 것이다.23
  2. as 캐스트는 검증 뒤에만 쓴다. 타입을 좁히는 방법에는 다섯 단계 우선순위가 있다.1
  3. pstack에서 paths: 필드를 가진 스킬은 이 스킬 하나다. 대상 파일을 **/*.ts, **/*.tsx로 선언한다.4
  4. 코드 예는 references/patterns.md에 있다. 규칙 16개 가운데 14개에 예가 있다.56

1

언제 켜지나

disable-model-invocation: true라서 모델이 스스로 이 스킬을 켜지 않는다.4 사용자가 /typescript-best-practices를 입력하면 켜진다. poteto-help는 ".ts나 .tsx 작업에 TypeScript 규칙을 적용할 때" 쓰라고 안내한다.7

paths: 필드는 이 스킬이 다루는 파일을 경로 패턴으로 적는다. reflect의 종합 담당 프롬프트도 "path-shaped triggers belong in paths:, not description prose"를 남길 패턴으로 든다.8 판정: 저자는 paths:를 경로 기반 트리거로 쓰려고 넣었다. 다만 이 필드가 disable-model-invocation: true와 함께 있을 때 실행 환경이 스킬을 자동으로 붙이는지는 원문에 명시 없음.4

pstack 안에서 이 스킬을 직접 부르는 스킬은 없다. principle-type-system-discipline이 이 스킬을 "특정 문법으로 구체화하는 스킬"의 예로 든다(r97).3 poteto-mode는 타입이나 시그니처를 설계할 때 그 원칙을 꺼낸다.9

2

어떤 규칙을 적용하나

잘못된 상태를 만들 수 없게 모델링한다.

규칙에이전트가 하는 일예외·조건
판별 유니온(Discriminated unions)변형마다 kind 같은 리터럴 판별 필드를 둔다. 선택 필드 묶음을 쓰지 않는다10판별 필드 이름(kind, type, tag)은 하나로 정해 지킨다11
브랜드 타입(Branded types)& { readonly __brand: "X" }로 원시 값을 구분한다. 경계에서 한 번 검증한다10이 모양을 그대로 쓰고 새 관례를 만들지 않는다12
구성으로 모델링잘못된 값이 아예 만들어지지 않는 모양을 고른다. 비어 있지 않은 배열은 [T, ...T[]], 짝수 길이는 [T, T][], 기간은 start와 duration10런타임 검사나 정제 타입에 기대지 않는다. durationMs는 원시 숫자가 섞일 위험이 있을 때만 브랜드를 붙인다13
가장 단순한 total 타입모든 연산이 total이면 T[]를 그대로 둔다10!, 캐스트, "should never happen" throw가 생기는 곳에서만 NonEmpty<T>로 강화한다14

외부 데이터는 경계에서 검증하고, 안에서는 타입을 믿는다.

규칙에이전트가 하는 일예외·조건

실제 테스트돌릴 수 있는 것은 가짜(mock)로 바꾸지 않는다. 프레임워크의 실제 테스트 도구와 누수 검사를 쓰고, UI는 실행 중인 빌드에서 확인한다22로컬에서 못 돌리는 것만 가짜로 바꾼다. patterns.md에 예 없음

as를 없앨 때 찾는 원인 네 가지다.18

  • 판별 필드가 없다. 하나 더하고 판별 유니온으로 바꾼다.
  • 원본 타입이 너무 넓다(예: Record<string, unknown>). 좁힌다.
  • 경계에 타입이 없다. 그 모양을 가진 스키마로 파싱한다. 스키마가 없을 때만 더한다.
  • 정말 표현할 수 없다. 브랜드 타입이나 satisfies를 쓴다.

코드는 어떻게 달라지나

선택 필드 묶음을 판별 유니온으로 바꾸는 예다. 고치기 전 모양은 "loading인데 error도 있는" 상태를 허용한다.24

느슨한 배열이 !를 부르는 곳에서만 입력 타입을 강화하는 예다.14 결과를 Session | undefined로 약하게 하는 것도 다른 total 시그니처로 인정한다.25

이 분석의 범위와 한계

  • 읽은 파일: SKILL.md, references/patterns.md. 두 파일 모두 원본이다.
  • 관계 확인용으로 읽은 줄: 위 출처 목록의 다른 스킬 줄. 각 줄만 확인했다.
  • 제외한 파일: SKILL.KO.md, references/patterns.KO.md. 원본이 있는 번역본이다.
  • 원문 비교: 다른 컬렉션에 이름이 같은 스킬이 없다.
  • 실제로 실행해 보지 않았다. 페이지의 동작은 모두 지시상 동작이다.
  • 분석 중 바뀐 파일: 없음.

확인하지 못한 것

paths:와 disable-model-invocation: true가 함께 있을 때 Cursor 환경이 경로에 맞는 파일을 열면 스킬을 붙이는지는 원문에 명시 없음.4 patterns.md는 "Code examples for each rule"이라고 적지만, "Real tests"와 "Structured telemetry"에는 절이 없다.622 SKILL.md는 principle-type-system-discipline을 먼저 적용하라고 하고, principle-boundary-discipline을 참고하라고 한다. 관계 원장에는 이 스킬에서 나가는 두 관계가 없다.226
