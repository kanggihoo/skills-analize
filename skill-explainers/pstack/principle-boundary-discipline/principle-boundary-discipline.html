Long image

A

Answer

principle-boundary-discipline을 읽은 에이전트는 검증, 타입 좁히기, 오류 처리를 시스템 경계에만 둔다. 경계 안쪽 코드는 조건 없이 믿고, 비즈니스 로직은 순수 함수로 뺀다.1

  1. 경계는 CLI 인자, 설정 파일, 외부 API, 네트워크 프로토콜이다. 여기서는 검증하고 오류를 돌려주며 방어적으로 다룬다.2
  2. 안쪽에서는 타입이 있는 데이터를 쓰고 오류를 전파만 한다. 다시 검증하지 않는다.2
  3. 원문은 이유를 두 가지로 든다. 흩어진 검증은 시끄럽고 중복되며 안전하다는 착각을 준다. 로직을 프레임워크 연결부에서 떼어야 프레임워크 없이 테스트할 수 있다.3
  4. 판단 질문은 둘이다. "이 데이터가 지금 경계를 넘는가?" "셸이 부르기만 하는 순수 함수로 만들 수 있는가?"4

확인하지 못한 것

원문이 꼽은 경계는 CLI 인자, 설정 파일, 외부 API, 네트워크 프로토콜이다. 데이터베이스 행이나 환경 변수가 경계인지는 이 원칙에 명시 없음. principle-type-system-discipline은 둘 다 파싱이 필요한 외부 데이터로 꼽는다. 그 원칙의 해당 줄만 확인했다.16
