검증 도구 묶음(verify-harness)은 어떻게 이어지나

Long image

A

Answer

이 묶음은 앱을 사용자처럼 직접 돌려 변경을 증명할 도구를 만들고 유지하는 스킬 세 개다. create-verification-skill이 대상 프로젝트에 검증 스킬을 만들고, maintain-verification-skill이 그 스킬을 앱에 맞게 고친다.12

  1. 두 스킬은 같은 폴더 .cursor/skills/verify-<app>/를 쓰고 읽는다. 이 폴더는 pstack 저장소가 아니라 대상 프로젝트 저장소에 있다.34
  2. 설정 마지막에 앱을 직접 돌릴 수단이 없으면, setup-pstack은 검증 스킬 만들기를 한 번만 제안한다. 사용자가 예라고 할 때만 실행한다.5
  3. create-verification-skill은 끝에서 유지 스킬을 안내만 한다. 유지 주기는 사용자가 물을 때만 제안한다.6
  4. maintain-verification-skill은 대상 검증 스킬이 없으면 멈추고 create-verification-skill을 가리킨다.4

어떤 순서로 이어지나

Diagram structure

  • create → skill · 생성
  • maintain → skill · 고침

  1. setup-pstack ↗

    setup-pstack은 설정 마지막 단계에서 프로젝트에 앱을 직접 돌릴 수단이 있는지 본다. 없으면 한 번만 제안하고, 사용자 답이 예일 때만 실행한다.

  2. 검증 스킬 생성 ↗

    create-verification-skill이 저장소를 조사해 프로젝트 전용 검증 스킬과 기능 지도를 만든다. 넘기기 전에 생성한 스킬을 한 번 끝까지 돌려 증명한다.

  3. 검증 스킬 유지 ↗

    maintain-verification-skill이 기능 지도의 기능마다 소스를 읽고 앱을 직접 돌려, 검증 스킬과 앱이 어긋난 곳을 고친다.

  4. verify 폴더 ↗

    create-verification-skill이 .cursor/skills/verify-<app>/에 만드는 SKILL.md와 features/다. 대상 프로젝트 저장소에 생긴다.

그림에 없는 안내가 두 가지 있다. create-verification-skill은 끝에서 사용자에게 유지 스킬을 안내한다(r80).6 maintain-verification-skill은 대상 검증 스킬을 찾지 못하면 멈추고 create-verification-skill을 가리킨다(r82).4

각 스킬의 내부 단계는 pstack/create-verification-skill/create-verification-skill.html, pstack/maintain-verification-skill/maintain-verification-skill.html에 있다.

이 상태는 대상 프로젝트 저장소에 있다. maintain-verification-skill은 이 폴더(검증 스킬의 SKILL.md, features/, 스킬이 가진 하네스 스크립트)만 고친다. 제품 코드는 고치지 않는다.10 maintain-verification-skill은 create-verification-skill이 만들지 않은 검증 스킬이라도, 기능 지도만 있으면 대상으로 삼는다.2

확인하지 못한 것

setup-pstack은 /create-verification-skill을 워크스페이스, 사용자, 플러그인 중 pstack을 설치한 위치에서 찾을 수 있다고 적는다. 셋 중 어느 것을 먼저 찾는지는 원문에 명시 없음.5 maintain-verification-skill을 얼마나 자주 돌릴지는 원문에 명시 없음. create-verification-skill은 사용자가 물을 때만 주기를 제안한다.6
