principle-guard-the-context-window 스킬은 에이전트를 어떻게 바꾸나

Long image

A

Answer

principle-guard-the-context-window를 읽은 에이전트는 컨텍스트 창을 세션 안에서 다시 채울 수 없는 자원으로 다룬다. 큰 출력은 서브에이전트에게 보내고, 메인 스레드에는 요약만 남긴다.12

  1. 원문의 이유: 컨텍스트가 넘치면 추론 품질이 떨어지고, 압축 흔적이 생기고, 진행이 멈춘다.3
  2. 큰 출력, 스크린샷, 큰 문서는 서브에이전트가 읽는다. 메인 컨텍스트는 원자료가 아니라 요약을 받는다.2
  3. 매번 쓰는 템플릿과 참고 자료는 스킬 파일 안에 둔다. 따로 두면 읽을 때마다 비용이 든다.4
  4. 에이전트는 단계 크기를 정하고 범위에 상한을 둔다. 단계당 파일 수를 제한하고 턴 예산을 정한다.5

언제 켜지나

disable-model-invocation: true라서 모델이 스스로 이 스킬을 켜지 않는다.6 사용자가 /principle-guard-the-context-window를 입력하거나, 다른 스킬이 이 원칙을 읽으라고 할 때 켜진다. description은 이 원칙이 어떤 상황에 맞는지 알려 주는 설명이다.
