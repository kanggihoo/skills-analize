unslop 스킬은 에이전트를 어떻게 바꾸나

Long image

A

Answer

unslop을 적용하면 에이전트는 자기가 쓴 글을 번호 붙은 패턴 목록과 대조한다. AI 티 나는 표현(AI tells)을 찾으면 뜻과 의도한 어조를 지키면서 고쳐 쓴다.1

  1. 절차는 두 단계뿐이다. 목록대로 훑고, 고쳐 쓴다.1
  2. 규칙은 28개이고 7개 범주로 나뉜다. 대상은 영어 산문이다.23
  3. 규칙 번호는 다른 스킬이 인용하는 고정 ID다. 지운 규칙의 번호는 빈칸으로 남긴다.4
  4. 이 스킬은 모델이 스스로 켜지 않는다. 대신 pstack의 다른 스킬 7개가 글을 쓸 때 이 스킬을 적용하라고 지시한다.

1

언제 켜지나

description은 "Must always apply."라고 적는다. 하지만 disable-model-invocation: true라서 모델이 스스로 이 스킬을 켜지 않는다.5

사용자가 /unslop을 입력하거나, 다른 스킬이 글을 쓰는 단계에서 적용하라고 할 때 켜진다. 판정: "항상 적용"은 다른 스킬이 적용을 지시할 때 실제로 작동한다. 아래 표가 그 지시들이다.

적용을 지시하는 스킬대상 글rel-id
poteto-mode모든 산문. 에이전트의 답변도 산문으로 본다6r06
teach모든 응답7r44
recall작업 맥락 요약8r47
blast-radius영향 범위 보고서9r51
technical-writing이 스킬이 다루는 모든 문서10r90
show-me-your-work결정 기록의 문장11r91

poteto-mode의 플레이북 세 개도 글을 쓴 뒤 적용하라고 한다. investigation은 답변에, multi-phase-plan은 계획 문서에, opening-a-pr는 PR 제목·설명과 commit 본문에 적용한다.131415 사용자 안내 표에서는 "글에서 AI 티를 걷어낼 때" 쓰는 스킬로 소개한다.16

2

규칙 번호는 왜 비어 있나

지운 규칙의 번호를 비워 두는 것은, 다른 스킬이 규칙을 번호로 인용하기 때문이다. 원문은 번호를 고정 ID로 두고, 지운 규칙은 빈 번호로 남긴다고 적는다.4 실제로 poteto-mode는 콜론 규칙을 "unslop rule 14"라고 번호로 가리킨다.17

규칙 수
28개(3~33번)
빈 번호
1, 2, 4, 6, 21
범주
7개. Content 2, Language 6, Style 7, Communication artifacts 2, Filler 3, Jargon 1, Plain speech 7
절차
훑기 → 고쳐 쓰기

technical-writing은 에이전트가 새로 찾은 추상 은유 명사를 규칙 26에 추가하자고, 답변에서 변경안(diff)으로 제안하게 한다. 이때 unslop 파일은 직접 고치지 않는다.18

평이한 말 규칙은 무엇을 요구하나

이 범주는 느낌 대신 동작과 수치를 쓰게 한다. 규칙 27에는 두 가지 시험이 붙어 있다. 문장을 구체적인 지시·사실·수치로 바꿔 말할 수 없으면 지운다. 다른 프로젝트 문서에 그대로 들어가도 되는 문장도 지운다.3

번호패턴에이전트가 하는 일원문 예
27느낌을 말하는 문장메커니즘이나 수치를 쓴다3"SQL you can read" → ".toSQL() returns the exact string sent to the database"
28빽빽한 문장둘로 나누거나 절을 뺀다. 한 문장에 생각 하나3독자가 되돌아 읽어야 하는 문장
29수동태행위자를 밝힌다3"queries are validated" → "the compiler validates queries"
30부사로 받친 동사부사를 지우고 더 강한 동사나 수치를 쓴다3"runs quickly" → "is fast", "significantly improves" → 잰 차이
31화려한 동의어쉬운 단어를 쓴다3utilize → use, facilitate → help, in the event that → if
32꾸민 문장문자 그대로의 표현을 쓴다3"A dial worth turning" → "a parameter worth varying"
33지나친 압축관사와 동사를 갖춘 문장으로 쓰고 화살표와 약어를 풀어 쓴다3"Parser rejects bad date → exit 2, no write" → "The parser rejects a bad date, exits with code 2, and writes nothing."

원문이 허용하는 예외는 세 가지다.

  • 목록이나 예시 앞의 콜론은 괜찮다(규칙 14).22
  • 마침표로 끝나고 새 정보가 뒤따르는 굵은 머리말은 괜찮다(규칙 16). 원문 예는 **Schema in TypeScript.** Tables live in one file.이다.22
  • 행위자를 모르거나 정말 상관없으면 수동태를 써도 된다(규칙 29).3

확인하지 못한 것

규칙 13은 "no parentheses"라고 적지만, 같은 줄이 괄호를 쓴다. 판정: 엠 대시 대신 괄호로 바꾸지 말라는 뜻으로 읽힌다. 괄호 전체를 금지하는지는 원문에 명시 없음. technical-writing은 괄호 안을 완전한 문장 단위로 쓰라고 한다.2125 규칙 사이에 우선순위가 있는지, 고친 글을 다시 훑는지는 원문에 명시 없음.
