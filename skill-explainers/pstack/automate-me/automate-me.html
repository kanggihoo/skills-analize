automate-me 스킬은 에이전트를 어떻게 바꾸나

Long image

A

Answer

automate-me를 켜면 에이전트가 사용자의 작업 습관을 -mode 스킬 하나로 만든다(예: jay-mode). 에이전트는 최근 대화 기록과 객관식 질문으로 습관을 모으고, create-skill로 초안을 쓰고, unslop으로 문장을 다듬는다.1

  1. 이 스킬은 기록 분석, 작성, 문장 다듬기 세 가지를 순서대로 엮을 뿐, 작성과 다듬기를 직접 하지 않는다. 기록 분석(mining)은 이 스킬 안에서 하고, 작성은 Cursor 내장 create-skill이, 문장 다듬기는 unslop이 맡는다.1
  2. 사용자가 개입하는 곳은 세 번이다. 에이전트가 기존 스킬을 고칠지 묻고, 객관식으로 선호를 묻고, 초안을 보여 주고 의견을 받아 고친다.234
  3. 에이전트는 대화 하나에서만 본 선호를 규칙으로 굳히지 않는다. 기록 조각 2곳 이상에서 나타나야 믿는다.56
  4. 에이전트는 결과를 main에 직접 push하지 않는다. worktree에서 commit하고 PR을 연다.7

  1. 기존 확인 ↗

    에이전트가 사용자 핸들과 맞는 .cursor/skills/**/*-mode/SKILL.md, ~/.cursor/skills/*-mode/SKILL.md를 하위 폴더까지 찾는다. 파일이 있으면, AskQuestion으로 고칠지 새로 쓸지 묻는다. 사용자가 이미 "update my skill"이라고 했으면, 묻지 않는다. 이 스킬을 반복해서 실행할 때 기본값은 고치기다. 새로 쓰기는 드문 경우이고, 새로 쓰기 전에 이유를 묻는다.

  2. 기록 분석 ↗

    에이전트는 현재 작업 공간의 agent-transcripts/만 본다. 기록을 여러 조각으로 나눠 서브에이전트들에게 병렬로 맡기면, 서브에이전트들은 각자 신호를 찾아 근거 위치와 함께 짧은 목록으로 돌려준다. 고치기 모드이면, 스킬을 마지막으로 고친 뒤의 기록만 본다.

  3. 직접 질문 ↗

    에이전트가 기록에 아직 드러나지 않은 의도를 묻는다. 먼저 AskQuestion 객관식으로 넓게 묻고, 사용자가 고른 영역을 좁혀 묻는다. 마지막에 자유 질문 하나로 빠진 것을 잡는다. 고치기 모드이면, 무엇이 바뀌었거나 빠졌는지 묻는다.

  4. 묶기 ↗

    에이전트가 모은 신호를 절로 묶는다. 해당하는 절만 쓴다. poteto-mode는 읽어서 세밀함의 수준만 참고하고, 내용은 베끼지 않는다.

  5. 초안 작성 ↗

    에이전트가 create-skill로 스킬을 쓴다. 고치기 모드이면, 기존 파일을 제자리에서 고친다. 사용자가 반박하지 않은 절은 남기고, 새 근거가 있는 절만 고치고, 정말 새 규칙에만 절을 더한다.

  6. 다듬기 ↗

    에이전트가 모든 줄에 unslop과 create-skill의 글쓰기 지침을 적용한다. 초안을 사용자에게 보여 주고 의견을 받는다. 여러 번 고치게 될 것으로 보고 과감히 줄인다.

  7. PR 열기 ↗

    에이전트는 main에서 갈라진 worktree에서 작업한다. commit하고 PR을 연다. main에 직접 push하지 않는다.

무엇을 금지하나

가드레일에이전트가 하는 일
대화 하나에 맞추지 않는다한 번 말하고 다른 때 뒤집은 선호는 잡음으로 본다. 여러 번 나와야 규칙으로 쓴다6
꾸미지 않는다다른 스킬의 내용을 되풀이하지 않고, 비유를 지어내지 않고, 시적인 문장을 쓰지 않는다. 실행에 쓰이는 문장만 쓴다6
붙이지 말고 가리킨다사용자가 쓰는 다른 스킬과 원칙 문서는 발췌를 붙이지 않고 경로로 적는다6
절을 최소로 둔다기본값과 다른 구체적 규칙이 있을 때만 절을 만든다. "Communicate clearly"는 절이 아니다6
이름을 일반화한다명령문에는 작성자 이름 대신 "the user"나 "the human"을 쓴다6
대칭을 억지로 맞추지 않는다적을 만한 작업 절차가 없으면 그 절을 통째로 뺀다6

다른 프로젝트의 대화를 읽지 않는다

원문은 에이전트가 ~/.cursor/projects/*/를 훑지 말라고 한다. 훑으면 작업 공간 경계를 넘어 관계없는 프로젝트의 비공개 대화를 읽게 되기 때문이다. 서브에이전트는 부모 에이전트가 넘겨 준 작업 공간 경로만 읽는다.5

확인하지 못한 것

create-skill과 AskQuestion은 Cursor 환경의 것이라 pstack 범위 밖이다(r92). 그 동작은 확인하지 못했다. 마이닝 서브에이전트의 모델, readonly 설정, 프롬프트 템플릿은 원문에 명시 없음. 고치기 모드의 기준 시각은 git log -1 --format=%cI <path>다. 스킬 파일이 git 밖에 있으면 어떻게 하는지는 원문에 명시 없음.2
