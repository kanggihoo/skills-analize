Long image

A

Answer

이 원칙을 적용하면 에이전트는 새 내부 API를 들이면서 옛 API를 남겨 두지 않는다. 호출자를 모두 옮기고, 같은 리팩터링 차례(wave)에서 옛 API를 지운다.1

  1. 호환 계층을 기본 구조로 두지 않는다. 임시 어댑터는 예외로만 쓰고 기한을 정한다.1
  2. 테스트는 새 계약을 확인하게 고친다. 옛 구현 세부만 지키던 테스트는 지운다.1
  3. 원문은 적용 조건 셋을 든다. 그중 첫째는 외부 사용자가 하위 호환에 기대지 않는 경우다.2
  4. poteto-mode와 refactoring 플레이북이 API 모양을 바꿀 때 이 원칙을 꺼낸다.34
