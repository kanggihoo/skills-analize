pstack 스킬 분석

묶음

run

작업 하나를 pstack 방식으로 끝까지 돌린다
  • poteto-mode 요청을 플레이북에 맞추고 필요한 스킬과 원칙을 불러 일을 끝까지 돌리는 작업 모드
  • poteto-help pstack 설정, 스킬·플레이북 고르기를 안내하고 보낼 프롬프트를 건넨다
  • setup-pstack 역할별로 쓸 모델과 추론 예산을 정해 규칙 파일에 적는다
  • figure-it-out 맞는 플레이북이 없는 큰 작업에 맞춤 플레이북을 설계해 돌린다
  • show-me-your-work 긴 작업의 결정을 한 줄씩 TSV로 기록하고 끝에 감사한다

understand

코드를 바꾸기 전에 이해한다
  • how 서브에이전트로 코드를 조사해 "어떻게 동작하나"를 설명한다
  • why git·티켓·문서·채팅 등 근거 갈래를 병렬로 뒤져 "왜 이렇게 생겼나"를 확신도와 함께 답한다
  • teach how와 why 결과를 엮어 사람이 이해하도록 쉽게 설명한다
  • recall 최근 대화 기록과 공유 기록으로 내 작업 맥락을 복원해 요약한다
  • blast-radius 작은 변경이 diff 밖에서 무엇을 깨뜨릴지 찾고 안전 근거를 실행으로 증명한다

design-review

구현 전에 모양을 정하고, 여러 번 시도하고, 리뷰한다
  • architect 코드 전에 타입·시그니처·모듈 구조를 병렬로 설계하고 구현까지 따라간다
  • arena 같은 과제를 여러 후보에게 맡겨 기반을 고르고 좋은 부분을 접붙인다
  • swarm 작업을 조각이나 경주로 나눠 병렬로 돌리고 보고서 하나로 모은다
  • interrogate 여러 모델 리뷰어가 변경을 서로 다른 각도에서 공격적으로 리뷰한다
  • no-comments 리뷰 전에 별도 리뷰어로 불필요한 주석을 지우고 지적을 고친다

verify-harness

앱을 사용자처럼 직접 돌려 증명할 도구를 만들고 유지한다
  • setup-pstack 역할별로 쓸 모델과 추론 예산을 정해 규칙 파일에 적는다
  • create-verification-skill 앱을 사용자처럼 조작해 동작을 증명하는 프로젝트용 검증 스킬을 만든다
  • maintain-verification-skill 검증 스킬과 기능 지도가 실제 앱과 맞는지 주기적으로 점검해 고친다

principles

poteto-mode가 판단 근거로 읽고 인용하는 한 줄 원칙 24개
  • principle-attack-the-premise 같은 전제의 수정이 두 번 이상 실패하면 전제 자체를 의심한다
  • principle-boundary-discipline 검증·오류 처리는 시스템 경계에 모으고 안쪽은 믿는다
  • principle-build-the-lever 손으로 하지 말고 일을 하거나 증명하는 도구를 만든다
  • principle-encode-lessons-in-structure 같은 지시를 두 번 쓰게 되면 린트·검사·스크립트로 굳힌다
  • principle-exhaust-the-design-space 선례 없는 결정이면 시제품 2~3개를 비교한 뒤 고른다
  • principle-experience-first 구현 편의보다 사용자 경험을 고른다
  • principle-explain-the-number 잰 수치를 믿기 전에 무엇이 그 값을 제한하는지 밝힌다
  • principle-fix-root-causes 증상을 덮지 말고 재현한 뒤 근본 원인을 고친다
  • principle-foundational-thinking 로직보다 먼저 핵심 타입과 자료 구조를 정한다
  • principle-guard-the-context-window 큰 출력은 서브에이전트에 넘기고 본 대화에는 요약만 둔다
  • principle-laziness-protocol 추상화를 더하기보다 지우고 가장 작은 변경을 고른다
  • principle-make-operations-idempotent 여러 번 돌거나 중간에 죽어도 같은 상태로 수렴하게 만든다
  • principle-migrate-callers-then-delete-legacy-apis 새 API를 들이면 호출자를 옮기고 옛 API를 같은 차례에 지운다
  • principle-minimize-reader-load 읽는 사람이 따라갈 계층과 숨은 상태를 줄인다
  • principle-model-the-domain 흩어진 조건문 대신 도메인을 구조(상태 기계, 타입 등)로 표현한다
  • principle-never-block-on-the-human 되돌릴 수 있는 일은 묻지 말고 해 보고 결과를 보여 준다
  • principle-outcome-oriented-execution 계획된 이전에서는 중간 호환 상태 대신 목표 구조로 바로 간다
  • principle-prove-it-works 완료 선언 전에 실제 산출물로 동작을 확인한다
  • principle-redesign-from-first-principles 새 요구를 덧붙이지 말고 처음부터 있던 것처럼 다시 설계한다
  • principle-separate-before-serializing-shared-state 동시 실행자가 같은 것을 쓰면 먼저 공유를 없앤다
  • principle-sequence-verifiable-units 일을 검사로 끝나는 작은 단위로 나눠 순서대로 확인한다
  • principle-subtract-before-you-add 더하기 전에 죽은 코드와 군더더기를 먼저 지운다
  • principle-test-behavior-not-implementation 테스트는 사용자처럼 호출하고 실제 값으로 결과를 확인한다
  • principle-type-system-discipline 잘못된 상태를 타입으로 표현할 수 없게 만든다
