# AI, LLM, 에이전트 보안 점검

#### 이 문서를 사용할 때

언어 모델이 신뢰와 권한에 영향을 주는 결정에 참여한다면 이 문서를 참고한다. 대상에는 챗봇과 어시스턴트, RAG 파이프라인, 영구 에이전트 메모리, 도구 호출 루프, MCP 서버와 클라이언트, 신뢰할 수 없는 입력으로 프롬프트를 구성하는 코드, 모델 출력을 받아 실제 동작을 수행하는 코드가 포함된다. 핵심 데이터 흐름은 *신뢰할 수 없는 콘텐츠 → 모델 또는 메모리 → 권한·능력·위험한 처리 지점*이다.

이 문서는 `ATTACK-CLASSES.md`와 함께 사용하며, 그 문서를 대체하지 않는다. 전송, 접근 제어, 쿼리 구성, 파일 시스템 사용, 출력 렌더링은 여전히 일반적인 신뢰 경계다. 여기서는 모델에 특화된 위임 계층을 다룬다. 규모가 큰 대상은 검색, 메모리, 도구 실행, MCP, 출력 처리 단위로 나눈다.

## 기본 원칙 (이 영역의 모든 에이전트 프롬프트에 포함)

```
- 프롬프트 인젝션 자체만으로는 취약점이 아니다. 콘텐츠가 다른 주체의 컨텍스트에 들어가거나, 요청자에게 없는 권한을 실행하거나, 읽을 수 없는 데이터를 노출하거나, 직접 접근할 수 없는 처리 지점에 도달하는 코드 수준의 경계 실패를 확인한다.
- 모델 출력, 메모리, 도구 설명, MCP 응답은 모두 신뢰할 수 없는 입력이다. 권한을 부여하거나, 출력을 신뢰하거나, 지속 상태에 기록하거나, 위험한 처리 지점으로 전달하는 코드를 짚는다.
- 가드레일 프롬프트는 보안 경계가 아니다. 결정론적 검사, 리소스 범위가 제한된 권한 확인, 격리, 요청과 동작의 결합, 제한된 자격 증명만 보안 통제로 인정한다.
- 공격자, 영향을 받는 주체, 실제 실행 ID, 리소스, 정확한 동작, 사용 권한, 관찰 가능한 영향을 밝힌다. 모델이 요청자의 기존 권한으로 요청자가 직접 의도한 일을 실행했다면, 위임 결함으로 보지 않는다.
- 권한 확인과 동작 결합은 서로 다른 통제다. 공격자가 조작한 콘텐츠로 피해자의 유효한 권한 아래 동작이 실행됐고 피해자가 그 동작을 정확히 요청하거나 승인하지 않았다면 동작 결합 실패다.
- 소스 근거와 제한된 로컬 검증으로 경계와 결과를 확인한 뒤에만 `confirmed`로 분류한다. 필요한 provider, 배포, 플랫폼, identity 또는 runtime 동작을 로컬에서 확인할 수 없다면 `needs_validation`을 사용한다.
```

## 컨텍스트·검색·메모리 공격 유형 (`subagent_type: general`)

**검색되거나 수집된 콘텐츠를 통한 간접 인젝션**
공격자가 작성한 RAG 문서, 색인 페이지, 파일, 이메일, 이슈 본문, 도구 응답, 메타데이터가 다른 주체의 모델 컨텍스트에 들어갈 수 있다. 각 데이터의 작성 권한, 검색 범위, 이를 소비하는 세션의 주체, 그 세션에서 사용할 수 있는 권한을 추적한다. 격리, 리소스 권한, 소비 주체의 의도와 동작이 결합되는지 각각 확인한다. 결함은 설득력 있는 문구 자체가 아니라 결정론적 통제가 빠진 데 있다.

**세션 또는 테넌트 간 컨텍스트 유출**
대화 기록, 임베딩, 검색 결과, 프롬프트 캐시의 키 범위가 지나치게 넓은지 확인한다. 쿼리와 모든 캐시 키에서 테넌트 및 ACL 필터가 적용되는지 검증한다. 객체에 테넌트 필드가 있어도 다른 쿼리, 공유 캐시, 일괄 처리 경로에서 빠지면 강제 수단이 아니다.

**지속 메모리 오염**
공격자가 제어하는 콘텐츠나 모델 요약이 나중에 다른 작업, 사용자, 권한 높은 세션에 영향을 주는 메모리에 기록되는지 살핀다. 누가 메모리를 만들고, 수정하고, 병합하고, 삭제할 수 있는지 확인한다. 출처와 테넌트 범위, 신뢰도가 낮은 관찰이 지속되는 지침이나 사실로 바뀌는지, 검색 과정에서 사용자 선호와 도구 정책을 구분하는지도 검토한다. 사용자가 자기 요청을 위해 의도적으로 저장한 메모리가 그 사용자에게 허용된 요청에만 쓰인다면 테넌트 간 경계 위반이 아니다.

**프롬프트 역할 및 출처 혼동**
프롬프트를 조립하면서 신뢰할 수 없는 텍스트가 system 메시지, 이전 대화, 도구 결과, 정책, 메모리 기록인 것처럼 보일 수 있는지 확인한다. 문자열 이어 붙이기, 유형 정보가 없는 대화 기록, 호출자가 정하는 role 필드, 출처 표시를 잃는 직렬화 왕복을 살핀다. 위조된 출처가 결정론적 신뢰 판단을 바꾸거나 의미 있는 권한에 도달하는지 확인한다.

## 도구 및 동작 공격 유형 (`subagent_type: general`)

**도구 인자에서 후속 처리 지점으로 이어지는 인젝션**
모델이 만든 인자가 handler 측 검증 없이 SQL, shell, 파일, URL 가져오기 또는 권한 높은 API에 전달되는지 추적한다. 도구 schema를 입력 파싱으로 보고, 디코딩된 호출의 각 필드가 어디로 이어지는지 확인한다. 구조화된 출력은 형식만 제한할 뿐 권한, 안전한 경로와 URL, 쿼리 의미를 보장하지 않는다.

**과도한 자율성과 혼동된 대리인 권한**
에이전트가 서비스 ID나 광범위한 자격 증명을 사용하지만 도구 handler가 요청 주체의 권한을 대상 리소스에 대해 다시 확인하지 않는지 살핀다. 실제 실행 ID와 호출자가 제품의 일반 인터페이스로 동일한 작업을 수행할 수 있는지 확인한다. 사용자별 쿼리 범위가 강제된다면 자격 증명을 공유한다는 사실만으로 결함은 아니다.

**동작 확인 및 승인 결합**
사용자가 한 동작을 승인했지만 실행 시 인자, 리소스, 주체 또는 이후 모델 턴이 바뀔 수 있는지 확인한다. 공격자 콘텐츠가 피해자의 유효한 권한으로 부작용을 일으키고 피해자가 이를 의도적으로 요청하거나 승인하지 않은 경우도 동작 결합 결함이다. 일반적인 권한 검사에서 피해자에게 작업 권한이 있더라도 마찬가지다. 승인이나 의도가 정규화된 도구 이름, 전체 인자 객체, 요청자, 대상, 금액, 만료 시간, 일괄 작업 구성원과 결합되는지 검토한다. 재시도와 재개 세션에서도 승인이 변경되거나 중복된 부작용을 허용하지 않는지 살핀다.

**도구 schema와 dispatcher 해석 불일치**
schema가 별칭, 추가 필드, 중복 키, 형 변환, 중첩된 자유 형식 객체, 범위를 벗어난 값을 허용해 dispatcher나 handler가 다르게 해석하는지 비교한다. schema 검증, 정규화, 생성된 binding, handler 기본값을 함께 살핀다. 값이 리소스 선택자나 보안 관련 옵션으로 쓰이는 지점에서도 다시 검증한다.

**제한되지 않은 위임 동작 반복**
범위가 정해진 요청 하나가 요청별 예산, 동작별 권한 확인, 취소, 멱등성 통제 없이 비용 발생·전송·변경·외부 API 호출을 반복해서 대기열에 넣을 수 있는지 확인한다. 공유 비용, 할당량, 다른 사용자, 지속 상태에 미치는 영향을 입증한다. 서비스를 고갈시키는 방식으로 시험하지 말고 코드 수준의 계산과 로컬에서 제한된 반복으로 확인한다.

## MCP 및 서브에이전트 신뢰 유형 (`subagent_type: general`)

**서브에이전트와 MCP의 신뢰 상속**
위임 작업에 필요한 최소 권한 대신 전체 세션, 자격 증명, 메모리, 권한이 전달되는지 확인한다. 각 호출에 주체와 테넌트가 유지되는지, 권한 범위가 좁혀지는지, 자격 증명의 audience가 적절한지, 돌아온 위임 결과를 신뢰할 수 없는 입력으로 다루는지 살핀다.

**MCP 서버 및 도구 ID 혼동**
인증된 연결과 대기 중인 요청이 아니라 공격자가 영향을 줄 수 있는 서버 이름, 도구 이름, 요청 ID, 리소스 URI, 모델이 선택한 별칭으로 호출이나 결과가 라우팅되는지 확인한다. 서버 두 곳이 같은 도구나 리소스 ID를 주장할 수 있는지, 재연결 때 binding이 바뀌는지, 한 서버의 응답이 다른 서버의 대기 중인 호출에 반영될 수 있는지 살핀다.

**MCP 메타데이터와 schema를 정책으로 오인**
MCP peer가 제공한 도구 설명, 리소스 메타데이터, 프롬프트, 자동 완성 힌트, schema가 정책이나 권한으로 신뢰되는지 확인한다. 이런 필드는 모델을 안내할 수 있지만 권한을 부여하지는 못한다. 메타데이터가 충돌해도 최종 기준으로 남는 결정론적 허용 목록, 서버 ID 확인, handler 권한 검사를 찾는다.

## 출력 및 정보 노출 공격 유형 (`subagent_type: general`)

**안전하지 않은 출력 렌더링**
모델 출력이 필요한 인코딩과 정책 적용 없이 HTML, Markdown, template, URL, command 실행 지점으로 전달되는지 확인한다. 브라우저 렌더링은 `CLIENT-SIDE.md`에서 자동 로드 리소스와 CSP 또는 sanitization을 확인한다. 저장소 밖의 renderer 동작에 달린 후보는 `needs_validation`으로 분류한다.

**민감한 컨텍스트 추출**
조립된 컨텍스트에 접근 권한을 부여할 수 있는 자격 증명, 다른 사용자 데이터, 비공개 소스, 정책 값이 포함되고 사용자 입력에 영향을 받는 출력이 이를 노출하는지 확인한다. 프롬프트 조립과 데이터 가져오기 코드를 읽는다. 데이터 경계를 넘지 않는 일반 지침이나 동작 설명의 노출은 취약점이 아니다.

## 공통 조사 방법

- 먼저 네 가지 지도를 그린다. 각 실행 ID, 각 권한, 쓰기 가능한 컨텍스트·메모리 원본, 모든 출력 대상을 정리한다. 그다음 시작 주체의 권한이 최종 동작까지 어떻게 이어지는지 연결한다.
- 부작용을 일으키는 도구에서 시작해 dispatcher, schema, 확인 절차, 모델 컨텍스트, 검색, 수집 경로를 거슬러 올라간다. 지속 메모리 읽기에서 시작할 때는 모든 작성 경로를 추적한다.
- 같은 동작의 직접 호출, 대기열 처리, 재시도, 재개, 일괄 처리, 위임 경로를 비교한다. 인자가 확정된 뒤, 각 부작용이 발생하기 직전에 가장 강한 통제가 적용돼야 한다.

## 보고 전 검증 규칙

1. 넘은 경계와 관찰 가능한 결과를 밝힌다. 공격자, 영향을 받는 주체 또는 공유 리소스, 실행 ID, 대상, 권한이 없거나 요청하지 않은 동작·정보 노출을 적는다.
2. 혼동된 대리인 권한을 주장하려면 도구에 요청자와 리소스 기준 권한 검사가 없고 공격자가 일반 경로로 같은 동작을 할 수 없음을 입증한다. 동작 결합 문제라면 대신 공격자 콘텐츠가 피해자의 권한으로 동작을 유발했고 피해자가 이를 의도적으로 요청하거나 승인하지 않았음을 입증한다. 일반 권한 검사가 통과된다고 해서 의도까지 확인된 것은 아니다.
3. 메모리 또는 검색 문제는 공격자가 제어하는 쓰기 경로와 이후 다른 주체의 읽기 또는 권한 높은 판단을 모두 제시한다. 소비자가 도달할 수 없는 공유 기록만으로는 충분하지 않다.
4. 동작 결합 문제는 의도적으로 요청했거나 정규화된 승인 객체가 있다면 이를 확인하고 handler가 실제로 사용하는 객체와 비교한다. 유해한 실행까지 시험하지 않고도 로컬에서 요청하지 않은 동작, 변경, 중복, 권한 변화를 관찰해야 한다. schema 불일치는 검증 후 정규화된 객체와 handler 객체를 비교한다.
5. MCP ID 문제는 인증된 연결, 요청 상관관계, 도구 namespace, 실제 자격 증명을 확인한다. 외부 서버 ID나 배포 라우팅 확인이 필요하면 `needs_validation`으로 표시한다.
6. 완전한 소스 추적과 의미 있는 결과가 있을 때만 `confirmed`로 보고한다. 해결되지 않은 구체적인 경계 사실이 있으면 `needs_validation`을 사용하고, 이를 확인할 제한된 로컬 검사나 담당자 관찰 절차를 적는다.
