# 94 · 이슬 너머 먼 불빛 — 멀티플레인 카메라 · 평면 일러스트의 깊이

> **가장 중요한 규칙: 기술만 가져간다.** 아래 "화면"은 이 데모가 그린 것이다. 기법을 보여 준 예일 뿐이니 소재·장면·이야기·구도·문구·색은 영상에 옮기지 않는다.
> 노트와 코드를 충분히 읽어 "기법과 원리"의 기술만 가져가고, 장면은 작업 중인 영상의 대본으로 새로 짓는다.

평면 일러스트 카드 열여섯 장을 깊이 z에 세워 두고, 핀홀 카메라가 그 사이로 미끄러져 들어간다. 9.5초, 1080×1920, Canvas 2D만 쓴다.
카드의 화면 배율은 층마다 정한 고정 계수가 아니라 `F / (z − camZ)`다. 그래서 가까운 층일수록 다가갈 때 빠르게 커지며 화면 밖으로 벌어지고, 먼 층은 거의 움직이지 않는다.
이 거리 d 하나에서 대기 원근(안개), 피사계 심도(흐림), 보케가 함께 나온다.

## 화면

해 뜨기 직전의 대숲이다. 대나무 줄기 사이로 먼 언덕 위의 작은 한옥 한 채가 보이고, 그 집 창 하나에만 불이 켜져 있다.
색 온도는 남보라 새벽에서 금빛 해돋이로 바뀐다. 강조색은 창빛의 금색(#ffc46b) 하나이고, "이슬"에만 차가운 하늘색을 쓴다.

| 시간 | 무엇이 보이나 |
|---|---|
| 0–1.0 | 검은 화면에서 밝아진다. 렌즈가 물방울 조금 뒤에서 초점을 찾아 물방울에 맞춘다(초점 헌팅). |
| 0.5–1.5 | 물방울과 같은 깊이(z 600)에 놓인 글자 "가까이 / **이슬** 한 방울"이 줄마다 0.12초 간격으로 떠오른다(expo.out). |
| 0–3.5 | 접사 장면이다. 댓잎 끝에 매달린 물방울에 초점이 맞아 있다. 물방울은 볼 렌즈라서 그 안에 뒤집힌 언덕과 창빛이 작게 맺힌다. 잎 위 이슬 알갱이가 반짝이고, 배경은 크림처럼 녹아 있다. 먼 창빛은 금색 보케 원판이 되고, 그 위로 굴뚝 연기가 번진다. 카메라는 앞으로 들어가며(dolly) 오른쪽으로 옮겨 가고(truck) 조금 올라간다(crane). 가까운 층은 확장 중심에서 바깥으로 벌어진다. |
| 2.0–3.5 | 물방울이 부풀며 아래로 늘어나고, 그 무게에 잎이 처진다. |
| 3.5 | 물방울이 떨어진다. 잎은 튕겨 올라갔다가 감쇠 진동하며 자리 잡는다. |
| 3.7–5.5 | **랙 포커스**(디옵터 공간에서 inOutCubic). 초점이 물방울에서 먼 집으로 건너간다. 댓가지는 거대한 초록 번짐이 되고, 이슬 알갱이는 보케 원판으로 부풀며, 앞 글자는 흐려지며 사라진다(4.1–5.1). 맨 앞 잎(z 260)은 카메라를 스치고 지나간다. 중간 층들은 차례로 초점면을 통과한다. |
| 4.2–6.2 | 해가 능선의 솔숲 사이로 떠오르며 빛줄기가 부챗살처럼 퍼진다. 줄기와 솔 실루엣이 그 빛을 가르고, 빛줄기 속 먼지가 반짝인다. |
| 4.85–5.7 | 집 앞 깊이(z 5600)에 놓인 글자 "멀리 / 먼저 깨어난 / **창 하나**"가 초점이 도착하는 때에 맞춰 떠오른다. 창의 빛무리도 커진다(5.0–6.0). |
| **5.7** | **절정**(포스터). 집에 초점이 맞고, 솔숲 사이로 해가 걸려 빛줄기가 가장 선명하다. 앞쪽은 보케로 가득하다. |
| 6–9.5 | 여운. 카메라는 계속 미끄러지고, 해가 올라가면서 빛줄기는 부드러워진다. 굴뚝 연기와 먼지가 흐른다. |

## 기법과 원리

- **기준 카메라로 그린 카드**(`main.js:23`, `main.js:517`)
  - 각 카드는 t = 0의 기준 카메라 `CAM0`에서 보이는 모습 그대로 기준 px로 그린다. 그래서 일러스트를 2D로 그리듯 짤 수 있다.
  - 세계 좌표는 `X = CAM0.x + (x − CX)·z/F`에서 암묵적으로 정해진다.
  - 프레임마다 `s = F/(z − camZ)`, `k = s/s0`를 구한다. 카드 → 화면 행렬은 `[k, 0, 0, k, CX(1−k) + (CAM0.x − camX)s, CY(1−k) + (CAM0.y − camY)s]`이다(`main.js:598-613`).
  - 회전(잎의 튕김), 이동(물방울 낙하), 비등방 배율(물방울 늘어남)은 피벗 기준 아핀으로 곱한다.
- **카메라**(`main.js:41`)
  - dolly 0 → 520, truck −30 → 80, crane 0 → −50을 쓴다. 시작에서 이미 움직이는 글라이드 `0.35p + 0.65·cosRamp(p)`다.
  - 핸드헬드는 카메라 위치에 사인 두 개를 더한 것이다. 화면 흔들림이 아니라 위치 흔들림이라서, 가까운 층은 크게, 먼 층은 거의 안 흔들린다(시차가 맞는 흔들림).
- **카드 굽기와 흐림 피라미드**(`main.js:539-566`)
  - 각 카드를 `m` 텍셀/기준 px로 한 번 그린다.
  - L1은 같은 크기에 `blur(2px)`다. Lk는 L(k−1)을 반 크기로 줄이며 `blur(√3 px)`를 건다. 그러면 σ가 레벨마다 정확히 두 배(2, 4, 8 … 레벨 0 텍셀)가 되고, 저장 크기는 σ에 반비례해 줄어든다(전체 ≈ 2.33배).
  - `ctx.filter`는 setup에서만 쓴다.
- **피사계 심도**(`main.js:20`, `main.js:773-781`)
  - 얇은 렌즈의 착란원 지름은 `b = APER·F·|1/d_f − 1/d|`(px)이고, 카드의 가우시안 σ는 `0.3·b`다.
  - σ를 레벨 0 텍셀로 바꾼 뒤(`÷k·m`) log2로 이웃한 두 레벨과 비율 w를 고른다.
  - 스크래치 캔버스에 A를 `globalAlpha = 1−w`로 그리고, B를 `'lighter'`로 w만큼 더한다. 미리 곱한(premultiplied) 색에서 정확한 선형 보간 `(1−w)A + wB`가 된다.
  - source-over로 두 장을 겹치면 투명 가장자리에서 선명한 쪽 윤곽이 남거나 배경이 비친다. 그래서 이 방식을 썼다.
- **랙 포커스**(`main.js:51`)
  - 초점은 `1/d_f`(디옵터)로 보간한다. 초점을 당기는 사람이 링을 돌릴 때처럼 흐림이 고르게 바뀐다.
  - 앞 단계에서는 카메라가 다가가도 초점이 물방울을 따라간다(follow focus).
- **대기 원근**(`main.js:783-789`)
  - 카드를 스크래치에 그린 뒤 `source-atop`으로 안개 그라디언트(위 → 지평선 → 아래)를 덮는다. 해 둘레에는 따뜻한 빛웅덩이를 하나 더 덮는다. 양은 `1 − exp(−(d − 300)/4600)`이다.
  - d는 카메라와의 거리이므로, 다가갈수록 같은 층의 안개가 걷힌다.
- **빛줄기**(`main.js:615-657`, 합성 `main.js:752-756`)
  - 1/4 크기 버퍼(270×480)에 해의 방사 그라디언트를 칠한다. 세기는 해가 능선 위로 드러난 비율 `sunVis`(`main.js:624`)를 곱한다.
  - 서 있는 실루엣(줄기·잎·능선의 솔숲)만 `destination-out`으로 깎는다. 이 마스크는 각 카드를 같은 난수로 "가림막 모드"로 다시 그려 만든다(`main.js:557`).
  - 바닥과 능선 몸통은 가림막에서 뺀다. 화면 공간 방사 번짐은 바닥이 공기와 해 사이를 막는다고 잘못 판단해서, 지평선 아래에 빛이 전혀 닿지 않게 되기 때문이다.
  - 해를 중심으로 `1.07^(2^i)`배 확대한 사본을 `'lighter'`로 반씩 평균하는 일을 다섯 번 한다. 그러면 최대 8.1배까지 방사 표본 32개가 된다.
  - CPU에서 대비 곡선을 걸고 빛 색을 입힌다. 같은 장에서 그림자 버퍼도 만든다.
  - 합성할 때는 그림자를 `multiply`로 어둡게 하고, 빛을 `screen`으로 밝힌다. 밝은 안개 위에서도 빛줄기가 갈라져 보인다.
  - 해가 다 떠오른 뒤에는 세기를 줄인다(`main.js:625`).
- **보케·반짝임·먼지**(`main.js:687`, `main.js:703`, `main.js:715`)
  - 점은 반지름 `R = hypot(r, b/2)`의 원판으로 그린다. 알파는 에너지 보존 `(r/R)²`에 바닥값(반짝임 0.24, 먼지 0.13)을 둔다.
  - `R/r`에 따라 부드러운 점 스프라이트에서 테두리가 밝은 원판 스프라이트로 넘어간다. 초점이 맞은 밝은 반사에는 4갈래 별을 얹는다.
  - 반짝임은 카드의 기준 좌표에 붙어 있어서, 카드 행렬(튕김·낙하 포함)을 그대로 따른다.
  - 먼지 420개는 저마다 깊이(로그 균등 480–7000)를 갖는다. Z순으로 정렬해 카드 사이에 깊이 순서대로 끼워 그린다.
  - 먼지의 밝기는 빛줄기 버퍼에서 읽는다. 빛 속에서만 금빛으로 반짝인다.
  - 창빛은 집 깊이의 금색 광원이다. 처음에는 커다란 보케 원판이었다가 초점이 오면 작은 빛과 빛무리가 된다.
- **물방울**(`main.js:377-418`)
  - 물방울은 볼 렌즈다. 안쪽에 뒤집힌 하늘(아래가 밝음), 뒤집힌 능선, 뒤집힌 창빛 점, 가장자리 굴절의 어두운 테두리, 바닥의 밝은 커스틱 초승달을 그린다.
  - 잎은 `leafRot`(`main.js:364`)으로 처지고 튕긴다. 감쇠 진동 `e^(−3.2u)·cos(15u)`다. 물방울은 회전한 잎끝을 따라가다가 3.5초에 자유낙하한다(`main.js:389`).
- **여러 장에 걸친 길**(`main.js:143-197`)
  - 기준 카메라에서 본 바닥 평면 위의 길을 한 번 정의한다. 중심은 `pathX(y)`, 폭은 `y − CY`에 비례한다.
  - 바닥 카드마다 자기 둑 아래 구간만 그린다. 시작에서는 한 줄로 이어지고, 카메라가 움직이면 층마다 다르게 밀리며 둑에서 끊겼다 이어진다. 멀티플레인 촬영의 특징적인 모습이다.
- **깊이에 놓인 글자**(`main.js:461`): 두 제목도 카드다. 그래서 자기 평면과 함께 시차로 움직이고 흐려지며, 랙 포커스를 따라 "가까이"에서 "멀리"로 초점이 옮겨 간다.
- **마무리**(`main.js:797-808`): soft-light 색보정(새벽 청색 → 금색), 미리 그린 비네트, 256² 노이즈 패턴의 overlay 그레인, 0–1초 페이드인.

## 결정성 전략

- 모든 값은 t의 닫힌 식이다. 카메라, 초점, 해, 잎의 진동, 낙하, 먼지 표류, 연기 위상이 모두 그렇다.
- 무거운 것은 전부 setup에서 한다. 카드 그림, 흐림 피라미드, 가림막, 스프라이트, 비네트, 그레인이 여기에 든다. 난수는 모두 `rand(seed)`다.
- 프레임 안의 상태는 매번 새로 만든다.
  - 스크래치는 카드마다 bbox를 지운다.
  - 빛줄기 버퍼는 매 프레임 지우고 다시 계산한다.
  - 그레인 위치는 `rand(5000 + round(t·30))`에서 정한다.
- 가림막은 같은 그리기 함수를 "가림막 모드"로 다시 부르는 방식이다. 그 모드에서도 난수 소비 순서가 같아야 실루엣이 그림과 정확히 겹친다. 그래서 반짝임을 모을지와 상관없이 같은 `r()` 호출을 한다.
- 찾아서 고친 버그: `imageSmoothingQuality = 'high'`를 빛줄기 합성 안에서만 설정하고 되돌리지 않았다. 그래서 새 페이지의 첫 빛줄기 프레임만 앞 카드들을 기본 품질로 그렸다(9.467초에서 최대 39/255 차이). 지금은 프레임 첫머리에서 두 캔버스 모두에 명시한다(`main.js:595`). 렌더러 검사 결과는 **byte-identical**이다.
- 헤드리스(`api.headless`)에서만 모든 캔버스를 CPU 래스터(`willReadFrequently`)로 만든다. GPU↔CPU 복사를 피하기 위해서다(`main.js:69`). 빛줄기 버퍼 두 장은 매 프레임 읽어 오므로 항상 CPU다.

## 한계와 다음 단계

- 카드 하나의 내용은 모두 같은 깊이다. 한 층 안의 줄기들 사이에는 시차가 없다. 가까운 카드(z 1000)는 끝에서 2.17배 확대되어 텍스처가 무르다. 이때는 흐림이 가려 주지만, 줄기를 각각 작은 카드로 나누면 더 풍부해진다.
- σ와 2σ의 교차 페이드는 진짜 중간 흐림이 아니다. 전환 중에 살짝 번쩍이는 "글로" 느낌이 있다. 카드 흐림은 가우시안이라 원판 보케 모양은 점(반짝임·먼지·창빛)에서만 나온다. 원판 커널로 피라미드를 구우면 카드 가장자리도 렌즈답게 번진다.
- 빛줄기는 화면 공간 근사다.
  - 바닥과 능선 몸통을 가림막에서 손으로 뺐다.
  - 해가 완전히 드러나면 해 바로 앞 줄기를 따라 세로 빛기둥이 생긴다. 그래서 6.4초 뒤에는 세기를 낮춘다.
- 실시간 비용: 프레임마다 카드 약 16장 × (지우기 + 그리기 1–2 + 안개 칠 2 + 합성)의 전 화면급 연산, 그리고 270×480 버퍼 읽기·쓰기가 든다. GPU 브라우저에서는 예산 안이라고 보지만, 여기서는 헤드리스 CPU 수치만 쟀다.
- 더 해 볼 것: 초점 브리딩(초점이 바뀔 때 화각이 미세하게 변하는 것), 디포커스에 따른 색수차, 바람에 흔들리는 잎 카드, 흐림 정도에 따라 카드 해상도를 고르는 LOD.
