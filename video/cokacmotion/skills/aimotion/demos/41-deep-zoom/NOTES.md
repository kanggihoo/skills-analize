# 41 · 끝없는 맨델브로트 — 섭동 이론 딥 줌 · 고정밀 기준 궤도 + GPU 델타

> **가장 중요한 규칙: 기술만 가져간다.** 아래 "화면"은 이 데모가 그린 것이다. 기법을 보여 준 예일 뿐이니 소재·장면·이야기·구도·문구·색은 영상에 옮기지 않는다.
> 노트와 코드를 충분히 읽어 "기법과 원리"의 기술만 가져가고, 장면은 작업 중인 영상의 대본으로 새로 짓는다.

## 화면

9.6초. 똑바로 선(가시가 위, 심장형이 아래) 맨델브로트 집합 전체로 시작해 0.3초 머문 뒤 가속하여, 시호스 밸리로
초당 약 2.1자릿수(×130)의 일정한 속도로 파고든다. 화면이 천천히 돌며 해마 꼬리 나선, 나선 속의 나선, 실 같은
가지들이 연이어 지나간다. 7.6초쯤 배율 10¹⁴(화면 반높이 ≈ 10⁻¹⁴)을 넘고, 마지막 1.5초 동안 감속하며 화면 한가운데에
**원래 집합과 똑같은 작은 사본**(주기 998의 미니브로트, 크기 ≈ 6·10⁻¹⁶)이 똑바로 선 채 나타나 멈춘다(절정·여운).
최종 화면 반높이 1.4·10⁻¹⁵ — 시작보다 1.6·10¹⁵배 확대, 픽셀 간격 2·10⁻¹⁸(배정도 double의 한계 10⁻¹⁶보다 훨씬 아래).

## 기법과 원리

1. **고정밀 기준점 — BigInt 고정소수점** (`main.js:31`–`main.js:58`). 소수 256비트(≈77자리) 정수 연산. 유명한 시호스
   밸리 좌표(위키백과 줌 시퀀스의 중심, `main.js:26`)에서 출발해 주기 p = 998(그 점의 궤도가 0에 가장 가까이 돌아오는
   반복 횟수)에 대한 뉴턴법 z_p(c) = 0으로 미니브로트의 **핵** c₀를 찾는다(`nucleus`, `main.js:45`, setup에서 실행).
   기준 궤도 Z₀…Z_p(핵이므로 Z_p = 0, 정확히 주기적)를 같은 정밀도로 계산해 float 텍스처로 올린다(`main.js:198`, `main.js:284`).
2. **미니브로트의 크기와 방향** (`main.js:203`–`main.js:214`). λ = Π 2Z_j, β = Σ 1/Π…로 s = 1/(βλ²)(복소수)를 구하면
   |s|가 크기, arg s가 회전이다. 끝 화면은 이 사본이 똑바로 서도록 돌리고(`main.js:213`), 핵이 아니라 몸통(c′ = −0.75)이
   가운데 오도록 중심을 s·(−0.75)만큼 옮긴다(`main.js:214`).
3. **섭동 반복 (GPU, float32)** (`main.js:111`). 픽셀마다 기준 궤도에서의 작은 차이만 δ ← 2Zδ + δ² + δc로 반복한다.
   δc ~ 10⁻¹⁵는 float32로 충분히 표현된다 — 정밀도가 필요한 것은 기준 궤도뿐. 미분 dz/dc도 함께(픽셀 크기로 축척해
   넘침 없이) 추적한다.
4. **글리치 방지 — Zhuoran 재기준(rebasing)** (`main.js:128`). |Z + δ| < |δ|(픽셀 궤도가 기준보다 0에 더 가까움 →
   δ의 상대 정밀도 손실 신호)이거나 기준 궤도 끝(m = p)에 이르면 δ = z, m = 0으로 기준 궤도의 처음부터 다시 따라간다.
   기준 궤도 하나로 화면 전체가 글리치 없이 그려진다.
5. **BLA(쌍선형 근사)로 반복 건너뛰기** (`main.js:216`–`main.js:246`, 셰이더 `main.js:94`). δ²가 무시될 만큼 작을 때
   δ → Aδ + Bδc가 2^l 반복을 한 번에 건너뛴다. 단일 단계 A = 2Z_m, B = 1, 유효 반경 R = ε|Z_m|(ε = 2⁻²³), 두 단계 병합은
   A = A_y A_x, B = A_y B_x + B_y, R = min(R_x, (R_y − |B_x|·|δc|max)/|A_x|). 반경은 화면 크기(|δc|max)에 따라 매 프레임
   다시 계산해 R 텍스처만 갱신한다(`main.js:302`). 끝 화면의 픽셀당 반복 ~5000–6000회가 루프 ~1400걸음이 된다
   (JS로 같은 알고리즘을 돌려 확인: 무BLA float 섭동과 같은 수준의 오차).
6. **내부 판정**: 넓은 화면에서는 주 심장형·주기 2 원판의 해석식(`main.js:84`), 깊은 화면에서는 m = p마다(Z_p = 0이므로
   z = δ가 미니브로트 자신의 궤도 점) Brent 순환 검사(`main.js:122`). 나머지는 걸음 상한 2500.
7. **색** (`main.js:133`–`main.js:143`). 매끈한 반복 수 ν = n + 1 − log₂(ln|z|/ln2)를 √ν와 ln ν로 섞어 순환 팔레트
   (먹 → 코발트 → 청록 → 크림 → 금 → 주홍 → 장미 → 자두)를 읽고, 법선 맵 u = z/z′의 조명(입체감)과 거리 추정
   DE = |z| ln|z| / |z′|(픽셀 단위)로 경계를 어둡게 — 가는 필라멘트가 잉크 선처럼 남고 계단도 줄어든다.
8. **줌** (`main.js:179`). ln r(t)는 0.3초 정지 → 1초 3차 가속 → 6초 일정 속도 → 2.3초 3차 감속(이음매에서 속도 연속).
   즉 r = exp(ln-스케일 함수) — t의 순수 함수. 회전도 t의 함수(`main.js:186`).

## 결정성 전략

- 기준 궤도·BLA 계수는 setup에서 한 번(정수 연산이라 매번 같다). 프레임마다 바뀌는 것은 r(t), 회전, BLA 반경뿐.
- 셰이더는 상태가 없다. 그레인은 좌표와 round(t·30) 해시.

## 성능과 한계

- 끝 화면 픽셀당 평균 ~1400 루프 걸음이 가장 무겁다. 그래서 캔버스를 0.7배(756×1344)로 그리고 무대 크기로 늘려
  보인다(`main.js:22`). 보통의 데스크톱 GPU에서 30 ms 안을 목표로 했지만 저사양 GPU에서는 끝부분 fps가 떨어질 수 있다.
  1e-6–1e-7 근처(약 4초)에는 주기 624 성분의 내부가 화면의 ~40%를 덮는데 이 내부는 걸음 상한까지 돌아 잠깐 무거워진다.
- 픽셀당 표본 1개(초과 표본화 없음). 빠른 줌 중 아주 가는 필라멘트는 반짝일 수 있다 — DE 어둡게 하기로 완화.
- BLA 반경은 float32 기준(ε = 2⁻²³)이다. 더 깊이(10⁻³⁸ 아래) 가려면 지수 확장(floatexp) 표현이 필요하다.
- 헤드리스 렌더는 돌리지 않았다(smoke 점검만).
