# 130 · 다음 숫자는? — 퀴즈 연출 · 카운트다운 링 + 긴장 리듬 + 정답 공개

> **가장 중요한 규칙: 기술만 가져간다.** 아래 "화면"은 이 데모가 그린 것이다. 기법을 보여 준 예일 뿐이니 소재·장면·이야기·구도·문구·색은 영상에 옮기지 않는다.
> 노트와 코드를 충분히 읽어 "기법과 원리"의 기술만 가져가고, 장면은 작업 중인 영상의 대본으로 새로 짓는다.

짧은 영상의 퀴즈 한 박자를 10초로 만든 데모다. 문제는 「1, 1, 2, 3, 5, ?」이고 보기는 A 6 · B 7 · C 8 · D 9, 정답은 C 8(피보나치 수열)이다.
숫자가 박자에 맞춰 튀어나오고, 카운트다운 링이 줄어드는 동안 심장 박동 같은 틱이 점점 빨라지며, 시간이 끝나면 정답 카드 하나만 크게 터진다. 마지막은 호가 숫자 사이를 이어 「2 + 3 = 5」「3 + 5 = 8」을 보여 주는 풀이다.
1080×1920. 판 전체를 Canvas 2D 한 장에 매 프레임 t로 다시 그린다. 등장·퇴장은 GSAP 타임라인 하나가 맡고, 링·넘김·틱·투표·임팩트·호는 t의 닫힌 식이다.

## 화면

짙은 남색 퀴즈 화면에서 숫자 줄이 박자에 맞춰 튀어나오고, 크림색 카운트다운 링이 노란색으로 바뀌며 빨라지는 틱 속에 비어 가고, 시간이 끝나면 정답 카드 C만 노랗게 터진 뒤 호가 피보나치 규칙을 그려 보인다.

색은 짙은 남색 바탕, 크림색 글자·도형, 강조색 따뜻한 노랑 하나뿐이다. 노랑은 「?」, 마지막 2초의 링, 정답, 풀이의 정답 쪽 호에만 쓴다. 글꼴은 Pretendard 하나다.
깊이는 세 겹이다. 원경은 남색 그라디언트 위에 흐린 보케와 흐릿한 수학 기호(+ × ÷ = % ?)가 천천히 흐르고, 중경은 판(숫자 타일·링·카드), 전경은 크게 흐린 원 몇 개와 기호 둘이다. 판 뒤로는 링 중심에서 퍼지는 옅은 햇살 무늬가 돈다.
되풀이되는 시각 장치는 **둥근 끝을 가진 노란 호**다. 카운트다운 링의 호 → 정답 카드에서 뻗는 방사선 → 풀이의 호로 이어진다.

## 기법과 원리

- **이야기 시계 한 곳**: 장면 시각은 `T`(`main.js:34`)에 모여 있다. 박자(숫자 등장), 카드 간격, 링 등장·충전, 카운트다운 시작·끝, 임팩트, 풀이의 시각을 모두 여기서 읽는다. 배치 상수(타일·링·카드·호·칩)는 바로 아래 `main.js:44-66`에 있다.
- **카운트다운 링 = 각도가 t의 닫힌 식인, 끝이 둥근 호**(`ringArc`, `main.js:122`; 그리기 `main.js:551-592`)
  - 남은 비율은 `rem = 1 − (t − 3)/(7 − 3)`이다. 호는 `[−90° + 360°·(1 − rem), 270°]` 구간이고 `lineCap = 'round'`로 긋는다. 한쪽 끝은 12시에 고정되고 다른 쪽 끝이 시계 방향으로 호를 먹어 간다.
  - 등장할 때는 같은 식을 거꾸로 쓴다. 2.42–3.0초 동안 `c = outCubic(진행률)`로 12시에서 `−90° + 360°·c`까지 차오른다. 그래서 머리 점(흰 점 + 옅은 원)은 충전과 소진 내내 시계 방향으로만 돈다.
  - 숫자는 호가 1/5을 지날 때 정확히 바뀐다. `t_k = 3 + 4·(1 − k/5)`, k = 4…0이다(`DIGIT_AT`, `main.js:131`). 링 색은 4.9–5.5초에 크림 → 노랑으로 섞이고, 두께는 `28 + 5·b`(b = 맥박), 크기는 마지막 2.4초에 `inCubic`으로 3.5% 커진다.
  - 바깥에는 눈금 60개(5개마다 굵게)를 setup에서 `Path2D` 두 개로 만들어 둔다(`main.js:336-341`).
- **숫자 넘김(스플릿 플랩)**(`Flap`, `main.js:174-212`)
  - 카드는 반쪽 넷으로 그린다: 위 고정면(새 숫자), 아래 고정면(옛 숫자), 위 날개(옛 숫자, 넘어감), 아래 날개(새 숫자, 내려옴). 두 반쪽 사이 3px 틈으로 뒤의 어두운 홈이 보여 경첩선이 된다. 글자는 카드 전체 위치에 그리고 반쪽의 둥근 사각형으로 잘라서, 두 반쪽이 한 글자로 이어진다.
  - 넘김 0.3초의 앞 절반에는 위 날개가 가속하며 앞으로 넘어온다: `θ = (π/2)·(u/0.5)²`. 뒤 절반에는 아래 날개가 내려와 두 번 튀며 멈춘다: `θ = (π/2)·e^(−3.2v)·|cos(1.62πv)|`.
  - 원근은 2D 한 번의 확대로 근사한다. 경첩에서 θ만큼 시점 쪽으로 기운 날개(반쪽 높이 hh, 시점 거리 P = 3.2·카드 높이)의 끝은 경첩에서 `hh·cosθ·P/(P − hh·sinθ)`에 보인다. 날개 중간 깊이의 폭은 `P/(P − hh·sinθ/2)`배다. 그래서 `scale(폭 배율, cosθ·P/(P − hh·sinθ))`를 경첩선 기준으로 건다(`main.js:178-181`).
  - 그늘: 넘어오는 날개는 `0.6·sinθ`, 드러나는 위 고정면은 `0.45·(1 − u/0.5)`, 덮이는 아래 고정면은 `0.4·(1 − sinθ)`만큼 어둡게 칠한다.
  - 같은 클래스가 링 숫자(5 → 0)와 「?」 → 「8」 타일(0.42초)을 맡는다(`main.js:358-364`). 면마다 바탕색·글자색이 따로 있어서, 마지막 「0」과 「8」은 노란 면으로 넘어온다.
- **긴장 리듬: 간격이 기하급수로 줄어드는 틱**(`TICK`, `main.js:71-82`)
  - 3.0–5.0초는 0.4초 간격으로 다섯 번이다. 5.0–7.0초는 열 번이고, k번째 간격이 `U·r^k`(U = 0.4)다. 열 간격의 합이 남은 2초와 같도록 `U·(1 − r^N)/(1 − r) = 2`를 이분법으로 풀면 `r = 0.8317`이다. 틱 시각은 `5 + U·(1 − r^k)/(1 − r)`이다.
  - 실제 틱: 3.0 3.4 3.8 4.2 4.6 · 5.0 5.4 5.733 6.009 6.239 6.431 6.590 6.722 6.832 6.924 → 7.0(시간 끝). 간격은 0.4에서 0.076까지 줄어든다.
  - t에서 마지막 틱 번호는 검색 없이 닫힌 식으로 구한다(`lastTick`, `main.js:84`). 앞 구간은 `⌊(t − 3)/U⌋`, 기하 구간은 합의 역함수 `k = ⌊ln(1 − (t − 5)(1 − r)/U) / ln r⌋`이다.
- **틱에 묶인 맥박(심장 박동)**(`beat`, `main.js:93-107`)
  - 틱 하나의 모양은 「쿵」 `(1 − e^(−s/0.014))·e^(−s/τ)`에, 간격의 32% 뒤에 오는 작은 「쿵」(0.42배)을 더한 것이다. 감쇠 `τ = min(0.15, 0.45·Δ)`를 그 틱의 간격 Δ에 묶었다. 그래서 틱이 몰려도 맥박이 뭉개지지 않고 하나하나 보인다. 세기는 틱 번호에 따라 0.7 → 1.15로 커진다. 최근 네 틱만 더한다.
  - 같은 b가 여러 곳을 함께 뛰게 한다: 카드 크기 `1 + 0.03·b`와 외곽선 밝기(`main.js:610-611`), 「?」 타일 `1 + 0.07·b`(`main.js:510`), 링 두께와 머리 점, 틱마다 링에서 퍼지는 물결(`main.js:577`), 링 뒤 배경 빛, 투표 줄의 점.
- **시청자 투표 막대(예시 숫자)**(`poll`, `main.js:110-118`; 막대 `main.js:618-621`)
  - 참여율 `F(t) = (1/15)·Σ_k outCubic((t − t_k)/0.22)`다. 틱마다 표가 같은 양씩 몰려 들어오고, 틱이 빨라지면 표도 빨리 쌓인다. 「참여 2,847명」은 `round(2847·F)`다.
  - 비율은 `ramp(t, 3.6, 6.6)`으로 이른 비율(A 22 · B 41 · C 22 · D 15)에서 마지막 비율(12 · 29 · 47 · 12)로 옮겨 간다. 그래서 B가 앞서다가 C가 따라잡는 작은 이야기가 생긴다.
  - 막대 높이는 `108·min(1, 비율/0.5)·(1 − (1 − F)²)`다. 참여율 곡선을 앞쪽으로 당겨서 초반에도 막대가 솟는 것이 보인다.
  - 캔버스에는 고정폭 숫자 설정이 없다. 그래서 숫자마다 '0'의 폭 칸을 주고 가운데 정렬로 한 글자씩 그린다(`tnum`, `main.js:161`). 세는 숫자가 좌우로 흔들리지 않는다.
- **정답 공개 안무: 겹치고 비대칭인 퇴장, 큰 박자는 한 번**(`main.js:388-393`, `main.js:623-697`)
  - 박자는 둘로 나눈다. 7.0초 시간 끝은 작은 박자다(링 번쩍임 + 노란 물결 + 숫자 「0」). 7.2초 정답은 큰 박자다. 그 사이 0.2초에 틀린 카드가 물러나고 C가 움츠린다.
  - 틀린 카드: B → D → A 순서로 0.02·0.07·0.11초에 시작한다. 각자 다른 방향(오른쪽 위, 오른쪽 아래, 왼쪽)과 기울기(+2.5°, +2°, −2.5°)로 0.9배까지 물러나고, 어둡게 덮인다(0.6). 길이는 0.26–0.30초 `power3.out`이라서 0.7초 등장보다 훨씬 빠르다.
  - 카드 C의 크기(`popC`, `main.js:144`): 0.12초 동안 0.96까지 움츠린 뒤(예비 동작), 감쇠 스프링 `x(s) = e^(−ζωs)·(x₀·cos ω_d s + (v₀ + ζωx₀)/ω_d · sin ω_d s)`로 놓인다(`main.js:135`). x₀ = −0.09, v₀ = 3.6, ω = 18, ζ = 0.35이고, 0.1초쯤 1.145배로 솟았다가 1.05에 자리 잡는다. 움츠림 끝과 스프링 시작이 같은 값(0.96)이라 이음매가 없다.
  - 색 채움(`main.js:651-660`): 카드 모양으로 자른 뒤 반지름 `270·outCubic(s/0.32)`인 원으로 한 번 더 잘라, 노란 면과 남색 글자로 된 카드 사본을 그린다. 글자색은 채움의 경계에서 정확히 바뀐다. 같은 순간 화면 전체에 노란 빛이 C에서 번진다(반지름 `140 + 1500·outExpo(s/0.75)`, 세기 `0.075 + 0.25·e^(−2.6s)`, `main.js:460`). 뒤에는 0.075가 여운으로 남는다.
  - 방사선 16개(`main.js:677-688`): 각도에 따라 카드 가장자리까지의 거리 `min(hw/|cos a|, hh/|sin a|)` + 20에서 출발한다(`boxRay`, `main.js:150`). 머리는 `outExpo`(0.36초), 꼬리는 0.07초 늦게 `outCubic`(0.42초)으로 따라가서 선이 뻗었다가 끊어지며 사라진다. 아래쪽 선은 `L·(1 − 0.62·max(0, sin a))`로 짧게 해서 자막 자리를 비운다. 크림·노랑을 번갈아 쓰고, 굵기·길이·지연은 `rand(13002)`로 정한다.
  - 충격선(`main.js:689-696`): 둥근 사각형이 가로로 150px, 세로로는 그 절반만 부풀며 가늘어지고 사라진다. 카드 둘레의 노란 후광은 굵은 테 다섯 겹으로 그리고, 1 → 0.42로 줄었다가 숨 쉬듯 흔들린다.
  - 「✓ 정답!」 탭은 0.14초 늦게 `back.out(2.6)`으로 −14°에서 돌며 튀어나온다.
- **점선 오프셋으로 그리는 풀이 호**(`main.js:531-549`; 길이 `main.js:327-335`)
  - 호는 원본 타일에서 합 타일까지 가는 반타원이다(`ellipse`, 위쪽은 시계 방향, 아래쪽은 반시계 방향). 바깥 호(2칸 떨어진 수)와 안쪽 호(바로 앞 수)가 같은 타일에 닿는다. 도착점을 ±16px 엇갈려 두 호가 겹쳐 지나가지 않고 둘러싼다.
  - 길이 L은 setup에서 반타원을 현 400개로 재서 구한다. 그리는 진행률 p에 대해 `setLineDash([L, L])`, `lineDashOffset = L·(1 − p)`다. 두 호는 0.08초 차이로 출발해 같은 순간 닿는다.
  - 출발점에는 점이 `outBack`으로 맺히고, 도착점에는 갈매기 모양 화살촉이 `outBack(2.4)`으로 펴진다. 출발 타일에는 테두리 빛이 켜지고(크림 / 노랑), 「5」 타일은 호가 닿을 때 한 번 튄다. 아래 호가 닿는 순간 「?」가 「8」로 넘어간다.
  - 식 칩(`main.js:699-711`)은 호 쪽에서 26px 미끄러져 나오며 가운데서 양옆으로 열린다(잘라내기 폭 0 → 100%).
- **카메라와 깊이**(`main.js:414-423`, `main.js:465`, `main.js:742-744`)
  - 밀기 양 `push`는 카운트다운 동안 `inOutCubic`으로 0 → 1이다. 7.2초에 `e^(−4s)`로 풀리면서 킥 `0.5·bump(s, 0.05)`를 받고, 8.2초부터 0.35까지 다시 천천히 들어온다.
  - 판은 링 중심 기준으로 `1 + 0.025·push`, 원경은 `1 + 0.03·push`, 전경은 `1 + 0.09·push`만큼 커진다. 겹마다 다르게 커지므로 시차가 생긴다.
  - 흔들림은 `12·e^(−8s)`에 어긋난 사인 둘을 곱한 값이고, 정수 픽셀로 반올림한다. 같은 동안 햇살 무늬가 빨리 돌고(회전 `0.05t + 0.4·inCubic(카운트다운 진행)`), 가장자리 비네트가 닫혀 온다(`main.js:452-458`).
- **GSAP의 몫**(`main.js:366-400`): 타임라인 하나가 DOM이 아니라 **보통 객체(프록시)**를 트윈한다. 알약·질문 어절·타일·카드·링·자막 줄·탭·칩·음절·설명 줄의 위치·크기·기울기·투명도·어둡기가 그 대상이다. frame은 `tl.time(t)` 뒤에 그 값을 읽어 캔버스에 그린다. 그래서 같은 안무를 DOM, 캔버스, three.js 어디에든 옮길 수 있다.

## 결정성 전략

- 움직임은 `gsap.timeline({ paused: true, defaults: { lazy: false } })` 하나다. 속성마다 첫 트윈은 `fromTo`이고, 같은 속성의 트윈이 시간상 겹치지 않는다. setup 끝에서 `tl.time(D); tl.time(0)`으로 모든 트윈을 순서대로 한 번 초기화한다(`main.js:400`).
- 링 각도, 넘김 각도, 틱 번호와 맥박, 투표, 스프링, 방사선, 충격선, 호의 진행, 반짝임, 카메라는 모두 t의 닫힌 식이다. 다른 효과가 끝나기를 기다리는 것은 없다.
- 난수는 `rand(13001)`(원경), `rand(13002)`(방사선), `rand(13003)`(전경), `rand(13004)`(그레인)뿐이고 모두 setup에서 뽑는다. 원경·전경·그레인은 setup에서 한 번 그린 그림이고, frame에서는 CSS 변환만 바꾼다.
- 판 캔버스는 매 프레임 변환·알파·합성·필터·점선·선 끝·자간을 기본값으로 되돌린 뒤 지우고 처음부터 그린다(`main.js:426-428`). 헤드리스 검사에서는 모든 캔버스를 CPU 래스터(`willReadFrequently`)로 만든다(`main.js:231`). GPU 캔버스로 두면 첫 합성이 뒤의 합성과 달라 캡처가 안정되지 않았다.
- **처음 DOM으로 만들었다가 캔버스로 옮긴 이유**: 크기·회전이 프레임마다 바뀌는 DOM 글자와 둥근 도형은 Chrome이 앞서 그린 프레임에 따라 다르게 래스터했다.
  - 판 전체에 건 소수 배율 카메라, 회전하며 들어오는 카드, 넘친 뒤 1배로 쉬는 칩, 반투명 외곽선이 덮인 카드에서 그랬다. 글리프가 1px 밀리거나(최대 220/255), 가장자리 안티에일리어싱이 최대 7/255 달라졌다.
  - 하나씩 피해도 탐색 순서가 바뀌면 다른 곳에서 다시 나왔다. 그래서 판을 CPU 래스터 캔버스 한 장으로 옮겼다. 계산식과 타임라인은 그대로다.
- 렌더러 검사(앞→뒤, 새 페이지에서 뒤→앞, 되돌아가기)는 바이트 단위로 같다. 그 밖에 65개 시각(임팩트·넘김·칩 구간 포함)을 앞→뒤와 뒤→앞으로 찍어 비교해도 모두 같았다.

## 한계와 다음 단계

- **소리가 없다**: 틱은 그림으로만 들린다. 틱 시각표(`TICK.t`)를 그대로 악보로 써서 setup에서 `OfflineAudioContext`로 똑딱 소리를 굽고 `onTransport`로 재생하면, 화면의 맥박과 소리가 한 표에서 나온다.
- **플랩 원근은 근사다**: 날개 하나를 2D 확대 한 번으로 그려서, 가까운 끝만 넓어지는 사다리꼴은 아니다. 숫자가 큰 화면 가득한 플랩이라면 날개를 가로 띠 여러 장으로 잘라 띠마다 `P/(P − z)` 배율을 주면 진짜 사다리꼴이 된다.
- **투표 반올림**: 중간 값에서 네 비율의 반올림 합이 99나 101이 될 수 있다. 정확히 100이어야 하면 가장 큰 나머지 방식으로 1을 나눠 준다.
- **글자 배치는 setup에서 한 번 잰다**: 질문·음절 위치·칩 폭·알약 폭을 `measureText`로 잰 표를 frame이 읽는다. 문구를 바꾸면 그 표가 다시 만들어지므로 자동으로 맞는다. 다만 마스크 높이는 한글 높이 비율(`M`, `main.js:153`)로 정하므로, 다른 글꼴로 바꾸면 확인해야 한다.
- **포스터 시각**: 렌더러 기본(0.6·D = 6.0초)은 카운트다운 장면(숫자 2, 노란 링, 뛰는 카드)이다. 절정은 7.4초(채움이 끝난 C, 방사선, 충격선)다.
- **조정 손잡이**: 긴장 길이는 `TICK`의 `A0`·`N`·`U`, 맥박 세기는 `beat`의 amp와 카드 배율 0.03, 임팩트 크기는 `popC`의 v₀·ω·ζ, 풀이 속도는 `ARCS[].d`에서 바꾼다.
- **다음 단계**: 문제 여러 개를 이어 점수판과 연속 정답 표시를 붙이거나, 틀린 보기를 고른 시청자 비율로 「가장 많이 틀린 답」을 짚는 두 번째 공개 박자를 더할 수 있다.
