# 01 · 먹 한 방울 — SVG 필터 · feTurbulence + feDisplacementMap

> **가장 중요한 규칙: 기술만 가져간다.** 아래 "화면"은 이 데모가 그린 것이다. 기법을 보여 준 예일 뿐이니 소재·장면·이야기·구도·문구·색은 영상에 옮기지 않는다.
> 노트와 코드를 충분히 읽어 "기법과 원리"의 기술만 가져가고, 장면은 작업 중인 영상의 대본으로 새로 짓는다.

## 화면

한지(섬유결이 비치는 아이보리 종이, 아래쪽은 찢긴 가장자리 너머 검은 펠트) 위로 먹 한 방울이 카메라 쪽에서 떨어진다.
처음엔 초점이 나간 큰 구슬이었다가 종이에 가까워지며 작고 선명해지고, 그림자가 방울 쪽으로 모여든다(0.15–1.35 s).
닿는 순간 먹이 튀며 번지고(1.35 s), 그 먹물이 봉우리 꼭대기로 빨려 들어가듯 줄어드는 동안 주봉이 위에서부터 번져 나온다.
이어 먼 산(청회색 옅은 먹), 중경 능선(잔 나무 점), 강과 물결, 전경의 바위와 소나무가 차례로 스며 나오고(2–7 s),
봉우리 밑동에는 안개가 흐른다. 마지막으로 나룻배, 옅은 주홍 해와 하늘의 온기, 날아가는 새 세 마리,
오른쪽 아래 붉은 낙관 「먹」이 찍힌다(7.9 s). 끝 0.55 초 동안 먹이 종이 속으로 가라앉아, 처음(빈 종이)으로 이어진다.
깊이는 먹의 농담으로 만든다: 먼 산은 옅고 흐리게(반해상도), 주봉은 진하고 테두리가 살아 있게, 소나무는 가장 짙고 날카롭게.

## 기법과 원리

- **먹 레이어 하나 = 필터 두 단계** (`inkLayer`, main.js:172).
  - **setup — 번진 먹을 굽는다** (`bake`, main.js:188): 레이어의 도형(알파 = 먹의 농도)을 feTurbulence(고정 seed) →
    `feDisplacementMap`(섬유 방향으로 흐트러진 가장자리) → `feGaussianBlur`(번짐)에 통과시켜 두 번 래스터한다 —
    **젖은 먹**(변위·블러 큼)과 **마른 먹**(가장자리가 자리 잡음). 값은 `LAYERS`의 d/s(main.js:216).
    번짐이 도착하는 시간을 담은 지도도 굽는다: B 채널 = 번짐 시작점 중심의 방사형 그라디언트 + 노이즈.
  - **frame — 싼 필터 하나**: `feImage`(젖은 먹) ⊕ `feImage`(마른 먹)을 `feComposite arithmetic`으로 섞고(k = 젖은 정도,
    main.js:179), 지도의 B로 `feColorMatrix` alpha = slope·(B − thr)를 만들어(main.js:180) 가린다. thr를 1.08 → −0.25로 내리면
    노이즈 때문에 손가락처럼 갈라지는 모세관 번짐 전선이 나아가고, `feComponentTransfer` table [0, 1, .84](main.js:182)가 전선
    띠에서만 알파를 1까지 올려 먹이 고이는 젖은 가장자리를 만든다. 젖은 먹은 전선이 지나간 뒤 마른 먹으로 스며든다.
- **농담(水墨)**: `wash`(main.js:71)는 능선 아래로 같은 투명도의 띠 N장을 겹쳐 능선을 따라 짙고 아래로 옅어지는 그라디언트를
  만든다(끝은 오므리고 바닥선 아래로는 내려가지 않는다). 그 위에 피마준 같은 붓 획(main.js:324), 끊긴 능선 윤곽, 태점,
  `brush`(main.js:86)로 만든 굵기 변하는 획(소나무 줄기·가지·솔잎 부채)을 얹는다.
- **먹방울과 튐**: 원 + 튀는 방울 14개에 고전적인 "gooey" 체인을 실시간으로 건다(main.js:454): 변위 → 블러 → 가파른 알파 임계 →
  알파 − 블러(알파)로 마른 테두리 강조. 560×480 영역에 한정되고 1.35–3.65 s에만 돈다. 반지름이 펼쳐졌다가 0으로 줄어 "산이 먹을 마신다".
- **떨어지는 먹방울**: 광택 있는 구슬을 한 번만 그려 두고(main.js:508), 떨어짐은 CSS `transform`(위치·크기), 초점은 CSS
  `filter: blur()`(main.js:548), 그림자는 부드러운/선명한 타원 두 장의 교차 페이드(main.js:523) — 모두 컴포지터가 적용하는
  속성이라 낙하 동안 다시 그리는 것이 없다.
- **종이**: `feTurbulence`(섬유, 5옥타브) → `feDiffuseLighting`(main.js:263)으로 결을 비추고, 다른 노이즈의 `feDisplacementMap`으로
  아래 가장자리를 찢는다. 그 위에 긴 닥섬유 곡선과 왼쪽 위 빛·가장자리 그늘.
- **안개**: 종이색 타원을 길게 늘인 노이즈로 휘게 하고(main.js:355, 반해상도) `mix-blend-mode: lighten`으로 얹는다 — 맨 종이 위에선
  보이지 않고 먹만 가린다. 타원이 고정된 변위장 속을 흘러가므로 윤곽이 계속 변한다.
- **낙관**: 막대로 짠 「먹」(ㅁ·ㅓ·ㄱ)을 붉은 판에서 오려낸 백문인. 작은 실시간 feTurbulence로 눌림 얼룩을 만들고(main.js:481),
  `feColorMatrix` 상수(압력)가 커지며 인주가 차오른다(main.js:605).

## 결정성 · 성능 전략

- 모든 값은 `t`의 순수 함수: `track`/`ramp` 트랙, `rand(seed)`로 만든 지오메트리, 고정 seed의 feTurbulence. 타이머·Math.random 없음.
- `put()`/`setStyle()`(main.js:34, 40)은 값이 바뀔 때만 쓴다 — 전선이 지나가고 마른 레이어는 다시 그려지지 않는다.
- **무거운 것은 setup에서**(`bakeAll`, main.js:117): 변위·블러로 번진 먹(젖은/마른), 도착 시간 지도, 종이를 SVG 문자열 →
  `<img>` → canvas(CPU) → PNG blob으로 한 번 래스터해 `feImage`로 쓴다. feImage는 load 이벤트가 없어 같은 blob을 `<image>`로
  먼저 읽혀 캐시를 데운 뒤 연결한다.
- **매 프레임의 필터 일은 한정된다**: 이전 버전은 번지는 레이어마다(주봉 920×800 등) 변위 + 블러 전체를 매 프레임 다시
  계산했고, 먹방울은 3배 크기 영역의 σ 28 블러를 매 프레임 다시 그렸다 — GPU 브라우저에서 낙하·충돌 순간의 프레임 드랍 원인.
  지금 프레임마다 도는 것은 레이어당 이미지 3장의 합성·행렬·테이블(픽셀당 몇 연산)뿐이고, 먹방울은 컴포지터 속성뿐이다.
- 각 레이어는 상자 크기의 자체 합성 레이어 `<svg>`(`sheet`, main.js:160). 보이고 숨기기는 `display`가 아니라 opacity로
  (main.js:560) — 레이어가 생겼다 사라지는 비용이 없다.
- 루프 디졸브는 먹 레이어 15장의 opacity를 각각 내리는 대신, 같은 종이 이미지를 위에 한 장 더 올려 그 opacity만 올린다
  (main.js:604) — 결과는 같고, 디졸브 동안 다시 그릴 것이 없다.

## 한계와 다음 단계

- Chromium 이상 동작: 원소를 참조하는 `feImage`(href="#id")는 부분영역 원점만큼 원소를 다시 옮겨 그리고, 어떤 그룹에서는 필터 전체가
  조용히 빠지는 일이 있었다(같은 필터를 복제해도). 모든 지도를 비트맵으로 구워 이 문제를 피했다.
- 번짐은 "도착 시간장 + 임계값"의 근사다. 실제 먹의 확산(물의 양, 종이 흡수율, 겹친 붓질의 번짐 경계)은 아니다 —
  반응-확산이나 격자 위 확산 시뮬레이션을 setup에서 구워 도착 시간장으로 쓰면 더 사실적인 갈래가 나온다.
- 해는 단순한 원이고, 글씨(제화시)가 없다. 붓글씨 폰트나 획 데이터가 있으면 세로 제화와 낙관의 배치를 완성할 수 있다.
- 젖음→마름은 두 장의 구운 먹 사이의 교차 페이드다. 변위 크기가 연속으로 줄어드는 원래 효과와 완전히 같지는 않다(중간 단계를 더 구우면 가까워진다).
- 먼 산을 반해상도로 그린 것은 헤드리스 예산 때문이다. GPU 재생만 생각하면 전체 해상도로 되돌려도 된다(`res: 0.5`).
