# 102 · 쌓으면, 꿈 — 아이소메트릭 복셀 글자 · 블록 조립과 재조립

> **가장 중요한 규칙: 기술만 가져간다.** 아래 "화면"은 이 데모가 그린 것이다. 기법을 보여 준 예일 뿐이니 소재·장면·이야기·구도·문구·색은 영상에 옮기지 않는다.
> 노트와 코드를 충분히 읽어 "기법과 원리"의 기술만 가져가고, 장면은 작업 중인 영상의 대본으로 새로 짓는다.

낱말 하나를 굵은 격자로 래스터화하고, 칸마다 장난감 블록(위에 돌기 하나 달린 정육면체) 하나를 둥근 놀이판 위에 놓는다.
블록은 획을 따라가는 순서로 떨어져 「쌓다」를 짓는다. 다 지어지면 모두 떠오르고, 카메라가 놀이판을 4분의 1바퀴 돈다.
그다음 **같은 블록 296개**가 공중제비를 돌며 날아가 새 방향에서 읽히는 「꿈」으로 다시 내려앉는다. 남는 44개는 획의 등줄기 위에 한 층 더 쌓여 글자가 도톰해진다.
10초, 1080×1920, Canvas 2D 한 장. 시뮬레이션은 없다. 블록 하나하나가 setup에서 푼 시각들로 만든 t의 작은 순수 함수다.

## 화면

미감은 파스텔 장난감 스튜디오다.
- 배경: 위는 하늘색, 아래는 라일락 바닥으로 넘어가는 그라디언트. 왼쪽 위에 소프트박스 빛이 있고, 지평선 근처에 초점이 나간 장난감 실루엣과 필름 그레인을 깔았다.
- 놀이판: 크림색 원판(돌기 판). 옆면에는 라일락·크림 사탕 줄무늬를 둘렀다.
- 블록: 여섯 가지 파스텔(하늘, 버터, 분홍, 민트, 라일락, 복숭아).
- 글자: 문구는 Pretendard 700/900, 먹 보라(#3B3460) 하나에 강조색 산호(#FF5A4A) 하나. 블록 글자의 원본 글꼴은 도현(Do Hyeon)이다.

| 시간 | 장면 |
|---|---|
| 0–0.5 | 빈 놀이판. 키커 "한 칸, 또 한 칸"이 줄 마스크 안에서 올라오고, 칩 "블록 000개"가 튀어나온다. |
| 0.5–2.8 | 「쌓다」가 지어진다. 블록이 위에서 늘어나며 떨어지고(속도만큼 세로로 늘어남), 닿으면 찌그러졌다가 두세 번 튄다. 떨어지는 동안 바로 아래의 접촉 그림자는 진해지면서 좁아지고, 빛 방향으로 밀린 그림자는 블록 쪽으로 미끄러져 들어온다. 닿는 순간 획의 바깥쪽으로만 흰 먼지가 퍼진다. 순서는 ㅆ → ㅏ → ㅎ → ㄷ → ㅏ, 각 자모 안에서는 펜이 지나가듯 이어진다. 칩의 숫자는 착지한 블록 수를 고정폭으로 센다. |
| 2.8–3.6 | 다 지어진 「쌓다」를 읽을 시간. 카메라가 천천히 돈다(16° → 20°). |
| 3.6–4.4 | 블록이 웅크렸다가(찌그러짐) 가운데부터 바깥으로 튀어 올라 공중에 뜬다. 가운데가 더 높아 떠오른 글자는 둥근 언덕 모양이 되고, 바닥에는 글자 모양 그림자가 떨어져 남는다. 키커가 "쌓은 블록 그대로"로, 칩이 "같은 블록 296개"로 바뀐다. |
| 4.1–5.5 | **카메라가 90° 돈다.** 고도가 43°에서 31°로 내려갔다가 44°로 돌아온다. 사탕 줄무늬와 바닥 돌기가 함께 돌고, 빛이 절반만큼 따라 돌아 그림자 방향도 45° 바뀐다. 배경과 앞쪽 보케는 시차를 두고 미끄러진다. |
| 4.6–6.2 | **절정.** 블록마다 포물선을 그리며 날아간다. 대부분 진행 방향에 수직인 축으로 한 바퀴 공중제비를 돌고, 짧게 뛰는 것은 90° 돈다. 새 자리에 「꿈」의 바닥 층이 가운데부터 바깥으로 내려앉으며 튀고 먼지를 일으킨다. |
| 6.3–6.9 | 남은 44개가 획의 등줄기(가장 안쪽 칸들이 이어진 줄) 위로 한 층 더 내려앉는다. 밑의 블록은 맞을 때마다 움찔한다. 마지막 블록이 앉는 순간 놀이판에 흰 링이 퍼지고 카메라가 짧게 펀치한다. 헤드라인 "**꿈**이 된다"가 올라온다. |
| 6.9–10 | 여운. 하늘이 노을빛으로 데워지고 빛 속 먼지가 떠다닌다. 7.7–8.7초에 빛띠가 블록 윗면을 비스듬히 훑고 지나가며, 카메라는 6° 더 돌면서 다가간다. |

## 기법과 원리

**1. 글자 → 격자** (`main.js:90` `rasterSyllables`)
- 음절을 칸당 20px로 크게 그리고, 칸마다 알파를 평균해 커버리지 ≥ 0.5인 칸을 채운다.
- 「쌓」「다」는 같은 크기로 그린다. 둘 중 큰 잉크 상자를 18칸에 맞춘다. 「꿈」은 21칸이다.
- 굵은 격자에서는 획 굵기가 고른 기하형 글꼴이 잘 읽혀서 도현을 쓴다. Pretendard 900이나 검은고딕으로 해 보니 「쌓」의 ㅆ·ㅎ가 뭉개졌다.
- 「쌓다」는 세로 화면에 맞춰 두 음절을 깊이 방향으로 세우고, 위에서 아래로 읽게 했다. 모든 칸 중심은 (i + ½, j + ½) 격자 위에 있어 바닥 돌기와 맞물린다.

**2. 획을 따라가는 순서** (`main.js:122` `components`, `main.js:145` `strokeDistance`, `main.js:353`)
- 음절마다 4-이웃 연결 성분(굵은 격자에서는 대개 자모 하나)을 구하고, 무게중심의 `y + 0.6x`로 정렬한다. 한글의 읽기 순서(초성 → 중성 → 종성, 왼쪽/위 먼저)에 대한 근사다.
- 성분 안에서는 가장 왼쪽 위 칸부터의 BFS 측지 거리로 순서를 매긴다. 그래서 ㄷ은 윗변과 왼쪽 기둥이 동시에 자라다가 아랫변으로 이어진다. 펜이 지나가는 것처럼 보인다.
- 다음 성분은 앞 성분이 절반쯤 쓰였을 때 시작한다. 전체를 [0.5, 2.8]초에 선형으로 맞춘다.
- 색은 성분마다 하나씩 준다. 같은 블록이 「꿈」으로 옮겨 가므로, 「꿈」은 「쌓다」의 자모 색이 조각조각 섞인 모자이크가 된다(블록이 보존된다는 것이 보인다).

**3. 닫힌 식 착지** (`main.js:54` `bounces`, `main.js:65`, `main.js:72`, `main.js:530` `state`)
- 낙하: `z = g/2·(t_L − t)²` (높이 8.5, 0.4초). 바운드 열은 v_k = eᵏ·v₀(e = 0.33)이고 각 포물선 `z = v_k·s − g/2·s²`는 setup에서 시각만 정해 둔다.
- 찌그러짐: 충격마다 임펄스 응답 `e^(−11s)·sin(27s)`에 세기 v_k/v₀를 곱해 더한다. 높이는 1 − 0.36q, 폭은 1 + 0.18q.
- 떨어지는 동안에는 속도만큼 늘이고, 나타날 때는 `outBack`으로 크기가 튀어나온다.
- 위층 블록이 앉으면 아래 블록에도 충격을 더한다(`hits`). 선형계라 더하기만 하면 된다.

**4. 같은 블록으로 다시 짓기** (`main.js:367`, `main.js:379`, `main.js:403`, `main.js:414`, `main.js:427`)
- 「꿈」은 돌고 난 뒤의 시점에서 읽히도록 세계 좌표를 `(u, v) → (v, −u)`로 놓는다. 방위각이 θ에서 θ + 90°로 바뀔 때 화면에서 (u, v)를 θ에서 본 것과 똑같아진다.
- 남는 블록(296 − 252 = 44)을 올릴 자리(`main.js:379`):
  - 글자 안쪽 깊이(`insideDepth`, `main.js:162`)가 2 이상인 칸, 곧 획의 중심선만 고른다.
  - 그 칸들을 연결된 줄 단위로 큰 줄부터 채운다. 흩어진 낱개 대신 획 하나가 통째로 솟는다.
- 짝 맞추기: 출발 칸과 도착 칸의 거리 제곱 합이 최소가 되도록 헝가리안 알고리즘(`main.js:182`, n = 296, 약 25 ms)으로 정한다. 경로가 짧고 거의 엇갈리지 않아 정돈된 재조립이 된다.
- 비행: 떠 있는 높이 z₀에서 목표 층까지 포물선으로 난다. `vz0 = (층 − z₀ + g/2·T²)/T`(`main.js:454`)이고, 수평은 등속이다. 내려앉는 속도로 다시 바운드 열을 만든다.
- 회전(`main.js:457`): 로드리게스 행렬로 2π(공중제비) 또는 π/2(요)만 돈다. 정확히 똑바로 선 채 착지한다.
- 착지 순서: 바닥 층은 「꿈」의 중심에서 바깥으로, 위층은 그다음이다. 위층은 아래 블록의 바운드가 끝난 뒤에만 앉도록 시각을 미룬다(`main.js:421`). 마지막 착지 시각이 링·펀치 시각 `tBeat`가 된다.

**5. 정사영 카메라와 깊이 정렬** (`main.js:284–304`, `main.js:693–712`)
- 투영: `X = S(x cosθ − y sinθ)`, `Y = S((x sinθ + y cosθ) sinφ − z cosφ)`이고, 깊이는 `(x sinθ + y cosθ) cosφ + z sinφ`다.
- 진짜 아이소메트릭(θ = 45°, φ = 35.26°)에서는 이 깊이가 x + y + z에 비례한다. 연속으로 도는 궤도에서도 같은 식이 맞는 정렬 키가 된다.
- 정렬이 정확한 이유: 같은 크기 정육면체가 정수 격자 위에 겹치지 않고 놓이면, 화면에서 겹치는 두 블록은 떨어진 모든 축에서 앞뒤 순서가 같다. 그러면 중심 차이와 시선 방향의 내적 부호가 곧 가림 순서다.
  - 날아가는 블록은 격자를 벗어나므로 근사다. 가까이 스칠 때 잠깐 어긋날 수 있다.
- 먼지 입자도 같은 목록에 깊이 키로 끼워 넣는다.

**6. 그리기** (`main.js:772` `drawBrick`)
- 면: 6면 중 시선 쪽 면만 그린다(최대 3면). 밝기는 `0.6 + 0.44·max(0, n·L)`인 평면 3톤이고, 어두운 면일수록 파랑을 조금 더 남겨 그림자가 라일락 쪽으로 식는다.
- 이음매: 면마다 바탕색 74%로 1px 테두리를 그어 블록 사이 경계가 보이게 했다.
- 돌기: 똑바로 선 블록은 축 정렬 타원 두 개와 사각형이다(땅 위의 원은 어느 방위에서나 축 정렬 타원).
- 도는 블록의 돌기(`main.js:810`): 윗면의 두 축을 화면 아핀 변환으로 놓고 단위원을 그린다. 원기둥 옆면은 단위원 공간에서 오프셋 방향에 수직인 사각형이며, 감김 방향을 원과 맞춰 nonzero로 합친다.
- 그림자(`main.js:651`): 두 겹을 놀이판 타원으로 클립한다.
  - 접촉 그림자: 블록 바로 아래의 부드러운 원판이다. 높이 h에 따라 진하기 0.42·(1 − h/7)², 반지름 0.78 + 0.16h.
  - 빛 방향 그림자: 블록 8꼭짓점을 빛을 따라 바닥에 투영한 볼록 껍질이다. 모든 블록의 껍질을 경로 하나에 같은 방향으로 넣고 한 번에 채운다(합집합이라 겹쳐도 진해지지 않는다).
- 먼지(`main.js:434`): 착지한 칸의 4-이웃 중 **비어 있는 쪽**으로만 두 줄기씩 퍼진다. x = v/k·(1 − e^(−ks))이고 위로 떠오른다. 획 안쪽 블록은 먼지를 내지 않으므로 먼지가 늘 열린 바닥 위에 보인다. 흰 퍼프 아래쪽에 라일락 그늘을 넣어 크림색 판에서도 보이게 했다.
- 빛과 시점: 빛은 카메라 방위의 절반만큼 따라 돈다(`main.js:295`). 세계에 완전히 고정하면 90° 뒤에 앞면이 그늘로 바뀌고, 카메라에 고정하면 그림자가 돌지 않아 회전이 덜 보인다.
- 놀이판(`main.js:599`, `:627`): 옆면 줄무늬는 세계 각도로 칠하고, 시점 각도 (0, π) 구간만 보이게 그린다. 돌기 약 1,400개는 옆면과 윗면 경로 두 개로 한 번씩 채운다.

**7. 문구** (`main.js:838` `drawCopy`)
- 낱말마다 0.08초씩 겹쳐 줄 마스크 안에서 `outExpo`로 올라오고, 퇴장은 `inCubic` 0.3초로 더 빠르다. 자간은 −0.03em이다.
- 칩의 숫자는 칸 너비를 고정해 한 자씩 놓는다(캔버스에 tnum이 없다).

## 결정성 전략

- 프레임은 t만 읽는다.
  - 블록의 모든 시각(착지, 이륙, 발사, 재착지, 위층 충격)과 바운드 열, 짝, 비행 속도는 setup에서 정한다.
  - frame은 그 조각 함수들을 평가하고, 매번 0에서 정렬 목록을 새로 만든다.
- 난수는 `rand(10201–10205)`(배경, 이륙 높이·위상, 회전 종류, 먼지 방향 흔들림, 떠다니는 먼지)뿐이다. 모두 setup에서 뽑는다.
- 정렬은 깊이 → 종류 → 번호 순이라 같은 키에서도 순서가 고정된다. 헝가리안도 결정적이다.
- `ctx.reset()`으로 매 프레임 컨텍스트 상태를 기본값으로 되돌린다(`main.js:575`). 자간·클립·변환·알파가 다음 프레임에 새지 않는다.
- 오프스크린 캔버스(배경 둘, 그림자·먼지·빛·보케 스프라이트)는 헤드리스에서 CPU 래스터로 만든다. setup에서 한 번씩 본 캔버스에 그려 첫 합성을 끝내 둔다(`main.js:501`).
- 렌더러 검사(정순, 새 페이지 역순, 되돌아가기 6회): **byte-identical**.

## 한계와 다음 단계

- **정렬 근사**: 날아가는 블록끼리, 또는 날아가는 블록과 앉은 블록이 아주 가까이 스칠 때는 중심 깊이 정렬이 틀릴 수 있다(격자를 벗어나면 정렬 정리가 성립하지 않는다). 지금 궤적에서는 눈에 띄지 않는다. 엄밀히 하려면 겹치는 쌍만 분리축 검사로 위상 정렬하면 된다.
- **그림자 근사**: 날아가는 블록의 그림자는 바닥에만 떨어지고, 아래 블록 윗면에는 떨어지지 않는다. 위층 블록의 빛 그림자도 아래층에 가리지 않는다.
- **굵은 격자의 한계**: 18칸 「쌓」의 ㅎ은 꼭지와 가로획이 붙는다. 맥락 속에서는 읽히지만, 더 복잡한 음절은 24칸 이상(블록 수 약 1.8배)이 필요하다.
  - 조정: 칸 수는 `main.js` setup의 `N1`, `N2`, 임계값은 `rasterSyllables`의 `thr`(0.5)에서 바꾼다.
- **획 순서는 근사다**: 연결 성분 정렬과 BFS 측지 거리이고 실제 필순 데이터가 아니다. 한 성분에 자모 둘이 붙으면(예: ㅆ의 두 ㅅ) 함께 자란다.
- **조정 손잡이**:
  - 이야기 시각: `main.js:34–40`(빌드 창, 이륙, 회전, 재착지, 위층, 빛띠).
  - 카메라: `main.js:284–287`(방위, 고도, 배율, 화면 중심).
  - 물리: `main.js:43–45`(낙하 높이·시간, 반발 계수, 비행 중력).
  - 남는 블록 수는 「꿈」의 칸 수(`N2`)로 정해진다. N2 = 20이면 약 67개가 위층으로 간다.
- **다음 단계**:
  - 2×1·2×2 블록(칸 합치기)으로 더 장난감다운 조립을 만든다.
  - 정렬 키를 x + y + z 정수 버킷으로 나눠 블록이 수천 개로 늘어도 버티게 한다.
  - three.js 인스턴싱으로 옮겨 진짜 그림자 맵을 쓴다.
