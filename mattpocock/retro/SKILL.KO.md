사용자가 **회고**를 요청했습니다. 향후 실행을 개선하기 위해 코딩 에이전트의 **환경**에 대한 개선안을 제안하는 것입니다.

## 단계

1. `writing-for-agents` 스킬을 사용하여 Skill 도구를 호출해 글쓰기 스타일 가이드를 확인합니다.

2. 사용자가 지정한 세션의 기본 자료를 읽습니다. 이 머신의 세션 로그를 검색해야 할 수도 있습니다. 사용자가 세션을 지정하지 않으면 현재 세션을 기본으로 합니다.

3. 다음 범주에서 개선 후보를 찾습니다.

- **내비게이션**: 에이전트가 올바른 파일을 찾기가 얼마나 쉬웠는가? 파일 사이에 숨은 의존성이 있는가? **내비게이션 포인터**가 있으면 더 쉬워지는가? _사용 시점_: 세션에서 특정 정보를 찾는 데 오랜 시간이 걸렸을 때.
- **자동 검사**: 에이전트가 저지른 실수를 잡아낼 수 있는 자동 검사가 있는가? 린팅, 타이핑, 테스트, 파일시스템 린터 등. 저장소의 기존 검사 명령을 먼저 읽으세요(`package.json`의 `lint`/`check` 스크립트, 빌드 도구 설정, CI 워크플로). 이미 존재하지만 연결되지 않았거나 조용히 깨진 검사가 있다면 그것이 발견 사항이며, 새로 만들 것이 아닙니다. 가드레일이 없는 저장소(린트/타입 검사/테스트 명령을 실행하는 pre-commit 훅도 CI 작업도 없는 경우)는 그 자체로 발견 사항입니다. 린트되지 않는 저장소는 중립적인 기본값이 아니라 지속적으로 놓치고 있는 기회입니다. _사용 시점_: 자동 검사로 잡을 수 있었던 실수를 에이전트가 저질렀을 때, 또는 저장소에 가드레일이 전혀 없을 때.
- **코딩 표준**: 리뷰 에이전트에 새 규칙을 추가해야 하는가? 기존 규칙을 제거하거나 명확히 해야 하는가? 먼저 위반 유형을 분류하세요. **기계적** 위반(고정된 문법 패턴, 금지된 API, import 형태, 파일 위치 규칙)에는 결정론적 검사를 적용합니다. 저장소 자체 린터의 커스텀 규칙, 새 pre-commit 훅, 새 CI 작업 중 저장소의 언어와 기존 가드레일에 가장 저렴한 방법을 택하세요. 규칙을 작성하는 것보다 검사를 만드는 것을 기본으로 합니다. `CODING_STANDARDS.md`는 진정한 **판단 사항**(파일 간 일관성, "주변 스타일과 일치하는지", 어떤 가드레일로도 대체할 수 없는 것)을 위해서만 사용하세요. _사용 시점_: 리뷰 에이전트가 실수를 잡아내지 못했을 때.
- **전역 AGENTS.md**: 조종 지침 중 코딩 표준(또는 자동 검사)으로 옮겨야 할 것이 있는가? _사용 시점_: 저장소 안이든 사용자의 전역 범위든 AGENTS.md 파일이 특히 길 때.
- **도구 경제성**: 에이전트가 줄일 수 있었던 비싼 도구 호출을 했는가? 토큰 효율이 특히 나쁜 커스텀 도구(CLI, MCP)가 있는가? _사용 시점_: 에이전트가 비싼 도구 호출을 했을 때.
- **무효 지침**: 조종 파일에 있지만 에이전트의 행동을 바꾸지 않는 지침을 찾습니다. _사용 시점_: 조종 파일이 크고 다루기 어려울 때.
- **정보 접근**: 에이전트가 정보에 접근할 수 있도록 개선할 기회를 찾습니다. 개발 서버 로그를 tee로 남기기, 외부 서비스에 읽기 전용 접근 권한 주기 등. _사용 시점_: 결정적인 정보가 에이전트에게 없었을 때.

4. 후보를 심각도 순으로 사용자에게 제시합니다.

## 참고

### 구현과 리뷰

모든 작업은 구현과 리뷰 두 단계를 거친다는 점을 기억하세요. 구현 에이전트는 가장 큰 **컨텍스트 압박**을 받습니다. 탐색, 코드 작성, 실패 디버깅을 담당하기 때문입니다.

리뷰 에이전트는 컨텍스트 압박이 가장 적습니다. diff를 받으므로 탐색이 필요 없고, 코드를 작성하거나 디버깅할 일도 대개 없습니다.

따라서 코딩 표준을 강제하는 책임은 구현 에이전트가 아니라 리뷰 에이전트에 있어야 합니다.

### 파일

저장소에는 다음과 같은 파일들이 있습니다.

- `CLAUDE.md`/`AGENTS.md`: 이 파일들은 이 저장소에서 작업하는 모든 에이전트의 컨텍스트 창에 전달됩니다. 아주 아껴서 사용해야 하며, 대개 다른 파일을 가리키는 **내비게이션 포인터** 용도로만 쓰세요.
- `CODING_STANDARDS.md`: 이 파일은 구현이 아니라 리뷰 중에 읽힙니다. 표준 파일이 1,000줄을 넘으면 docs 폴더로 가는 **내비게이션 포인터**를 추가하세요.
- Docs: 문서는 다른 파일이 가리키는 참고 자료로 사용하세요. 새로 쓰기 전에 기존 문서를 먼저 찾아보세요.
- Skills: 설명이 에이전트의 컨텍스트 창에 들어가므로 문서용으로, 또는 사용자가 호출하는 명령용으로 스킬을 사용하세요. `writing-for-agents` 스킬의 조언을 따르세요.
