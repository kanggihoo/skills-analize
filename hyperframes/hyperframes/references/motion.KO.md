# 모션

## 모션 기법

HyperFrames 공식 론칭 필름을 프레임 단위로 측정한 값이다. 이것은 기본값이다. 사용자가 준 레퍼런스나, 특정 순간이 의도적으로 다르게 하는 경우에는 그 비트에 한해 그쪽이 우선한다.

- **움직임**: 빠른 움직임은 0.3–0.6초가 걸리며, 자체 이즈에 모션 블러를 붙인다. 가장 빠른 프레임에서 정점을 찍는다. 텍스트 크기 요소는 6–12 px, 전체 프레임은 15–20 px이다. 가로 움직임은 가로 방향으로만 한다. 움직임 하나는 트윈 하나다.
- **렌더 시점 블러**: 빠르게 움직이는 2D 요소에는 컴포지션 루트에 `data-motion-blur="on"`을 준다. 그러면 미리보기와 렌더링에서 실제 경로를 따라 잔상이 생긴다(옵트인. 더 긴 잔상이 필요하면 `data-motion-blur-shutter`, 360이면 강하다. 움직임이 타임라인 콜백, 예를 들어 `render(t)` 함수에서 설정된다면 `-events="on"`을 쓴다). 사용자가 블러나 필름 같은 룩을 요청했고 영상이 빠르게 움직이면 이것을 제안한다. 요소별 필터로 그리며, WebGL 위에서도, 어떤 Chrome에서도 동작한다. 비용은 영상마다 다르다. 실제 두 영상에서는 캡처보다 비용이 더 컸다. 회전과 줌은 잔상을 만드는 대신 부드러워진다. `data-motion-blur-tier="capture"`는 더 정확한 캡처 방식을 선택한다. 다만 움직이는 요소 앞에 있는 것은 사라지고, 블렌드 모드는 무시된다. HDR 렌더링과 엔진 자체의 서브 프레임 블러를 쓰는 렌더링에서는 꺼져 있다. 분산 렌더링과 `--start`/`--end` 범위 렌더링은 전체 렌더링처럼 블러를 적용한다. `hyperframes render --page-motion-blur off`는 블러 없이 렌더링한다. 하위 트리 하나를 빼려면 `data-motion-blur="off"`를 준다. 예를 들어 이미 자체 블러를 가진 이음새가 그렇다. 추가한 뒤에는 `hyperframes check`를 실행한다. 가이드: /guides/motion-blur.
- **도착은 천천히, 떠날 때는 깔끔하게**: 도착에는 긴 꼬리를 가진 ease-out을 쓴다. 착지는 떠나는 것보다 오래 걸린다. 퇴장은 한 번의 부드러운 움직임이어야 한다. 미끄러지고, 멈추고, 떠나는 식이면 안 된다. 너무 빠른 등장은 글리치처럼 읽힌다. 영상 전체를 약 1초 느리게 하면 종종 해결된다.
- **역할에 따른 이즈**: 도착은 긴 꼬리로 착지한다(`expo.out`, `power4.out`). 카메라 이동이나 색면 채우기는 양방향으로 이즈한다(`power2.inOut`). 줌을 통과하거나 퇴장할 때는 가속한다(`power3.in`). 모든 것에 0.5초짜리 같은 `power2.out`을 쓰면 평평한 기본값이 되고, 그것이 필름을 생성된 것처럼 보이게 만든다. 선형은 회전, 진행률, 등속 움직임처럼 그것이 핵심인 경우에만 쓴다.
- **스프링**은 감쇠 비율로 이름을 붙인다. 1.0은 튀지 않는다. 0.7–0.85는 고급스럽게 읽힌다. 0.4–0.6은 장난스럽다. 0.3 미만은 만화 같다. 위치와 크기는 튈 수 있다. 불투명도와 색은 절대 튀지 않는다. GSAP의 `elastic.out(1, 0.5)`와 `back.out(1.4)`가 가장 가까운 내장 함수다. `t`에 대한 닫힌 형태의 스프링은 어떤 프레임이든 그 자체로 렌더링할 수 있게 한다.
- **퇴장**은 등장보다 40–50% 짧다. **겹침**: 이전 요소가 30–50% 진행되었을 때 다음 요소가 시작한다. 완전히 순차적이면 로봇처럼 보이고, 전부 동시에 나오면 싸 보인다. **스태거**: 글자는 한 프레임 간격, 단어는 60–120 ms, 목록 항목은 40–80 ms 간격이다.
- **비트 격자**: 비트당 프레임 수 = fps × 60 / BPM. 각 비트는 인덱스에서 계산하고 반올림한다. 반올림된 비트를 반복해서 더하지 않는다(128 BPM, 30 fps에서 그렇게 하면 32비트마다 2프레임씩 어긋난다). 비트에 맞춰 컷하고, 레이아웃은 마디에 맞춰 바꾼다.
- **컷**: 움직임이 가장 빠른 프레임에서 자른다. 양쪽의 방향과 속도를 맞춘다. 새 화면으로 들어가는 클릭은 클릭의 반동 지점에서 매치 컷이 된다. 새 화면은 약간 크게 들어와 자리를 잡는다.
- **타이틀**: 착지한 타이틀은 완전히 정지해 있다. 움직임은 다음 요소, 카메라, 뒤의 세계로 옮아간다. 등장 방식은 필름 안에서 다양하게 바꾼다. 페이드와 위로 슬라이드를 매번 쓰지 않는다.
  - 단어 단위: `blur(6px)` → 0, 불투명도 0 → 1, 0.13초 동안, 단어 사이 0.067초 간격, translate 없음;
  - 단어 단위로 연회색에서 잉크색으로, 0.07–0.1초 간격, 위치 변화 없음;
  - 줄 전체가 블러에서 선명하게, 8 px → 0, 0.13–0.2초;
  - 이름은 글자 단위로, 0.1초 간격, 불투명도 0.3 → 1과 약간의 블러;
  - 피사체 뒤에서: 타이틀이 배경 플레이트와 사람의 매트 사이에 놓인다;
  - 문장의 한 단어가 슬롯 머신처럼 여러 옵션을 굴러간다. 한 번 구르는 데 약 0.1초.
- **홀드**: 시청자가 읽어야 하는 줄은 약 0.5초에 단어당 0.3초를 더한 시간 동안 머문다. 필름의 마지막 줄은 최소 2초다. 한두 단어짜리 챕터 줄은 0.4초 머물 수 있다. 그다음 블러 아웃과 0.13–0.25초의 페이드로 퇴장한다. 단어 단위로 하거나, 씬의 움직임으로 퇴장한다.
- **타이틀 크기**: 프레임 높이의 4–9%, 한두 줄. 조용한 줄은 2.5–4%, 핵심 단어는 너비의 60–90%를 채운다. 강조 색으로 단어 하나를 강조하며, 그 색은 의미를 담는다.
- **리듬**: 속도를 대비시킨다. 몽타주는 0.13–0.8초마다 컷한다. 데모는 UI가 움직이는 동안 한 프레이밍을 7–10초 유지한다. 샷은 평균 1.8–3초이며, 그 안에 움직임이 있다. 페이오프 전에는 0.3–0.75초 멈추고, 페이오프는 정상 속도로 재생한다.
- **잘 작동하는 지속적 움직임**: 제품 UI가 작동하는 모습, 재생되는 푸티지, 연기하는 캐릭터, 돌아가는 3D 세계, 배경 스테이지의 느린 궤도 회전(초당 3–5°).
- **생성된 것처럼 보이는 기본값**: 타이틀과 UI의 움직임을 대신하는 숨쉬기, 떠다니기, 맥박 같은 반복 동작. 자리 잡은 뒤에도 계속 미끄러지거나 커지는 타이틀. 씬 후반의 느린 확대 스케일이나 느린 밀기. UI에 붙는 바운스. 클릭 링. 모든 씬이 같은 방식으로 들어오는 것. 모든 요소가 페이드되고 위로 슬라이드하는 것. 캐릭터의 대기 동작과 오버슈트는 연기이며, 이 항목에 해당하지 않는다(`types/character.md`).

## 이유가 있는 전환

한 영상에는 3–5가지 종류의 전환만 쓴다. 각 전환은 화면의 무언가가 일으켜야 한다. 하드 컷은 씬 안에서(푸시인) 쓴다. 이음새 중 하드 컷은 최대 3분의 1이다. 세계끼리는 크로스페이드하지 않는다. 공식 필름에서 측정한 값은 다음과 같다.

| 전환                     | 만드는 방법                                                                                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 버튼을 통과하는 줌       | 카메라가 블러(0.6초)와 함께 버튼으로 이동한다. 그다음 버튼이 0.35초 동안 프레임의 약 8%에서 약 250%까지 커진다. 강한 ease-in. 버튼의 채움이 다음 프레임이 된다                              |
| 오브젝트가 세계가 된다   | 알약 모양이나 카드가 0.65초 동안 프레임 밖으로 커진다. ease-in-out이며, 모서리 반경은 줄어든다. 주변은 약 15 px 블러되고 0.3초 동안 페이드된다. 새 콘텐츠는 여전히 커지는 동안 페이드인한다 |
| 모프                     | 하나의 컨테이너가 다음 것으로 넓어진다(아이콘 카드 → 프롬프트 상자, 약 110 → 약 880 px, 0.2초 `power3.out`), 가로 블러 12 → 0과 함께                                                       |
| 넘겨 가져가기            | 결과물이 1 → 0.6으로 줄어든다. 블러는 이동 중간에 6 px까지 올라간다. 다음 앱 안에 들어가서 그 안에서 만들어지며 자리를 잡는다                                                               |
| 색상 플러드              | 주인공 오브젝트는 그대로 두고, 전체 바닥의 색이 약 0.4초 동안 `power2.inOut`으로 바뀐다                                                                                                       |
| 휩                       | 가로 또는 세로로 0.13–0.3초 동안 번지는 잔상. 들어오는 요소는 블러된 채 착지하고, 약 0.13초 만에 선명해진다                                                                                    |
| 클릭에서 열리는 아이리스 | `clip-path: circle()`이 클릭한 지점에서 열리며 0.15초 만에 다음 세계로 넘어간다                                                                                                                 |
| 딥 컷                    | 나가는 프레임이 3프레임 동안 약 40% 어두워진 뒤 하드 컷한다. 그래서 컷이 의도된 것으로 읽힌다                                                                                                   |
| 한 무대 위의 블러 교체   | 나가는 쪽: 불투명도 → 0, 약 8 px 블러, 0.13–0.2초. 들어오는 쪽: 블러 → 0, 0.13초. 바닥은 절대 끊기지 않는다                                                                                     |

레지스트리 버전: `npx hyperframes catalog --tag transition --json`.

| 사용자의 말              | 바꿀 것                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------ |
| "too fast"               | 모든 줌과 팬을 원래 속도의 0.7배로 늦춘다. 그 밖은 건드리지 않는다                  |
| "speed this up"          | 콘텐츠를 빠르게 하고, 같은 양만큼 비트를 짧게 한다. 뒤의 비트는 앞당겨진다           |
| "the titles move"        | 타이틀을 착지시킨 뒤, 떠날 때까지 완전히 정지시킨다                                  |
| "it feels like slides"   | 다음 씬은 화면의 오브젝트를 통해 들어온다. 움직임을 비행 중에 끊는다                  |

## 올바른 메커니즘

| 요청                                      | 메커니즘                                                                                                                       |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 푸시인, 줌, 팬, 켄 번스, 리프레이밍        | 클립 안의 래퍼에 `scale`과 `x`/`y`를 트윈한다. 시간이 있는 미디어 요소에는 주지 않는다. 상태들을 한 타임라인에 체인으로 잇는다 |
| 크롭이나 마스크 공개                      | 내부 래퍼에 `clip-path`나 마스크를 트윈한다. 원본 시간은 건드리지 않는다                                                         |
| 일정한 속도 변화                          | 미디어에 `data-playback-rate`를 준다. 0.1–10. 화면과 소리 모두 피치가 보존된다                                                  |
| 속도 램프                                 | 미디어에 `data-automation`의 `rate` 레인을 준다(`t`는 클립 안의 초, `v`는 0.1–10). 일정한 속도보다 우선한다                       |
| 홀드나 프리즈                             | 마지막 프레임이나 끝난 씬을 홀드한다. 원본 중간을 프리즈하려면 먼저 정지 이미지를 내보내고, 그것을 독립된 클립으로 배치한다       |

이미 만들어진 움직임: `npx hyperframes catalog --tag camera --json`, 또는 `catalog --query "<the move>" --tag motion-primitive --json`.

## 움직임 보기

영상 전체에 대한 검토(비트 시트, 컷, 휴대폰 너비, 크래프트 경고)는 `review.md`에 있다. 한 가지 움직임만 확인하려면:

- `npx hyperframes keyframes --json [--selector '#id'] [--runtime all]`은 키프레임과 모션 경로(GSAP, CSS, anime.js)를 나열한다: 속성, 시간, 값, 이즈.
- `npx hyperframes keyframes --shot motion.png --selector '#id'`는 실제 요소의 샘플을 시간에 따라 그리고, 그 경로를 함께 보여 준다(9개 샘플. `--samples N`). 제자리 움직임은 `--layout strip`, 한 구간만 보려면 `--from`/`--to`, 3D는 `--angle iso|top|side|'yaw,pitch'`, `<canvas>`는 `--ghost`.
- `npx hyperframes snapshot --range 2,4 --frames 8`은 한 구간을 샘플링한다. `--composition <id>`는 씬 하나를 샘플링한다. `--at <t,…>`은 정확한 시점. `--zoom '#id'`는 선명한 확대 크롭. `--angle iso`는 깊이와 겹침을 보여 준다.
- 레퍼런스 영상과 비교하려면: `snapshot --at <t,…> --against ref.mp4`는 나란히 놓인 시트를 쓴다.
- 눈으로 대충 보지 말고 의도를 단언한다. 컴포지션 옆에 `<name>.motion.json`을 두면 `check`가 seek된 타임라인에서 이를 검증한다. 실패는 오류로 나온다(`motion_appears_late`, `motion_out_of_order`, `motion_off_frame`, `motion_frozen`):

```json
{
  "assertions": [
    { "kind": "appearsBy", "selector": "#headline", "bySec": 0.5 },
    { "kind": "before", "a": "#headline", "b": "#cta" },
    { "kind": "staysInFrame", "selector": ".card" },
    { "kind": "keepsMoving", "withinSelector": ".scene" }
  ]
}
```

## 흔한 문제

| 증상                              | 흔한 원인                                                                                                                                       |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 빈 화면이나 정지된 씬             | 비동기 빌드가 끝나기 전에 타임라인이 등록되었거나, `.clip`에서 `visibility`를 트윈했거나, 호스트 id가 씬의 타임라인 키와 다르다                |
| 렌더링마다 끊기거나 어긋남         | `onUpdate`, `requestAnimationFrame`, 또는 clock time에서 레이아웃을 잰다. 한 속성에 타임라인이 두 개 있다                                         |
| 컷에서 튐                         | 나가는 상태와 들어오는 상태가 이음새에서 다르다. 컷 직전과 직후를 스냅샷으로 찍어 본다                                                         |
| 핸드오프에서 이즈가 어색함         | 이음새에서 속도가 맞지 않는다. 이즈를 거울처럼 맞춘다(나갈 때 `power3.in`, 들어올 때 `power3.out`)                                              |

Studio의 키프레임 다이아몬드와 모션 경로 핸들은 컴포지션 파일의 GSAP 스크립트를 다시 쓴다. 그러므로 사용자가 당신이 쓴 뒤로 움직임을 바꾸었을 수 있다.
