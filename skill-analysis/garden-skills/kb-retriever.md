# kb-retriever 분석

## 1. 개요

- **원본 경로**: `skills-collections/garden-skills/kb-retriever/`
- **핵심 파일**: `SKILL.md` (13,984 bytes)
- **보조 파일**:
  - `references/pdf_reading.md` — PDF 텍스트/표/메타데이터 추출 방법 (빠른 결정표 + 도구 우선순위)
  - `references/excel_reading.md` — pandas Excel 읽기 방법
  - `references/excel_analysis.md` — Excel 데이터 분석 방법
  - `scripts/convert_pdf_to_images.py` — PDF → 이미지 변환 (스캔 PDF/OCR 경로)
  - `manifest.json`, `README.md`, `README.zh-CN.md`
- **성격**: **로컬 지식베이스 디렉토리 검색·질의응답 스킬**. 디자인 스킬이 아니며, 이 컬렉션에서 유일하게 시각 산출물이 없다. 핵심 가치는 **컨텍스트 절약형 점진 검색** — 큰 파일을 통째로 읽지 않는 것.

원문 자기 규정: "按文件类型组合使用 grep、Read、pdfplumber、pandas 进行渐进式检索，**避免整文件加载**"

## 2. 활성화 조건 (언제 켜지는가)

frontmatter `description` 원문 (중국어, 전문):

> "面向本地知识库目录的检索和问答助手。核心流程：(1)分层索引导航 (2)遇到PDF/Excel时必须先读取references学习处理方法 (3)处理文件后再检索。按文件类型组合使用 grep、Read、pdfplumber、pandas 进行渐进式检索，避免整文件加载。用户问题涉及\"从知识库目录回答问题/检索信息/查资料\"时使用。"

**매칭되는 사용자 발화** (description이 트리거 문구를 직접 지정)
- "知识库에서 답 찾아줘" — `从知识库目录回答问题`
- "정보 검색해줘" — `检索信息`
- "자료 찾아줘" — `查资料`
- "우리 knowledge/ 폴더에서 2023 Q1 매출 찾아줘"
- "내 지식베이스는 /data/kb에 있어" (경로 지정형)

**특이점**: description이 **핵심 흐름 3단계를 트리거 문구 앞에 배치**한다. 즉 활성화 조건과 함께 필수 절차를 미리 각인시키는 구조.

`allowed-tools` / `metadata`: **원문에 명시 없음.** 다만 본문이 사용할 도구(Grep, Read, Glob, shell)와 **금지할 도구 사용법**을 구체적으로 지정한다.

## 3. 적합한 상황 / 부적합한 상황

**적합**
- 로컬에 다층 디렉토리로 정리된 지식베이스가 있고, `data_structure.md` 인덱스 관례를 따를 때
- **큰 PDF·Excel이 섞인 자료 검색** — 통째로 읽으면 토큰이 폭발하는 상황
- 출처 추적이 필요한 답변 — 원문이 "来源：design/api_gateway.md 第 100 行附近" 형태의 출처 표기를 요구
- 사내 문서·보고서·설계문서에 대한 반복 질의

**부적합 / 과한 상황**
- `data_structure.md` 인덱스가 없는 디렉토리 — 스킬의 2단계(계층 인덱스 탐색)가 성립하지 않음. 이 경우의 폴백은 **원문에 명시 없음**
- 웹 검색이 필요한 질문 — 명시적 금지: "**使用本 Skill 查询知识库时，禁止使用网络搜索等其他工具获取知识**"
- 작은 파일 몇 개뿐인 경우 — grep 한 번으로 끝나는 일에 5단계 워크플로우가 과함
- 스캔된 이미지 PDF — OCR 경로가 있으나 "无其他选择"로 최후 수단 취급

**형제 스킬 대신 이걸 고르는 기준**: 이 컬렉션에서 유일한 **입력측(검색·추출) 스킬**이다. 나머지 4개는 출력측(기사·이미지·웹·영상). 실질적으로 `beautiful-article`의 Phase 1(소스 → Markdown) 앞단계나, 자료 조사 단계에서 조합해 쓰는 성격 — 다만 **상호 참조는 원문에 없다**.

## 4. 외부 의존성

- **API 키**: **불필요.** 환경변수 참조 없음.
- **폴백 모드**
  - PDF 도구 우선순위 자체가 폴백 체인: pdftotext → pdfplumber → pypdf → OCR
  - 지식베이스 루트가 없을 때: "**不要猜测其他目录，明确告诉用户未找到默认根目录，并让用户指定实际知识库路径**"
  - 5회 검색 실패 시: "明确告知用户信息缺失或可能不在当前知识库中"
- **필요한 CLI/런타임/패키지**
  - **shell** — `test -d knowledge` (디렉토리 존재 확인)
  - **`pdftotext`** (poppler-utils) — PDF 텍스트 추출 1순위
  - **Python 3** + **`pdfplumber`** (표 추출), **`pypdf`** (메타데이터), **`pandas`** (Excel), **`pytesseract`** (OCR, 스캔 PDF)
  - Excel 읽기에 pandas + (암시적으로) openpyxl
  - `scripts/convert_pdf_to_images.py` 실행 환경
- **네트워크**: **불필요** — 오히려 금지됨 ("禁止使用网络搜索")
- **비용 발생 지점**: 유료 API 없음. 비용은 **토큰**이며, 스킬 전체가 그 절감을 목표로 설계됨.

## 5. 워크플로우

### 지식베이스 관례 (전제)
- 다층 디렉토리, 각 층에 **`data_structure.md`** 인덱스 파일
  - 루트: "说明主要的「领域目录」及其用途"
  - 각 영역 디렉토리: "说明该目录下有哪些子目录/文件，以及各自用途"
  - 더 깊은 하위 디렉토리도 계속 가능 → "形成多级索引树"
- 루트 기본값: **`knowledge/`** (현재 프로젝트 루트 하위)

### 루트 디렉토리 확정 — **게이트**
1. 사용자가 경로를 주면 그것을 사용 ("根目录优先听用户")
2. 아니면 `knowledge/`를 시도. **확인 방법이 강제됨**: "优先使用 `test -d knowledge`，或退而求其次使用 `ls -d knowledge`"
3. **금지**: "禁止使用 `Glob \"knowledge\" in .` 这类模式来判断目录是否存在，`Glob` 只返回文件路径，不返回目录本身，**空结果并不能区分'目录不存在'和'目录存在但为空'**"
4. 존재 확인 후에야 Glob 사용 — 예: `pattern="**/data_structure.md", path="knowledge"`
5. 없으면 **추측 금지**, 사용자에게 확인 요구

### 핵심 원칙: 先学习，再处理 (먼저 배우고, 그 다음 처리) — **강제 체크리스트**
PDF 또는 Excel을 만났을 때 (원문 그대로):
```
- [ ] ✅ 已读取对应的 references 文档学习处理方法
- [ ] ✅ 已理解推荐的工具和命令
- [ ] ✅ 已将文件处理（提取/转换）完成
- [ ] ⏭️ 现在可以开始检索
```
**禁止行为** (원문):
```
❌ 在未读取 pdf_reading.md 的情况下直接尝试处理 PDF
❌ 在未读取 excel_reading.md 的情况下直接尝试处理 Excel
❌ 跳过文件处理步骤，直接对原始 PDF/Excel 进行检索
```

### 총 흐름 6단계

**1. 사용자 요구 이해**
추출 항목: 主题/领域关键词 / 时间或范围限定 / 需要的输出类型. 그리고 지식베이스 루트 확정.

**2. 계층 인덱스 탐색 (`data_structure.md`)**
- "当前工作目录" 개념을 유지
- 현재 디렉토리에 `data_structure.md`가 있으면 **부분 읽기** ("读取该文件的前若干行（例如 limit=300），必要时分段继续读取")
- 목표: 하위 디렉토리·파일 목록과 각각의 용도 파악
- 문제와 **가장 관련 있는 몇 개**를 후보 집합으로
- 후보 디렉토리는 재귀 진입. **분기 제한**: "**避免一次性深入所有分支，优先沿着与问题最相关的路径向下钻取**"
- 우선순위 규칙:
  1. "用途说明与问题主题高度匹配的领域目录和文件"
  2. 시간/버전 제약 (인덱스에 있으면)
  3. "通用说明类文档（如 README.md、总体设计类文档）**放在较后优先级**"

**3. 파일 처리 방법 학습 (PDF/Excel 시 강제)**
- PDF 전: `references/pdf_reading.md` **필독**. 중점 — "pdftotext 命令、pdfplumber 用法、表格提取方法"
- Excel 전: `references/excel_reading.md` + `references/excel_analysis.md` **둘 다 필독**. 중점 — "pandas 读取、列筛选、数据过滤"
- 경로 주의가 반복 명시됨: "注意这个目录位于 Skills 目录下，而不是 Knowledge 目录下"
- 목적: "确保使用正确的工具和方法，避免盲目检索"

**4. 파일 타입별 처리·검색 실행** (아래 3개 전략)
총원칙: "优先从最相关、最精确的文件开始 / 每个文件内都渐进式地局部检索，避免一次性加载全内容 / 若当前文件得不到满意信息，切换到下一个候选文件"

**5. 반복 검색** — 통일된 「多轮迭代检索机制」

**6. 답변 조직과 출처 추적 (溯源)**
- 명확하고 직접적인 답변
- "指出使用过的文件名（必要时包含大致位置，如章节或大概行数/页数）"
- 추론 기반이거나 정보가 불완전하면: "**明确标注假设与不确定性**" + 범위를 좁힐 방법 안내

### 파일 타입별 전략

**① Markdown / 텍스트 (.md, .txt, .log)**
1. `data_structure.md` + 파일명·경로로 관련도 판단. "优先检索标题和目录类文件"
2. Grep으로 위치 특정 → **부분 읽기**: "通过行号偏移和 limit 控制读取（例如从匹配行附近往前后各读取几十行）/ **避免整文件读取**"
3. 특수 처리: 내용이 목차/제목뿐이면 링크나 절 이름으로 계속 심화

**② PDF**
1. **먼저 `pdf_reading.md` 필독**
2. 후보 선정: "选择最相关的 **1-3 个**文件"
3. 학습한 방법으로 추출. **핵심 규칙**: "使用 `pdftotext input.pdf output.txt` 将文本提取到文件，**不要直接输出到 stdout（避免占用大量 token）**"
4. 추출 결과에 grep → 히트 주변 컨텍스트 ("上下数十行或相邻几页") → "保存「文件名 + 页码/大致位置 + 文本片段」"

**③ Excel**
1. **먼저 `excel_reading.md` + `excel_analysis.md` 둘 다 필독**
2. 후보 선정: "优先选择包含「报表」「统计」「日志」「配置」「映射」等关键词的工作簿/工作表"
3. 구조 탐색: "使用 pandas 读取前 **10-50 行**（使用 `nrows` 参数限制）". 중점 — 열 이름/필드명, 데이터 타입, 핵심 필드. "将列名与用户问题比对，识别潜在关键字段（如「收入」「销售额」「error_code」等）"
4. 데이터 검색·분석: `df[df['column'] == value]` 형태 필터·집계. "每次只读取匹配行附近的数据，避免一次性读取整表". 시간 범위가 있으면 시간 필터 추가

### 공통 검색 원칙

**키워드 선택**
- "从用户问题提取 **3-8 个**关键词（含可能的英文缩写、同义词、上位/下位词）"
- 조합 가능: "销售 报表", "API 接口 超时"
- 업무어·기술용어·약어 포함 (예: "uv", "pv", "GMV")

**grep 기본 원칙**
- "**始终指定尽量精准的 include 和 path，避免搜索整个目录**"
- 패턴은 핵심 명사·용어 먼저, 그 다음 동의어
- "对于每个命中，**只读取匹配附近的局部区域**（上下若干行）"
- "保存「文件名 + 位置信息 + 文本片段」"

**多轮迭代检索机制 (최대 5회)** — 모든 파일 타입 공통
1. **반복 제어**: "维护「已尝试检索次数」计数，**最多 5 次**"
2. **매 라운드 흐름**: 키워드 생성/갱신 → 아직 충분히 검색되지 않은 파일/부분 선택 → 검색 실행 → 컨텍스트 분석 → 충분한지 판단
3. **종료 조건**: 충분한 컨텍스트 확보 / 5회 도달
4. **정보 부족 시**: 결핍 사실 명시 + 가장 가까운 정보 제공 + 불확실성 설명 + 범위 축소 방법 제시

**도구 사용 원칙**
- **Grep**: "按关键词在指定文件中查找行号与匹配片段，始终指定尽量精准的 include 和 path"
- **Read**: "**只用于局部读取文件**，始终设置合理的 limit（如 **200-500 行**）和合适的偏移"
- 큰 파일: "**禁止直接从头读到尾** / 始终先通过索引、目录、关键词等方式缩小范围后再读"

**사용자 확인 요구 지점**: 지식베이스 루트를 찾지 못했을 때 (강제 정지 + 사용자 지정 요구). 그 외 강제 Checkpoint는 없음.

## 6. 디자인 지침 분석

**이 스킬은 미적 지침을 전혀 담지 않는다.** 디자인 컬렉션 내에서 유일하게 시각 산출물이 없는 스킬이다. 다만 "지침을 강제하는 방식"에는 이 컬렉션 공통의 패턴이 있으므로 그 관점에서 분석한다.

### 금지 규칙 (anti-pattern) — 원문 그대로

- "**不要直接用 Read 读取整文件**"
- "**禁止使用 `Glob \"knowledge\" in .` 这类模式来判断目录是否存在**" — 근거까지 명시: "空结果并不能区分'目录不存在'和'目录存在但为空'"
- "**禁止第一次就直接调用：`Glob \"knowledge\" in .` 或任何试图用 Glob 判定目录存在性的调用**"
- "如果默认 `knowledge/` 不存在（`test -d` 失败）：**不要猜测其他目录**"
- "❌ 在未读取 pdf_reading.md 的情况下直接尝试处理 PDF"
- "❌ 在未读取 excel_reading.md 的情况下直接尝试处理 Excel"
- "❌ 跳过文件处理步骤，直接对原始 PDF/Excel 进行检索"
- "**避免一次性深入所有分支**"
- "**避免整文件读取**"
- "**不要直接输出到 stdout（避免占用大量 token）**" (pdftotext)
- "**避免搜索整个目录**" (grep)
- "**避免一次性读取整表**" (Excel)
- "**禁止直接从头读到尾**" (큰 파일)
- "**禁止使用网络搜索等其他工具获取知识**"
- "**不臆造事实**"
- `pdf_reading.md`: "**不要在未阅读本文档的情况下盲目尝试处理 PDF**" / "❌ 错误：不要使用 stdout（会占用大量 token）"

### 강제 규칙 — 수치 인용

| 항목 | 수치 |
| --- | --- |
| 반복 검색 최대 횟수 | **5 次** |
| 키워드 추출 개수 | **3-8 个** |
| `data_structure.md` 읽기 | 예 **limit=300** |
| Read 일반 limit | **200-500 行** |
| PDF 후보 파일 수 | **1-3 个** |
| Excel 구조 탐색 행 수 | 전 **10-50 行** (`nrows`) |
| grep 히트 주변 읽기 | "上下若干行" / "上下数十行或相邻几页" (정확한 수치는 원문에 없음) |

**PDF 도구 우선순위** (`pdf_reading.md`, 원문):
1. **pdftotext 命令行工具**（最快，适合大多数 PDF）
2. pdfplumber（适合需要保留布局或提取表格）
3. pypdf（轻量级，适合简单提取）
4. OCR（仅用于扫描PDF或无法直接提取文本的情况）

**PDF 빠른 결정표** (`pdf_reading.md`, 원문):

| 场景 | 推荐工具 | 原因 | 命令/代码示例 |
|------|----------|------|--------------|
| 纯文本提取（最常见） | pdftotext 命令 | 最快最简单 | `pdftotext input.pdf output.txt` |
| 需要保留布局 | pdftotext -layout | 保持原始排版 | `pdftotext -layout input.pdf output.txt` |
| 需要提取表格 | pdfplumber | 表格识别能力强 | `page.extract_tables()` |
| 需要元数据 | pypdf | 轻量级 | `reader.metadata` |
| 扫描PDF（图片） | OCR (pytesseract) | 无其他选择 | 先转图片再OCR |

### 지침을 주는 방식 자체

1. **강제 체크리스트 (checkbox 형식)**: PDF/Excel 처리 전에 4개 체크박스를 통과. 마지막 항목이 `⏭️ 现在可以开始检索`로 게이트임을 표시. **참조 문서 읽기를 절차적으로 강제**하는 방식이 이 스킬의 고유 장치.
2. **`❌ 禁止行为` 목록**: 금지를 별도 섹션으로 분리하고 이모지로 시각적 강조.
3. **오도구 사용을 이름 단위로 금지 + 근거 제시**: `Glob "knowledge" in .`을 명시적으로 지목하고 "왜 안 되는가"(빈 결과의 모호성)를 설명. 도구의 의미론적 함정을 지침에 박아넣은 사례.
4. **점진적 축소 (progressive narrowing)를 관통 원칙으로**: 인덱스 → 후보 → grep → 국소 읽기. 모든 파일 타입 전략이 같은 형태를 반복.
5. **반복 횟수 상한 + 종료 조건**: 5회 + 명시적 종료 조건 + 실패 시 처리. 무한 탐색을 구조적으로 차단.
6. **빠른 결정표 (快速决策表)**: 상황 → 도구 → 이유 → 명령 4열. `emilkowalski`의 "Need → Tool" 테이블과 동형.
7. **우선순위 체인**: PDF 도구 4단, 인덱스 우선순위 3단. "가장 싼 것부터"의 변형.
8. **토큰 비용을 지침의 근거로 명시**: "避免占用大量 token"이 반복 등장. 성능·비용을 규칙의 이유로 쓰는 방식.
9. **참조 문서 경로 혼동 방지 반복**: "注意这个目录位于 Skills 目录下，而不是 Knowledge 目录下"가 5회 이상 반복. 실제 오작동 경험이 반영된 흔적.
10. **참조 문서 자체에 읽기 경고 삽입**: `pdf_reading.md`·`excel_reading.md` 첫머리에 "⚠️ 使用本文档前请注意：本文档应在实际处理…之前完整阅读". 즉 게이트가 SKILL.md와 reference 양쪽에 이중으로 박혀 있음.
11. **페르소나 부여 없음**, **실물 참조 없음**, **체크리스트 외 검증 장치 없음**.

## 8. 주의점 / 한계

- **`data_structure.md` 관례에 강하게 의존**: 지식베이스가 이 인덱스 파일 관례를 따르지 않으면 워크플로우 2단계가 무력화된다. 그 경우의 대안(파일명·디렉토리명만으로 탐색, 전역 grep 등)은 **원문에 명시 없음.** 인덱스 파일을 생성해주는 기능도 없다.
- **인덱스의 정확성이 검색 품질을 결정**: `data_structure.md`의 용도 설명이 낡거나 부정확하면 후보 선정이 틀리고, 그 사실을 스킬이 감지할 수단이 없다. 원문에 경고 없음.
- **5회 상한의 양면**: 무한 탐색을 막지만, 큰 지식베이스에서 5회로 부족할 수 있다. 상한 조정 방법은 **원문에 명시 없음.**
- **"충분한가" 판단의 주관성**: 반복 종료 조건이 "找到足够支撑回答的上下文"이며 조작적 정의가 없다. 조기 종료(정보 부족한데 답변)와 과잉 탐색 양쪽으로 흐를 수 있음.
- **네트워크 금지의 부작용**: "禁止使用网络搜索等其他工具获取知识"는 지식베이스 답변의 순수성을 보장하지만, 지식베이스에 없는 것을 알아내야 하는 복합 질문에서는 마찰이 된다. 사용자가 명시적으로 웹 검색을 원할 때의 처리는 **원문에 명시 없음.**
- **외부 CLI/패키지 전제**: `pdftotext`, `pdfplumber`, `pypdf`, `pandas`, `pytesseract`가 없으면 해당 경로가 막힌다. 설치 안내나 사전 확인 절차는 **원문에 명시 없음** (도구 우선순위가 사실상 폴백 체인이지만, 4개 다 없는 경우는 다루지 않음).
- **스캔 PDF의 품질**: OCR은 "无其他选择"로만 언급되고, OCR 정확도 검증이나 실패 처리는 원문에 없음. `scripts/convert_pdf_to_images.py`가 그 경로를 지원하나 SKILL.md 본문에서는 이 스크립트를 언급하지 않는다 — **문서와 스크립트의 연결이 누락**된 지점.
