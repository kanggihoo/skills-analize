# define-goal 분석

## 원본

- 원본 경로: `.agents/skills/define-goal/`
- 핵심 파일: `SKILL.md`
- 보조 파일: `agents/openai.yaml`, `LICENSE.txt`
- 확인한 규모: 3개 파일, 약 307줄
- 성격: 사용자의 의도를 검증 가능한 목표 문장으로 정제하고 goal tool 사용 여부를 판단하는 프로세스 스킬

## 적용 조건

이 스킬은 사용자가 목표를 만들거나, goal tool을 사용하거나, 모호한 의도를 측정 가능한 목표로 바꾸고 싶다고 할 때 동작한다.

대표 요청은 다음과 같다.

- 목표를 만들어줘
- goal tool 써줘
- 이 작업의 성공 기준을 정리해줘
- 이 의도를 구체적인 objective로 바꿔줘
- `$define-goal` 사용

반대로 사용자가 평범한 구현, 수정, 배포, 분석 작업을 요청한 경우에는 이 스킬로 goal 생성을 강요하지 않는다. 그 경우에는 바로 작업을 수행하는 것이 규칙이다.

## 동작 과정

1. goal 정의가 정말 필요한 요청인지 확인한다.
   사용자가 단순히 일을 시킨 것인지, 아니면 목표 생성 자체를 요청한 것인지 구분한다.

2. 사용자의 의도를 구체적인 결과 상태로 다시 쓴다.
   좋은 goal은 “무엇을 한다”가 아니라 “완료 시 무엇이 참인가”를 말해야 한다.

3. 검증 근거를 goal 안에 포함한다.
   테스트 명령, 파일 경로, 산출물 개수, 리뷰 상태, 성능 수치, 수동 확인 기준처럼 completion evidence가 필요하다.

4. 정량화 가능한 경우 수치로 만든다.
   예를 들어 latency, error rate, coverage, bundle size, 성공 횟수, 처리한 이슈 수 등을 사용한다.

5. 약한 목표를 보정한다.
   “개선하기”, “조사하기”, “진행하기” 같은 활동형 목표는 검증 가능한 완료 조건으로 바꾼다.

6. 필요한 경우 하나의 짧은 clarification question만 한다.
   누락된 정보가 목표나 검증 기준을 바꿀 때만 질문한다.

7. active goal 상태를 확인한다.
   `get_goal`을 호출해서 기존 goal이 있는지 확인한다.

8. 기존 goal이 없고 목표 품질 기준을 만족하면 `create_goal`을 호출한다.
   active goal이 이미 같은 의도를 다루면 중복 생성하지 않고 이어서 수행한다.

9. active goal이 새 요청과 충돌하면 사용자에게 현재 goal을 끝낼지, 별도 goal을 시작할지 확인한다.

## 핵심 규칙

- 이 스킬은 goal 정의와 goal tool 생성에만 사용한다.
- 일반 구현 작업에 대해 불필요하게 goal 생성을 요구하지 않는다.
- `create_goal` 전에 반드시 `get_goal`로 현재 상태를 확인한다.
- token budget은 사용자가 명시적으로 요청했을 때만 goal에 넣는다.
- 목표에는 완료 증거가 들어가야 한다.
- 모호한 목표는 “측정 가능한 결과”로 고쳐야 한다.
- 순수 활동 목표는 거절하거나 검증 가능한 objective로 바꿔야 한다.

## 좋은 목표의 구성 요소

`SKILL.md`가 요구하는 usable goal은 다음 정보를 포함한다.

- 완료 시 참이 될 구체적 결과
- 주요 artifact, 시스템, 저장소, 환경 또는 사용자 행동
- 완료를 증명할 검증 방법
- 범위 안에 포함되는 것
- 모호성이 문제 될 때 범위 밖에 있는 것
- 계속 진행하지 않고 사용자에게 물어야 하는 중단 조건

## 산출물 특성

이 스킬의 산출물은 코드나 문서 파일이 아니라 보통 다음 중 하나다.

- 구체화된 objective 문장
- `create_goal`로 생성된 active goal
- 기존 active goal을 계속 사용한다는 판단
- goal 충돌 시 사용자에게 묻는 짧은 질문

## 주의점

- “작업 계획 문서”, “스냅샷”, “결정 로그”, “resume 파일”은 이 스킬의 책임이 아니다.
- 사용자가 직접 goal-backed work를 요청하지 않았다면 일반 multi-step 작업에 `create_goal`을 남용하지 않는다.
- 연구성 작업이라도 “어떤 결정을 가능하게 할 것인지”, “어떤 evidence standard를 쓸 것인지”를 명시해야 한다.
- `agents/openai.yaml`은 UI 표시명과 기본 prompt를 제공할 뿐이며, 목표 품질 기준은 `SKILL.md`가 정의한다.
