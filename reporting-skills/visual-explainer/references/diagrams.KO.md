# 손으로 그린 SVG 피규어

인라인 SVG가 기본 피규어입니다. 정확한 배치, 페이지 토큰과 폰트, 모션을 제어할 수 있습니다. 킷(`kit.md`)이 여기 나온 모든 패턴의 스타일을 지정하고 실행합니다. 이 파일은 마크업 계약과 규칙을 설명합니다.

## 격자 위에 계획하기

```
x:  40        280        520        760      열 간격 240
    ┌──────┐  GET /u   ┌──────┐  miss   ┌──────┐
y:90│Client│──────────►│ API  │────────►│  DB  │
    └──────┘           └──┬───┘         └──────┘
                     hit  │ reads
y:210                  ┌──▼───┐
                       │Cache │
                       └──────┘
```

- 먼저 ASCII로 스케치한 뒤, 열과 행을 좌표로 바꾸세요. viewBox 너비를 720–1000으로 두면 `14` 단위가 대략 14px가 됩니다.
- 상자 사이는 최소 40 단위를 두세요. 직교 엣지(`M x y H x V y`)를 쓰세요. 라벨은 선 위 9 단위에 두세요.
- SVG 텍스트는 줄바꿈되지 않습니다. 한 줄은 약 18자로 제한하고, 두 번째 줄은 `<tspan x=".." dy="1.2em">`을 쓰세요.
- 경계(프로세스, 네트워크, 신뢰 영역)는 점선 사각형에 왼쪽 위 모서리의 고정폭 라벨을 붙이세요.
- 노드가 약 12개를 넘으면 5–8개 노드짜리 개요도를 그리고, 세부 내용은 카드나 두 번째 피규어에 넣으세요.
- 시퀀스: 액터마다 열 하나에 얇은 생명선을 두고, 시간은 아래로 흐르게 하며, 각 화살표에 호출 내용을 라벨로 붙이세요. 스키마: 테이블마다 상자 하나에 주요 필드를 고정폭으로 적고, 다대일 끝에는 까마귀발 표기를 쓰세요.

## 형태

- **형태는 사물이 무엇인지 말해야 합니다.** 서비스는 사각형. 데이터 저장소는 원통형(`path.sh` + `ellipse.sh.lid`). 큐는 짧은 구분선 3개가 있는 사각형. 선택적이거나 비활성인 것은 점선 사각형.
- **글리프**(`.gl`): 이름만으로 종류를 알 수 없을 때만, 노드 왼쪽 위 모서리에 16 단위 선화를 넣으세요. 이모지는 절대 쓰지 마세요.
- **엣지:** 실선 = 동기 호출 · 점선 = 비동기 또는 선택적 · 굵고 빛나는 강조색 = 이 피규어가 다루는 경로 · 빨간 ✕ = 차단됨.

## 치수

구간을 재는 수치는 그 구간 위에 놓으세요. 시퀀스의 시간축에 있는 지연 시간, 타임라인의 TTL 윈도우, 바이트 레이아웃의 필드 크기 등이 해당합니다.

```
   ┼                       ┼    측정 지점 두 곳에서 뻗는 보조선
   │◄─────── 9 ms ────────►│    치수선, 값은 중간의 빈틈에
```

```html
<g class="ve-dim"><path class="ext" d="M120 300V322M380 300V322"/><path class="ln" d="M120 316H380M116 320l8-8M376 320l8-8"/><text x="250" y="310">9 ms</text></g>
```

- 양 끝에 짧은 45° 틱을 넣으세요. 값은 선 위 6 단위 가운데에 두고, 선 위에 겹치지 마세요.
- 치수선은 도형 옆의 레일에 놓되, 가장 짧은 것을 가장 가까이 두세요. 합산되는 구간(`1 ms` 다음 `9 ms`)은 한 레일에 이어 쓰고, 합계는 그 바깥쪽 다음 레일에 두세요.
- 주장을 담은 치수는 강조(`.is-key`)를 받으며, 피규어마다 하나만 둡니다.

## 흐름 점

트래픽이나 데이터가 움직일 때, 움직이는 점으로 주요 피규어에서 방향과 양을 보여주세요. 생성 간격의 비율이 실제 분배 비율이어야 합니다.

```html
<path data-flow="hit"  data-every="420"  d="M95 105H375V80H695V105H375"/>   <!-- 보이지 않는 경로 -->
<path data-flow="miss" data-every="7000" d="M95 105H355V270H395V130H695"/>  <!-- 420:7000 ≈ 94:6 -->
<g class="ve-dots" aria-hidden="true"></g>                                   <!-- 엣지 뒤, 노드 앞 -->
```

경로는 노드 중심을 지나가므로, 점은 한 상자에 들어가서 다음 상자로 나옵니다. 페이지당 움직이는 레이어는 하나만 두세요.

## 연결된 강조

같은 `data-ref`를 공유하는 요소는 함께 빛납니다. 산문의 용어, 노드, 엣지, 카드, 버튼 모두 해당합니다. 산문 용어에는 `tabindex="0"`을 주세요. 하나의 요소가 여러 ref를 가질 수 있습니다(`data-ref="hit miss"`). 피규어마다 명사 전부가 아니라 핵심 용어 2–4개만 연결하세요.

## 단계 진행과 장면 플레이어

각 단계에서 해당 부분을 한 줄짜리 캡션과 함께 앞으로 가져옵니다. 재생과 탐색 막대를 추가하면 장면 플레이어가 됩니다.

```
<figure class="ve-steps">  부분: data-s="N"(N단계에 나타남) · pathLength="1"인 경로는 그려지며 나타남
  .ve-player → ol.ve-cap > li[data-n="1/5"] · button[data-go=-1] · button[data-play] · input[type=range] · button[data-go=1]
```

완성된 그림으로 시작하세요. 장면마다 주장은 하나이며, 단계마다 눈에 띄게 무언가가 바뀌어야 합니다. 자동 재생은 절대 하지 마세요.

**콜아웃.** 번호가 붙은 원과, 가리키는 지점에서 정확히 끝나는 짧은 지시선. 계획 히어로에서도 같은 표시를 씁니다. 콜아웃 N은 N단계입니다. 원과 지시선에 `data-s="N"`을 주세요. 단계 진행이 없으면 피규어 아래에 한 줄 메모(`③ the miss reads Postgres`)로 나열하세요. 피규어마다 3–6개.

```html
<path class="ann" data-s="3" d="M520 71V96"/><g class="ve-co" data-s="3" transform="translate(520 60)"><circle r="11"/><text>3</text></g>
```

## 재생: 상태와 이벤트

상태 머신, 워크플로, 리듀서의 경우 각 단계가 이벤트 하나입니다. 캡션에는 무슨 일이 일어났는지와 이유를 적으세요: `miss → fetch, because the TTL expired (cache.ts:48)`. "because"는 실제로 작동한 가드나 분기여야 합니다. 인용하고, 절대 지어내지 마세요. 주장 하나를 담은 이벤트 6–12개를 고르고, 다른 분기는 두 번째 단계 진행이나 작은 다중 그림으로 보여주세요. 이벤트가 실제 실행에서 나왔다면 figcaption에 그렇게 밝히세요.

`data-s`에는 여러 단계를 나열할 수 있습니다. 부분은 첫 단계에서 나타나고 각 단계마다 빛납니다. `0`이면 처음부터 그립니다. 전체 머신은 `0`으로 그리고, 실행이 경로를 밝히게 하세요. 어떤 단계에서는 발화된 엣지와 노드 테두리가 빛나고, 토큰은 각각 한 번씩 움직입니다. 경로를 밝히려면 그 경로의 모든 엣지에 해당 단계를 주고, 이어진 `d`를 따라 토큰 하나를 달리게 하세요. 마지막 단계가 완성된 그림입니다.

```html
<path class="ve-e" data-s="0 3 5" d="M730 90H800"/>                                              <!-- 처음부터 그려짐; 3과 5에서 빛남 -->
<g class="ve-co q" data-s="0 3 5" transform="translate(765 68)"><circle r="11"/><text>3</text></g>   <!-- 번호; 3과 5에서 채워짐 -->
<circle class="ve-tok" data-s="6" r="5" style="offset-path: path('M910 150V295H650V150'); --dur: 2200ms"/>   <!-- 경로 -->
<circle class="ve-tok" data-s="1" r="5" style="offset-path: path('M170 90H240'); --d: 130ms"/>   <!-- 연속된 토큰 중 하나 -->
<g class="ve-at job" data-s="3 4" style="--d: 850ms"><rect x="217" y="72" width="26" height="26" rx="4"/><text x="230" y="85">J3</text></g>   <!-- .ve-at은 표시와 숨김을 제어; .job은 직접 그린 빈 슬롯 위의 채우기와 선 -->
<g class="ve-vals"><text class="sub" data-s="0" x="236" y="52">0 / 8</text><text class="sub" data-s="2" x="236" y="52">5 / 8</text></g>
```

- **토큰**은 노드 아래에서 움직이며, 각 상자에 들어갔다가 반대편으로 나옵니다. 슬롯에 들어가거나 나오는 토큰은 노드 뒤에 둡니다. `--dur`는 실행 시간을 늘리고(기본 900 ms), `--d`는 지연을 줍니다. 연속된 토큰은 약 150 ms 간격으로 두세요.
- **나타났다 사라지는 부분**(대기 중인 작업, 바쁜 워커, 현재 상태의 링)은 `.ve-at` 그룹입니다. `data-s`에 나열된 단계에서만 보입니다. 빈 슬롯은 그 아래에 그리세요.
- **변하는 값**(개수, TTL, 상태 이름)은 `.ve-vals` 안의 한 위치에 단계 순서대로 단계마다 텍스트 하나씩 둡니다.
- **공유 자원**(워커 풀, 허가권)은 슬롯과 개수를 담은 점선 경계로 표현하세요.
- **종류 라벨:** 노드 이름 위에 `<text class="ve-kind">`를 두세요: `fact`, `decision`, `state`, `effect` 중 하나. 캡션이 엣지를 가리키면 `.ve-co.q`로 번호를 붙이세요.

## 변경 전 / 후

같은 좌표에 그린 하나의 도면에 토글을 붙이세요(`button[aria-pressed]`가 `figure[data-view]`를 뒤집고, `.only-before` / `.only-after` 그룹을 사용). 추가된 것 = `--ok` 선, 제거된 것 = `--risk` 점선. 정적 버전은 같은 축척으로 나란히 놓인 두 패널입니다.

## 라이브 피규어

그림을 다시 계산하는 컨트롤을 두어, 독자가 설정을 직접 느끼게 하세요. TTL 슬라이더가 적중률, 점 분배, 헤드라인을 함께 움직이게 할 수 있습니다. 정책 토글로 잘못된 규칙이 그럴듯하지만 틀린 숫자를 보여주는 것도 가능합니다.

- 컨트롤은 1–3개(`input[type=range]`, `button[aria-pressed]`)로, 각각 독자가 신경 쓰는 무언가를 바꾸게 하세요.
- 순수 함수 `model(settings)` 하나가 피규어, 숫자, 문장에 모두 값을 공급하게 하세요.
- 기본값은 실제 현재 값으로 두고, 눈금에 표시하세요. 컨트롤은 JS로 삽입하고 인쇄에서는 숨겨서, 인쇄본과 JS가 없는 환경에서도 그 상태가 보이게 하세요.
- 공식은 캡션이나 `<details>`에 보여주고, 단순화된 모델에는 "illustrative"라고 표시하세요. 개념을 모델링하되, 실제 운영 로직을 복사하지 마세요.

## 작은 다중 그림

사례마다 같은 작은 다이어그램을 같은 좌표에 한 번씩 그려, 눈이 차이만 보게 하세요. 바뀌는 부분은 그 사례의 상태 색을 받습니다(`.case[data-st]`; `.is-st`로 표시). 카드마다 상태 칩, 짧은 제목, 미니 다이어그램을 두고, 문장은 넣지 마세요. 미니 라벨은 14 단위 이상이어야 합니다.

## 작은 차트

span을 재지 않는 수치 옆에는 작은 차트를 두세요. "100 중 N"은 `<ve-waffle>`, 2–5개 값은 `<ve-bars>`(중요한 것에 `hot`), 전체에 대한 비율은 `<ve-stack>`(`kit.md`). 추세는 스파크라인으로 표현합니다: `0 0 100 24`, `polyline` 하나, `vector-effect: non-scaling-stroke`, 그리고 값을 담은 `role="img"`와 `aria-label`.

## three.js로 만든 3D

깊이가 데이터를 담을 때만 쓰세요: 임베딩, 물리적이거나 공간적인 배치, 높이가 양을 의미하는 스택, 기하 구조. 상자와 화살표로 된 그래프는 절대 3D로 만들지 마세요.

```html
<script type="importmap">{"imports":{"three":"https://cdn.jsdelivr.net/npm/three@0.186/build/three.module.js","three/addons/":"https://cdn.jsdelivr.net/npm/three@0.186/examples/jsm/"}}</script>
```

- 고정 종횡비의 `.frame` 안에 캔버스를 두고, `role="img"`, `aria-label`, `Fig. N` 캡션, 핵심 수치를 담은 한 줄 텍스트 대체 문구를 넣으세요.
- 색상은 `getComputedStyle`로 페이지 토큰에서 가져오고, 라벨은 `CSS2DRenderer`로 그리세요. 방향광 하나와 주변광 하나만 쓰세요. 블룸, 안개, 파티클은 쓰지 마세요.
- `OrbitControls`는 감쇠와 줌 한계를 두고, "Reset view"를 추가하세요. 답이 보이는 각도로 열고, 자동 회전은 첫 상호작용 전까지만 하며, 동작 축소 설정에서는 절대 하지 마세요.
- `setPixelRatio(Math.min(devicePixelRatio, 2))`, `ResizeObserver`를 쓰고, 보일 때만 렌더링하세요.

## 4개 이상 섹션을 위한 페이지 구조

왼쪽에 고정된 `<nav>` 목차를 두세요. 1000px 이하에서는 고정된 상단 바를 쓰되, 링크 목록만 옆으로 스크롤되게 하세요(스크롤바는 숨기고, 오른쪽 가장자리는 `mask-image`로 흐리게). 활성 섹션은 `IntersectionObserver`(`rootMargin:'-10% 0px -80% 0px'`)로 표시하세요. `history.replaceState`는 `try/catch`로 감싸세요. `file://` 페이지에서는 예외가 발생합니다.

## 기타 형태

- **파일 맵:** 고정폭 글꼴의 중첩 `<ul>`. 각 경로에 상태 칩(added, modified, deleted)과 `+12 −3` 개수를 붙이세요.
- **타임라인:** 하나의 레일 선과 날짜가 있는 노드를 둔 CSS 그리드. 가장 최근 항목에 강조색을 주세요.
