# 스타일 가이드

내용에서 레지스터를 고른 뒤, 주제가 그 레지스터에 약간의 색을 입히게 하세요(주제 모티프). `templates/page.html`은 이 가이드에 맞춰 만든 Instrument 레지스터입니다.

## 레지스터

| 레지스터 | 사용처 | 디스플레이 / 본문 / 고정폭 | 시그니처 |
|---|---|---|---|
| **Instrument** | diff 및 계획 리뷰, 감사, 지표, 상태 | Geist 600 / Geist / Geist Mono | 지표가 있으면 상단 근처에 KPI 띠. 모든 곳에 표 숫자(tabular numbers). 셀은 떠 있는 카드가 아니라 가는 선으로 구분. 상태는 형태 + 단어로 표시. |
| **Blueprint** | 아키텍처, 데이터 흐름, 시스템, 시각적 계획 | IBM Plex Sans 600 / IBM Plex Sans / IBM Plex Mono | 배경에 24px 격자. 경계는 고정폭 태그가 붙은 점선 프레임. 그림 위에 번호 콜아웃 ① ②. 구간에는 치수선. |
| **Paper** | 개념, 작동 방식, 사실 확인, 긴 글 | Newsreader 500 / Atkinson Hyperlegible Next / Atkinson Hyperlegible Mono | 좁은 텍스트 단, 넓은 피규어. 1200px 이상에서 여백 메모. `Fig. N` 라벨. |
| **Editorial** | 요약, 서사, 덱, 쇼케이스 | Instrument Serif / Instrument Sans / JetBrains Mono | 디스플레이 타입을 최대 크기로. 큰 빈 영역이 있는 비대칭 격자. 화면마다 숫자 하나나 문구 하나가 페이지를 이끎. |

프로젝트 자체의 디자인 시스템이 레지스터를 덮어씁니다. 이름 있는 팔레트는 `themes.md`를 보세요. 각 레지스터의 토큰은 두 가지 색 방식 모두 `kit/kit.css`에 있습니다. 킷 페이지는 `data-register`로 이를 받고, 슬라이드나 영상 덱은 그 레지스터 블록을 거기서 복사합니다. 텍스트 토큰은 `--bg`와 `--surface` 위에서 4.5:1에 도달합니다. 의미 있는 윤곽선에는 `--border-bright`(3:1)를, 장식용 규칙선에만 `--border`를 쓰세요.

## 시각 원칙

1. **조용한 바탕, 신호는 하나.** 페이지의 약 90%는 중립색입니다. 강조색은 독자가 지금 봐야 할 것만 표시합니다: 핵심 노드, 강조 경로, 활성 컨트롤, 중요한 숫자 하나.
2. **피규어가 인터페이스입니다.** 산문의 용어와 피규어 속 그 요소는 함께 빛납니다(`diagrams.md` → 연결된 강조).
3. **개요가 먼저, 세부는 다음.** 전체 그림을 먼저 보여주고, 독자는 단계 진행, 마우스 올리기, 펼치기로 세부를 봅니다. 원자료는 `<details>`에 넣되, 출처는 끝에 보이는 섹션에 두세요.
4. **모션은 변화나 흐름을 보여줍니다.** 블록은 한 번 떠오르고, 점은 실제 속도로 움직이며, 단계는 부분을 드러냅니다. 패럴랙스, 스크롤 하이재킹, 장식용 반복 루프는 없습니다. 동작 축소 설정에서는 최종 상태를 보여주세요.
5. **세공도 의미의 일부입니다.** 노드는 점 격자 무대 위에 살짝 솟아 있고, 형태는 사물이 무엇인지 말해야 합니다(원통은 저장소). 가장 중요한 요소에는 부드러운 후광을, 강조 경로에는 빛을 줍니다.

## 타이포그래피

| | 규칙 |
|---|---|
| 위계 | 크기 단계는 적게, 점프는 크게. 대비는 본문과 디스플레이 사이의 간격에서 나옵니다. 각 단계는 크기, 굵기, 색 중 한두 가지만 바꿉니다. 조용하게 시작하고, 가장 먼저 읽혀야 하는 것만 강조하세요. |
| 행 길이 | 본문 약 65ch; 곁 메모 40–50ch; 리드 40–50ch. |
| 줄바꿈 | 디스플레이 줄은 구 단위에서 끊으세요. 왼쪽 정렬, 오른쪽은 들쭉날쭉하게; 양끝 정렬은 절대 쓰지 마세요. |
| 숫자 | 표, KPI, 갱신되는 모든 곳에는 `tabular-nums`; 산문에는 비례 숫자(Paper에서는 oldstyle). 숫자 열은 오른쪽 정렬. 읽기 좋은 형식(`5.6k`, `−86%`)으로 쓰고, 모든 라벨에 단위를 반복하며, 비교 대상을 밝히세요(`from 5,600`). |
| 문자 | 둥근 따옴표. 범위에는 `–`, 중단에는 `—`, 마이너스에는 `−`, 배수에는 `×`, `…`, `≤`. 숫자와 단위 사이에는 줄바꿈 금지 공백(`1&nbsp;ms`). |
| 강조 | 굵게 또는 기울임, 둘을 함께 쓰지 않기; 기울임과 대문자는 몇 단어에만. 밑줄은 링크와 연결된 용어에만. |

## 레이아웃

| | 규칙 |
|---|---|
| 격자 | 12열, `s-5` 거터. 텍스트는 약 8열, 피규어는 12열, 섹션 라벨과 곁 메모는 3열. 모든 왼쪽 가장자리는 열 선 위에. |
| 하나의 축 | 키커, 헤드라인, 부제, 피규어, 캡션, 섹션 라벨이 하나의 왼쪽 정렬 가장자리를 공유. 가운데 정렬은 숫자 하나나 제목 슬라이드에서만. |
| 진입점 | 키커 → 헤드라인 → 부제 → 피규어 → 캡션 → 본문. 각 화면에는 지배적인 요소 하나, 보조 요소 한두 개, 조용한 텍스트. 흐리게 보아도 지배적 요소가 읽혀야 합니다. 위치를 보여주세요(`2 / 5`, 섹션 내비게이션). |
| 섹션 시작부 | 페이지마다 한 종류. Swiss 머리글: 가는 선, 1–3열의 고정폭 라벨, 4–12열의 `h2`가 같은 기준선에(리뷰). 키커 머리글: `h2` 위의 작은 라벨(설명문). 피규어 머리글: 전체 너비 피규어, `h2`는 그 제목(서사). |
| 근접성 | 제목 위 공간은 제목 아래 공간의 2–3배. 캡션은 피규어에서 `s-3` 떨어져 놓입니다. 관련된 것은 무관한 것보다 가까이 둡니다. |
| 리듬 | 너비와 밀도를 바꾸세요: 넓은 피규어 → 숫자 띠 → 작은 다중 그림 → 짧은 텍스트. 같은 블록 세 개가 연속으로 나오면 안 됩니다. |
| 구조 | 공간이 먼저, 가는 선이 다음, 프레임은 마지막. 카드 안에 카드를 넣지 마세요. 비대칭의 빈 공간은 의도적으로 보이고, 고르게 퍼진 간격은 미완성으로 보입니다. |

## 피규어

| | 규칙 |
|---|---|
| 관계로 고르기 | 시간에 따른 변화 → 꺾은선 또는 스파크라인. 크기 → 막대. 전체의 일부 → 와플 또는 누적 막대. 순위 → 정렬된 막대. 편차 → 0 주변의 막대. 분포 → 스트립 또는 히스토그램. 상관 → 산점도. 흐름 → 흐름 점이 있는 다이어그램. 위치 → 지도. |
| 데이터 잉크 | 모든 표시는 데이터를 담거나 시선을 안내해야 합니다. 차트 테두리, 플롯 배경, 두꺼운 격자선, 3D 막대는 없습니다. 격자는 값을 읽어야 할 때만 `--border`로. |
| 레이어 | 바탕 < 구조 < 데이터 < 신호(강조), 위로 갈수록 더 조용하게. 가까이 있는 두 선은 세 번째 형태를 만듭니다. 간격을 주거나 합치세요. |
| 최소 차이 | 각 구분은 분명하면서도 가능한 한 미묘하게. 라벨 수준은 두 단계: 작고 흐리게, 크고 선명하게. |
| 라벨 | 데이터 위에, 가로로, 왼쪽 정렬, 단위와 함께. 5개 시리즈 미만이면 범례를 쓰지 않음. 라벨이 선과 교차하는 곳에는 `--bg` 후광. |
| 주석 | 캡션이 가리키는 지점에 차트당 한두 개의 메모: 짧은 지시선과 평범한 문구. |
| 정직한 눈금 | 막대는 0에서 시작. 작은 다중 그림은 같은 눈금 공유. 순서에 의미가 없다면 값으로 정렬. 꺾은선 차트는 약 2:1–3:1. |
| 선 굵기 | 구조 1, 데이터와 윤곽 1.5–1.75, 신호 2.5–3. |
| 색 척도 | 연속형: OKLCH 명도 단계의 한 색조. 발산형: 중립 중간값 주변의 두 색조. 범주형: 명도와 채도가 같은 색조 최대 5개. |

## 주제 모티프

주제가 자체적으로 약간의 개성을 더해, Postgres에 관한 페이지가 오디오에 관한 페이지처럼 보이지 않게 하세요. 최대 2–3가지 손질만 허용합니다.

| 요소 | 규칙 | 예시 |
|---|---|---|
| 강조 색조 | 주제 고유의 색을 두 색 방식 모두에서 4.5:1이 되도록 조정. 색조가 상태로 읽히면(빨강 ≈ 위험, 초록 ≈ 정상) 레지스터의 강조색을 유지. | Postgres 파랑 · Rust 주황 · Redis 빨강 → 레지스터 강조색 유지 |
| 바탕 질감 | 기본은 점 격자; 시스템과 계획에는 24px 선 격자, 글에는 줄 노트, 하드웨어에는 등각 격자. 대비 15% 이하. | |
| 글리프 | 노드 글리프는 도메인 고유의 기호에서 가져와 선으로 그리기. | 회로 기호 · 지도 핀 · 파형 · git 브랜치 |
| 타입 세부 | 도메인의 고유한 타이포그래피 습관 하나. | 금융의 가격 열 · 사고의 고정폭 타임스탬프 · 사양의 작은 대문자 |
| 형태 언어 | 도메인 고유의 다이어그램 관행. | 프로세스의 수영 레인 · 회계의 원장 · 프로토콜의 타이밍 차트 |

그것을 빼도 페이지가 읽기 더 어려워지지 않고 덜 구체적이지 않다면, 그 손질은 잘라내세요. 말장난, 마스코트, 일러스트는 쓰지 마세요.

## 척도

킷이 단계를 정의합니다: `--t-label`부터 `--t-h1`까지, `--s-1`부터 `--s-8`까지, `--r-1`과 `--r-2`, 그리고 `--ease`와 함께 `--fast`, `--med`, `--slow`. 여러분의 CSS도 이것만 사용하세요.

| 결정 | 규칙 |
|---|---|
| 간격 | 컴포넌트 내부는 `s-2`–`s-4`; 컴포넌트 사이는 `s-5`–`s-6`; 섹션 사이는 `s-8`. 간격이 클수록 관련성이 낮습니다. |
| 타입 | `--t-small`은 버튼, 코드, 고정폭 라벨에만. |
| 라벨 | `.ve-label`; 대문자(`.caps`)는 3단어 이하에만. |
| 반경 | 칩, 버튼, 입력란, 인라인 강조에는 `r-1`; 프레임, 표, 오버레이에는 `r-2`. 그 밖에는 둥글리지 않습니다. |
| 강조 | 강조색은 하나, 화면의 10% 이하에만. 상태 색(`ok warn risk info`)은 상태만 의미합니다. |
| 모션 | 직접 만든 모션은 `transform`, `opacity`, `stroke-dashoffset`만 사용: 호버는 `fast`, 상태 변화는 `med`, 단계는 `slow`, 항상 `--ease`. |
| 효과 | 그림자(`--lift`)는 떠 있는 노드와 오버레이에만; 후광은 핵심 노드와 강조 엣지에만. |
| 레이아웃 | 피규어는 전체 너비를 사용. 카드 그리드: `repeat(auto-fit, minmax(13rem, 1fr))`. |

## 컴포넌트

| 컴포넌트 | 사양 |
|---|---|
| 페이지 머리글 | `h1`이 답을 말함; 답이 되는 숫자는 강조색으로 앞에 둠. 한두 문장의 리드, 굵은 구 하나. |
| 흐리게 처리 | 텍스트를 흐리게 하지 마세요: 흐려진 라벨은 `--text-dim`으로 바꿉니다. `--accent-dim` 위에 강조색 텍스트를 쓰지 말고, 그곳에서는 `--text`를 쓰세요. |
| KPI 띠 | 각 셀: 라벨 → 값 → 그 그림. |
| 표 | 머리글은 표면 위의 라벨 스타일; 셀은 `t-body`, 여백 `s-3 s-4`; 행 구분선만; 숫자는 오른쪽 정렬이며 tabular; `r-2` 프레임이 있는 스크롤 컨테이너 안. |
| 콜아웃 | 표면, `r-2`, 여백 `s-4`, 제목으로 상태 칩. 색이 들어간 옆 막대는 쓰지 마세요. |
| 코드 | 고정폭 `t-small`, 표면, `r-2`, 여백 `s-4`, 옆으로 스크롤. 인라인 코드는 `.875em`, 상자 없음. |

## 마무리 손질

- 직접 그린 것은 모두 킷의 클래스를 재사용하여, 같은 요소가 어디서나 같아 보이게 하세요.
- 섹션은 고정된 내비게이션 아래에서 가려지지 않도록 `scroll-margin-top`을 받게 하세요.
- 로드할 때 아무것도 움직이지 않게 하세요: 모든 SVG에는 `viewBox`, 모든 이미지에는 너비와 높이.
