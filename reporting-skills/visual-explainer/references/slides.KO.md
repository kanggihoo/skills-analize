# 슬라이드

슬라이드는 긴 페이지를 잘라 놓은 것이 아니라 다른 매체입니다. `templates/slide-deck.html`의 엔진(크롬, `SlideEngine`, `autoFit()`, 전달 점검)은 그대로 복사하고, 나머지는 모두 다시 스타일링하세요.

## HTML 전에 계획하기

소스의 모든 항목(섹션, 행, 결정, 세부 사항)을 목록으로 만들고, 각각을 슬라이드 하나에 매핑하세요(매핑되지 않은 항목이 없어야 합니다. 내용을 빼지 말고 슬라이드를 추가하세요). 그다음 구성을 다양하게 하세요(가운데, 왼쪽, 오른쪽, 분할, 여백 없음). 섹션이 7개인 소스는 보통 슬라이드 18–25장이 필요합니다. 검증 방법: 소스를 본 적 없는 독자가 덱만 보고 주요 요점을 모두 재구성할 수 있어야 합니다.

## 슬라이드당 분량(`100dvh` 하나, 스크롤 없음)

| 유형 | 최대 수용량 |
|---|---|
| 제목 / 여백 없음 | 제목 + 부제목 |
| 구분 | 번호 + 제목 + 부제 |
| 내용 | 제목 + 2줄 이하 글머리 기호 5개, 또는 제목 + 피규어 하나 |
| 분할 | 패널 2개, 각각 해당 유형의 한도 이내 |
| 다이어그램 | 제목 + SVG 피규어 하나(상자 10개 이하, 라벨 18px 이상, 선 2px 이상) |
| 대시보드 | 제목 + KPI 6개; 핵심 값은 6자 이하 |
| 표 | 제목 + 8행; 다음 슬라이드로 이어짐 |
| 코드 | 제목 + 10줄 |
| 인용 | 25단어 이하 + 출처 |

- 슬라이드마다 초점은 하나만 두고, 제목은 그 요점을 말해야 합니다. 본문은 산세리프 18px 이상으로 쓰고, 디스플레이 서체는 제목에만 쓰세요. 글머리 기호보다 피규어를 우선하세요.
- 슬라이드 크기의 피규어: 노드 텍스트 24, 엣지 라벨 18, 선 굵기 2.5(강조 3.5), `userSpaceOnUse`에서 화살촉 16, `max-height: 56dvh`. 너비 768px 미만에서는 SVG가 스크롤 래퍼 안에서 `min-width: 720px`을 유지합니다.
- 덱은 기본적으로 Editorial 레지스터를 씁니다. 지표나 아키텍처는 Instrument나 Blueprint를 써도 됩니다.
- 가운데 정렬 슬라이드가 세 장 연속으로 나오면 안 됩니다.
- 글자 크기는 `rem`이 아니라 `clamp(px, vw, px)`로 지정하세요. `max-height: 700/600/500px`에서는 여백을 줄이고 장식을 숨기세요.
- 엔진은 `.diagram-shell`, `.table-scroll`, `.code-scroll`, 또는 폼 필드에 포커스가 있으면 슬라이드 키를 멈춥니다. 스크롤이 필요한 내용은 이런 곳에 넣으세요.

## 전달 점검

`overflow:hidden`은 조용히 잘라냅니다. 배포하기 전에 `prefers-reduced-motion: reduce`를 켜고(Chrome DevTools → Rendering), 목표 크기와 약 1280×600에서 덱을 여세요. 템플릿은 문제 있는 슬라이드마다 윤곽선을 그리고(빨강 = 넘침, 호박색 = autoFit 사용), `Slide delivery check failed`를 기록합니다. `passed`가 기록될 때까지 나누거나 줄이세요.

## PPTX

`visual-explainer-pptx`는 각 `section.slide`의 제목, `.slide__subtitle`, 목록, 문단, 표, `pre`를 읽으므로, 이 구조를 의미 있게 유지하세요. SVG, 피규어, 캡션은 버려집니다. PPTX가 요청되면, 피규어 슬라이드마다 주장을 `<p class="slide__body">`에도 넣으세요.
