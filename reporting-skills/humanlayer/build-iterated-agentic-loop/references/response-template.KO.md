# 응답 템플릿

이 템플릿은 CI 에이전트가 최종 응답을 어떻게 형식화해야 하는지 정의합니다. 이 응답은 GitHub PR의 본문이 됩니다.

작업 유형과 리뷰어에게 필요한 정보에 맞게 이 템플릿을 맞춤 설정합니다.

---

## 예시: 수정/마이그레이션 작업

```markdown
`<tool-name>` 이슈 N개 처리 완료:
  - `resolved`: X
  - `ignored`: Y
  - `skipped`: Z

상세 내용은 아래와 같습니다.

---

## 이슈 1
- **파일**: `path/to/file.ts`
- **요약**: [이슈에 대한 간결한 설명]
- **해결**: **FIXED**. [수정 내용에 대한 간결한 설명]
- **위험도**: [HIGH / medium / low]
- **수동 검증** (HIGH/medium 위험도의 경우): [변경 사항을 테스트하는 단계]

## 이슈 2
- **파일**: `path/to/other.ts`
- **요약**: [...]
- **해결**: **IGNORED**. [규칙을 무시 목록에 추가한 이유]

## 이슈 3
- **파일**: `path/to/another.ts`
- **요약**: [...]
- **해결**: **SKIPPED**. [사람의 확인이 필요한 이유]
```

---

## 예시: 생성 작업

```markdown
새로운 `<artifact type>` N개 생성:

| 파일 | 설명 | 상태 |
|------|-------------|--------|
| `path/to/new-file.ts` | [생성된 내용] | Created |
| `path/to/updated.ts` | [변경된 내용] | Updated |

## 검증
- Typecheck: PASS
- Tests: PASS
- Lint: PASS

## 참고
[리뷰어가 알아야 할 추가 맥락]
```

## 예시: 리팩터링 작업

```markdown
컴포넌트/모듈 N개 리팩터링 완료:

## 변경 사항

### `path/to/file.ts`
- **이전**: [이전 패턴에 대한 간단한 설명]
- **이후**: [새 패턴에 대한 간단한 설명]
- **위험도**: low

### `path/to/other.ts`
- **이전**: [...]
- **이후**: [...]
- **위험도**: medium
- **검증**: [이 변경을 테스트하는 방법]

## 검증
- Typecheck: PASS
- Tests: PASS
- 동작 변경은 예상되지 않음
```

## 템플릿 변수

응답 템플릿을 작성할 때 다음 플레이스홀더를 사용할 수 있습니다.

- `<tool-name>` - 이슈를 찾아낸 CLI 도구 또는 프로세스
- `<artifact-type>` - 에이전트가 생성하는 것 (tests, types, docs 등)
- `<task-name>` - 에이전트 작업의 이름
- `<date>` - 현재 날짜 (MM/DD 형식)

## 가이드라인

1. **요약 통계를 먼저 제시** - 리뷰어가 범위를 즉시 파악할 수 있어야 합니다.
2. **해결 유형별로 그룹화** - 수정, 무시, 건너뜀, 생성 여부로 나눕니다.
3. **위험 수준을 포함하고 눈에 띄게 강조** - 리뷰어가 우선순위를 정하는 데 도움을 줍니다.
4. **검증 단계 제공** - 중간/높은 위험도 변경에 대해서는 반드시 제공합니다.
5. **간결하고 훑어보기 쉽게 유지** - 표, 제목, 글머리 기호를 사용합니다.
