# 기술 설계 문서 반복 개선

기존 TDD를 피드백에 따라 수정하거나, 시스템 설계 및 프로그램 설계 인터뷰를 이어갑니다. 두 관심사를 분리해 유지하고, 메인 대화에서 한 번에 하나의 선택을 해결하세요.

다음 단계를 순서대로 따르세요.

## 1. TDD와 맥락 읽기

선택한 TDD, 관련 워크플로 문서, 지정된 소스를 전체적으로 읽으세요. 필요에 따라 보조 자료도 읽으세요. 확정된 시스템 및 프로그램 선택과 기록된 승인 내용을 파악하세요.

## 2. 다음 기술 결정 정하기

사용자의 피드백을 따르거나 미완료 설계를 이어가세요. 완성된 TDD이고 피드백이 없다면 수정할지, 기술 질문을 더 탐색할지 선택지를 제시하세요.

인터뷰를 이어갈 때는 프로그램 설계를 열기 전에 시스템 설계를 확정하고 승인받으세요. 기존 피드백으로 두 섹션 중 어느 쪽이든 수정할 수 있으며, 아키텍처가 바뀌면 코드 형태도 바뀌어야 할 수 있습니다.

## 3. 현재 동작과 패턴 확인하기

관련 코드를 읽고, 유용하다면 `codebase-locator`, `codebase-analyzer`, `codebase-pattern-finder`를 사용하세요. 관련이 있다면 외부 리서치도 활용하세요. 결과를 기다리고, 리서치 문서가 있다면 새로운 사실을 그곳에 추가하세요.

## 4. 템플릿과 시각화 가이드 읽기

`$SKILLBASE/references/iterate-tdd/references/tdd_template.md`와 `$SKILLBASE/references/show-me.md`를 읽으세요.

## 5. 선택을 확정하고 TDD 갱신하기

옵션, 트레이드오프, 추천안과 함께 결정 하나를 제시하세요. 시스템 선택이라면 구성 요소 간의 다이어그램이나 계약을 보여 주세요. 프로그램 선택이라면 구체적인 코드 형태 옵션을 각각 별도의 코드 블록으로 보여 주세요. 사용자가 선택을 확정할 때까지 기다린 뒤 편집하세요.

영향을 받는 섹션을 그 자리에서 다시 작성하세요. 현재 동작과 제안된 변경은 **System Design** 안에, 코드 내부 구조는 **Program Design** 안에 표현하세요. 경로와 메타데이터는 유지하고, 필요하면 `repos`를 갱신하세요.

섹션 제목은 발견 사항이나 합의된 동작을 드러내도록 쓰고, 문단은 짧게 유지하며, 시각 자료는 설명 바로 옆에 두세요. 연결된 HTML 다이어그램과 패턴을 최신 상태로 유지하세요. 사용자가 동의하면 기술 선택이 제품 동작을 바꿀 때 PRD와 목업도 갱신하세요.

## 6. 설계를 이어가거나 검토하기

각 섹션 검토 시점마다 VS Code, Cursor, 또는 사용자가 선호하는 편집기나 브라우저에서 문서를 열지 제안하세요.

인터뷰를 계속하는 중이라면 다음으로 해결되지 않은 질문을 던지세요. 구체적인 피드백을 반영한 뒤에는 사용자에게 제어를 넘기세요. 설계를 마무리하거나 수정할 때는 시스템 설계와 프로그램 설계 각각에 대해 승인을 받으세요.

## 7. 최종 답변 템플릿을 읽고 응답하기

설계가 승인되면 `$SKILLBASE/references/iterate-tdd/references/tdd_final_answer_resolved.md`를 읽고 아웃라인이나 바로 구현을 제안하세요.
