# 리서치 질문 반복 개선

사용자의 피드백을 사용해 기존 리서치 질문 문서를 다듬거나, 일부만 작성된 질문 세트를 마무리합니다.

다음 단계를 순서대로 따르세요.

## 1. 질문과 피드백 읽기

선택한 리서치 질문 문서를 전체적으로 읽고, 사용자가 지정한 피드백 파일이 있다면 함께 읽으세요. `/rpi`가 선택한 문서나 사용자가 제공한 경로를 사용하세요.

문서가 완성되어 있고 사용자가 피드백을 주지 않았다면 무엇을 바꾸고 싶은지 물어보세요. 일부만 완성된 문서라면 기존 범위에서 이어서 작성하세요.

## 2. 질문 다듬기

피드백을 관련 소스 파일과 대조해 확인하고, 필요하면 가벼운 리서치를 수행하세요. 필요에 따라 `$SKILLBASE/references/create-research-questions/process.md`에 설명된 리서치 에이전트를 사용하세요.

질문은 현재 시스템에 대해 서술적이고 집중되게 작성하세요. 무엇이 존재하는지, 어디에 있는지, 어떻게 동작하는지, 부품들이 어떻게 상호작용하는지를 다루세요. 리서치 에이전트에게는 구체적인 출발점과 객관적으로 조사하는 데 필요한 맥락을 주세요. 향후 설계 선택은 설계 단계에 남겨 두세요.

유용한 질문 형태는 다음과 같습니다:

- 기능이 처음부터 끝까지 어떻게 동작하며 어떤 시스템이 관여하는지 설명하기.
- 두 구성 요소 사이의 계약과 양쪽의 구현을 살펴보기.
- 엔드포인트에서 데이터 저장소까지의 로직을 추적하기.
- 테이블이나 필드가 어디에서 쓰이는지 찾고, 그 데이터가 무엇을 뒷받침하는지 설명하기.

질문의 개수와 깊이는 작업에 맞추세요. 보통 두 개에서 일곱 개 사이입니다. 프론트엔드 작업이라면 기존 컴포넌트 라이브러리, 색상, 타이포그래피, 간격, 테두리, 그림자, 테마를 다루세요.

## 3. 템플릿을 읽고 문서 갱신하기

질문을 갱신하기 전에 `$SKILLBASE/references/iterate-research-questions/references/research_questions_template.md`를 읽으세요.

기존 문서를 그 자리에서 수정하고, 피드백을 질문과 맥락 포인터에 자연스럽게 반영하세요. 경로, 형식, 프런트매터는 유지하고, 사용자가 요청하면 선택된 flow를 갱신하세요. 정확한 경로, 패키지 이름, 저장소 이름, URL은 그대로 유지하고, 피드백에 따라 관련 포인터를 추가하세요.

## 4. 최종 답변 템플릿을 읽고 응답하기

`$SKILLBASE/references/iterate-research-questions/references/research_questions_final_answer.md`를 읽고, 그 템플릿에 저장된 파일 경로, 작업 디렉터리, 선택된 flow를 채워 응답하세요.

검토를 위해 VS Code, Cursor, 또는 사용자가 선호하는 편집기나 브라우저에서 문서를 열지 제안하세요.

이 단계는 갱신된 질문과 권장 리서치 명령을 전달하며 마무리하세요. 그다음 사용자가 리서치를 시작하라고 요청할 때까지 기다리세요.
