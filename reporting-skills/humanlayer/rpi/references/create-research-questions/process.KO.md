# 리서치 질문 작성

사용자의 작업을 현재 시스템이 어떻게 동작하는지에 대한 집중된 질문으로 바꿉니다. 이 질문들이 다음 리서치 세션의 범위와 출발점이 됩니다.

다음 단계를 순서대로 따릅니다.

## 1. 요청 읽기

사용자가 지정한 파일과 소스를 전체 읽습니다. 리서치 에이전트가 맥락으로 쓸 수 있도록 정확한 경로, 패키지 이름, 저장소 이름, URL은 그대로 보존합니다.

`/rpi`가 정한 작업 디렉터리와 선택된 flow를 사용합니다.

## 2. 좋은 질문을 던질 만큼 컨텍스트 확인하기

관련 코드를 찾고 요청을 이해하기 위해 가벼운 리서치를 합니다. 필요하면 서브에이전트를 사용합니다.

- `codebase-locator`는 관련 소스 파일, 설정, 테스트를 찾습니다.
- `codebase-analyzer`는 파일과 라인 참조를 포함해 현재 동작과 상호작용을 설명합니다.
- `codebase-pattern-finder`는 관련 구현과 컨벤션을 찾습니다.
- `web-search-researcher`는 필요할 때 외부 웹 자료와 라이브러리 문서를 확인합니다.

Explore 에이전트나 도구가 있다면 그것도 사용할 수 있습니다.

외부 질문에는 사용 가능한 웹이나 라이브러리 문서 도구를 활용합니다. 웹에 접근할 수 없으면 그 한계를 적고, 코드와 로컬 문서만으로 계속합니다.

이 단계는 작게 유지합니다. 전체 조사는 다음 리서치 세션에서 합니다.

## 3. 현재 상태에 대한 질문 초안 작성하기

무엇이 존재하는지, 어디에 있는지, 오늘날 어떻게 동작하는지를 묻습니다. 관련 동작, 데이터 흐름, 테스트, 제약, 엣지 케이스, 라이브러리 기능을 다룹니다. 각 질문은 기존 시스템에 대한 서술형 질문으로 구성하고, 미래의 설계 선택은 설계 단계로 남겨 둡니다.

구체적인 출발점을 사용합니다. 예를 들면 "`packages/ui`에서 테마는 공유 컴포넌트까지 어떻게 전달되는가?" 또는 "워커는 재시작 후 대기 중인 작업을 어떻게 복구하는가?"처럼 씁니다.

보통 질문은 두 개에서 일곱 개 사이로 작성하며, 작업이 요구하면 더 많이 씁니다. 질문의 범위와 깊이는 작업에 맞춥니다.

프론트엔드 작업이라면 기존 디자인 시스템을 포함합니다. 컴포넌트, 색상과 hex 코드, 타이포그래피, 간격, 테두리, 그림자, 테마가 여기에 해당합니다. 그래야 이후 목업이 프로젝트의 시각 컨벤션을 따를 수 있습니다.

## 4. 템플릿을 읽고 질문 저장하기

요청을 읽고 컨텍스트를 확인한 뒤, `$SKILLBASE/references/create-research-questions/references/research_questions_template.md`를 읽습니다. 변경을 시작하는 경우에는 `$SKILLBASE/references/create-research-questions/references/request_template.md`도 함께 읽고, 원래 요청을 이후 설계 및 구현 세션에서 쓸 수 있도록 `NN-request-<description>.md`에 저장합니다. 사용자가 원하는 결과와 정확한 소스 포인터는 여기에 보존합니다.

선택한 작업 디렉터리에 다음 번호와 짧은 kebab-case 설명을 붙여 `NN-research-questions-<description>.md`를 씁니다.

요청이 제공한 컨텍스트 포인터는 포함합니다. 리서치 세션에는 독립적이고 중립적인 질문과 구체적인 소스 포인터를 줍니다. 원하는 변경은 별도의 요청 문서에 두어, 리서치가 객관성을 유지하도록 합니다.

## 5. 최종 답변 템플릿을 읽고 응답하기

`$SKILLBASE/references/create-research-questions/references/research_questions_final_answer.md`를 읽고, 저장된 파일 경로, 작업 디렉터리, 선택한 flow를 채워 그 템플릿으로 응답합니다.

문서를 VS Code, Cursor, 또는 사용자가 선호하는 편집기나 브라우저에서 검토할 수 있게 열지 제안합니다.

저장된 질문과 제안하는 리서치 명령으로 이 단계를 마칩니다. 그 뒤 사용자가 리서치를 시작하라고 요청할 때까지 기다립니다.
