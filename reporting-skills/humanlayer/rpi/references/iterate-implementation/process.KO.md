# 구현 반복 개선

이미 진행 중인 코드에 버그 리포트, 리뷰 피드백, 후속 변경 사항을 반영합니다.

다음 단계를 순서대로 따르세요.

## 1. 피드백과 워크플로 맥락 읽기

사용 가능한 아웃라인, 설계, 리서치 문서와 사용자가 지정한 소스를 전체적으로 읽으세요. 문서 우선순위를 확인하려면 `$SKILLBASE/references/implement-outline/process.md`를 읽으세요. 필요에 따라 보조 자료도 읽으세요.

## 2. 구현된 작업 파악하기

현재 diff와 관련 커밋을 살펴보세요. 합의된 동작을 현재 코드 및 테스트와 비교하세요. 아직 시작하지 않은 아웃라인 단계라면 `$SKILLBASE/references/implement-outline/process.md`를 읽고 그 일반 구현 절차를 따르세요.

## 3. 보고된 동작 검증하기

문제를 재현하거나 요청된 변경을 코드와 테스트에 대조해 확인하세요. 필요하면 관련 로그나 픽스처를 사용하세요. 기대 동작이 불분명하면 추천 접근 방식과 함께 명확한 질문을 하나만 하세요.

## 4. 변경 적용 및 검증하기

확인된 수정 사항을 기존 패턴에 맞춰 구현하세요. 적절하다면 회귀 테스트를 추가하고 관련 검사를 실행하세요. 합의된 결과가 바뀌면 영향을 받는 설계나 아웃라인 섹션도 갱신하세요. 아웃라인의 검증 표시가 정확하도록 유지하세요.

## 5. 최종 답변 템플릿을 읽고 응답하기

`$SKILLBASE/references/iterate-implementation/references/iterate_implementation_final_answer.md`를 읽고 변경 사항, 근거, 남은 리뷰 단계를 보고하세요.

워크플로 문서가 갱신되었다면 VS Code, Cursor, 또는 사용자가 선호하는 편집기나 브라우저에서 리뷰용으로 열지 제안하세요.
