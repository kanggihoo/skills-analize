# 디자인 디스커션 작성

사용자 요청과 리서치를 바탕으로 무엇을 바꿀지, 그리고 각 구성 요소가 어떻게 맞물릴지 논의합니다. 설계 선택의 결정권은 사용자에게 둡니다.

다음 단계를 순서대로 따릅니다.

## 1. 컨텍스트 읽기

선택한 작업 디렉터리의 워크플로 문서와 사용자가 지정한 파일을 메인 대화에서 전체 읽습니다. 완료된 리서치로 현재 동작을 파악하고, 요청으로 원하는 결과를 파악합니다. 필요하면 보조 목업과 다이어그램도 읽습니다.

사용자의 최신 지시와 이후의 설계 문서에서 확정된 선택 사항을 그대로 이어받습니다. 현재 동작은 실제 코드로 검증합니다. 원하는 변경 내용이 없으면 설계 초안을 작성하기 전에 사용자에게 원하는 결과를 먼저 묻습니다.

## 2. 리서치 공백 메우기

선택이 리서치로 확인되지 않은 사실에 달려 있으면 `codebase-locator`, `codebase-analyzer`, `codebase-pattern-finder`로 조사합니다. 관련 외부 자료는 `web-search-researcher`로 찾습니다. 결과를 기다린 뒤 관련 코드를 확인하고 나서 선택지를 제시합니다. 리서치 문서가 있으면 새로 확인된 사실을 거기에 반영합니다.

## 3. 템플릿과 시각 가이드 읽기

`$SKILLBASE/references/create-design-discussion/references/design_discussion_template.md`와 `$SKILLBASE/references/show-me.md`를 읽습니다.

현재 시스템, 제안하는 결과, 선택 사항을 설명할 때는 초점이 맞는 전후 비교 다이어그램, 트리, 계약(contract), 의사코드를 사용합니다. 각 시각 자료는 그것이 뒷받침하는 짧은 설명 바로 옆에 둡니다.

핵심이 무엇이 바뀌는지에 있으면 `diff` 블록을 사용합니다. 소유권이나 순서를 더 분명히 보여 줄 때는 완성된 최종 형태를 보여 줍니다.

## 4. 초안 디스커션 작성

작업 디렉터리에 다음 번호를 붙여 `NN-design-discussion-<description>.md` 파일을 씁니다. `repos` 항목에는 관련 저장소 식별자와 SHA를 채우거나, `repos: []`를 사용합니다.

현재 경험, 원하는 결과, 범위, 제안하는 아키텍처, 따를 기존 패턴을 설명합니다. 파일 위치와 그 패턴의 짧은 예시, 기존 테스트 방식도 포함합니다.

현재 경험과 원하는 경험은 사용자가 보고 할 수 있는 것을 기준으로 설명합니다. 코드 구조, 소스 참조, 구현 예시는 아키텍처와 패턴 섹션에서 다룹니다.

사용자 결정을 기다리는 선택은 **Design Questions** 아래에 둡니다. 각 선택에는 옵션, 트레이드오프, 코드베이스에 근거한 추천을 함께 적습니다. 사용자가 이미 확정한 선택은 **Resolved Design Questions**로 옮깁니다. 그런 선택이 없으면 이 섹션은 비워 둡니다.

섹션 제목은 주요 내용을 드러내도록 씁니다. 독자가 제목만 훑어봐도 제안된 변경을 이해할 수 있어야 합니다.

## 5. 결정 사항 하나씩 정하기

인터뷰는 메인 대화에서 진행합니다. 결정 사항을 한 번에 하나씩 옵션과 추천안과 함께 제시하고, 사용자의 답을 기다립니다. 명확화 질문에는 선택이 확정될 때까지 답합니다.

사용자가 분명한 결정을 내리면 영향을 받는 섹션을 제자리에서 업데이트하고, 그 선택을 **Resolved Design Questions**로 옮깁니다. 선택한 방식, 근거, 버린 대안과 그 이유를 기록합니다. 본문과 다이어그램이 결정과 어긋나지 않도록 맞춘 뒤, 다음 열린 선택을 제시합니다.

시각적 선택에는 초점이 맞는 HTML 목업이나 다이어그램을 문서 옆에 저장하고, 일반 로컬 링크로 제공합니다. 프로젝트의 시각 규칙을 따르고 실제 라벨을 사용합니다.

## 6. 적절한 최종 답변 템플릿 읽기

문서를 VS Code, Cursor, 또는 사용자가 선호하는 편집기나 브라우저에서 검토할 수 있게 열지 제안합니다.

아직 열린 선택이 남아 있으면 `$SKILLBASE/references/create-design-discussion/references/design_discussion_final_answer.md`를 읽고, 문서 경로와 다음 질문을 채웁니다.

사용자가 모든 설계 선택을 확정하면 `$SKILLBASE/references/create-design-discussion/references/design_discussion_final_answer_resolved.md`를 읽습니다. 다음 명령은 `$SKILLBASE/references/workflow.md`를 참고해 정합니다. 아웃라인 작성이나 바로 구현을 제안합니다.

사용자가 조기 인계를 요청하면, 합의된 결정과 남은 열린 선택을 저장한 뒤 요청된 다음 단계를 따릅니다.
