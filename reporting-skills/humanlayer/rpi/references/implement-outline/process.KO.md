# 합의된 변경 구현하기

아웃라인이 있으면 아웃라인을 바탕으로, 없으면 사용 가능한 리서치와 설계 문서를 바탕으로 구현합니다. 코드 변경에는 `outline-implementer-agent`를 사용합니다.

다음 단계를 순서대로 따릅니다.

## 1. 문서와 진행 상황 읽기

선택한 작업 디렉터리의 frontmatter를 가진 워크플로 문서를 전체 읽습니다. 도움이 된다면 참조된 스크린샷, HTML 목업, 다이어그램도 읽습니다. 저장소 지침, 현재 변경 사항, 관련 소스 파일을 확인합니다.

구현 선택의 우선순위는 다음과 같습니다: 아웃라인 > TDD > PRD > 디자인 디스커션 > 리서치 > 원래 요청. 사용자의 최신 지시가 합의된 결과를 바꾸면 최신 지시를 따릅니다.

아웃라인이 있으면 완료된 단계 제목과 체크된 검증 항목을 진행 기록으로 삼아, 첫 번째 미완료 단계부터 재개합니다. 아웃라인이 없으면 사용 가능한 문서를 활용해 한 번의 실행으로 변경을 구현합니다.

## 2. 구현 위임하기

`outline-implementer-agent`를 실행합니다. 프롬프트에는 짧게 문서 경로, 그 우선순위, 구현할 단계나 범위를 담습니다. 문서는 에이전트가 직접 읽도록 합니다.

아웃라인이 있으면 기본적으로 다음 단계를 단계 번호와 리뷰 시점과 함께 할당합니다. 사용자가 그룹이나 전체 단계를 요청하면 그 범위를 할당합니다. 바로 구현하는 경우에는 제공된 문서를 바탕으로 전체 변경을 완료하도록 요청합니다. 서브에이전트를 사용할 수 없으면 메인 스킬의 대체 지침을 따릅니다.

## 3. 검증하고 진행 상황 기록하기

에이전트의 결과와 검증 증거를 검토합니다. 실패한 검사는 고친 뒤에 통과로 표시합니다. 아웃라인에서는 자동 검증 항목이 통과하면 체크합니다. 수동 항목은 사용자가 확인할 때 체크합니다. 모든 검증이 확인되면 개요 항목과 단계 제목을 `✅`로 완료 표시합니다.

자동 검사가 통과하고 남은 수동 검사가 없으면 다음 단계로 넘어갑니다. 기본적으로 대기 중인 수동 검사가 있으면 멈춥니다. 그룹이나 전체 단계를 연속으로 실행하라는 요청이 있으면 단계 사이마다 검증하고, 확인되지 않은 수동 검사는 최종 검토를 위해 대기 상태로 남깁니다.

코드와 설계가 합의된 결과를 바꾸는 방식으로 어긋나면, 그 불일치를 제시하고 접근 방식을 정해 달라고 요청합니다.

## 4. 현재 결과 보고하기

무엇이 바뀌었는지, 어떤 검사를 실행했는지, 어떤 수동 검증이 필요한지 요약합니다. 단계에서 멈추는 경우에는 다음 단계를 밝히고, 사용자의 테스트 결과나 계속 진행하라는 요청을 기다립니다.

워크플로 문서가 업데이트되었다면 문서를 VS Code, Cursor, 또는 사용자가 선호하는 편집기나 브라우저에서 검토할 수 있게 열지 제안합니다.

요청이 있으면 저장소 규칙을 따라 커밋합니다. 아티팩트의 진행 상황은 기존 문서에 기록합니다.

## 5. 요청된 범위 계속 진행하기

요청된 범위 안에서 다음 아웃라인 단계마다 문서 경로와 함께 구현 에이전트를 실행하고, 결과를 검증합니다. 요청된 작업이 모두 끝나면 `$SKILLBASE/references/implement-outline/references/implement_outline_final_answer.md`를 읽고, 그 템플릿으로 완료 또는 대기 중인 검증을 보고합니다.
