# 기술 설계 문서(TDD) 작성

사용 가능한 제품 컨텍스트를 기술 설계로 바꿉니다. **System Design**을 먼저 논의하고, 그다음 **Program Design**을 논의합니다. 각 섹션마다 사용자의 승인을 별도로 받습니다.

다음 단계를 순서대로 따르며, 인터뷰는 메인 대화에서 진행합니다.

## 1. 사용 가능한 컨텍스트 읽기

선택한 워크플로 문서와 지정된 소스를 전체 읽습니다. PRD가 있으면 유용하고, 요청과 리서치만 있어도 시작하기에 충분합니다. 입력을 반복해서 옮기지 말고 참조하며, 빠진 동작은 질문합니다.

결정에 영향을 주는 사실을 확인하거나 코드 패턴을 찾을 때는 리서치 에이전트를 사용합니다. 결과를 기다린 뒤, 리서치 문서가 있으면 업데이트합니다.

## 2. 템플릿 읽고 짧은 시작 문서 쓰기

`$SKILLBASE/references/create-tdd/references/tdd_template.md`와 `$SKILLBASE/references/show-me.md`를 읽습니다.

다음 번호를 붙여 `NN-tdd-<description>.md`를 씁니다. frontmatter, 제목, 비어 있는 **System Design**과 **Program Design** 섹션, **Patterns to Follow**로 시작합니다. `repos`에는 관련 식별자와 SHA를 채우거나, `repos: []`를 사용합니다.

첫 번째 시스템 설계 결정으로 시작합니다. 짧은 설명, 옵션, 트레이드오프, 사용자에게 던지는 질문 하나를 제시합니다.

## 3. 시스템 설계 논의하기

서비스, 엔드포인트, 스키마, 큐, 저장소, 외부 시스템 등 구성 요소가 어떻게 상호작용하는지 설명합니다. 이 섹션 안에서 현재 동작과 제안하는 변경을 함께 보여 줍니다.

데이터 흐름, 제어 흐름, 시퀀스에는 Mermaid를 사용합니다. 중요한 계약은 보여 줍니다. 엔드포인트나 메시지 형태, 상위 수준 시그니처, 프로젝트 언어나 ORM의 스키마가 여기에 해당합니다.

메시지마다 결정 하나만 제시하고 사용자의 답을 기다립니다. 선택이 확정될 때까지 명확화 질문을 처리합니다. 사용자가 결정하면 섹션을 다시 작성하고, 본문과 다이어그램이 아키텍처를 일관되게 설명하도록 유지합니다.

다이어그램에 더 많은 공간이 필요하면 초점이 맞는 `diagram-<description>.html` 파일을 작업 디렉터리에 저장하고, 그 설명 옆에 링크합니다. 프로젝트의 시각 컨벤션을 따르고 실제 라벨을 사용합니다.

## 4. 시스템 설계 승인받기

사용자에게 **System Design**을 처음부터 끝까지 검토해 달라고 요청합니다. 피드백을 반영하고, 프로그램 설계로 넘어가기 전에 승인을 받습니다.

각 섹션 검토 때마다 문서를 VS Code, Cursor, 또는 사용자가 선호하는 편집기나 브라우저에서 열 수 있다고 제안합니다.

## 5. 프로그램 설계 논의하기

시스템을 구현하는 코드 형태를 보여 줍니다. 호출 트리, 상태와 패키지 경계가 포함된 컴포넌트 트리, 파일 트리 변경, 의존성 주입 맵, 메서드 시그니처, 의사코드처럼 구체적인 코드 뷰를 논의에 포함합니다.

옵션을 비교할 때는 각각을 별도의 코드 블록으로 보여 줍니다. 기존 형태의 변경에는 초점이 맞는 diff를, 새 코드에는 완전한 최종 형태를 사용합니다. 결정을 드러내는 뷰를 고르고, 파일 목록의 상세한 내용은 아웃라인에서 다룹니다.

한 번에 질문 하나만 하고, 사용자의 결정을 기다린 뒤 **Program Design**을 제자리에서 다시 작성합니다. "워커는 재시도 타이밍을 테스트할 수 있도록 clock을 받는다"처럼 주요 내용을 말하는 헤더를 사용합니다. 각 뷰는 설명 옆에 둡니다.

따를 패턴은 소스 경로와 짧은 예시와 함께 문서화합니다. 기술적 선택이 제품 범위나 사용자 경험을 바꾼다면 사용자와 논의하고, PRD와 목업이 있으면 함께 업데이트합니다.

## 6. 프로그램 설계 승인받기

사용자에게 **Program Design**을 검토하고 코드 형태를 승인해 달라고 요청합니다. 수정 사항을 반영합니다.

## 7. 최종 답변 템플릿을 읽고 응답하기

두 섹션이 모두 승인되면 `$SKILLBASE/references/create-tdd/references/tdd_final_answer_resolved.md`를 읽습니다. 아웃라인이나 바로 구현을 제안합니다.
