# 구조 아웃라인 반복 개선

기존 아웃라인의 단계 순서, 범위, 코드 형태, 검사를 수정하거나, 일부만 작성된 아웃라인을 마무리합니다.

다음 단계를 순서대로 따르세요.

## 1. 아웃라인과 맥락 읽기

선택한 아웃라인, 관련 워크플로 문서, 지정된 파일을 전체적으로 읽으세요. 합의된 동작, 기존 진행 표시, 사용자의 피드백을 파악하세요.

완성된 아웃라인이고 피드백이 없다면 무엇을 수정하고 싶은지 물어보세요. 미완료 아웃라인이라면 남은 범위와 질문에서 이어서 진행하세요.

## 2. 영향받는 코드와 명령 확인하기

피드백을 소스 파일과 기존 테스트에 대조해 확인하세요. 공백이 있으면 리서치 에이전트를 사용하고, 그 결과를 기다리세요. 검증 단계를 바꾸기 전에 저장소의 검증 명령을 확인하세요.

## 3. 템플릿과 시각화 가이드 읽기

`$SKILLBASE/references/iterate-structure-outline/references/structure_outline_template.md`와 `$SKILLBASE/references/show-me.md`를 읽으세요.

## 4. 단계 재구성하기

작업을 독립적으로 테스트 가능한 결과 단위로 재편성하세요. 유용하다면 관련 모듈 경계를 가로질러도 됩니다. 각 단계의 검사는 그 시점까지 완료된 코드와 함께 동작해야 합니다. 각 결과를 검토할 수 있도록 코드 형태, 책임 소유, 테스트 변경, 충분한 설명을 포함하세요.

범위와 순서에 관한 피드백은 단계와 개요에 함께 반영하세요. 답변된 질문은 관련 섹션에 반영하세요. 이미 검증된 작업의 유효한 완료 표시는 유지하고, 범위가 바뀌어 다시 실행해야 하는 검사는 표시하세요.

## 5. 아웃라인을 그 자리에서 갱신하기

기존 경로와 메타데이터를 유지하고, 필요에 따라 `repos` 목록을 갱신하세요. 간결한 설명, 초점이 맞춰진 시각 자료, 실제 자동 검사를 사용하세요. 사용자의 판단이 필요한 경우에는 수동 검증도 포함하세요. 개요는 단계 제목과 항상 일치하도록 유지하세요.

아웃라인에 대한 피드백은 아웃라인을 갱신하라는 요청으로 취급하세요. 구현하라는 요청은 구현 절차로 넘어갑니다.

## 6. 최종 답변 템플릿을 읽고 응답하기

`$SKILLBASE/references/iterate-structure-outline/references/structure_outline_final_answer.md`를 읽고 갱신된 파일 경로와 다음 명령을 제공하세요.

검토를 위해 VS Code, Cursor, 또는 사용자가 선호하는 편집기나 브라우저에서 문서를 열지 제안하세요.
