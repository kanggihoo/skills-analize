# 예시 제어 루프: React Doctor

분류 체계를 구체화하기 위해, 완전히 작성된 루프 하나를 소개합니다. **이것은 템플릿이 아니라 예시입니다.** 프로덕션 모노레포의 실제 루프로, 단일 앱의 React 코드 품질을 개선합니다. 여러분의 루프에서 설정값, 센서, 컨트롤러, 액추에이터는 다르게 보일 것입니다. *형태*를 복사하고, 세부 사항은 복사하지 마세요.

이 예시가 유용한 이유는 센서와 컨트롤러가 거의 전부 기존의 설정 가능한 도구에서 오기 때문에 루프 전체가 작기 때문입니다.

## 설정값

`apps/riptide-ui`가 영향이 큰 React 문제(린트, 접근성, 정확성, 아키텍처)에서 자유롭게 유지되는 것. 고정된 임계값보다는 방향에 가깝습니다. 실행할 때마다 앱이 조금씩 더 건강해집니다.

## 센서 — `react-doctor` + `doctor.config.ts`

[`react-doctor`](https://github.com/millionco/react-doctor) CLI가 앱을 스캔해 우선순위가 매겨진 문제를 보고합니다. `doctor.config.ts`는 어떤 규칙이 실행되고 어떤 경로/규칙이 무시되는지를 설정합니다. CI에서와 똑같이 로컬에서도 실행됩니다.

```bash
bunx react-doctor --project '@codelayer/riptide-ui' --diff false --yes
```

반복 가능하고, 설정할 수 있으며, 에디터/린트 설정 밖에 있어서 흩어진 인라인 주석 하나가 조용히 끄지 못하도록 하기 때문에 선택되었습니다. 이것은 *이 팀에* 중요했던 트레이드오프이지, 모든 센서의 요건은 아닙니다.

## 컨트롤러 — 센서와 융합

별도의 컨트롤러는 없습니다. `react-doctor`가 "영향도 상위 3개 규칙"을 반환하고, 루프의 정책은 "이번 실행에서 그 상위 3개 규칙의 문제를 최대 5개까지 수정"입니다. 이 선택 로직은 액추에이터의 프롬프트에 있습니다. 이것이 **센서 + 컨트롤러의 경계가 흐려진** 경우입니다. 도구 하나와 작은 정책이 두 가지 일을 모두 합니다.

## 액추에이터 — CodeLayer + 저장소 로컬 스킬

CodeLayer 에이전트가 저장소의 `react-doctor` 스킬로 실행됩니다. 문제별 루프는 에이전트에게 정직한 세 가지 선택지를 줍니다. **수정(fix)**, **무시(ignore)**(이유와 함께 `doctor.config.ts`에 추가), 또는 **건너뛰기(skip)**(사람에게 남김). 그리고 각 변경은 커밋 전에 개별적으로 검증됩니다.

```bash
bun run typecheck
bun run quality
bunx react-doctor --project '@codelayer/riptide-ui' --staged   # 스테이징된 파일에 새 문제 없음
```

## 교란 + 댐퍼

**교란:** 루프가 실행되는 동안 팀원들이 React 코드를 계속 배포합니다.

**댐퍼:** 두 번째 워크플로(`react-doctor.yml`)가 모든 풀 리퀘스트와 `main`으로의 push에서 실행됩니다. 이것은 merge base와 diff를 떠서 *새로 도입된* 문제에만 댓글을 답니다. **기본값은 권고(advisory)**입니다(팀원의 PR을 빨간 X로 막지 않음). 팀이 신호를 신뢰하게 되면 차단 모드로 전환하는 문서화된 경로가 있습니다. 이것이 예약된 루프가 문제를 조금씩 줄여 나가는 동안 문제가 더 나빠지지 않도록 막아 줍니다.

## 루프 — `agent-react-doctor.yml`

예약된 워크플로(매일, 그리고 수동 디스패치와 `/iterate`)가 루프를 실행하고, 본문이 에이전트의 최종 메시지인 PR을 엽니다. 여기서는 센서, 컨트롤러, 액추에이터가 하나의 에이전트 단계로 융합되어 있으므로, 워크플로는 세 개의 별도 단계를 **갖지 않습니다**. 설계에 맞춰 이것들을 합쳤습니다. 결정론적이고 독립적인 센서와 컨트롤러가 있는 루프라면 대신 개별 단계를 가졌을 것입니다.

## 사람이 루프에 참여

- `.github/agent-memory/react-doctor.md`가 매 실행마다 에이전트에 로드됩니다. 예를 들어 "`useEffect` 수정에는 항상 `no-use-effect` 스킬을 사용할 것"이나 "특정 파일만 예외가 필요할 때 규칙을 전역적으로 무시하지 말 것" 같은 지속적인 피드백입니다.
- 메인테이너가 PR에 `/iterate`를 댓글로 남깁니다. PR 본문의 숨겨진 마커가 댓글을 그것을 만든 워크플로로 보내고, 그 워크플로는 PR 컨텍스트와 피드백을 로드해 메모리 파일과 PR을 업데이트합니다. 결정론적인 접착 로직은 `ci-scripts/`(`agent-iteration.ts`, `codelayer-output.ts`)에 있습니다.

## 흐름 제어

모든 PR에는 `agent-react-doctor` 라벨이 붙습니다. 그 라벨이 붙은 열린 PR이 이미 있으면 예약 실행은 건너뛰므로, 루프당 열린 PR은 최대 하나입니다. 수동 디스패치는 이 게이트를 우회합니다.

## 여기서 가져갈 것

- **재사용 가능한 형태:** 교란 하에서의 설정값 → 센서 → 컨트롤러 → 액추에이터, 그리고 댐퍼, 메모리 파일, `/iterate` 조종, 루프당 PR 하나의 흐름 제어.
- **재사용 불가능한 것:** `react-doctor`, bun/CodeLayer 명령, "상위 3개 규칙 / 수정 5개" 정책, `riptide-ui` 범위. 이것들은 이 저장소에 맞춰진 것입니다. 여러분의 것은 인터뷰에서 나와야 합니다.
