# 동작을 증명하라

모든 작업 결과를 실제 대상을 직접 확인해 검증한다. 프록시, 자체 보고, "컴파일된다"로 추측하지 않는다.

**이유:** 검증하지 않은 작업은 정확성을 알 수 없다. 파일 mtime, 출력 최신성, 에이전트의 자체 보고, 캐시된 스크린샷 같은 간접 검증은 직접 관찰보다 싸게 느껴진다. 그러나 잘못된 추론에 따라 행동하는 비용은 원본을 확인하는 비용보다 훨씬 크다.

프록시가 아니라 실제 대상을 확인한다:
- 프로세스가 살아 있는지는 파생된 상태를 거치지 말고 직접 확인한다
- 캐시되거나 파생된 표현이 아니라 실제 값을 읽는다
- 검증이 실패하면 시스템을 의심하기 전에 관찰 방법을 먼저 의심한다

## 가능하면 검사를 스크립트로 만든다

가장 강력한 증명은 같은 비교를 다시 실행하는 결정적 스크립트다. 한 번 눈으로 확인하는 방식이 아니다. 스크립트를 작성해 실행하고, 그 출력을 검토자가 다시 실행할 수 있는 산출물로 남긴다. 내 말을 믿게 하지 않는다.

사람이 볼 수 있도록 산출물을 눈에 띄게 둔다. 감사 가능한 기록이 나중에도 필요한 대규모 또는 복잡한 작업, 예를 들어 큰 포팅이나 마이그레이션에서만 커밋한다(**show-me-your-work** 스킬 참고).
