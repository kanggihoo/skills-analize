# ELI5 스킬

밀도 높고 전문 용어가 많은 기술 문서를 누구나 이해할 수 있는 설명으로 바꿔 주는 에이전트 스킬입니다. 콘텐츠의 명확성 문제를 분석하고, 인라인 정의를 추가하며, 기술적 정확성을 유지한 채 before/after 비교 결과를 만들어 냅니다.

## 이 스킬을 사용할 때

ELI5는 넓거나 다양한 독자층을 대상으로 하는 문서에 사용하세요. 독자마다 도메인 전문성이 다를 수 있는 페이지입니다.

**적합한 대상:**

- 보안 및 네트워킹 문서 (DDoS, WAF, Zero Trust, Browser Isolation, Tunnel)
- 시작하기 및 개요 페이지
- 비개발자를 대상으로 한 개념 페이지
- 여러 도메인에 걸친 제품 간 문서

**사용하지 않는 경우:**

- 개발자용 API 및 SDK 레퍼런스 (Workers, D1, R2, KV)
- 독자가 스스로 선택해 들어오는 코드 중심 튜토리얼
- 전문 용어 자체가 내용인 설정 레퍼런스

## 동작 방식

이 스킬은 SKILL.md에 정의된 9단계 워크플로를 실행합니다.

1. **파일 경로 입력** — 하나 이상의 `.md` 또는 `.mdx` 파일을 받습니다
2. **읽기 및 파싱** — 콘텐츠 유형(overview, concept, how-to, reference, tutorial)을 판별하고 사용자에게 확인을 요청합니다
3. **보강 제약 적용** — 1.5~2배 확장을 목표로 하며, 전면 재작성이 아닙니다. 기존 콘텐츠, 구조, 다이어그램, 컴포넌트를 모두 보존합니다
4. **단순화할 섹션 선택 요청** — 모든 섹션, 특정 섹션, 가장 복잡한 섹션 자동 감지, 사용자 지정 범위 중에서 고를 수 있습니다
5. **선택된 섹션 분석** — 정의되지 않은 전문 용어, 명시되지 않은 가정, 빠진 "이유", 불명확한 논리, 맥락 공백을 표시합니다
6. **용어 추출** — 용어집 정의나 상호 링크가 필요한 용어를 중복 없이 모아, 줄 번호와 제안 조치와 함께 정리합니다
7. **비교 생성** — 원본 콘텐츠, 식별된 문제, 쉬운 말로 된 요약, 비유, 사용 사례, 주의할 점을 포함한 단순화 버전을 담은 before/after 보고서를 만듭니다
8. **보고** — 개선 사항 요약, 원본이 혼란스러웠던 이유, 전체 용어 색인을 제시합니다
9. **적대적 검토** — 새로운 서브에이전트를 실행해 이 저장소의 원본 문서를 기준으로 새로 추가된 모든 주장을 검증합니다. 서브에이전트는 확증 편향을 피하기 위해 ELI5 스킬 지침에 접근할 수 없습니다

적대적 검토는 건너뛸 수 없는 필수 단계입니다. 이 단계는 잘못된 메커니즘을 설명하는 단순화된 설명을 걸러냅니다. 이런 설명은 원래의 전문 용어보다 더 나쁩니다.

모든 결과는 대화창에 인라인으로 제시됩니다. 이 스킬은 출력 파일을 쓰지 않습니다.

## 호출 방법

작업이 스킬 설명과 일치하면 스킬이 자동으로 로드됩니다. 다음과 같이 명시적으로 호출할 수도 있습니다.

```
Run ELI5 on /path/to/docs/folder/
```

스킬은 시작하기 전에 어떤 페이지와 섹션을 처리할지 물어봅니다.

## 프로젝트 구조

```
eli5/
├── README.md                              # 이 파일
├── SKILL.md                               # 스킬 정의 — 전체 9단계 워크플로, 제약, 적대적
│                                          #   검토 프로토콜, 출력 형식, 품질 체크리스트, 안티패턴
├── references/
│   ├── content-type-guide.md              # 콘텐츠 유형별 판별 신호와 전략 (687줄)
│   ├── EXAMPLES_REFERENCE.md              # 상세한 before/after 예시와 출력 템플릿 (1,834줄)
│   └── pattern-library.md                 # 일반적인 명확성 문제를 위한 재사용 가능한 변환 패턴 (634줄)
└── recommendations/
    └── internal-dns/
        └── index.eli5.mdx                 # 예시: Internal DNS 개요 페이지의 제안된 교체본
```

### SKILL.md

실행 명세입니다(439줄). 다음 내용을 담고 있습니다.

- 파일 입력부터 적대적 검토까지 이어지는 전체 9단계 워크플로
- 콘텐츠 유형 판별 신호와 유형별 단순화 전략
- 보강 제약(무엇을 추가하고 무엇을 추가하지 않는지, 문서당 최대 추가량)
- 서브에이전트에 전달하는 적대적 검토 프롬프트 템플릿
- 의사결정 프레임워크(단순화, 내용 추가, 결과 명시, 그대로 두기를 언제 선택할지)
- 품질 체크리스트(18개 항목)
- 사람이 검토한 AI 생성 편집에서 확인된 8개 안티패턴
- 출력 형식 템플릿

### references/

SKILL.md가 상세 예시가 필요할 때 참조하는 보조 자료입니다.

- **content-type-guide.md** — 콘텐츠 유형(overview, concept, how-to, reference, tutorial)을 판별하고 단순화하기 위한 실무 가이드. 판별 기준, 단순화 전략, 유형별 패턴을 포함합니다.
- **EXAMPLES_REFERENCE.md** — 확장된 before/after 예시, 상세한 작성 패턴, 출력 형식 템플릿. SKILL.md가 너무 길어지지 않도록 장황한 예시를 담고 있습니다.
- **pattern-library.md** — 일반적인 단순화 시나리오(전문 용어 치환, 맥락 추가, 비유 구성)를 위한 재사용 가능한 before/after 패턴.

### recommendations/

이전 실행에서 나온 ELI5 출력 예시를 담고 있습니다. `internal-dns/index.eli5.mdx` 파일은 Internal DNS 개요 페이지의 제안된 교체본으로, 편집 내용을 페이지에 직접 적용했을 때 완성된 ELI5 결과물이 어떤 모습인지 보여 줍니다.

## 핵심 원칙

1. **세부 사항보다 맥락 먼저** — 어떻게 동작하는지 설명하기 전에 왜 중요한지 설명합니다
2. **정확성은 타협할 수 없습니다** — 언어를 단순하게 만들되 사실은 단순하게 만들지 않습니다. 새로 추가하는 모든 주장에는 출처가 있어야 합니다
3. **잘 작동하는 것은 보존합니다** — 올바른 문장을 어조 때문에 다시 쓰지 않습니다. 실제 명확성 문제가 있을 때만 수정합니다
4. **독자의 지능을 존중합니다** — 독자에게 부족한 것은 지능이 아니라 맥락입니다. 동의어를 쌓지 말고 무엇을 하는지로 용어를 정의합니다
5. **콘텐츠 유형 인식** — 개요는 문제/해결 프레임이, 개념은 비유가, 레퍼런스는 사용 사례 중심 구성이 필요합니다
6. **Cloudflare 특화 검증** — 업계 표준 동작이 Cloudflare 제품에도 적용된다고 가정하지 않습니다. 이 저장소의 문서와 대조해 검증하세요
