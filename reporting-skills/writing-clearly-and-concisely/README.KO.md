# 명확하고 간결하게 쓰기

윌리엄 스트렁크 주니어(William Strunk Jr.)의 시대를 초월한 글쓰기 원칙을 적용하여, 더 명확하고 힘 있으며 전문적인 문장을 만들고 LLM이 흔히 보이는 AI 특유의 글쓰기 패턴을 피하도록 돕는 스킬이다.

## 목적

이 스킬은 사람이 읽을 글을 더 잘 쓰도록 돕는다. 두 가지 출처에서 가져왔다.

1. **The Elements of Style** (Strunk, 1918) - 명확하고 힘 있는 글쓰기를 위한 시간이 검증한 규칙
2. **AI 패턴 회피** - LLM이 흔히 만들어 내는 모호하고 과장된 언어를 피하기 위한, 연구에 기반한 지침

문서, 커밋 메시지, 오류 메시지 등 사람이 읽을 모든 글에서 이 스킬은 군더더기를 덜어내고 의도한 바를 말하도록 돕는다.

## 사용 시점

사람을 위한 문장을 쓸 때마다 이 스킬을 사용한다.

- **문서** - README 파일, API 문서, 기술 설명
- **Git 작업 흐름** - 커밋 메시지, 풀 리퀘스트 설명
- **사용자에게 보이는 텍스트** - 오류 메시지, UI 문구, 도움말, 툴팁
- **코드 주석** - 인라인 문서, docstring
- **보고서와 요약** - 상태 보고, 분석, 설명
- **편집** - 기존 글의 명확성 개선

**트리거 문구:**
- "...에 대한 문서를 작성해 줘"
- "README 초안을 작성해 줘"
- "명확하게 다듬어 줘"
- "더 간결하게 만들어 줘"
- "이 커밋 메시지를 검토해 줘"

## 작동 방식

1. 사람이 읽을 글을 쓸 때 **스킬을 불러온다**
2. **Strunk의 핵심 원칙을 적용한다** - 능동태, 긍정 형식, 구체적인 언어, 불필요한 단어 생략
3. **AI 패턴을 피한다** - 과장, 빈 표현, 홍보성 형용사를 쓰지 않는다
4. 특정 규칙이 필요할 때는 **상세 가이드를 참조한다**

### 문맥 효율적 접근

이 스킬은 점진적 공개 방식을 써서 문맥을 아낀다.

- **SKILL.md** (약 1,000 토큰)는 핵심 규칙과 함께 먼저 로드된다
- **참조 파일** (각 1,000-4,500 토큰)은 필요할 때만 로드된다
- **대부분의 작업에는 파일 하나면 충분하다**: `03-elementary-principles-of-composition.md`

문맥이 빠듯할 때는 초안과 관련 섹션 파일을 가지고 하위 에이전트(subagent)를 띄운다.

## 주요 기능

### Strunk의 핵심 규칙

이 스킬은 *The Elements of Style*의 다음 원칙을 강조한다.

| 규칙 | 원칙 |
|------|------|
| 10 | 능동태를 사용한다 |
| 11 | 진술은 긍정 형식으로 쓴다 |
| 12 | 명확하고 구체적인 언어를 쓴다 |
| 13 | 불필요한 단어를 생략한다 |
| 16 | 관련된 단어는 가까이 둔다 |
| 18 | 강조할 단어는 문장 끝에 둔다 |

### AI 패턴 탐지

이 스킬은 LLM의 흔한 글쓰기 패턴을 찾아내 제거한다.

- **과장(Puffery)**: 중추적인, 결정적인, 필수적인, 증거, 영속하는 유산
- **빈 "-ing" 표현**: 신뢰성을 보장하는, 기능을 과시하는, 역량을 부각하는
- **홍보성 형용사**: 획기적인, 매끄러운, 견고한, 최첨단의
- **과다 사용되는 AI 어휘**: delve, leverage, multifaceted, foster, realm, tapestry
- **서식 과다 사용**: 과도한 글머리 기호, 이모지 장식, 두 단어마다 굵은 글씨

## 사용 예시

### 예시 1: 커밋 메시지 다듬기

**수정 전:**
> 이 커밋은 사용자 인증이 올바르게 처리되도록 하는 기능을 구현하며, 강력한 오류 처리 능력을 보여 준다.

**수정 후:**
> 오류 처리를 포함한 사용자 인증 추가

### 예시 2: 문서 다시 쓰기

**수정 전:**
> 이 획기적인 기능은 최첨단 기술을 활용해 매끄러운 경험을 제공하며, 더 나은 참여를 촉진하고 영향력 있는 성과를 이끌어 낸다.

**수정 후:**
> 이 기능은 WebSocket 연결을 사용해 대시보드를 실시간으로 갱신한다.

### 예시 3: 수동태 고치기

**수정 전:**
> 구성 파일은 시작 시 애플리케이션에 의해 읽힌다.

**수정 후:**
> 애플리케이션은 시작 시 구성 파일을 읽는다.

### 예시 4: 얼버무리는 표현 제거하기

**수정 전:**
> 특정 상황에서 API가 오류를 반환할 수도 있다는 점을 짚어 두는 것이 중요하다.

**수정 후:**
> 토큰이 만료되면 API가 오류를 반환한다.

## 모범 사례

1. **거창하지 않고 구체적으로 쓴다** - 얼마나 중요한지가 아니라 실제로 무엇을 하는지 말한다
2. **먼저 덜어내고, 나중에 더한다** - 의미가 훼손될 때까지 단어를 줄인 뒤 필요한 것만 다시 넣는다
3. **능동태를 선호한다** - "함수가 X를 반환한다"가 "X는 함수에 의해 반환된다"보다 낫다
4. **긍정 형식으로 쓴다** - "그는 잊었다"가 "그는 기억하지 못했다"보다 낫다
5. **구체적인 언어를 쓴다** - "서버가 다운되었다"가 "문제가 발생했다"보다 낫다
6. **참조 파일은 아껴서 불러온다** - 대부분의 작업에는 `03-elementary-principles-of-composition.md`만 필요하다
