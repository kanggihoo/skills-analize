# AI, LLM, 에이전트 헌팅

#### 이 파일을 사용하는 경우

언어 모델이 신뢰와 관련된 결정에 관여할 때 이 파일을 참조하라. 챗봇과 어시스턴트, RAG 파이프라인, 영속적인 에이전트 메모리, 에이전트/도구 호출 루프, MCP 서버와 클라이언트, 신뢰할 수 없는 입력으로 프롬프트를 구성하는 코드, 또는 모델 출력을 소비하여 그에 따라 동작하는 코드가 해당한다. 중요한 데이터 흐름은 *신뢰할 수 없는 콘텐츠 → 모델 또는 메모리 → 권능, 권한, 또는 싱크(sink)*이다.

이 파일은 `ATTACK-CLASSES.md`를 대체하지 말고 함께 사용하라. 전송, 접근 통제, 쿼리 구성, 파일 시스템 사용, 출력 렌더링은 여전히 일반적인 신뢰 경계이다. 이 파일은 모델에 특화된 위임 계층을 다룬다. 큰 대상은 검색(retrieval), 메모리, 도구 디스패치, MCP, 출력 처리로 분할하라.

## 핵심 원칙 (이 도메인의 모든 에이전트 프롬프트에 포함)

```
- 프롬프트 인젝션(prompt injection)만으로는 발견 사항이 아니다. 코드 수준의 경계 실패가 필요하다. 콘텐츠가 다른 주체의 컨텍스트에 도달하거나, 요청자에게 없는 권한을 호출하거나, 그들이 읽을 수 없는 데이터를 노출하거나, 그들이 직접 도달할 수 없는 싱크를 구동해야 한다.
- 모델 출력, 메모리, 도구 설명, MCP 응답은 신뢰할 수 없는 입력이다. 권한을 부여하거나, 출력을 신뢰하거나, 영속 상태를 쓰거나, 싱크에 공급하는 코드를 가리켜라.
- 가드레일 프롬프트는 보안 경계가 아니다. 결정적 검사, 자원 범위 인가, 격리, 바인딩, 제약된 자격 증명만 인정하라.
- 공격자, 영향받는 주체, 유효 실행 신원, 자원, 정확한 동작, 사용된 권한, 관찰 가능한 영향을 명시하라. 요청자의 기존 권한을 사용하라는 의도적인 직접 요청은 모델이 그것을 실행한다는 이유만으로 위임 결함이 아니다.
- 인가와 동작 바인딩은 별개의 통제이다. 공격자가 제어하는 콘텐츠가 영향받는 주체의 유효한 권한으로 동작을 일으켰고 그 주체가 해당 정확한 동작을 의도적으로 요청하거나 승인하지 않았다면 이는 동작 바인딩 실패이다.
- 모든 후보는 소스 증거와 제한된 로컬 검증이 경계와 결과를 입증한 뒤에만 `confirmed`로 분류하라. 필요한 제공자, 배포, 모델, 렌더러, 또는 신원 동작을 로컬에서 관찰할 수 없을 때는 `needs_validation`을 사용하라.
```

## 컨텍스트, 검색, 메모리 공격 클래스 (subagent_type: `general`)

**검색되거나 수집된 콘텐츠를 통한 간접 인젝션**
공격자가 다른 주체의 모델 컨텍스트로 들어가는 RAG 문서, 인덱싱된 페이지, 파일, 이메일, 이슈 본문, 도구 응답, 또는 메타데이터를 쓸 수 있다. 각 소스를 누가 쓸 수 있는지, 검색이 이를 어떻게 범위 지정하는지, 누구의 세션이 이를 소비하는지, 그곳에서 어떤 권능이 활성화되어 있는지 추적하라. 격리, 자원 인가, 소비 주체의 의도에 대한 바인딩을 별개로 확인하라. 결함은 설득력 있는 텍스트 자체가 아니라 결정적 통제의 부재이다.

**세션 간 또는 테넌트 간 컨텍스트 유출**
대화 이력, 임베딩, 검색 결과, 또는 프롬프트 캐시의 키가 지나치게 넓다. 쿼리 자체와 모든 캐시 키에서 테넌트와 ACL 필터를 검증하라. 객체에 저장된 테넌트 필드는 대체 쿼리, 공유 캐시, 또는 배치 경로가 이를 빠뜨리면 강제가 아니다.

**영속 메모리 포이즈닝**
공격자가 제어하는 콘텐츠나 모델 요약이 이후 다른 작업, 사용자, 또는 특권 세션을 형성하는 메모리에 기록된다. 누가 메모리를 생성, 갱신, 병합, 삭제할 수 있는지, 출처(provenance)와 테넌트 범위, 낮은 신뢰의 관찰이 영속적인 지시나 사실이 되는지, 검색이 사용자 선호와 도구 정책을 구분하는지 검토하라. 사용자가 의도적으로 저장하고 그 사용자의 의도적이고 허용된 요청에만 사용되는 메모리는 경계 간 발견 사항이 아니다.

**프롬프트 역할 및 출처 혼동**
프롬프트 조립이 신뢰할 수 없는 텍스트가 시스템 메시지, 이전 턴, 도구 결과, 정책, 또는 메모리 레코드를 가장하게 허용한다. 문자열 연결, 타입이 없는 이력, 호출자가 제어하는 역할 필드, 소스 레이블을 잃는 직렬화 왕복을 찾아라. 위조된 출처가 결정적 신뢰 결정을 바꾸거나 의미 있는 권능에 도달함을 확인하라.

## 도구 및 동작 공격 클래스 (subagent_type: `general`)

**하위 싱크로의 도구 인자 인젝션**
모델이 생성한 인자가 핸들러 측 검증 없이 SQL, 셸, 파일, URL 가져오기, 또는 특권 API에 도달한다. 도구 스키마를 입력 파싱으로 취급하고, 디코딩된 호출에서 싱크까지 각 필드를 따라가라. 구조화된 출력은 형태를 좁힐 뿐이며, 인가, 안전한 경로, 안전한 URL, 쿼리 의미론을 입증하지 않는다.

**과도한 대리 권한(excessive agency)과 혼동된 대리인(confused-deputy) 권한**
에이전트가 서비스 신원이나 넓은 자격 증명을 사용하지만, 도구 핸들러가 지명된 자원에 대한 요청 주체의 권한을 다시 검사하지 않는다. 유효 신원과, 호출자가 정상적인 제품 인터페이스를 통해 정확히 그 연산을 수행할 수 있는지를 모두 검증하라. 사용자별 쿼리 범위가 강제되는 공유 자격 증명은 결함이 아니다.

**동작 확인 및 승인 바인딩**
사용자가 설명된 하나의 동작을 승인했지만 실행이 변경된 인자, 다른 자원, 다른 주체, 또는 이후의 모델 턴을 사용할 수 있다. 일반 인가가 피해자의 수행을 허용하더라도, 공격자가 제어하는 콘텐츠가 피해자의 의도적인 요청이나 승인 없이 피해자의 유효한 권한으로 부수 효과를 일으키는 경우에도 동작 바인딩 결함이 존재한다. 의도나 확인이 정규화된 도구 이름, 완전한 인자 객체, 요청자, 대상, 금액, 만료, 배치 구성원을 바인딩하는지 검토하라. 재시도와 재개된 세션을 확인하라. 승인이 변형되었거나 중복된 부수 효과를 인가해서는 안 된다.

**도구 스키마와 디스패처의 불일치**
스키마가 별칭, 추가 필드, 중복 키, 강제 변환, 중첩된 자유 형식 객체, 또는 범위를 벗어난 값을 수용하고, 디스패처나 핸들러가 이를 다르게 해석한다. 스키마 검증, 정규화, 생성된 바인딩, 핸들러 기본값을 비교하라. 값이 자원 선택자나 보안과 관련된 옵션이 되는 지점에서 다시 검증하라.

**제한 없는 위임 동작 루프**
제한된 요청이 요청별 예산, 동작별 인가, 취소, 또는 멱등성 통제 없이 반복적인 지출, 전송, 변경, 또는 외부 API 작업을 큐에 넣을 수 있다. 공유 비용, 쿼터, 다른 사용자, 또는 영속 상태에 대한 영향을 확인하라. 서비스를 고갈시키는 방식으로 테스트하지 말고, 코드 수준의 계정 산정과 로컬에서 제한된 루프를 사용하라.

## MCP 및 서브에이전트 신뢰 클래스 (subagent_type: `general`)

**서브에이전트와 MCP 신뢰 상속**
위임된 작업이 필요한 최소 권한 대신 전체 세션, 자격 증명, 메모리, 또는 권능을 받는다. 각 호출에 전달되는 주체와 테넌트, 권능 축소, 자격 증명 audience, 그리고 위임된 결과가 반환 시 신뢰할 수 없는 것으로 취급되는지 확인하라.

**MCP 서버와 도구 신원 혼동**
호출이나 결과가 인증된 연결과 미해결 요청이 아니라 공격자가 영향을 줄 수 있는 서버 이름, 도구 이름, 요청 ID, 자원 URI, 또는 모델이 선택한 별칭으로 라우팅된다. 두 서버가 동일한 도구나 자원 신원을 주장할 수 있는지, 재연결이 바인딩을 바꾸는지, 한 서버의 응답이 다른 서버의 대기 중인 호출을 충족할 수 있는지 확인하라.

**정책으로서의 MCP 메타데이터와 스키마**
MCP 피어가 제공하는 도구 설명, 자원 메타데이터, 프롬프트, 완성 힌트, 또는 스키마가 정책이나 인가로 신뢰된다. 이 필드는 모델을 안내할 수는 있지만 권능을 부여할 수는 없다. 메타데이터가 충돌할 때도 권위를 유지하는 결정적 허용 목록, 서버 신원 검사, 핸들러 인가를 찾아라.

## 출력 및 노출 공격 클래스 (subagent_type: `general`)

**안전하지 않은 출력 렌더링**
모델 출력이 싱크가 요구하는 인코딩과 정책 없이 실행되는 HTML, Markdown, 템플릿, URL, 또는 명령 싱크에 도달한다. 브라우저 렌더링에서는 자동으로 로드되는 리소스와 CSP 또는 새니타이제이션을 `CLIENT-SIDE.md`에서 검증하라. 저장소 밖의 렌더러 동작은 후보를 `needs_validation`으로 만든다.

**민감한 컨텍스트 추출**
조립된 컨텍스트에 자격 증명, 다른 사용자의 데이터, 비공개 소스, 또는 그 자체로 접근을 부여하는 정책 값이 들어 있고, 사용자가 영향을 줄 수 있는 출력이 이를 노출한다. 프롬프트 조립과 데이터 가져오기 코드를 읽어라. 데이터 경계를 넘지 않는 일반적인 지시나 동작의 노출은 발견 사항이 아니다.

## 공통 기법 (위 전체에 적용)

- 먼저 네 가지 맵을 그려라. 각 실행 신원, 각 권능, 쓰기 가능한 모든 컨텍스트 또는 메모리 소스, 각 출력 목적지이다. 그런 다음 시작 지점의 주체를 끝 지점의 권한에 연결하라.
- 부수 효과가 있는 도구에서 시작하여 디스패처, 스키마, 확인, 모델 컨텍스트, 검색, 수집까지 거슬러 올라가라. 영속 메모리 읽기에서 시작하여 모든 작성자를 추적하라.
- 동일한 동작에 대한 직접, 큐잉, 재시도, 재개, 배치, 위임 경로를 비교하라. 가장 강한 게이트는 인자가 확정된 후, 모든 부수 효과 이전에 적용되어야 한다.

## 검증 규칙 (여기서 어떤 발견 사항이든 보고하기 전에 적용)

1. 넘어간 경계와 관찰 가능한 결과를 명시하라. 공격자, 영향받는 주체 또는 공유 자원, 실행 신원, 대상, 무단 또는 요청되지 않은 동작이나 노출이다.
2. 혼동된 대리인 권한 주장에는 도구에 요청자-및-자원 인가가 없고 공격자가 정상적으로 동일한 동작을 수행할 수 없음을 입증하라. 동작 바인딩 주장에는 대신 공격자가 제어하는 콘텐츠가 영향받는 주체가 의도적으로 요청하거나 승인하지 않은 동작을 그 주체의 권한으로 일으켰음을 입증하라. 유효한 일반 인가가 그 의도를 입증하지는 않는다.
3. 메모리나 검색 주장에는 공격자가 제어하는 쓰기와 이후의 주체 간 읽기 또는 특권 결정을 모두 인용하라. 도달 가능한 소비자가 없는 공유 레코드는 충분하지 않다.
4. 동작 바인딩에서는 의도적인 요청 또는 정규화된 승인 객체가 있다면 이를 확정하고 핸들러가 사용하는 객체와 비교하라. 해로운 실행으로 테스트를 확장하지 않고, 로컬에서 관찰 가능한 요청되지 않은 동작, 변경, 중복, 또는 권한 변화를 확인하라. 스키마 불일치에서는 정규화되어 검증된 객체를 핸들러의 객체와 비교하라.
5. MCP 신원 주장에는 인증된 연결, 요청 상관관계, 도구 네임스페이스, 유효 자격 증명을 검증하라. 외부 서버 신원이나 배포 라우팅이 필요하면 `needs_validation`으로 표시하라.
6. 완전한 소스 추적과 의미 있는 결과가 있을 때만 `confirmed` 발견 사항을 반환하라. 특정한 미해결 경계 사실에는 `needs_validation`을 반환하고, 이를 해소하는 데 필요한 제한된 로컬 또는 소유자 관찰 검사를 명시하라.
