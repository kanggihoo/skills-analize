# 출시 및 배포 (Shipping and Launch)

## 개요 (Overview)

자신감을 가지고 배포하세요. 목표는 단순히 코드를 배포하는 것이 아닙니다 — 모니터링을 갖추고, 롤백 계획을 준비하며, 성공의 기준을 명확히 이해한 상태에서 **안전하게 배포하는 것**입니다. 모든 출시는 **되돌릴 수 있고(reversible), 관찰 가능하며(observable), 점진적(incremental)**이어야 합니다.

## 사용 시점 (When to Use)

- 기능을 처음으로 프로덕션에 배포할 때
- 사용자에게 중요한 변경 사항을 릴리스할 때
- 데이터 또는 인프라를 마이그레이션할 때
- 베타 또는 얼리 액세스 프로그램을 시작할 때
- 위험이 따르는 모든 배포 (즉, 사실상 모든 배포)

## 출시 전 체크리스트 (The Pre-Launch Checklist)

### 코드 품질 (Code Quality)

- [ ] 모든 테스트 통과 (단위, 통합, E2E)
- [ ] 경고 없이 빌드 성공
- [ ] 린트 및 타입 검사 통과
- [ ] 코드 리뷰 완료 및 승인됨
- [ ] 출시 전 해결해야 할 TODO 주석이 남아있지 않음
- [ ] 프로덕션 코드에 디버깅용 `console.log`가 없음
- [ ] 예상되는 실패 모드를 다루는 에러 처리가 마련됨

### 보안 (Security)

- [ ] 코드나 버전 관리에 시크릿 노출 없음
- [ ] 의존성 보안 감사(`npm audit`, `pip-audit`, `cargo audit` 등)에서 Critical/High 취약점 없음
- [ ] 모든 사용자 대면 엔드포인트에 입력 유효성 검사 적용
- [ ] 인증 및 인가 검사 적용
- [ ] 보안 헤더(CSP, HSTS 등) 설정 완료
- [ ] 인증 관련 엔드포인트에 속도 제한(Rate limiting) 적용
- [ ] CORS가 와일드카드(*)가 아닌 특정 오리진으로 제한됨

### 성능 (Performance)

- [ ] Core Web Vitals 지표가 "좋음(Good)" 범위 내에 있음
- [ ] 핵심 경로에 N+1 쿼리가 없음
- [ ] 이미지 최적화 완료 (압축, 반응형 크기, 지연 로딩)
- [ ] 번들 크기가 허용 예산 내에 있음
- [ ] DB 쿼리에 적절한 인덱스 적용
- [ ] 정적 에셋 및 반복 쿼리에 대한 캐싱 구성

### 접근성 (Accessibility)

- [ ] 모든 대화형 요소에 키보드 내비게이션 동작
- [ ] 스크린 리더로 페이지 콘텐츠와 구조 파악 가능
- [ ] 텍스트 색상 대비가 WCAG 2.1 AA(4.5:1) 기준 충족
- [ ] 모달 및 동적 콘텐츠의 포커스 관리 정상 동작
- [ ] 폼 필드에 명확한 설명적 오류 메시지 연동
- [ ] axe-core 또는 Lighthouse에서 접근성 경고 없음

### 인프라 (Infrastructure)

- [ ] 프로덕션 환경 변수 설정 완료
- [ ] DB 마이그레이션 적용됨 (또는 적용 준비 완료)
- [ ] DNS 및 SSL 인증서 구성 완료
- [ ] 정적 에셋용 CDN 구성 완료
- [ ] 로깅 및 에러 리포팅 시스템 연동 완료
- [ ] 헬스 체크(Health check) 엔드포인트가 정상 응답함

### 문서화 (Documentation)

- [ ] 새로운 설정 요구사항이 README에 반영됨
- [ ] 최신 API 문서 유지
- [ ] 아키텍처 결정 사항에 대한 ADR 작성 완료
- [ ] 변경 로그(Changelog) 업데이트
- [ ] 사용자용 가이드 문서 업데이트 (해당 시)

## 피처 플래그 전략 (Feature Flag Strategy)

배포(Deployment)와 릴리스(Release)를 분리하기 위해 피처 플래그 뒤에 코드를 숨겨 배포하세요:

```typescript
// 피처 플래그 확인 예시
const flags = await getFeatureFlags(userId);

if (flags.taskSharing) {
  // 새 기능: 작업 공유
  return <TaskSharingPanel task={task} />;
}

// 기본값: 기존 동작 유지
return null;
```

**피처 플래그 라이프사이클:**

```
1. 플래그 OFF 상태로 배포   → 코드는 프로덕션에 존재하지만 비활성 상태
2. 사내/베타 사용자 활성화  → 프로덕션 환경에서 내부 테스트 수행
3. 점진적 롤아웃           → 5% → 25% → 50% → 100% 사용자로 확장
4. 각 단계별 모니터링       → 오류율, 성능, 사용자 피드백 관찰
5. 정리(Clean up)          → 전체 롤아웃 후 플래그 및 레거시 분기 코드 제거
```

**규칙:**
- 모든 피처 플래그에는 담당자와 만료 기한이 있어야 함
- 전체 롤아웃 후 2주 이내에 플래그 코드를 정리할 것
- 플래그를 중첩하지 말 것 (조합이 기하급수적으로 늘어남)
- CI에서 플래그 ON/OFF 양쪽 상태를 모두 테스트할 것

## 단계적 롤아웃 (Staged Rollout)

### 롤아웃 순서

```
1. 스테이징 배포
   └── 스테이징 환경에서 전체 테스트 스위트 실행
   └── 핵심 흐름에 대한 수동 스모크 테스트

2. 프로덕션 배포 (피처 플래그 OFF)
   └── 배포 성공 확인 (헬스 체크)
   └── 에러 모니터링 확인 (신규 에러 없음)

3. 사내 팀 활성화 (내부 사용자 대상 플래그 ON)
   └── 프로덕션에서 팀원들이 실제 사용
   └── 24시간 모니터링 관찰

4. 카나리(Canary) 롤아웃 (사용자의 5%에게 플래그 ON)
   └── 오류율, 지연 시간, 사용자 행동 모니터링
   └── 기준선 대비 카나리 지표 비교
   └── 24~48시간 모니터링 관찰
   └── 모든 임계값을 통과할 때만 다음 단계로 진행 (아래 표 참조)

5. 점진적 확장 (25% -> 50% -> 100%)
   └── 각 단계마다 동일한 모니터링 수행
   └── 문제 발생 시 언제든 이전 비율로 즉시 되돌릴 수 있는 상태 유지

6. 전체 롤아웃 (모든 사용자 대상 플래그 ON)
   └── 1주일간 모니터링 유지
   └── 피처 플래그 정리
```

### 롤아웃 판단 임계값 (Rollout Decision Thresholds)

| 지표 | 진행 (Green) | 보류 및 원인 조사 (Yellow) | 즉시 롤백 (Red) |
|---|---|---|---|
| 오류율 | 기준선 10% 이내 | 기준선 대비 10~100% 증가 | 기준선 대비 2배(>2x) 초과 |
| P95 지연 시간 | 기준선 20% 이내 | 기준선 대비 20~50% 증가 | 기준선 대비 50% 초과 |
| 클라이언트 JS 오류 | 새로운 오류 유형 없음 | 세션의 0.1% 미만에서 신규 오류 | 세션의 0.1% 초과에서 신규 오류 |
| 비즈니스 지표 | 중립 또는 긍정적 | 5% 미만 하락 (단순 노이즈 가능성) | 5% 초과 하락 |

### 즉시 롤백해야 하는 상황

다음 상황에서는 즉시 롤백하세요:
- 오류율이 기준선 대비 2배 이상 증가할 때
- P95 지연 시간이 50% 이상 증가할 때
- 사용자 장애 리포트가 급증할 때
- 데이터 정합성 문제가 감지되었을 때
- 보안 취약점이 발견되었을 때

## 모니터링 및 관찰 가능성 (Monitoring and Observability)

### 모니터링 대상

```
애플리케이션 지표:
├── 오류율 (전체 및 엔드포인트별)
├── 응답 시간 (p50, p95, p99)
├── 요청량 (Request volume)
├── 활성 사용자 수
└── 핵심 비즈니스 지표 (전환율, 참여도)

인프라 지표:
├── CPU 및 메모리 사용률
├── DB 커넥션 풀 사용률
├── 디스크 공간
├── 네트워크 지연 시간
└── 큐 대기열 깊이 (해당 시)

클라이언트 지표:
├── Core Web Vitals (LCP, INP, CLS)
├── JavaScript 런타임 오류
├── 클라이언트 관점의 API 에러율
└── 페이지 로드 시간
```

### 에러 리포팅

```typescript
// React 에러 바운더리
class ErrorBoundary extends React.Component {
  componentDidCatch(error: Error, info: React.ErrorInfo) {
    reportError(error, {
      componentStack: info.componentStack,
      userId: getCurrentUser()?.id,
      page: window.location.pathname,
    });
  }

  render() {
    if (this.state.hasError) {
      return <ErrorFallback onRetry={() => this.setState({ hasError: false })} />;
    }
    return this.props.children;
  }
}

// 서버 측 에러 리포팅 미들웨어
app.use((err: Error, req: Request, res: Response, next: NextFunction) => {
  reportError(err, {
    method: req.method,
    url: req.url,
    userId: req.user?.id,
  });

  res.status(500).json({
    error: { code: 'INTERNAL_ERROR', message: '오류가 발생했습니다' },
  });
});
```

### 배포 후 첫 1시간 점검 (Post-Launch Verification)

배포 직후 첫 1시간 동안:

```
1. 헬스 체크 엔드포인트 200 반환 확인
2. 에러 모니터링 대시보드 확인 (새로운 에러 유형 없는지)
3. 지연 시간 대시보드 확인 (성능 회귀 없는지)
4. 핵심 사용자 흐름을 직접 수동 테스트
5. 로그가 정상적으로 유입되고 읽기 쉬운지 확인
6. 롤백 메커니즘이 정상 동작 준비 상태인지 확인
```

## 롤백 전략 (Rollback Strategy)

모든 배포는 실행 전에 문서화된 롤백 계획이 있어야 합니다:

```markdown
## 롤백 계획: [기능/릴리스 이름]

### 트리거 조건 (Trigger Conditions)
- 오류율이 기준선 대비 2배 초과
- P95 지연 시간이 [X]ms 초과
- [특정 이슈]에 대한 사용자 리포트 발생

### 롤백 단계 (Rollback Steps)
1. 피처 플래그 비활성화 (해당되는 경우)
   또는
1. 이전 버전 재배포: `git revert <commit> && git push`
2. 롤백 상태 검증: 헬스 체크, 에러 모니터링 확인
3. 커뮤니케이션: 팀에 롤백 상황 공유

### 데이터베이스 고려사항
- 마이그레이션 [X]의 롤백 명령어: `npx prisma migrate rollback`
- 새 기능에 의해 삽입된 데이터: [보존 / 정리]

### 예상 롤백 소요 시간
- 피처 플래그 롤백: 1분 미만
- 이전 버전 재배포: 5분 미만
- 데이터베이스 롤백: 15분 미만
```

## 흔한 합리화 및 반박 (Common Rationalizations)

| 합리화 (Rationalization) | 실제 현실 (Reality) |
|---|---|
| "스테이징에서 잘 됐으니 프로덕션에서도 잘 될 것이다" | 프로덕션은 데이터, 트래픽 패턴, 엣지 케이스가 다릅니다. 배포 후 모니터링이 필수입니다. |
| "이 정도 기능엔 피처 플래그가 필요 없다" | 모든 기능은 킬 스위치(Kill-switch)가 있을 때 안전합니다. 사소한 변경도 장애를 냅니다. |
| "모니터링은 나중에 추가하겠다" | 출시 전에 추가하세요. 보이지 않는 것은 디버깅할 수 없습니다. |
| "롤백하는 것은 실패를 인정하는 것이다" | 롤백은 책임감 있는 엔지니어링입니다. 고장 난 기능을 방치하는 것이 진짜 실패입니다. |

## 위험 신호 (Red Flags)

- 롤백 계획 없이 배포를 진행하는 것
- 프로덕션에 모니터링이나 에러 리포팅이 없는 상태
- 빅뱅 릴리스 (단계적 배포 없이 모든 것을 한 번에 적용)
- 만료 기한이나 담당자가 없는 방치된 피처 플래그
- 배포 후 첫 1시간 동안 아무도 모니터링을 보지 않는 것
- "금요일 오후인데 그냥 배포해버리자"

## 최종 검증 체크리스트 (Verification)

배포 전:
- [ ] 출시 전 체크리스트 완료 (모든 항목 통과)
- [ ] 피처 플래그 구성 완료 (해당 시)
- [ ] 롤백 계획 문서화 완료
- [ ] 모니터링 대시보드 설정 완료
- [ ] 배포 일정 팀 공유 완료

배포 후:
- [ ] 헬스 체크 정상 (200 OK)
- [ ] 오류율 정상 범위
- [ ] 지연 시간 정상 범위
- [ ] 핵심 사용자 흐름 정상 동작
- [ ] 로그 정상 유입 확인
- [ ] 롤백 준비 상태 검증 완료
