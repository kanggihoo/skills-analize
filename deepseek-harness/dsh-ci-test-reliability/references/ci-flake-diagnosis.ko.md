# CI flake 진단

이 워크플로는 기존의 확률적 테스트나 CI 실패를 조사하는 작업에만 사용한다. 요청된 읽기/쓰기 범위를 지킨다. 진단은 수정, 워크플로 재실행, CI 설정 변경을 허가하지 않는다.

## 증거 고정

저장소, 워크플로, job, commit SHA, runner 라벨, 타임스탬프, 정확히 실패한 테스트나 명령, 처음으로 안정적으로 나타난 실패 시그니처를 기록한다. 인프라 메시지는 테스트 출력과 분리해 둔다.

실패한 실행과 성공한 실행을 여러 개 비교한다. 같은 SHA의 실행을 우선한다. 그것이 불가능하면, 비교하는 commit들 사이에서 관련 테스트와 CI 설정이 동일한지 확인한다. 한 번 다시 실행해 통과했다고 해서 인프라 결함이 증명되지 않으며, 타임아웃 한 번으로 제품 race가 증명되지도 않는다.

Actions 로그와 메타데이터로 실패가 한 host나 리소스 네임스페이스에서 겹치는지 확인한다. 큰 로그를 붙여 넣지 말고, 근거가 되는 실행의 링크를 보존한다.

## 실패 분류

최종 수정이 아니라 기록된 증거로 분류한다:

- **호스트 리소스 충돌:** 같은 포트, 소켓, 데이터베이스, 예측 가능한 경로, 캐시, 외부 네임스페이스를 독립적인 프로세스나 job이 점유한다.
- **불완전한 수명 주기:** teardown이 자식 프로세스, worker, 스트림, 서버, 콜백이 조용해지기 전에 반환되어, 이후의 출력이나 변경이 다른 테스트에 나타난다.
- **프로세스 전역 오염:** 결과가 테스트 순서나 새어 나간 `process.env`, `cwd`, fake timer, 전역 변수, mock, locale, 모듈 상태에 달려 있다.
- **부하에 민감한 동기화:** sleep, 폴링 간격, 가정한 event-loop 턴이 관찰 가능한 준비 완료나 작업 완료를 대신한다.
- **플랫폼 또는 진입 경로 불일치:** 실패가 운영체제, 셸, 파일시스템 규칙, 소스/빌드 모드, 실행 파일 진입점을 따라 일관되게 나타난다. 타임스탬프 정밀도, 환경 변수 이름의 대소문자, 핸들 해제 타이밍, 권한 의미는 Windows와 POSIX host마다 다르므로, macOS에서 통과한 케이스는 Windows 레인에 대해 아무것도 말해 주지 않는다.
- **제품 동시성 결함:** 테스트가 자신의 리소스를 통제하고, 명시적인 겹침으로 결정적으로 재현되며, 출하된 동작의 race를 드러낸다.
- **외부 제공자의 일시적 장애:** 실패의 소유자가 실시간 API나 네트워크 경계이며, 문서화된 재시도 정책과 일치한다.
- **Runner 인프라:** checkout, 의존성 다운로드, 디스크, host 프로세스, runner 서비스가 테스트 명령과 무관하게 실패한다. 이 분류를 붙이기 전에 runner의 직접 증거를 요구한다. self-hosted 풀이 host 메트릭을 제공하지 않으면 그 사실을 밝히고, 로그에 남은 정보로 분류한다. 한 풀에서 서로 무관한 브랜치 여러 곳에 같은 시그니처가 반복된다면, host를 직접 들여다볼 수 없어도 공유 host 경합의 증거다.

증거가 독립적인 사실을 둘 이상 뒷받침하면 각각 보고한다. 타임아웃, 시그널, 종료 코드, 단언(assertion)을 하나의 추론된 결과로 뭉개지 않는다.

## 가장 작은 관련 토폴로지로 재현

소유한 테스트 파일이나 집중 대상 테스트 이름에서 시작한다. 시그니처를 재현하는 첫 토폴로지까지만 동시성을 높인다:

1. 테스트 프로세스 하나;
2. 동시에 실행되는 테스트나 파일;
3. 여러 개의 독립된 Vitest 프로세스;
4. 설정된 worker 수로 실행하는, 소유한 저장소 게이트;
5. 문제의 host 리소스를 공유하는 별도 job이나 runner 프로세스.

활성 Vitest 설정, 환경 조절 값, 소스/빌드 모드, 플랫폼을 맞춘다. 다른 실패를 만들어 내려고 운영 타임아웃을 낮추거나 무작위 부하를 추가하지 않는다.

시그니처가 사용 가능한 host에서 실행할 수 없는 플랫폼의 것이라면, 사다리는 도달 가능한 마지막 단계에서 멈춘다. 다른 플랫폼에서 통과한 실행으로 대체하지 말고 그 한계를 기록한다. 그다음 CI를 재현 수단으로 사용하되, 실행마다 의심 소유자를 하나만 바꿔서 결과가 원인에 귀속될 수 있게 한다.

race가 의심되면, 확률적 타이밍 대신 경합이 일어나는 전환 지점에 barrier를 둔다. host 충돌이 의심되면, 같은 식별자를 동시에 점유했음을 증명하거나, 원자적 고유 할당이 충돌을 없앤다는 것을 증명한다.

## 소유자에서 수정

구현이 허가되면, 할당하거나, 준비 완료를 게시하거나, 전역 상태를 바꾸거나, teardown을 소유한 컴포넌트를 수정한다. 스냅샷 normalizer, 재시도 래퍼, 더 넓은 타임아웃, 전역 직렬화 설정, 더 약한 단언 뒤에 실패를 숨기지 않는다.

안정적인 fixture 데이터는 실시간 리소스 할당과 분리한다. 기록된 URL은 fixture가 전송 계층을 OS가 할당한 포트로 매핑하는 동안에도 안정적으로 유지될 수 있다. 안정적인 기대 경로는 공유된 쓰기 가능 디렉터리가 되지 않고 단언으로 남을 수 있다.

## 조사 마무리

다음 조건을 모두 충족하면 증거가 완결된다:

- 원래 시그니처에 뒷받침되는 분류가 있다;
- 가장 작은 관련 토폴로지가 이를 재현하거나, 외부 증거가 충분하고 재현 한계가 명시되어 있다;
- 승인된 수정은 negative control이나 수정 전 상태에서 실패하고, 이후 같은 토폴로지에서 통과한다;
- 리소스 소유자가 요구하는 동시 프로세스, 복원, 조용한 teardown 증명이 통과한다;
- 남은 Actions 검사는 관찰된 상태에 따라 passing, pending, skipped, failing 중 하나로 보고된다.

테스트가 우연히 통과할 때까지 돌려서 그 결과를 안정적이라고 부르지 않는다. 선택한 증거가 결론을 세우면 멈추고, 분류를 막는 빠진 사실이 있으면 그것을 보고한다.
