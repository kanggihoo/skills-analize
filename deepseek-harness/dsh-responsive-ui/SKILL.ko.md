# 반응형 클라이언트 UI

## 1. 최소 viewport

기본 수용 기준은 viewport 너비 390 CSS px다. 의도하지 않은 겹침, 잘림, 페이지 전체의 가로 스크롤, 접근할 수 없는 주요 액션이 없어야 한다. 390px 미만에서는 레이아웃 요구사항을 완화할 수 있다.

## 2. 결정 순서

1. 먼저 공간 배분을 조정하거나 요소를 다른 줄로 wrap한다. 그다음 텍스트 truncation, 아이콘 전용 컨트롤, 또는 More 메뉴로 아이콘을 옮기는 방법을 검토한다.
2. 주요 액션과 주요 상태를 생략하지 않는다.
3. 전역 clipping, 모든 글자 크기 축소, 클릭 영역 축소로 충돌을 숨기지 않는다.
4. 제품 디자인에서 특별히 요구할 때만 글자 크기를 줄인다.

## 3. 텍스트 truncation

1. 잘린 내용은 보조 페이지나 메뉴를 열어 전부 볼 수 있어야 한다. 예: 입력창 아래의 세션 통계.
2. Truncation으로 오류나 다른 핵심 정보를 잃으면 안 된다.
3. 탭 내비게이션, 표시되는 selector, 버튼, tag 같은 컴포넌트는 한 줄 truncation을 우선한다.
4. 다른 페이지에서 볼 수 없는 중요한 정보는 잘리지 않고 전부 표시한다.

## 4. 제목

1. 페이지 제목은 전부 표시하는 것을 우선한다. 필요하면 액션 영역을 다른 줄로 옮긴다. 예: Plugins 페이지의 제목 wrapping 동작.
2. 카드 제목은 자연스러운 wrapping을 우선한다. 줄 수를 제한하면 전체 제목을 계속 볼 수 있어야 한다.

## 5. 아이콘 전용 컨트롤

1. 컨트롤을 아이콘으로 줄이려면 두 조건을 모두 충족해야 한다.
   - 아이콘이 의미를 분명히 전달하거나, 사용자에게 익숙한 동작이어야 한다.
   - Hover 시 tooltip이 나타나야 한다. 필요하면 추가한다.
2. "More account information"은 별도 페이지로 이동하므로 아이콘으로 줄이지 않는다.
3. 입력창의 모델 selector는 사용자가 자주 보고 메뉴에서 모델을 바꿀 수 있으므로 아이콘으로 줄일 수 있다.
4. 자동화 작업의 연결된 conversation도 같은 예다.

## 6. 모바일 hover 동작

1. Hover 효과는 viewport 너비와 무관하게 `@media (hover: hover)` 아래에서만 켠다. 이 쿼리는 현재 이벤트가 아니라 기본 pointing device를 본다. 입력 방식이 섞인 기기에서 JavaScript hover handler는 touch 이벤트를 무시해야 한다.
2. 휴대폰에서 탭한 뒤에도 hover 전용 배경, 하이라이트, 액션 버튼 표시가 남으면 안 된다. Hover가 없으면 액션을 계속 보이게 하거나 명시적인 컨트롤로 접근할 수 있어야 한다. 키보드 사용자도 같은 액션에 도달하고 표시할 수 있어야 한다.
3. 선택됨, 펼쳐짐, 활성화됨, 눌림 상태와 focus 표시기는 그대로 유지한다. 이 스타일은 hover 가능 여부와 무관해야 한다. Hover 효과를 없애려고 focus를 지우지 않는다. `:focus-visible`은 터치로 focus된 텍스트 필드에도 적용될 수 있다.
4. 컨트롤이 계속 보이고 상호작용 가능하면 너비가 바뀌어도 focus를 유지한다. 레이아웃을 바꾸려고 컨트롤을 다시 mount하지 않는다. Focus된 컨트롤이 숨겨지거나 제거되면, 모바일 키보드를 불필요하게 띄우지 않으면서 적절한 남은 컨트롤로 focus를 옮긴다.

## 7. 모바일 tooltip

1. 액션 이름이나 키보드 단축키 같은 보조 정보만 제공하는 tooltip은 모바일에서 표시하지 않는다. 예: 복사 버튼의 "Copy" tooltip은 생략한다. 탭하면 원래 동작을 바로 수행한다.
2. 추가 설명을 제공하는 tooltip은 모바일에서 탭해서 표시할 수 있어야 한다. 예: Plugins 페이지 설명 옆의 정보 tooltip.

## 8. 모바일 키보드

모바일에서는 명시적으로 의도한 경우가 아니면 입력 키보드를 자동으로 띄우지 않는다.

## 9. 입력 기능과 모바일 텍스트 필드

1. 표현은 CSS media feature로 제어하는 것을 우선한다. `(pointer: coarse)`는 기본 포인터의 정확도를, `(hover: none)`는 hover 불가 여부를 나타내며, 너비 쿼리는 레이아웃 분기점을 고른다. 이 쿼리들은 물리 키보드를 감지하지 않는다. 파싱한 user agent로 레이아웃을 분기하지 않는다.
2. `(pointer: coarse)`에서 텍스트 필드는 최소 16px를 쓴다. iOS Safari의 focus 확대를 막기 위해서다. 정밀 포인터에서는 기존의 컴팩트한 필드 크기를 유지한다. 필드 규칙의 기준은 `packages/client/ui-plugin-manager/src/client/PluginManagerPage.module.css`를 따른다.
