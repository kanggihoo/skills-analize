# 공식 플러그인 아트워크

공식 아이콘과 같은 시각 언어에 맞는 인식 가능한 아트워크를 그린다. 공식 플러그인과 공식 실험 플러그인은 이 시각 언어를 공유하며, 실험 상태는 UI 라벨이 알려 준다. 이 지침은 디자이너 승인을 대체하지 않는다.

## 선택 기능 미리보기

공식 번들의 상세 문서 상단에 들어갈 큰 이미지를 그리기 전에, [플러그인 기능 미리보기 추가](../../../docs/cookbook/adding-a-plugin-preview.md)를 읽고 그 절차를 따른다. 이 가이드가 선택 여부, 이미지 개수, 디자인 캔버스, 위치, 언어별 변형, 파일 위치, 승인 기준을 정한다. SVG 미리보기에 임베드된 래스터를 허용하는 예외도 이 가이드가 정한다. 작은 아이콘은 여전히 기하 도형만 사용한다. 아래의 아이콘 크기는 미리보기에 적용되지 않는다. 실제 기능을 확인하고, 그 기능이 만든 산출물은 그대로 보존한다.

## 대상 파악

- 그리기 전에 실제 기능, 출력, 소유한 매니페스트를 확인한다. 배지를 만드는 스킬이라면 메달이 아니라 태그가 맞을 수 있다. 디자이너가 제공한 에셋은 재사용한다. 승인 없이 브랜드 마크를 만들거나 제품 이름, 식별자, 관련 없는 아이콘을 바꾸지 않는다.
- [기존 아트워크](../../../packages/client/ui-primitives/src/plugin-artwork.tsx)와 가장 가까운 관련 패키지 SVG를 읽는다. 참조에 있는 모든 효과가 아니라 일관된 처리 방식 하나를 가져온다. 액션 아이콘은 [dsh-client-ui-ux](../dsh-client-ui-ux/SKILL.md#reuse-before-adding)에 남긴다.
- 영향을 받는 모든 항목, 목록, 상세, 컴포넌트 행을 확인한다. 번들 아트워크와 컴포넌트의 이름·아이콘은 메타데이터 소유자가 서로 다를 수 있다. 한쪽을 바꿔도 다른 쪽은 갱신되지 않는다.

## 그리기와 다듬기

1. **단순하게 시작한다.** 주된 대상 하나와, 그것을 설명하는 데 필요한 세부만 쓴다. 관련 기능끼리는 같은 은유를 공유할 수 있다. 추가 패널, 기호, 배지 대신 비율, 실루엣, 팔레트로 구분한다.
2. **광학적 크기를 판단한다.** `width="36" height="36" viewBox="0 0 36 36"`을 사용한다. 여백을 의도적으로 두고 아트워크를 가운데에 놓는다. 18~22 단위는 출발점으로 쓸 만한 범위이지, 모든 실루엣이나 넓은 텍스트 태그에 대한 요구사항은 아니다. 표시 크기와 바깥 타일 프레이밍은 [페이지 렌더러](../../../packages/client/ui-plugin-manager/src/client/PluginManagerPage.tsx)가 맡는다. 타일을 SVG에 구워 넣지 않고, 툴바 글리프를 키워서 타일을 채우지 않는다.
3. **기하를 일관되게 유지한다.** 주된 대상과 보조 요소의 균형을 맞춘다. 반복되는 표시와 모서리를 정렬하고, 꼬리와 손잡이는 의도한 대로 둔다. 요청된 치수 하나만 한 번에 다듬고, 승인된 부분은 바꾸지 않는다.
4. **색은 절제해서 기본으로 쓴다.** 채도와 명도를 주변 아이콘과 맞춘다. [Auto Authorization Review](../../../packages/experimental/auto-review/icon.svg)와 [Codex subagent](../../../packages/subagent/subagent-codex/icon.svg) 같은 기존 팔레트를 우선 쓴다. 매우 선명하거나 밝거나 네온 색은 승인된 브랜드 요구, 필수 대비, 디자이너의 명시적 지시가 있을 때만 쓴다. 채도는 색조·명도와 따로 조정한다. 채도를 줄이려고 아트워크를 회색이나 탁한 색으로 만들지 않는다. 단색 채우기나 짧은 그라데이션, 제한된 레이어를 쓴다. 글로우, 드롭 섀도, 광택 하이라이트, 이모지는 피한다. 페이지 CSS는 여전히 의미 기반 테마 토큰을 쓴다.
5. **글자는 보이는 잉크 기준으로 맞춘다.** 글자 모양, 대문자 높이, 베이스라인, 굵기, 자간을 일관되게 맞춘다. 경로 좌표만 비교하지 말고 렌더링된 획의 가장자리를 비교한다. 획 끝과 이음부 때문에 같은 좌표도 다르게 보일 수 있다. 글자는 폰트 의존성 없이 경로로 내보내고, 실제 크기에서도 읽히게 한다.
6. **빈 영역은 진짜로 투명하게 만든다.** 속이 빈 렌즈는 겹치는 도형 아래에서도 배경이 보여야 한다. 국소 마스크나 컷아웃으로 아래 채우기를 제거한다. 흰색이나 어두운 원을 대신 넣지 않는다. 두 테마 모두 확인한다.

## 소유자에서 내보내기

- 매니페스트의 `icon` 경로를 사용하고 리소스를 게시한다. 의도적으로 복사된 번들·컴포넌트 사본은 함께 갱신한다. 범위에 있으면 현지화된 표시 이름과 설명도 확인한다. 플러그인 아이콘을 바꾸려고 기능이 만든 산출물을 바꾸지 않는다.
- 패키지 이미지는 `<img>`로 렌더링되므로, 자체 포함된 SVG 기하를 내보낸다. 그라데이션, 마스크, 클립 참조는 로컬이고 고유한 이름이어야 한다. 스크립트, 이벤트 핸들러, 애니메이션, 외부 이미지·스타일, 폰트, `foreignObject`를 쓰지 않는다. 인라인 React 아트워크에는 인스턴스별 ID가 필요하다. 별도 이미지 문서는 ID를 공유하지 않는다.
- 아트워크 변경은 로컬에 둔다. 표시하려고 런타임 의존성, 프리미티브 export, 렌더러 특수 처리를 추가하지 않는다.

## 검토와 검증

1. 확신이 없는 기하를 다듬기 전에 번호 붙은 대안을 몇 개 보여 준다. 검토 과정에서 라벨을 유지하고, 선택된 버전을 적용한다. 기존 파일이나 생성된 초안은 디자이너 승인을 뜻하지 않는다. 비교용 산출물은 패키지 안이 아니라 gitignore된 디렉터리에 둔다.
2. 변경 전후 아트워크를 변경되지 않은 참조와 나란히 라이트·다크 테마에서 비교한다. 실제 행·카드 크기와 확대 상태 모두 확인한다. 균형, 글자, 빈 공간, 잘림, 이미지 디코딩을 본다.
3. [패키지 메타데이터와 SVG 아트워크](../../../scripts/verify-package-meta.ts)에는 `pnpm run verify-package-meta`를, 표준 패키지 페이로드에는 `pnpm run constraints`를, 공식 번들 카탈로그에는 `pnpm run verify-official-bundle-catalog`를 실행한다. 오래된 카탈로그는 손으로 고치지 말고 `pnpm run gen-official-bundle-catalog`로 다시 생성한다. 구조 검사는 시각 검토를 대체하지 않는다.
4. 영향을 받는 산출물을 빌드하고 `dsh web`으로 실제 페이지를 확인한다. 메타데이터를 캐싱하는 Host를 재시작하기 전에 승인된 다듬기를 모아서 적용한 뒤, 두 테마에서 항목과 중첩된 컴포넌트 행을 검증한다.
5. 저장소의 UI 테스트 정책을 따르고, GUI PR에는 [record-browser-gif](../record-browser-gif/SKILL.md)를 사용한다. 새 글리프를 머지하기 전에 디자이너 승인을 받는다. 재사용 가능한 그리기 원칙만 여기에 기록하고, 거절된 초안의 이력은 기록하지 않는다.
